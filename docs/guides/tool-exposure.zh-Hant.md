# 為甚麼 ChatGPT 看不到所有工具

## 四個不同環節

工具已註冊、目前設定檔有公開工具、ChatGPT 已存連接有啟用該工具，以及本機允許執行該操作，是四回事。已複製網址或隧道健康，不代表帳戶的對話已載入工具命名空間。

工作區的 ChatGPT 設定現有 **Tool exposure／工具公開狀態**，讀取運行中 MCP 的即時設定。MCP 未運行時會明確標示只顯示已存設定。內容包括公開／已註冊定義數目、被設定檔排除的名稱、實際中繼資料的 SHA-256 及不可執行的定義。MCP 的 `server_info.tool_catalog` 提供相同依據。`client_loaded_tools` 保持 null；並非遠端 ChatGPT 註冊檢查。

## 正確選擇目錄

0.4.3-rc.1 預設使用 `core`，並把 `full` 正規化為 `advanced`，但下拉選單沒有 `core` 或 `advanced`。0.4.3-rc.2 的選單正確表示這兩個值，並把 `full` 視為 `advanced` 的別名。核心設定不再於首次顯示時看似 Full，Advanced 亦不再變成空白選項。

選擇 **Advanced／Full** 並儲存，才會公開所有已註冊定義。Core 仍是明確的較小目錄；唯讀及相容設定檔保留既有服務端行為。本更新不會靜默修改現有設定檔、增加工具、停用批准或允許螢幕擷取。部分定義需要本機啟用；`sandbox_exec` 仍是不可用的佔位定義，並非可執行後端。

## 刷新接收端

開發者模式連接請於 ChatGPT Plugins 開啟既有連接，按 Refresh，檢查及啟用所需操作，再於已選擇該連接的新對話測試。正式發佈的 Plugin 使用經審查的中繼資料快照，可能需要管理員批准更新。本機權限模式與該工具快照並不相同。只修改權限仍保留 MCP、端點及 OAuth；安裝新執行檔後仍須重新啟動應用程式一次。

若桌面程式顯示完整公開目錄，但 ChatGPT 仍沒有部分操作，請查看連接已啟用的操作、所選帳戶／工作區／對話及實際掃描錯誤。不可把所有操作偽裝成唯讀以繞過用戶端批准。不要單憑模型說沒有工具，就刪除 OAuth 憑證或重建連接器。沒有實際連接／掃描依據，就不能完成用戶端根因診斷。

OpenAI 目前的開發者指南與工作區說明文章對方案資格的描述有差異。本程式不會只根據方案名稱推斷資格，也不會硬性封鎖 Pro；以實際帳戶及工作區可用的控制項為準。此處亦不假設固定的工具數目上限。

## 範圍及學習

Paseo／Anneal 自主引擎，以及完整 Codex 私有／內部工具對等功能，屬於未完成的實作，不是隱藏的目錄項目。現有免模型命令、共用看板、記憶體視覺、本機同意及停止控制保持不變。原生模型操作仍須另行啟用；此修正不會發出模型請求。目錄修正亦不會加入靜默帳戶授權或發佈者簽署。

人類與 AI 的流程：界定目標 → 查看目前目錄 → 找出支援的工具 → 確認本機權限 → 執行最小獲准步驟 → 檢視結果 → 記錄觀察 → 由人類審查 → 保存檢查點。任務觀察是待審依據，不是自動的人類批准。已存筆記改善後續上下文重用，不會訓練模型權重。
