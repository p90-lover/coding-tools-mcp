# MCP 內的 Codex 工具：本機執行與真實限制

## 執行環境及範圍

ChatGPT 負責推理，本程式提供經認證及權限檢查的工具，不會啟動 Codex 模型或消耗 Codex 配額。`codex_tools_status` 顯示目前實際開放的全部工具、即時權限修訂版，以及固定於 `openai/codex` Commit `634ebc1865c6ac840ed3ba118f040d527bf4b55d` 的處理器分類清單。清單項目不等於可執行工具；只有已註冊 Schema 並連接實際執行路徑者，才標示為本機對應功能。

既有命令／標準輸入／輸出／停止、Patch、檔案、Git、計劃、工具搜尋、權限申請、圖片及原生電腦操作，仍按工作區設定開放。新增七項具有真實處理器的免模型工具：`list_mcp_resources`、`list_mcp_resource_templates`、`read_mcp_resource`、`request_user_input`、`read_user_input`、`clock_sleep` 及 `wait_for_environment`。

這些是適用 Codex 介面的本機實作，不是 Codex Agent 的全部內部功能。模型及子 Agent 執行、宿主上下文視窗管理、動態擴充回呼、宿主 Plugin 安裝、主動傳送宿主訊息，以及 Code Mode 編排，都需要真正的宿主／供應商；不會用只回傳假成功的工具取代。未驗證的原生命令沙箱及未完成的推論橋接仍未納入；命令安全仍由既有策略層負責，不會冒稱新增作業系統沙箱。

## 資源工作流程

使用 `list_mcp_resources` 取得目前監聽服務的環境及計劃 URI。`read_mcp_resource` 要求清單回傳的伺服器名稱及支援的 URI。`list_mcp_resource_templates` 提供目前監聽服務已擁有的命令 ID 之有限 stdout／stderr 資源範本。這三個處理器亦支援標準 MCP `resources/list`、`resources/templates/list` 及 `resources/read`，使用相同認證及策略檢查，不會宣稱提供訂閱或資源變更通知串流。

介接器不會擷取任意網絡端點、其他 MCP 伺服器、`file://` URI，或未批准的工作區路徑。命令輸出每頁最多 8192 位元組，資源最多 64 KiB。持有其他監聽服務的命令 ID 不代表有權讀取，其既有輸出保留期限亦維持不變。讀取資源不會啟動命令或寫入截圖檔。

## 人類參與的工作流程

用戶端呼叫 `request_user_input`，提供一至三條問題，每條包括 ID、短標題、問題及兩至三個選項。系統立即回傳 `status: pending` 及 `request_id`，不會長時間佔用 MCP HTTP 連線。桌面程式會以英文或繁體中文介面顯示真實問題，讓使用者選擇選項或輸入其他答案，再明確按下傳送或取消。

用戶端以相同 ID 呼叫 `read_user_input`，取得真正答案或待答／取消狀態，不能透過 MCP 自行回答問題。只有可見而且取得焦點的本機主視窗，才能透過本機 IPC 提交答案。每個問題具有獨立的本機表單 Nonce，防止舊表單誤答另一會話的問題。答案只作資訊用途，不會授予權限、啟動命令或代替使用者點擊。

問題按監聽服務隔離，只在記憶體保留最多十分鐘，每個服務最多 32 筆。以同一請求 ID 提交不同問題會被拒絕。權限變更後，下次存取會取消待答問題並清除答案；替換監聽服務後不會沿用舊的活動問題庫。不要輸入密碼或 Token。這不代表密碼學層面的記憶體抹除，亦不能控制接收用戶端保留資料。

## 等待及即時權限

`clock_sleep` 可等待 1–5000 毫秒並回報實際經過時間，不等於上游的十二小時等待，也不會假稱收到 ChatGPT 新訊息事件。`wait_for_environment` 先立即檢查，再按需要等待最多 5000 毫秒，確認目前工作區目錄能否讀取，不會管理遠端環境。兩者在權限修訂變更時停止等待，而且不會在整段延遲期間鎖住權限寫入。

只修改權限時，仍會直接生效，不必重啟監聽服務、更改隧道網址或重新連接 MCP。本版本新增工具，因此升級後須刷新既有 ChatGPT Plugin 的工具定義一次；這與日後一般權限修改是不同操作。安裝新 EXE 後仍須重新啟動桌面程式一次，才能載入新執行檔。

## 連線修復及驗證

本版本保留 [MCP 連線修復](mcp-connection-repair.md) 所述的 OAuth 資源認證挑戰、空白 HTTP 202 通知回應、經認證的 SSE-GET 405 回應、資源探索別名及只含狀態的診斷。能識別 @mention 或複製端點，不代表某個對話已載入工具；只有缺少命名空間，不能證實隧道過期或 ChatGPT 後端被停用。

重點測試涵蓋真實資源處理器／協議路徑、實際答案狀態與隔離、權限變更中斷有限等待，以及原有三項本機 HTTP 連線案例。前端及安裝程式檢查不代表已在使用者實際的 Windows、Cloudflare 或 ChatGPT 帳戶完成端到端驗證。這些驗證不用呼叫模型、Codex 推論或 AI 審查員。

## AI 與人類學習

實際流程為目標 → 小範圍計劃 → 獲准工具 → 可觀察結果 → 人類提問／審查 → 修訂計劃 → 已驗證檢查點。證據不足時，AI 可直接提問，不必捏造使用者偏好。人類可比較預測與實際輸出，選擇修正方式，並把原因寫入已批准的專案筆記；後續會話再重用筆記。這是上下文重用，不是自動訓練模型權重。不要單憑問題已回答或清單已勾選，就把任務標示為完成。

舊有 `compat-readonly-all` 設定檔現會保留真實安全標示，與進階目錄一致，不會再把寫入偽裝成讀取來影響宿主批准。用戶端仍可能正常要求批准或限制寫入工具。
