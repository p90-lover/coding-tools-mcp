# Coding Tools v0.7.0-rc.2 Consolidation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Consolidate the approved provider, subagent, orchestrator, Paseo, Anneal, proxy, Traditional Chinese, OAuth, and release work into one tested v0.7.0-rc.2 lineage and promote it safely.

**Architecture:** The published v0.7.0-rc.1 source remains the trusted release baseline. A normalized provider/agent registry feeds Paseo routing and Anneal-compatible structured workflows; Anneal owns monitoring and completion evaluation, while the Electron UI exposes provider, agent, orchestrator, task, monitor, proxy, and locale controls. Legacy fixes are ported by verified behavior rather than by merging stale branches.

**Tech Stack:** TypeScript, React/Electron, Svelte routes retained by the Rust/Tauri control surface, Node test runner, Rust/Cargo, GitHub Actions, Electron Builder.

**Spec:** `docs/superpowers/specs/2026-09-16-v0.7-rc2-consolidation-design.md`

## Global Constraints

- Never delete files, branches, tags, releases, or retained evidence.
- Put temporary scripts and validation evidence under `aiTemp/`; put replaced retained material under `Trash/`.
- Never bundle provider credentials or browser session secrets.
- Preserve the published `v0.7.0-rc.1` tag and installer.
- Keep local-loopback control traffic out of externally configured proxy routes.
- Do not mark a task complete without fresh GitHub Actions or equivalent exact-source verification evidence.
- Promote to `main` only after the rc.2 source and installer gates pass.
