# Coding Tools v0.8.138

## English

### MCP: OpenAI Platform's sign-in happens in your Chrome and is kept for the account

- **The problem.** Connect MCP stopped with "OpenAI Platform asked this account to sign in again" when the account's saved OpenAI sign-in was missing or had run out. Only you can sign in, and on Windows the app's own browser hands sign-ins to Chrome, so there was nowhere to finish it.
- **What changed.**
  - When Connect MCP stops at Platform's sign-in, it starts the sign-in by itself: Chrome opens Platform's login page. Sign in there with the same account. The card's **Sign in to OpenAI Platform** button does the same.
  - Coding Tools adds that OpenAI sign-in to the account's own saved session, only if your Chrome's ChatGPT login is the same account, then connects again once. Later setups use it without asking. The account's ChatGPT session is not changed.
  - The Chrome connector is now 1.2.0. After updating, choose **Reload** for Coding Tools in `chrome://extensions` so Chrome opens Platform's page for you. Until then the 1.1 connector still works: sign in to Platform in Chrome yourself.

### CPA: the app no longer names CPA Helper

- Provider Manager 0.10.0 removes CPA Helper's quota polling, account routing and Auto Review account-chain refusals, at your request. CPA's own account rotation decides, including its cooldowns after rate limits. Usage and cost history stay. The live app gets Provider Manager 0.10.0 through App plugins' automatic update.
- The chat's plan-limit meter says "Plan limits aren't tracked: Provider Manager no longer reads account quota" instead of "CPA Helper is not installed in CPA". Nothing asks CPA to re-check account quota any more.
- The cost tooltip names Provider Manager's price book, and the Auto Review error points at Provider Manager > Auto Review.

### Verification

- New tests fail on the old code and pass now: the connector's Platform mode, keeping only OpenAI cookies and only for the matching account, and Connect starting the sign-in once.
- 88 test files around the browser, the Chrome connector, the runtime and the app pass (2,031 tests). The quota and usage tests pass (34). The full TypeScript check passes.
- Platform's signed-out behaviour was checked in a browser: every Platform page goes to /login.
- Not checked in the installed app with a real Platform sign-in before release.
- Includes everything in 0.8.137.

## 繁體中文

### MCP：OpenAI Platform 登入改在你的 Chrome 中進行，並為該帳號保存

- **問題。** 帳號儲存的 OpenAI 登入遺失或過期時，「Connect MCP」會停在「OpenAI Platform asked this account to sign in again」。只有你本人能登入，而在 Windows 上 App 內建瀏覽器會把登入交給 Chrome，所以沒有地方可以完成登入。
- **變更。**
  - 「Connect MCP」停在 Platform 登入時，會自動開始登入：Chrome 會開啟 Platform 的登入頁面，請用同一個帳號在那裡登入。卡片上的「Sign in to OpenAI Platform」按鈕也會這樣做。
  - 只有在你 Chrome 中的 ChatGPT 登入是同一個帳號時，Coding Tools 才會把這次 OpenAI 登入加入該帳號自己的已儲存工作階段，然後再連線一次。之後的設定會直接使用，不再詢問。該帳號的 ChatGPT 工作階段不會被更改。
  - Chrome 連接器現在是 1.2.0。更新後，請在 `chrome://extensions` 中為 Coding Tools 按「Reload」，Chrome 才會自動為你開啟 Platform 頁面。在那之前，1.1 版連接器仍可使用：請自行在 Chrome 中登入 Platform。

### CPA：App 不再提及 CPA Helper

- 依你的要求，Provider Manager 0.10.0 移除了 CPA Helper 的額度輪詢、帳號路由，以及 Auto Review 帳號鏈的拒絕。改由 CPA 自己的帳號輪替決定，包括遇到速率限制後的冷卻。用量與費用記錄仍保留。執行中的 App 會透過 App plugins 的自動更新取得 Provider Manager 0.10.0。
- 聊天的方案用量表會顯示「Plan limits aren't tracked: Provider Manager no longer reads account quota」，不再顯示「CPA Helper is not installed in CPA」。App 也不再要求 CPA 重新檢查帳號額度。
- 費用提示改為標示 Provider Manager 的價目表；Auto Review 的錯誤訊息改為指向 Provider Manager > Auto Review。

### 驗證

- 新測試在舊程式碼上失敗、現在通過：連接器的 Platform 模式、只為相符的帳號保存 OpenAI cookie，以及「Connect MCP」只自動開始一次登入。
- 瀏覽器、Chrome 連接器、runtime 與 App 相關的 88 個測試檔通過（2,031 項）；額度與用量測試通過（34 項）；完整 TypeScript 檢查通過。
- 已在瀏覽器中確認 Platform 未登入時的行為：所有 Platform 頁面都會導向 /login。
- 發佈前沒有在已安裝的應用程式內以真實的 Platform 登入檢查。
- 包含 0.8.137 的所有內容。
