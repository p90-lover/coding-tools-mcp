# Coding Tools v0.8.132

## English

### CPA: Provider Manager 0.8.0

- **Smart routing now covers every sign-in account, not just Codex.** Until now it chose only between Codex accounts, and only when Codex was the sole provider for a model. Everything else went to CPA's round-robin, which kept sending requests to spent accounts and paid API keys. That covered a model several providers serve (GPT-6 Astra on Codex accounts and an OpenAI key), Claude models on Antigravity accounts and a Claude key, and every Antigravity account.
- **What changed.** Provider Manager now reads quota about once a minute for Claude sign-in accounts (five-hour and weekly limits, plus the Opus and Sonnet weeklies) and for Antigravity accounts (per model group). Within each priority tier it uses accounts with quota left first, then accounts without a fresh reading, then API keys. A spent account is never chosen while another can answer. An Antigravity request is judged by its own model's group, so a spent Claude group doesn't stop Gemini requests.
- **What you will see.** Provider Manager's Accounts page has new **Claude quota** and **Antigravity quota** views. The bundled plugin moves from 0.7.1 to 0.8.0 when the app next starts CPA.

## 繁體中文

### CPA：Provider Manager 0.8.0

- **智慧路由現在涵蓋所有登入帳號，不只 Codex。** 過去它只在 Codex 帳號之間選擇，而且只在某個模型只由 Codex 提供時才會介入。其他請求都交給 CPA 的輪流分配，因此一直被送到已用完的帳號和需付費的 API 金鑰。受影響的包括：由多個供應商提供的模型（Codex 帳號和 OpenAI 金鑰都提供的 GPT-6 Astra）、Antigravity 帳號和 Claude 金鑰提供的 Claude 模型，以及所有 Antigravity 帳號。
- **改了什麼。** Provider Manager 現在大約每分鐘讀取一次 Claude 登入帳號的配額（5 小時和每週限制，以及 Opus 與 Sonnet 的每週限制），以及 Antigravity 帳號的配額（按模型群組）。在每個優先級內，先用還有配額的帳號，再用沒有最新讀數的帳號，最後才用 API 金鑰。只要還有其他帳號能處理，就不會選用已用完的帳號。Antigravity 的請求依它自己模型所屬的群組判斷，所以 Claude 群組用完不會擋住 Gemini 的請求。
- **你會看到的變化。** Provider Manager 的「帳號」頁新增「Claude 配額」和「Antigravity 配額」檢視。應用程式下次啟動 CPA 時，內附外掛會從 0.7.1 換成 0.8.0。
