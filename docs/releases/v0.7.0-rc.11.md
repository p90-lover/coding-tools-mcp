# Coding Tools v0.7.0-rc.11

## English

This prerelease lands the one-app managed five-stack on `main` as working Desktop functions: Codex Router, CPA / CLIProxyAPI, CommandCode Proxy, Anneal, and Paseo. It is the next exact-source Windows publish after frozen `v0.7.0-rc.8`, `v0.7.0-rc.9`, and `v0.7.0-rc.10`. Those tags are not moved.

### Why a new version

- `v0.7.0-rc.10` already published the rc.8 release-line Windows installer.
- This revision continues the one-app managed design onto latest `main` (including #181 CommandCode surgical wiring) and therefore publishes as `v0.7.0-rc.11`.

### Desktop contents

- App-managed install, repair, start, stop, and health for Codex Router (`127.0.0.1:4202`), CPA (`127.0.0.1:8317`), CommandCode Proxy (`127.0.0.1:9090`), Paseo (`127.0.0.1:6768` HTTP and matching execution WebSocket), and Anneal (web `5173`, API `3000`).
- **In-app cross-use:** Start injects the same loopback map into every managed process and the MCP/runtime supervisor. Codex Router defaults OpenAI-compatible calls to local CPA (`:8317/v1`); CommandCode Proxy sees CPA as `COMMANDCODE_UPSTREAM_*`; Paseo/Anneal get each other’s URLs plus CPA. CPA itself does **not** inherit `OPENAI_BASE_URL` (no self-proxy loop). Router Start writes `state/codex-router/router/in-app-providers.json` for CPA + CommandCode. `router integrate --with-cpa` registers the same CPA loopback without a key prompt.
- Integrations Control Plane **Start all** unpacks the five-stack runtimes shipped inside the Desktop app bundle (CPA first, then Codex Router and CommandCode, then Paseo, then Anneal). Start uses local app resources only: there is no network install gate and no “download component first” panel.
- CPA / Codex Router 7-day keep-alive from #190 is composed in (cherry-picked from the rc.8 line). It is not reimplemented here.
- Anneal still needs host Docker and, on Windows, WSL2; those host services are not fully offline-bundled. Paseo/Anneal `npm ci` is a package-time step; Start fails closed if `node_modules` was not shipped.
- Original CPA management UI and Codex Router Control Center remain hosted inside Coding Tools.
- Paseo and Anneal original UIs stay embedded on real upstream routes.
- Tauri `0.4.11` identity is unchanged. This tag is the Electron Desktop product identity.

### Packaging and migration

- Electron Builder publication autodetection stays disabled; only the exact-source release publisher may upload GitHub assets.
- The Windows installer keeps the validated legacy NSIS and MSI migration path, the stable Electron app id, and user data.
- Release validation covers identity alignment, focused five-stack and bootstrap contracts, isolated renderer inspection, Windows packaging, packaged launcher smoke, migration acceptance, checksums, provenance, and remote asset readback.

### Exact-source provenance

- The publisher checks out the immutable triggering SHA and refuses publication if remote `main` advances during verification.
- Existing tags are never force-moved: if `v0.7.0-rc.11` already exists on another SHA, publication fails closed.
- Frozen tags `v0.7.0-rc.8`, `v0.7.0-rc.9`, and `v0.7.0-rc.10` are not retargeted.

### Validation boundary

Automated validation does not consume paid provider quota. Live account login, Anneal WSL2/Docker prerequisites, and external local-service acceptance remain explicit manual boundaries.

## 繁體中文

呢個 prerelease 把 one-app managed 五棧以真正可用功能合入 `main`：Codex Router、CPA／CLIProxyAPI、CommandCode Proxy、Anneal 同 Paseo。佢係凍結咗 `v0.7.0-rc.8`、`v0.7.0-rc.9`、`v0.7.0-rc.10` 之後嘅下一個 exact-source Windows 發佈，唔會移動舊 tag。

### 點解要用新版本

- `v0.7.0-rc.10` 已經發佈咗 rc.8 release 線嘅 Windows installer。
- 今次把 one-app managed 設計接到最新 `main`（含 #181 CommandCode 外科接入），所以用 `v0.7.0-rc.11`。

### Desktop 內容

- Codex Router（`127.0.0.1:4202`）、CPA（`127.0.0.1:8317`）、CommandCode Proxy（`127.0.0.1:9090`）、Paseo（`127.0.0.1:6768` HTTP 同對應 execution WebSocket）、Anneal（web `5173`、API `3000`）都由 App 內建執行環境負責啟動、修復、停止同健康檢查。
- **App 內交叉使用：** Start 會把同一套 loopback map 注入每個托管進程同 MCP／runtime supervisor。Codex Router 預設把 OpenAI 兼容呼叫打去本機 CPA（`:8317/v1`）；CommandCode Proxy 用 `COMMANDCODE_UPSTREAM_*` 指住 CPA；Paseo／Anneal 互相知道對方 URL 同 CPA。CPA 自己唔會繼承 `OPENAI_BASE_URL`，避免自迴圈。
- Integrations 控制台「全部啟動」會解包 Desktop **app bundle 內**嘅五棧 runtime（先 CPA，再 Codex Router 同 CommandCode，再 Paseo，最後 Anneal）。Start 只用本機 app 資源，冇網絡安裝閘，亦冇「先下載元件」面板。
- #190 嘅 CPA／Codex Router 7 日 keep-alive 已合成入嚟（從 rc.8 線 cherry-pick），今次唔會重寫。
- Anneal 仍然需要主機 Docker，Windows 仲要 WSL2；呢啲主機服務今次未做到完全離線內建。Paseo／Anneal 嘅 `npm ci` 係打包時做；如果 `node_modules` 冇隨包出，Start 會 fail closed 而唔會上網裝。
- 原本 CPA management UI 同 Codex Router Control Center 仍然托管喺 Coding Tools 入面。
- Paseo 同 Anneal 原版 UI 繼續用真實上游路由嵌入。
- Tauri `0.4.11` 身份不變；呢個 tag 係 Electron Desktop 產品身份。

### 打包同 Migration

- 仍然停用 Electron Builder 自動推斷 publication；只有 exact-source release publisher 可以上傳 GitHub asset。
- Windows installer 保留已驗證嘅舊 NSIS／MSI migration 流程、穩定 Electron app id，同使用者資料。
- Release 驗證涵蓋 identity 對齊、五棧同 bootstrap contract、隔離 renderer 檢查、Windows 打包、packaged launcher smoke、migration acceptance、checksum、provenance 同遠端 asset readback。

### Exact-source 來源保證

- Publisher 只會 checkout 觸發 workflow 嘅固定 SHA；如果驗證期間遠端 `main` 有更新，就會拒絕發佈。
- 現有 tag 永遠唔會被 force-move：如果 `v0.7.0-rc.11` 已經指向另一個 SHA，發佈會 fail closed。
- 唔會改寫已凍結嘅 `v0.7.0-rc.8`、`v0.7.0-rc.9`、`v0.7.0-rc.10`。

### 驗證邊界

自動驗證唔會消耗付費 provider quota。真實帳戶登入、Anneal 嘅 WSL2／Docker 前置，同外部本機服務驗收仍然係明確人工邊界。
