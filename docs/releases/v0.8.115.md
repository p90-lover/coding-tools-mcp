# Coding Tools 0.8.115

## English

### Chats (#1261, #1258, #1262, #1263, #1265, #1273, #1259)
- **A new context window applies to an open chat right away (#1261).** Picking one no longer needs a message: the chat's agent restarts at the new size on its own conversation, so it still knows the whole chat. Before, the next message went to a fresh agent that got only a summary of the chat. A pick made while the agent is working applies when its turn ends.
- **A chat no longer fails for good when the agent's version check couldn't run on a busy machine (#1258).** Agent Orchestrator reports it as a passing failure and the chat is started again. It also stops re-scanning every usage transcript every 5 minutes when one transcript file is gone.
- **Subagent avatars no longer show up empty on a second chat page (#1262).** Two subagents with the same avatar shared one colour definition, and when the first one was on a hidden page the visible one drew blank. Each avatar now has its own.
- **The chat details show a pull request as soon as the turn that opened it ends (#1263).** The PR row used a saved answer for up to 2 minutes, so a pull request the agent had just opened could stay missing.
- **A subagent's header shows the reasoning effort it actually runs at (#1265).** When a model takes other levels than the one saved, or the agent picks its own (agy), the header no longer shows the saved effort.
- **Queued messages recover from a failed read after a restart without reopening the chat (#1273).** If delivery can't be checked yet, the app waits and checks again instead of sending the same message twice.
- **A message sent right after an update keeps its chat's agent (#1259).** For about a minute after the app restarted its agent service, a follow-up could go to a chat the service was still reconnecting. It then failed, and the chat went on with a new agent that knew only a summary. The message now waits a moment for the reconnect.
- **Fewer stalled requests while an agent waits for approval (#1259).** The install note on an approval card was looked up again on every refresh after a failed lookup, and once per open chat page. On a busy disk these lookups timed out in bursts and held up other requests. It's now looked up once per project a minute and shared.

### ChatGPT accounts (#1259)
- **Switching ChatGPT accounts while the disk is busy updates the models.** Switching the Browser tab to an account with another plan could fail with "core-setup timed out after 15000ms" and ask you to run Install models again: a 15-second check before setup was cut off while it was still working. It now gets a minute. The bridge connect that runs beside it no longer fails with "Another launcher operation is active".

### MCP accounts (#1266, #1269)
- **Automatic MCP setup no longer marks the account in use as "ChatGPT verification is required" while it is signed in (#1266).**
- **A failed automatic connect is retried after a while instead of never (#1266),** so accounts and their tunnels connect by themselves once the cause passes.
- **You can log out of ChatGPT, remove a Browser account or sign in while MCP connector setup is running (#1269).** The setup stops and tries again later. ChatGPT's own Log out no longer gets stuck on "Logging out...", and the address bar works during MCP setup.

## 繁體中文

### 對話（#1261、#1258、#1262、#1263、#1265、#1273、#1259）
- **在已開啟的對話中選擇新的上下文視窗會立即生效（#1261）。**不必傳送訊息：對話的代理會以新的大小在原本的對話上重新啟動，因此仍然記得整個對話內容。以前，下一則訊息會交給一個只拿到對話摘要的新代理。若在代理工作時選擇，則會在該輪結束後生效。
- **電腦忙碌導致代理程式版本檢查無法執行時，對話不再永久失敗（#1258）。**Agent Orchestrator 會將其視為暫時性失敗，對話會重新啟動。當某個使用量記錄檔已不存在時，它也不再每 5 分鐘重新掃描所有使用量記錄。
- **子代理頭像在第二個對話頁不會再變成空白（#1262）。**兩個外觀相同的子代理原本共用同一個顏色定義，當第一個位於隱藏的頁面時，可見的那個就會畫成空白。現在每個頭像都有自己的定義。
- **開啟 PR 的回合一結束，對話詳細資料就會顯示該 PR（#1263）。**PR 列原本會沿用最多 2 分鐘前的結果，所以代理剛開啟的 PR 可能一直不出現。
- **子代理的標題會顯示它實際使用的推理強度（#1265）。**當模型支援的等級與儲存的不同，或代理自行決定（agy）時，標題不再顯示儲存的推理強度。
- **重新啟動後，排隊訊息能從暫時的讀取失敗中自動恢復，不必重新開啟對話（#1273）。**若暫時無法確認訊息是否已送出，應用程式會稍後再檢查，而不是重複傳送。
- **更新後立即送出的訊息會保留對話原本的代理（#1259）。**應用程式重新啟動代理服務後約一分鐘內，後續訊息可能送往服務仍在重新連接的對話，結果失敗，對話改由只知道摘要的新代理接手。現在訊息會稍候重新連接完成。
- **代理等待批准時，卡住的請求減少（#1259）。**批准卡片上的安裝說明在查詢失敗後，每次重新整理都會再查一次，而且每個開啟的對話頁面各查一次。磁碟繁忙時，這些查詢會成批逾時並拖慢其他請求。現在每個專案每分鐘只查一次，並共用結果。

### ChatGPT 帳號（#1259）
- **磁碟繁忙時切換 ChatGPT 帳號也會更新模型。**將瀏覽器分頁切換到不同方案的帳號時，可能因設定前 15 秒的檢查在仍進行中時被中止，而以「core-setup timed out after 15000ms」失敗，並要求重新執行「安裝模型」。現在這項檢查有一分鐘時間。同時進行的橋接連線也不再以「Another launcher operation is active」失敗。

### MCP 帳號（#1266、#1269）
- **自動 MCP 設定不會再在帳號已登入時，把正在使用的帳號標示為「需要 ChatGPT 驗證」（#1266）。**
- **自動連線失敗後會稍後重試，而不是永遠停止（#1266），**因此問題消失後帳號及其通道會自行連上。
- **MCP 連接器設定進行中時，現在也能登出 ChatGPT、移除瀏覽器帳號或登入（#1269）。**設定會先停止，稍後再自動重試。ChatGPT 本身的「登出」不再卡在「Logging out...」，MCP 設定期間網址列也可正常使用。
