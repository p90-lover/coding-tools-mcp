# Coding Tools v0.7.0-rc.8

## English

This release completes architecture B: Codex Router, Paseo, and Anneal remain separately installed local services, while Coding Tools owns one unified GUI, encrypted CPA-style Provider Hub, health/lifecycle control plane, and execution-routing policy.

### Complete five-stack control plane

- Codex Router is configured and monitored from the Integrations surface, and its loopback URL plus encrypted caller key are injected only into owned runtime processes.
- CPA-style Provider Hub manages multiple Codex, CommandCode, Antigravity, API-key, browser-session, and custom provider accounts with default/fallback routing.
- CommandCode Proxy supports OAuth, CLI-session import, encrypted account binding, model discovery, and health probing.
- Paseo and Anneal expose persisted execution endpoints, install/start/stop/restart/health controls, and full embedded local-service interfaces.
- Codex subagents, Paseo, and Anneal share the same provider/account/model/fallback/proxy policies.
- Codex OAuth and ChatGPT Web login fail closed until the isolated BrowserHost proves an authenticated session.

### Packaging and migration

- Electron Builder publication autodetection is disabled; only the exact-source release publisher may upload GitHub assets.
- The Windows installer keeps the validated legacy NSIS and MSI migration path and preserves user data.
- Release validation covers strict TypeScript, runtime syntax, focused five-stack contracts, isolated renderer inspection, Windows packaging, packaged launcher smoke, migration acceptance, checksums, provenance, and remote asset readback.

### Exact-source provenance

- The release publisher checks out the immutable triggering SHA and refuses publication if the remote release branch advances during verification.
- Windows installer assets, checksums, and provenance are uploaded only after the five-stack routing, packaged-runtime, migration, and no-deletion gates all pass.
- Superseded branches, workflows, source files, and retained evidence remain available; the publication path does not delete project material.

### Validation boundary

Automated validation does not consume paid provider quota. Live account and external local-service acceptance remains an explicit manual boundary.

## 繁體中文

今次 release 完成架構 B：Codex Router、Paseo 同 Anneal 保持為另外安裝嘅本機服務，而 Coding Tools 會統一管理 GUI、加密 CPA 形式 Provider Hub、健康／生命週期控制，同執行路由政策。

### 完整五項控制平面

- Codex Router 可以喺 Integrations 頁面設定同監察；loopback URL 同加密 caller key 只會注入由 App 擁有嘅 runtime process。
- CPA 形式 Provider Hub 管理多個 Codex、CommandCode、Antigravity、API Key、瀏覽器 Session 同自訂供應商帳戶，支援預設同後備路由。
- CommandCode Proxy 支援 OAuth、CLI Session 匯入、加密帳戶綁定、模型探索同健康檢查。
- Paseo 同 Anneal 提供持久化執行端點、安裝／啟動／停止／重新啟動／健康控制，同完整內嵌本機服務介面。
- Codex subagent、Paseo 同 Anneal 共用同一套供應商／帳戶／模型／後備／Proxy 政策。
- Codex OAuth 同 ChatGPT Web 登入會 fail closed，直至隔離 BrowserHost 證明已完成驗證。

### 打包同 Migration

- 已停用 Electron Builder 自動推斷 publication；只有 exact-source release publisher 可以上傳 GitHub asset。
- Windows installer 保留已驗證嘅舊 NSIS／MSI migration 流程，並保留使用者資料。
- Release 驗證涵蓋 strict TypeScript、runtime syntax、五項集中 contract、隔離 renderer 檢查、Windows 打包、packaged launcher smoke、migration acceptance、checksum、provenance 同遠端 asset readback。

### Exact-source 來源保證

- Release publisher 只會 checkout 觸發 workflow 嘅固定 SHA；如果驗證期間遠端 release branch 有更新，就會拒絕發佈。
- 只有五項路由、packaged runtime、migration 同 no-deletion gate 全部通過，先會上傳 Windows installer、checksum 同 provenance。
- 被取代嘅 branch、workflow、source file 同保留證據全部繼續存在；發佈流程唔會刪除 project 內容。

### 驗證邊界

自動驗證唔會消耗付費 provider quota。真實帳戶同外部本機服務驗收仍然係明確人工邊界。
