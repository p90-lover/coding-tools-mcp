# Coding Tools 0.8.49

## English

### Freeze diagnostics
- When the main thread is held for 4 s or longer and no tracked call explains it, the launcher log now names the code that was waiting (`launcher.main_stall_caller`): a helper thread briefly pauses the main thread once it runs again and records its stack, then resumes it at once. A 61 s freeze on 0.8.48 had no named cause (PR #862).

### Antigravity CLI and Agent Orchestrator
- The agy terminal, Agent Orchestrator's own view and its project board no longer cover the sidebar when it opens over the page from its icon rail, or while a full-page prompt is shown; the page returns as soon as it closes (PR #864).

### Smoother app
- The Services status no longer re-reads the saved proxy settings from disk on the main thread for every refresh; on 0.8.48 those reads froze the app for up to 12.8 s on a busy hard disk. A change to the proxy settings still shows at once, and CPA and agy always start with the current proxy (PR #867).
- CPA's saved config is likewise read once and reused until CPA rewrites it, instead of on every Services refresh (PR #881).
- Several slow chats refreshing at once no longer pile up requests: Agent Orchestrator board and run reads are shared while one is still running, and a board poll no longer throws away the run cache (PR #886).
- Startup does less disk work: a warm launch checks only the installed runtime, files are hashed in chunks instead of whole, old-runtime cleanup waits 30 s after the window shows, routine app logs stay in memory (set `CODING_TOOLS_PERSIST_LOGS=1` to keep them on disk), and an unchanged state save is written once (PR #885).
- Output from the Agent Orchestrator daemon, CPA and other helpers no longer piles up while the main thread is busy; on 0.8.49 that backlog grew the main process to 11.3 GB and froze the window for 408 s. The CPA update check and project-card git calls also moved off the main thread (that check blocked it for up to 18 s), and memory warnings now say where the memory is (PR #887).

### Chat
- A reply's summary (changed files, a team's cards, then the model, status, time and file totals) now sits under the answer instead of above it; a failed turn still shows its error first (PR #865).
- Annotations stay with their message: a steered message keeps its annotations, comments, typed text and attachments together instead of a cut-off preamble and a second pending bubble, and drafts and sent messages share a Codex-style annotation attachment (PR #814).
- The agent's own task list shows in the default transcript, open while it runs and folded once done; other models' activity uses DeepSeek's specific headings and readable arguments, and every thought opens the same way (PR #869).
- Setting a custom context size no longer sends what is typed in the chat box, and Enter now applies the size (PR #835).

### Chat and agents
- The first message of a chat now sits inside its agent's reply card, with its attachments and actions, instead of in a separate bubble above it (PR #870).
- A native chat send that was accepted but lost its acknowledgement can be found again, so retrying no longer starts a second turn (PR #872).
- A tool search that is still pending keeps its receipt instead of failing as an invalid page (PR #873).
- File reads with escaped or invalid characters fit the tool-result limit and keep their continuation (PR #875).
- A wall-clock correction between a tool call and its result no longer leaves the turn looking busy (PR #877).
- Checkpoints saved by two overlapping chat requests are both kept (PR #879).
- A chat's history scroll position is recovered after a reload, and derived files that didn't change are left untouched (PR #880).
- Permission saves stay with the chat and project they were made in (PR #815), and the mission and new-chat selectors use the team they show (PR #816).
- Typing into, reading or stopping a sandboxed command after a restart, or once its output expired, reports that it has ended instead of asking to type into another terminal and then failing (PR #834).
- Parallel tool requests are reviewed at the same time, with one lookup of where the agent works, instead of one after another (PR #845).
- A WebGPT reply survives its browser helper closing after ChatGPT accepted the prompt: a new helper finds that same reply and streams the rest, without sending the prompt again (PR #839). A WebGPT turn's identity is also recorded only once (PR #837).

### Browser, accounts and services
- Browser Management can set up an account on the main MCP tunnel, without an extra tunnel (PR #871).
- A browser broker that closes while starting no longer takes over or removes a newer broker's endpoint (PR #874).
- Overlapping CPA starts, or Stop during a start, no longer leave duplicate or untracked processes, and an unverified saved process ID is never stopped (PR #876).
- Moving a Codex thread between accounts keeps its routing unchanged when saving fails (PR #878).
- Switching CPA usage between 24h and 7d and back no longer lets an older reply overwrite newer usage or show a stale error (PR #884).
- The CPA panel reads account quotas one at a time, with a 2 s gap, instead of all at once (PR #829).

### Verification and limitations
- Everything in 0.8.48 is included.
- The contributor guide now says every change ships as a pull request, a merge and a release (PR #883).
- The stack is taken at the main thread's first function call after the wait ends; a waiting function that returns without another call is reported by its caller or by whatever runs next.

## 繁體中文

### 停頓診斷
- 主執行緒被佔住 4 秒或以上、而沒有已追蹤的呼叫可解釋時，啟動器日誌現在會記錄當時在等待的程式碼（`launcher.main_stall_caller`）：輔助執行緒會在主執行緒恢復運作時短暫暫停它、記錄其呼叫堆疊，然後立即恢復。0.8.48 曾有一次 61 秒的停頓找不到原因（PR #862）。

### Antigravity CLI 與 Agent Orchestrator
- 從圖示列展開側邊欄、或顯示全頁提示時，agy 終端機、Agent Orchestrator 本身的畫面及其專案看板不再遮住側邊欄；關閉後畫面即恢復（PR #864）。

### 更流暢的程式
- 「服務」狀態每次更新時不再在主執行緒從磁碟重新讀取已儲存的代理設定；在 0.8.48，這些讀取曾在忙碌的硬碟上令程式停頓最多 12.8 秒。代理設定變更仍會即時顯示，CPA 和 agy 啟動時一律使用目前的代理（PR #867）。
- CPA 的已儲存設定同樣只讀取一次，並沿用至 CPA 重寫為止，不再於每次「服務」更新時讀取（PR #881）。
- 多個緩慢的對話同時更新時不再堆積請求：Agent Orchestrator 的看板與執行讀取在進行中時會共用，看板輪詢亦不再清除執行快取（PR #886）。
- 啟動時的磁碟工作更少：暖啟動只檢查已安裝的執行環境，檔案以分段而非整個檔案計算雜湊，舊執行環境的清理延至視窗顯示 30 秒後，日常程式記錄只保留在記憶體（設定 `CODING_TOOLS_PERSIST_LOGS=1` 可保留於磁碟），內容不變的狀態只寫入一次（PR #885）。
- 主執行緒忙碌時，Agent Orchestrator 常駐程式、CPA 及其他輔助程式的輸出不會再堆積；在 0.8.49，這些積壓令主程序增長至 11.3 GB，並令視窗停頓 408 秒。CPA 更新檢查與專案卡片的 git 呼叫亦已移出主執行緒（該檢查曾阻塞主執行緒最多 18 秒），記憶體警告現會指出記憶體用在何處（PR #887）。

### 對話
- 回覆的摘要（變更的檔案、團隊卡片，以及模型、狀態、時間和檔案統計）現在位於答案下方而非上方；失敗的回合仍會先顯示錯誤（PR #865）。
- 註解會留在所屬的訊息：引導訊息的註解、評論、輸入文字和附件會保持在一起，不再變成被截斷的前言和第二個待處理對話框；草稿和已送出的訊息共用 Codex 風格的註解附件（PR #814）。
- 代理自己的工作清單會顯示在預設對話記錄中，執行時展開、完成後收合；其他模型的活動使用 DeepSeek 的具體標題和易讀的參數，每段思考的展開方式一致（PR #869）。
- 設定自訂上下文大小時，不會再送出輸入框中的文字，按 Enter 也會套用大小（PR #835）。

### 對話與代理
- 對話的第一則訊息現在連同附件和操作，位於其代理的回覆卡片內，而非卡片上方的獨立對話框（PR #870）。
- 原生對話送出已被接受但確認遺失時可再次找到，重試不會再開始第二個回合（PR #872）。
- 仍在處理中的工具搜尋會保留其回執，不會被當成無效頁面而失敗（PR #873）。
- 含跳脫字元或無效字元的檔案讀取會符合工具結果上限，並保留續讀位置（PR #875）。
- 工具呼叫與結果之間的系統時間校正，不會再令回合一直顯示忙碌（PR #877）。
- 兩個重疊對話請求所儲存的檢查點都會保留（PR #879）。
- 重新載入後會恢復對話歷史的捲動位置，未變更的衍生檔案則保持不變（PR #880）。
- 權限設定會儲存在建立它的對話和專案中（PR #815），任務和新對話的選擇器會使用其顯示的團隊（PR #816）。
- 在重新啟動後或輸出過期後，對沙箱指令輸入、讀取或停止，會回報該指令已結束，不再要求在其他終端機輸入然後失敗（PR #834）。
- 平行的工具請求會同時審查，並只查詢一次代理的工作位置，不再逐一等待（PR #845）。
- ChatGPT 接受提示後，即使瀏覽器輔助程式關閉，WebGPT 的回覆仍可保留：新的輔助程式會找到同一則回覆並串流其餘內容，而不會再次送出提示（PR #839）。WebGPT 回合的身分也只會記錄一次（PR #837）。

### 瀏覽器、帳號與服務
- 瀏覽器管理可在主要 MCP 通道上設定帳號，無需額外通道（PR #871）。
- 啟動期間關閉的瀏覽器代理程式不會再接管或移除較新代理程式的端點（PR #874）。
- 重疊的 CPA 啟動，或在啟動期間停止，不會再留下重複或未追蹤的程序，且不會停止未經驗證的已儲存程序 ID（PR #876）。
- 在帳號之間移動 Codex 對話串時，若儲存失敗，其路由維持不變（PR #878）。
- 在 24 小時與 7 天之間來回切換 CPA 用量時，較舊的回覆不會再覆蓋較新的用量或顯示過時的錯誤（PR #884）。
- CPA 面板會逐一讀取各帳號的配額，每次間隔 2 秒，不再同時讀取（PR #829）。

### 驗證及限制
- 包含 0.8.48 的所有內容。
- 貢獻指南現註明每項變更都以拉取請求、合併及發行版本推出（PR #883）。
- 堆疊取自等待結束後主執行緒的第一個函式呼叫；若等待中的函式直接返回而沒有再呼叫其他函式，則會記錄其呼叫者或之後執行的程式碼。
