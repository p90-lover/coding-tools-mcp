# Coding Tools v0.7.0-rc.3

## English

v0.7.0-rc.3 carries forward the complete v0.7.0-rc.2 integration and adds the verified Provider Hub, multi-account routing, global proxy management, and strict Paseo/Anneal execution-planning layer.

### Provider Hub and multiple accounts

- Adds the packaged Electron Provider Hub for managing multiple accounts per provider.
- Keeps Codex OAuth, Claude OAuth, ChatGPT Web, OpenAI API, Anthropic API, Gemini API, AI Studio Reverse Proxy, Gemini Reverse Proxy, OpenRouter, AIStudioToAPI, CLIProxyAPI / Antigravity, CommandCode Proxy, Ollama, and custom OpenAI-compatible providers in one catalogue.
- Supports default-account selection, account enable/disable state, connection health, model catalogues, and account-specific routing.
- Keeps secret values outside renderer snapshots and execution plans. Runtime execution receives an ID-only credential handle instead of raw credentials.

### Global and scoped proxy routing

- Adds reusable proxy profiles with account, provider, and global routing precedence.
- Resolves routes in this order: account policy, account profile, provider policy, then global policy.
- Supports explicit direct routing when provider or account inheritance is disabled.
- Preserves localhost and loopback bypass handling and keeps unrelated providers isolated.

### Strict Paseo and Anneal execution planning

- Adds a typed execution-planning API for both `paseo` and `anneal` workloads.
- Supports explicit provider, account, and model selection.
- Strict mode fails closed when a requested provider or requested account is unavailable.
- Optional fallback selects the next healthy provider account according to the approved priority catalogue.
- Plans include provider protocol, selected account, model, resolved proxy route, fallback status, and an ID-only credential handle.
- No raw OAuth token, API key, proxy password, or stored secret is returned to the renderer.

### Existing v0.7 capabilities retained

- Electron Provider Center and structured Anneal Orchestrator Plan A.
- Paseo and Anneal authenticated execution bridge.
- Codex Router multi-provider subagents and managed native V2 `agent_type` definitions.
- AI Studio, Gemini-compatible, OpenAI-compatible, and image-generation adapters.
- ChatGPT Web `/goal`, browser-profile isolation, OAuth persistence and security contracts.
- Traditional Chinese control-center localization and onboarding improvements.
- Authenticated Rust headless service and typed Electron IPC boundary.

### Release integrity

- Windows x64 installer is built from one exact source SHA.
- Package identity, runtime bundle identity, installer contents, launcher smoke, and release assets are verified before publication.
- Release assets include the installer, `SHA256SUMS.txt`, `provenance.json`, and `validation-evidence.json`.
- Temporary and retained evidence stays under `aiTemp/` and `aiTemp/Trash/`.
- No project file or branch is deleted by the integration or release process.
- The installer remains per-user and does not request administrative elevation.

### Validation boundary

Automated validation does not spend provider quota. Final live acceptance with real provider accounts, OAuth sessions, paid API quotas, and external Paseo/Anneal services remains an explicit manual validation boundary.

## 繁體中文

v0.7.0-rc.3 保留 v0.7.0-rc.2 嘅完整整合，並加入已驗證嘅 Provider Hub、多帳戶路由、全域代理管理，同嚴格 Paseo／Anneal execution planning。

### Provider Hub 同多帳戶管理

- 已打包嘅 Electron Provider Hub 可以為每個供應商管理多個帳戶。
- 統一支援 Codex OAuth、Claude OAuth、ChatGPT Web、OpenAI API、Anthropic API、Gemini API、AI Studio Reverse Proxy、Gemini Reverse Proxy、OpenRouter、AIStudioToAPI、CLIProxyAPI／Antigravity、CommandCode Proxy、Ollama 同自訂 OpenAI-compatible provider。
- 支援預設帳戶、帳戶啟用／停用、連線健康狀態、模型清單，同帳戶級路由。
- Secret 唔會進入 renderer snapshot 或 execution plan；執行時只會傳送由 provider ID 同 account ID 組成嘅 credential handle。

### 全域同分層 Proxy Routing

- 加入可重用 proxy profile，支援帳戶、供應商同全域路由優先次序。
- 路由次序係：account policy、account profile、provider policy、global policy。
- 當帳戶或供應商關閉繼承時，可以明確使用 direct routing。
- 保留 localhost／loopback bypass，並維持不同供應商之間嘅隔離。

### 嚴格 Paseo／Anneal Execution Planning

- 為 `paseo` 同 `anneal` 加入 typed execution-planning API。
- 可以明確指定 provider、account 同 model。
- Strict mode 喺指定 provider 或 account 無法使用時會 fail closed，唔會靜默轉用其他帳戶。
- 開啟 fallback 後，先會按已批准 priority catalogue 選擇下一個健康帳戶。
- Plan 會包含 provider protocol、所選帳戶、model、已解析 proxy route、fallback 狀態，同只含 ID 嘅 credential handle。
- Renderer 唔會收到 OAuth token、API key、proxy password 或任何已儲存 secret。

### 保留現有 v0.7 功能

- Electron Provider Center 同 Structured Anneal Orchestrator Plan A。
- Paseo／Anneal authenticated execution bridge。
- Codex Router 多供應商 subagent 同原生 V2 `agent_type`。
- AI Studio、Gemini-compatible、OpenAI-compatible 同 image-generation adapter。
- ChatGPT Web `/goal`、browser profile isolation、OAuth persistence 同 security contract。
- 繁體中文 Control Center 本地化同 onboarding 改善。
- 已驗證 Rust headless service 同 typed Electron IPC boundary。

### Release 完整性

- Windows x64 installer 由單一精確 source SHA 建置。
- 發佈前會驗證 package identity、runtime bundle identity、installer contents、launcher smoke 同 release assets。
- Release 會提供 installer、`SHA256SUMS.txt`、`provenance.json` 同 `validation-evidence.json`。
- 臨時同保留證據只會放喺 `aiTemp/` 同 `aiTemp/Trash/`。
- Integration 同 release 流程唔會刪除任何 project file 或 branch。
- Installer 維持 per-user 安裝，唔會要求管理員權限。

### 驗證範圍

自動驗證唔會消耗 provider quota。使用真實 provider 帳戶、OAuth session、付費 API quota 同外部 Paseo／Anneal service 嘅最終 live acceptance，仍然屬於明確嘅手動驗證範圍。
