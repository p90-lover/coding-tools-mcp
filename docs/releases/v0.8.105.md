# Coding Tools 0.8.105

## English

### Chats: a reply's changed files open in the side panel (#1138)
- **Click a file in a reply's "N files" list to see its diff.** The side panel opens on its **Changes** tab, in the worktree of the agent whose edit wrote the file, with that file selected.
  - **View all changes** opens the whole diff.
  - Since 0.8.65 the list only showed names and line counts: nothing was wired to open them.
  - The tab reads the diff again on each click, so a file the reply has just written is there.
  - The agent's edit can name a file as an absolute Windows path (`G:\…\src\App.tsx`). It still finds the diff's `src/App.tsx`, with or without matching case.
  - If the worktree no longer lists the file, for example because it was committed since, the tab opens on its first file.
  - A ChatGPT web turn has no worktree diff, so its files stay plain text, as before.
- **Claude style: the jump-to-latest button has no shadow,** like the default style's.

### Chats: ten split panes stay responsive (#1144)
- **A page of ten working chats in split panes no longer lags, and switching back to it no longer hangs.**
  - With Settings › Chat › "Keep work expanded on a mission" on (the default), every working chat drew every thought and tool call it had made. Ten such chats put about 63,000 elements on one page, and every frame redrew all of them.
- **A long turn shows its newest 40 steps.** "Show earlier steps · N not shown" above them shows 40 more per click. The steps you went back for stay while the turn keeps working. An open step group with more than 40 steps works the same way.
- **Turns far above or below what a pane shows are not drawn** until you scroll near them. They keep their size, so scrolling doesn't jump.
- In a ten-pane test built from the real chat (ten working chats, 400 steps each):
  - The ten-chat page drew 4 to 5 times as many frames (87 → 347–481 in 8 s).
  - Switching back to it went from a 3.5 s freeze to a longest pause of 0.25–0.33 s, with the first frame after 0.08–0.1 s instead of 1.4 s.
  - The two-chat page went from 2.8 s busy in 5 s to 0.26 s.

### Chats: "Let the model judge" no longer looks stuck (#1139)
- **Right after the judge took over a request, or allowed one AO hadn't dropped yet, the chat said "waiting for approval · waiting for you for 8m"** and offered Continue, which restarts the agent.
  - It now says "the reviewer is checking", then "the reviewer allowed" or "denied".
  - Turning the judge on gives a waiting request a fresh review.

### Codex chats' own shell commands go through RTK (#1140)
- **Claude Code chats already had rtk's hook; Codex's own shell ran commands as written.** Each new Codex chat now starts with rtk's PreToolUse hook on its own command line, trusted for that chat only.
  - So `git status` runs as `rtk git status`, and the model reads a fraction of the output.
  - Your Codex settings don't change. It needs rtk 1.0.1 or later; the RTK page shows a "Codex shell" row.

### Activity: Action time (#1142)
- **Activity has a new Action time section: each tab's and page's render time and response time.**
  - **Tabs:** how long each tab takes to draw after you pick it (median, 95th percentile, slowest and last). Its first open is shown apart, because a tab mounts once and stays loaded. Also how long the app takes to answer the requests made while that tab is shown, naming the slowest request.
  - **Pages:** every web page the app opens (Browser tab accounts, GPT Browser, sign-in pages), by account and address. Response is the time until the server answers; render is the time until the page has loaded. The last HTTP status shows too, so Cloudflare's check appears as 403, along with failed loads.
  - Slow values are coloured. **Clear** starts the record again.
  - The record stays in memory (at most 60 tabs and pages, 40 recent samples each) and is gone when the app quits. Nothing is written to disk, and nothing runs inside the pages.

### Verification and limitations
- New tests cover: the click opening the Changes tab on the right agent and file; View all changes; ChatGPT web turns keeping plain text; the pane picking the file only once its diff has loaded, keeping your own choice through Refresh, reading a new file whole, and falling back to the first file; and the path matching.
- The renderer typecheck passes. The full desktop suite passes 4,405 of 4,428 tests locally (20 skipped). The three failures are environmental: two Keysmith tests timed out under suite load, and native-ao-tree needs the AO submodule, which that worktree had not checked out. GitHub Actions is unavailable for this repository.
- Not checked in the running app: the tests render the real chat and Changes pane, not the packaged window.
- Two fix notes that missed their releases are added: `docs/fixes/annotation-message.md` (0.8.49) and `docs/fixes/cpa-quota-refresh-delay.md` (0.8.49).
- #1144: new render tests cover both transcripts: a 300-step turn draws its newest steps under the control and counts what it leaves out, and a 100-step group draws steps 61–100. The chat suites (529 tests) and the renderer typecheck pass. The ten-pane numbers come from a production build of the real chat components in Electron, not the installed app.
- #1139: a new workflow test replays the live sequence (it fails on main and passes), plus a renderer test.
- #1140: a real Codex app-server ran `rtk git status` for the model's `git status` through AO's driver (10 tokens read instead of 51); the rtk tests (18/18) and the desktop typecheck pass. It moves module/agent-orchestrator to c4c453b35, so the AO daemon is rebuilt from that pin.
- Includes everything in 0.8.104.

## 繁體中文

### 對話：回覆變更的檔案可在側邊面板開啟（#1138）
- **在回覆的「N 個檔案」清單中點一個檔案，即可查看它的差異。** 側邊面板會開啟在 **Changes** 分頁，位於寫入該檔案的代理的工作樹中，並選取該檔案。
  - **View all changes** 會開啟完整差異。
  - 自 0.8.65 起，這個清單只顯示檔名與行數，沒有任何動作可以開啟它們。
  - 每次點擊都會重新讀取差異，所以回覆剛寫入的檔案也會出現。
  - 代理的編輯可能以 Windows 絕對路徑（`G:\…\src\App.tsx`）指稱檔案，仍可找到差異中的 `src/App.tsx`，大小寫不同也可以。
  - 若工作樹已不再列出該檔案（例如之後已提交），分頁會開啟在第一個檔案。
  - ChatGPT 網頁回合沒有工作樹差異，因此它的檔案仍是純文字，與之前相同。
- **Claude 樣式：跳到最新的按鈕不再有陰影，** 與預設樣式相同。

### 對話：十個分割窗格保持流暢（#1144）
- **一頁有十個正在工作的分割窗格對話時不再卡頓，切換回該頁也不再停頓。**
  - 開啟「設定 › 對話 ›『任務期間保持工作展開』」時（預設開啟），每個正在工作的對話都會繪製它做過的每個思考與工具呼叫。十個這樣的對話會在一頁放進約 63,000 個元素，每一格畫面都要全部重繪。
- **較長的回合只顯示最新的 40 個步驟。** 其上方的「Show earlier steps · N not shown」每按一次再顯示 40 個；回合仍在工作時，你回頭查看的步驟會保留。超過 40 個步驟的展開步驟群組也一樣。
- **遠離窗格可見範圍的回合不會繪製**，捲動到附近時才繪製；它們保持原本的大小，所以捲動不會跳動。
- 以真實對話元件建成的十窗格測試中（十個正在工作的對話，每個 400 個步驟）：
  - 十個對話的頁面繪製的畫面多了 4 至 5 倍（8 秒內 87 → 347–481 格）。
  - 切換回該頁由停頓 3.5 秒，變為最長停頓 0.25–0.33 秒，第一格畫面在 0.08–0.1 秒後出現，而非 1.4 秒。
  - 兩個對話的頁面在 5 秒內的忙碌時間由 2.8 秒降至 0.26 秒。

### 對話：「讓模型判斷」不再看似卡住（#1139）
- **判斷者剛接手一個請求，或允許了一個 AO 尚未移除的請求時，對話會顯示「等待核准 · 已等待你 8 分鐘」**，並提供會重新啟動代理的 Continue。
  - 現在會顯示「審查者正在檢查」，然後是「審查者已允許」或「已拒絕」。
  - 開啟判斷者時，正在等待的請求會重新接受審查。

### Codex 聊天自己的殼層指令也經過 RTK（#1140）
- **Claude Code 聊天早已有 rtk 的掛鉤，而 Codex 自己的殼層一直按原樣執行指令。** 現在每個新的 Codex 聊天啟動時，都會在自己的命令列加上 rtk 的 PreToolUse 掛鉤，只信任該聊天。
  - 因此 `git status` 會以 `rtk git status` 執行，模型只需讀取一小部分輸出。
  - 你的 Codex 設定不會改變。需要 rtk 1.0.1 或以上；RTK 頁面新增「Codex shell」一列。

### 活動：操作耗時（#1142）
- **「活動」新增「操作耗時」區塊：記錄每個分頁及網頁的繪製時間與回應時間。**
  - **分頁：** 選取分頁後多久繪製完成（中位數、第 95 百分位、最慢及最近一次）。首次開啟另外列出，因為分頁只掛載一次並保持載入。也記錄在該分頁顯示時應用程式回應請求所需的時間，並標示最慢的請求。
  - **網頁：** 應用程式開啟的每個網頁（Browser 分頁帳戶、GPT Browser、登入頁面），依帳戶及位址列出。回應是伺服器回應前的時間；繪製是網頁載入完成前的時間。也會顯示最近的 HTTP 狀態（Cloudflare 檢查顯示為 403）及載入失敗次數。
  - 較慢的數值會以顏色標示。**清除** 會重新開始記錄。
  - 記錄只保存在記憶體中（最多 60 個分頁及網頁，各保留最近 40 筆），應用程式結束後即清除。不會寫入磁碟，也不會在網頁中執行任何程式碼。

### 驗證與限制
- 新測試涵蓋：點擊會在正確的代理與檔案上開啟 Changes 分頁；View all changes；ChatGPT 網頁回合保持純文字；面板只在差異載入後才選取檔案、重新整理時保留你自己的選擇、完整讀取新檔案，以及退回第一個檔案；還有路徑比對。
- 介面型別檢查通過。完整桌面測試套件在本機通過 4,428 項中的 4,405 項（20 項略過）；三項失敗屬環境因素：兩項 Keysmith 測試在套件負載下逾時，native-ao-tree 需要 AO 子模組，而該工作樹沒有簽出。此儲存庫無法使用 GitHub Actions。
- 未在執行中的應用程式內檢查：測試呈現的是真實的對話與 Changes 面板，而不是封裝後的視窗。
- 補上兩份錯過發佈的修正說明：`docs/fixes/annotation-message.md`（0.8.49）與 `docs/fixes/cpa-quota-refresh-delay.md`（0.8.49）。
- #1144：新的繪製測試涵蓋兩種對話呈現：300 個步驟的回合會在控制項下方繪製最新的步驟，並計算未顯示的數量；100 個步驟的群組會繪製第 61–100 個步驟。對話測試（529 項）及介面型別檢查通過。十窗格的數據來自真實對話元件在 Electron 中的正式建置，而不是已安裝的應用程式。
- #1139：新的流程測試重播實際發生的順序（在 main 上失敗、修正後通過），另有一個介面測試。
- #1140：實際的 Codex app-server 經 AO 驅動程式，把模型的 `git status` 執行為 `rtk git status`（讀取 10 個 token 而非 51 個）；rtk 測試（18/18）及桌面型別檢查通過。它把 module/agent-orchestrator 移到 c4c453b35，所以 AO 背景程式會由該版本重新建置。
- 包含 0.8.104 的所有內容。
