# Coding Tools v0.8.173

## English

### After the antivirus quarantine
On Nov 27 Bitdefender quarantined parts of Coding Tools' data, and files it later restored kept refusing changes until Windows restarted. Coding Tools now survives that:
- **Window settings come back if the window's storage is wiped.** The split view (which chats sit in which panes, column widths and the row split), chat pages, open projects and their order, sidebar sections, toolbar, terminal, the last open chat and the response style are now also kept in a file in Coding Tools' data folder, and put back before anything is shown if the window's storage is ever reset. Nothing that names a secret, token, password or key is copied.
- **A profile save that Windows refuses no longer fills the disk.** The chat service saves its profile store through a temporary copy. When Windows refused the final step, every try left a 21 MB copy behind, about every 17 seconds, which filled the data drive twice. A failed save now removes its copy and waits before trying again, from 5 seconds up to 5 minutes.
- **A refused runtime file no longer stops the background runtime or hangs quitting.** When Windows refuses the file that records which background processes Coding Tools owns, Coding Tools writes the record beside it instead, uses whichever is newer, and goes back to the usual file once Windows allows it again. Before, the runtime failed every start, retried every 2 minutes with the windows held for over a second each time, and quitting never finished.

### Native Codex accounts
- **Codex account storage works on a data drive.** The orchestrator keeps Codex sign-ins only in folders that no other Windows account can rename or delete. A data drive's root folder lets every signed-in account modify it by default, so on such a drive the storage never started. A drive's root can't be renamed or deleted, so that permission no longer counts against it (checked on the folder itself, so a drive letter mapped onto an ordinary folder isn't mistaken for a root). Every other permission that could let another account swap the folder still does.

### Chats
- **A queued message leaves the queued bar once Coding Tools sends it.** A message sent from the queue after a turn ended stayed in the "1 message queued" bar although the agent had answered it. The bar now updates within 5 seconds.

### SSH hosts
- **Open terminal appears only where the window can show the terminal.** Where it can't, the page says so in one line, and the hosts list and the agent rules work as usual.

Includes all changes from v0.8.172.

## 繁體中文

### 防毒軟體隔離事件之後
11 月 27 日 Bitdefender 隔離了 Coding Tools 的部分資料，之後還原的檔案在 Windows 重新啟動前一直拒絕修改。Coding Tools 現在能承受這種情況：
- **視窗儲存區被清除後，視窗設定會恢復。** 分割畫面（哪些對話在哪個窗格、欄寬與列的分割）、對話頁面、開啟的專案及其順序、側邊欄區段、工具列、終端機、最後開啟的對話與回覆風格，現在也會保存在 Coding Tools 資料資料夾中的檔案；若視窗儲存區被重設，會在顯示任何畫面前放回。名稱涉及機密、權杖、密碼或金鑰的項目一律不會複製。
- **Windows 拒絕的設定檔儲存不再塞滿磁碟。** 對話服務會透過暫存副本儲存設定檔。當 Windows 拒絕最後一步時，每次嘗試都會留下 21 MB 的副本，大約每 17 秒一次，曾兩度塞滿資料磁碟。現在失敗的儲存會刪除副本，並在重試前等待，從 5 秒逐步延長到 5 分鐘。
- **被拒絕的執行階段檔案不再讓背景執行階段停擺或讓結束卡住。** 當 Windows 拒絕記錄 Coding Tools 擁有哪些背景處理程序的檔案時，Coding Tools 會改把紀錄寫在它旁邊，採用較新的一份，並在 Windows 再次允許時改回原本的檔案。先前執行階段每次啟動都會失敗、每 2 分鐘重試一次，每次讓視窗停頓超過一秒，而且結束永遠無法完成。

### Native Codex 帳戶
- **Codex 帳戶儲存在資料磁碟上也能運作。** 協調器只會把 Codex 登入資料保存在其他 Windows 帳戶無法重新命名或刪除的資料夾中。資料磁碟的根資料夾預設允許每個已登入帳戶修改，因此在這類磁碟上儲存一直無法啟動。磁碟的根目錄無法被重新命名或刪除，所以這項權限不再被視為不安全（直接在資料夾本身確認，因此對應到一般資料夾的磁碟代號不會被誤認為根目錄）。其他任何可能讓別的帳戶替換資料夾的權限仍會被拒絕。

### 對話
- **Coding Tools 送出排隊的訊息後，它會從排隊列中消失。** 回合結束後從佇列送出的訊息，即使代理已經回覆，仍留在「1 則訊息排隊中」列裡。現在這一列會在 5 秒內更新。

### SSH 主機
- **只有在視窗能顯示終端機的地方才會出現「開啟終端機」。** 無法顯示時，頁面會用一行說明，主機清單與代理規則照常運作。

包含 v0.8.172 的所有變更。
