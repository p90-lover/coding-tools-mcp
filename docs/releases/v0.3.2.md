# Coding Tools MCP v0.3.2 — security and persistence

This release combines the verified security branch with newer main-branch fixes, preserving the Rust-native application and pinned upstream archive.

## Authentication and privacy

OAuth callbacks must match the configured callback list exactly. PKCE, JWT signing configuration, duplicate authorization headers and unsupported authentication modes fail closed. The consent form uses a short-lived, one-use browser cookie and a server-side fingerprint covering the client, callback, PKCE challenge and state; tampering and replay are rejected. Public HTTP pages no longer reveal the workspace path. Issuer URLs come from trusted desktop/tunnel state, not Host or forwarded headers. Token responses and public HTTP pages have no-store, no-referrer, anti-framing and content-type protections. The desktop webview enables a restrictive content security policy.

## Reliability and execution

Desktop configuration saves preserve concurrent token rotation and credential updates instead of overwriting them with stale snapshots. Initial secret generation is serialized. Valid profile backups are recoverable, and unchanged saves avoid needless additional backups. Linked-project changes and reversible file operations preserve their existing rollback behavior.

MCP and Actions share process-wide HTTP admission and blocking-worker limits; each listener also has a local request limit. OAuth pages and token exchange use separate rate budgets and smaller body limits. Actions blocking tools no longer execute on the async executor. Worker permits and mutation locks remain owned by accepted blocking operations after an HTTP timeout; timeout errors warn callers to inspect state before retrying.

Explicit Ask approval is preserved. Legacy permission aliases migrate to canonical modes; unknown settings fail closed. Public tunnels cannot start or restore unauthenticated tool endpoints.

## Upgrade notes

Install the new package over the existing installation; do not remove the application data directory. Profiles and credentials remain in the existing data location. Verify the exact callback displayed by your OAuth client in authentication settings. A callback not already registered must be added explicitly; wildcard and arbitrary-HTTPS callbacks are not accepted. Passwords shorter than 12 bytes and signing keys shorter than 32 bytes require regeneration. Changing an OAuth signing key invalidates existing access tokens.

## Security boundaries

Execution modes enforce application policy, not an operating-system sandbox. Only authorize trusted clients and trusted projects; commands and project scripts can run with your desktop account's privileges. No UAC, authentication or host-scope bypass is introduced. Locally stored application secrets and recoverable backups must remain private to your OS account; this release does not claim hardware-backed or OS-keyring encryption. HTTP overload limits are not a substitute for upstream network-level denial-of-service protection. A timed-out tool request is not proof that its operation was canceled.

Installers are not represented as publisher-signed or Apple-notarized. SHA-256 files provide integrity comparison against the published release assets, not an independent publisher identity guarantee.

本版本整合較新的 main 分支修正與安全強化：精確 OAuth 回呼註冊、一次性瀏覽器同意驗證、可信任通道網址、權杖驗證及回應標頭保護，並修正桌面設定儲存覆蓋已輪替憑證的問題。MCP／Actions 加入共享請求與阻塞工作容量限制、分開的 OAuth 速率限制，以及較小的 OAuth 表單限制。工作區變更維持可復原備份，未知權限設定採取拒絕或唯讀處理。

升級時直接安裝新版本，保留現有應用程式資料目錄。請在認證設定中核對 OAuth 用戶端顯示的完整回呼網址；不要使用萬用字元。短於 12 bytes 的密碼及短於 32 bytes 的簽署密鑰需重新產生。

權限模式是應用程式政策，不是作業系統沙箱；只應授權可信任的用戶端及專案。應用程式密鑰與備份仍需受本機帳戶保護，本版本不宣稱使用系統鑰匙圈或硬體加密。安裝程式不宣稱具備發行者簽署或 Apple 公證；雜湊只供核對資產完整性。請求逾時不代表操作已取消，重試前應先檢查實際狀態。
