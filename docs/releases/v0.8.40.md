# Coding Tools 0.8.40

## English

### Chats
- A chat whose agent was still running when the app restarted or updated now continues. Before, the next message (or "Retry automatically") failed with "Launch failed" (`CHAT_CONTROLLER_NOT_READY`): the new background service couldn't reconnect to the agent and kept it running where nothing could reach it. Now the message reconnects the agent first, or restarts it from its saved conversation. A chat left in that state is released after 30 minutes instead of 2 hours (PR #721).
- Computer control is asked on a card in the chat whose agent asked, next to its other requests. Before, a "Computer control" window came up on top of whatever you were doing and took the keyboard focus. When the app isn't in front, its taskbar button flashes instead (PR #725).
- After a chat was compacted, a new message showed far up the history beside an old turn, and looked as if it was never sent. New messages now show beside their own turns. This hit paused goal chats most (PR #724).
- A chat already open in split view can be dragged from the sidebar into another split. It moves there and its old pane closes (PR #723).
- Chats on a model CPA serves from an API key (Claude API key, StepFun, Antigravity, OpenCode Go) show a **Spend** section in the context meter: estimated cost today, over 7 days and over 30 days for each account that served it (PR #716).
- A tool call that times out no longer stops the chat. Before, "Headless request timed out" showed "Step failed" and waited for a click, even with "Retry automatically" on. Now the chat keeps going by itself and shows one red line saying a tool call timed out (PR #722).
- "Retry automatically" no longer gives up when its own retry fails for a moment (for example while the local service restarts). It tries again after the next pause (PR #722).

### Speed
- Two disk checks that ran every 15–20 seconds no longer block the app. On the busy hard disk, each froze every window for up to 26 seconds (PR #721).
- Opening a long chat reads its turn costs from CPA Helper three at a time instead of all at once, so they no longer time out together and stay blank (PR #721).
- Snapshots of retired services that nothing reads are no longer written (PR #715).

### Verification and limitations
- Build the Windows installer, portable ZIP and update packs from main, and confirm CI before publication.
- The restart fix was tested with unit tests and matched against the failed chats of 2026-10-31. It hasn't yet been seen working after a real update.
- Everything in 0.8.39 is included.

## 繁體中文

### 對話
- 若應用程式重新啟動或更新時對話的代理仍在執行，該對話現在可以繼續。過去下一則訊息（或「Retry automatically」）會失敗並顯示「Launch failed」（`CHAT_CONTROLLER_NOT_READY`）：新的背景服務無法重新連接該代理，代理繼續執行，卻沒有任何途徑可以連上。現在訊息會先重新連接代理，或從已儲存的對話重新啟動。處於這種狀態的對話會在 30 分鐘後釋放，而非 2 小時（PR #721）。
- 電腦控制改為在提出要求的對話中，以卡片形式與其他請求並列詢問。過去「Computer control」視窗會蓋在你正在使用的畫面上，並搶走鍵盤焦點。若應用程式不在前景，工作列按鈕會閃爍提示（PR #725）。
- 對話經壓縮後，新訊息會顯示在歷史紀錄上方、與舊的回合並列，看似從未送出。現在新訊息會顯示在其所屬回合旁。暫停中的目標對話最常遇到此問題（PR #724）。
- 已在分割檢視中開啟的對話，可從側邊欄拖曳到另一個分割窗格。對話會移到該處，原本的窗格隨之關閉（PR #723）。
- 使用 CPA 以 API 金鑰提供之模型（Claude API 金鑰、StepFun、Antigravity、OpenCode Go）的對話，會在 context 計量表中顯示「Spend」區段：列出每個提供服務的帳戶今日、7 日及 30 日的估計費用（PR #716）。
- 工具呼叫逾時不再令對話停止。過去「Headless request timed out」會顯示「Step failed」並等待你點擊，即使已開啟「Retry automatically」亦然。現在對話會自行繼續，並以一行紅字顯示有工具呼叫逾時（PR #722）。
- 「Retry automatically」本身的重試若短暫失敗（例如本機服務正在重新啟動），不再就此放棄，而會在下一次暫停後再試（PR #722）。

### 速度
- 兩項每 15–20 秒執行一次的磁碟檢查不再阻塞應用程式。在繁忙的硬碟上，每次檢查都曾令所有視窗凍結最多 26 秒（PR #721）。
- 開啟長對話時，各回合的費用改為每次最多三項向 CPA Helper 讀取，而非同時全部讀取，因此不會一起逾時而留白（PR #721）。
- 不再寫入沒有任何功能讀取的已停用服務快照（PR #715）。

### 驗證及限制
- Windows 安裝程式、免安裝 ZIP 和更新檔需由 main 編譯及通過 CI 才能公開。
- 重新啟動的修正已通過單元測試，並與 2026-10-31 失敗的對話比對，但尚未在實際更新後觀察到其運作。
- 包含 0.8.39 的所有內容。
