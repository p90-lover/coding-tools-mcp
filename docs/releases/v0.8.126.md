# Coding Tools v0.8.126

## English

### Updates

- **Updates install themselves again when many old chats are kept.** To decide whether an agent is in the middle of a turn, the app asks Agent Orchestrator for its sessions. Agent Orchestrator keeps ended sessions too. With about 1,200 of them, that list grew past the size the app accepts, and the check failed every time. An update waits for the answer "no agent is working", so it never installed by itself; only the **Update to** button worked. The app now asks for live sessions only, which is a third of the size, and accepts a longer list.
- **Idle and stale chat agents are released again.** The same oversized list also stopped the app from releasing idle chat agents, ending old sessions and finding unused pre-warmed sessions. Those sweeps use the smaller list too.

### CPA

- **API-key providers that point at OpenAI's own API (api.openai.com) now send `max_completion_tokens`.** CPA used to send `max_tokens`, which OpenAI refuses for its newer models, so every request to them failed with HTTP 400 ("Unsupported parameter: 'max_tokens' ... Use 'max_completion_tokens' instead"). The app turns the setting on for every model of such a provider whenever it writes CPA's settings, so a re-fetched model list gets it again the next time the app starts CPA. Other OpenAI-compatible providers are unchanged.

### Agent Orchestrator

Agent Orchestrator is pinned at fa999bb19 (AO#52, on top of 0.8.125's 3fe7cbdf0).

- **The first start after an update no longer waits for a database index (AO#52).** 0.8.125 built a new index while Agent Orchestrator was starting, before it could answer anything. On a large history and a busy disk that read can take minutes, and the app stops and restarts an Agent Orchestrator that is not ready within 15 minutes. The index is now built a few minutes after the start, in the background. Chats keep working while the history is read. When the index is put in place, saving pauses once for a short time: about 8 seconds for each GB of event history in our measurement. If chats have to wait for that step longer than 30 seconds, it is abandoned and tried again later with more time.
- **If you already installed 0.8.125**, the index exists and nothing is rebuilt.

### Verification

- The batch is main a5708f65c (v0.8.125) plus the three changes, merged without conflicts.
  - Session list: a new test covers the five session checks asking for live sessions only, with room for a long list. 210 of 210 tests passed in the Agent Orchestrator transport, lifecycle, chat-archive, startup-busy and update-gate files. On the running app the full list was 946,212 bytes against a 900,000-byte limit; the live list was 313,316 bytes.
  - CPA: a new test fails on the old code and passes now; the 14 test files that load `cpa-managed.cjs` pass (170 of 170). On the developer's machine, a gpt-5-nano request through CPA went from HTTP 400 to 200 once the setting was on.
  - Agent Orchestrator fa999bb19, checked on Windows; the AO fork has no CI and the full AO suite was not run. Two new tests fail with the old migration and pass now. The whole `store` and `cdc` packages pass, the backend builds, and `go vet` and `gofmt` are clean. The whole `sqlite` package did not finish: its run stopped at Go's 10-minute limit on the slow disk, after one failure that also happens without this change, and it was not run again. Its migration ledger test and the new test pass on their own.
- Release identity checks validate the matching product, package and packaging versions. CI ran the full desktop suite on this batch before it merged. Packaging and publication run through GitHub Actions.
- None of these changes was checked in the installed app before publishing. The index build was not run on a real database or from a cold disk cache; its timing comes from a 324 MB test archive.
- Everything in 0.8.125 is included.

## 繁體中文

### 更新

- **保留大量舊對話時，更新又能自動安裝了。** 應用程式會向 Agent Orchestrator 查詢工作階段，以判斷是否有代理程式正在回合中。Agent Orchestrator 也會保留已結束的工作階段。累積到約 1,200 個時，這份清單超過了應用程式能接受的大小，檢查每次都失敗。更新要等到「沒有代理程式在工作」才會安裝，所以一直不會自動安裝，只有按下 **更新至** 按鈕才有效。應用程式現在只查詢仍在運作的工作階段，大小只有原來的三分之一，也能接受更長的清單。
- **閒置和過期的對話代理程式又會被釋放了。** 同一份過大的清單也讓應用程式無法釋放閒置的對話代理程式、結束舊的工作階段，以及找出未使用的預熱工作階段。這些清理工作現在也使用較小的清單。

### CPA

- **指向 OpenAI 官方 API（api.openai.com）的 API 金鑰供應商，現在會送出 `max_completion_tokens`。** CPA 之前送出 `max_tokens`，OpenAI 的新模型不接受，所以送往這些模型的每個請求都以 HTTP 400 失敗（「Unsupported parameter: 'max_tokens' ... Use 'max_completion_tokens' instead」）。應用程式每次寫入 CPA 設定時，都會為這類供應商的所有模型開啟這個設定，所以重新抓取模型清單後，下次應用程式啟動 CPA 時也會再補上。其他 OpenAI 相容供應商不受影響。

### Agent Orchestrator

Agent Orchestrator 固定在 fa999bb19（AO#52，建立在 0.8.125 的 3fe7cbdf0 之上）。

- **更新後第一次啟動不再等待資料庫索引（AO#52）。** 0.8.125 在 Agent Orchestrator 啟動期間建立新的索引，這時它還無法回應任何要求。歷史紀錄很大、硬碟又忙碌時，這次讀取可能要好幾分鐘；而 Agent Orchestrator 若在 15 分鐘內沒有就緒，應用程式會將它停止並重新啟動。現在索引改為啟動幾分鐘後在背景建立。讀取歷史紀錄期間，對話照常運作。索引寫入時，儲存會暫停一次，時間很短：依我們的測量，每 GB 事件歷史約 8 秒。如果對話為了這個步驟要等待超過 30 秒，就會放棄這次建立，稍後以更長的時間再試。
- **如果你已經安裝 0.8.125**，索引已經存在，不會重新建立。
