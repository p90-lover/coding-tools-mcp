# Coding Tools 0.8.55

## English

### Chats
- "Let the model judge" no longer leaves a request waiting for you. With it on, a command or tool request still landed on its card for you in three cases:
  - The reviewer failed three times in a row, for example while CPA was restarting.
  - Asked a second time to choose, the reviewer still couldn't decide.
  - The reviewer couldn't decide on one of the app's own screen tools, such as computer control.

  Each of these is now denied in doubt. The agent is told why and goes another way. With the switch off, nothing changes: these requests wait for you as before (PR #932).
- Still yours with the switch on: a question the agent asks you, a plan it asks you to approve, and letting computer control use an app (PR #932).
- A chat stuck on "may be stuck" recovers by itself when Retry automatically is on. The stall check used to send only an interrupt. When that never landed, it failed "stop needs attention" every 10 minutes. When AO had lost the agent's controller, it read as stopped while the turn stayed running. Either way the card never retried; two chats sat for over an hour. It now shuts the hung agent down like "keep going" does, so the step retries and resumes the same session (PR #930).
- Stop and retry no longer fail on an agent that is still exiting ("The agent is already exiting"). That agent goes to a background worker that confirms its exit. The retry starts a fresh agent with the chat so far, instead of continuing the one on its way out and losing its turn (PR #931).
- Stop, Pause and approvals stay responsive while several long chats load or poll at once. Two of the 12 request slots are kept for them, waiting requests take turns across chats, and identical reads in flight are shared. Twelve slow reads used to hold every slot until the 15-second timeout (PR #928).
- Long chats keep going: the chat's record is rolled over only when it reaches its size limit, even with an old `/autocompact off` setting saved, and compacting the model's context is left to the agent itself, as in Codex. A rollover failure now says what failed instead of suggesting `/compact` (PR #935).
- In split panes and narrow windows the chat box uses two rows: the harness, model, effort and window on top; attach, permissions, Single | Team, the context ring and Send below. Single | Team is a two-logo toggle. The goal's last check is folded by default: the goal icon shows a dot when a check is waiting, and a click opens it above the goal bar (PR #934).

### Performance
- Fewer freezes with several chats working. Each running card checked that its chat host was alive by opening a new local connection about twice a second. With four chats that was 7.7 connections a second, costing main 6.6 ms each on a busy machine, and it froze every window for 2–7 s about every 90 s. The card display now reuses a host's recent answer for 10 seconds (about 0.4 connections a second). A host that stops is still noticed within 10 s, and sending a message still checks it directly (PR #933).
- Freeze diagnostics: each stall probe reports the length of its own stall; it used to count from the first one (PR #933).

### Verification and limitations
- Built and published by GitHub CI from main; no local build was made for this version.
- "Let the model judge": covered by tests of a reviewer that never answers and one that can't decide on a screen tool (511 tests pass). The cases were found by reading the code, not caught live (PR #932).
- The stall recovery is covered by tests of an interrupt that never lands, a lost controller, and a stop that read as settled while the card's turn stayed hung. It hasn't yet been watched recovering a stuck chat in the installed app (PR #930).
- Everything in 0.8.54 is included.

## 繁體中文

### 對話
- 「Let the model judge」不再讓請求等候你處理。開啟此選項時，以下三種情況下指令或工具請求仍會停留在卡片上等你決定：
  - 審查者連續三次失敗，例如 CPA 重新啟動期間。
  - 再次要求審查者作出選擇時，它仍無法決定。
  - 審查者無法就應用程式自身的螢幕工具（例如電腦控制）作出決定。

  以上情況現在一律在有疑問時拒絕。代理會收到原因並改用其他方法。關閉此選項時行為不變：這些請求照舊等候你處理（PR #932）。
- 開啟此選項時仍由你處理的項目：代理向你提出的問題、要求你批准的計劃，以及允許電腦控制使用某個應用程式（PR #932）。
- 開啟「自動重試」時，顯示「可能卡住」的對話會自行恢復。停滯檢查過去只會發送中斷：中斷一直沒有生效時，每 10 分鐘都以「stop needs attention」失敗；AO 失去代理的控制器時，則被當作已停止，但回合仍在執行。兩種情況下卡片都不會重試，曾有兩個對話停留超過一小時。現在它會像「繼續」一樣關閉卡住的代理，步驟隨即重試，並在同一工作階段中繼續（PR #930）。
- 「停止」及重試不會再因代理仍在結束而失敗（「The agent is already exiting」）。該代理會交由背景工作程序確認結束，重試則以目前的對話啟動新代理，而不是延續正在結束的代理並遺失其回合（PR #931）。
- 多個長對話同時載入或輪詢時，「停止」、「暫停」及審批仍能即時回應。12 個請求名額中保留兩個給它們，等候中的請求會在各對話之間輪流，進行中的相同讀取亦會共用。過去 12 個緩慢的讀取會佔用所有名額，直到 15 秒逾時（PR #928）。
- 長對話可以持續進行：對話記錄只會在達到大小上限時才輪轉，即使已儲存舊的 `/autocompact off` 設定亦然；模型上下文的壓縮則交由代理本身處理，與 Codex 相同。輪轉失敗時會說明實際失敗的原因，而不再建議使用 `/compact`（PR #935）。
- 在分割窗格及較窄的視窗中，對話框分為兩行：上行為 harness、模型、推理強度及視窗；下行為附件、權限、Single | Team、內容圓環及「傳送」。Single | Team 改為雙圖示切換。目標的最近一次檢查預設摺疊：有檢查待閱讀時目標圖示會顯示圓點，按一下即在目標列上方展開（PR #934）。

### 效能
- 多個對話同時運作時減少停頓。每張執行中的卡片過去約每秒兩次開啟新的本機連線，以確認其對話主機仍在運作。四個對話即每秒 7.7 次連線，在繁忙的電腦上每次耗用主程序 6.6 ms，令所有視窗約每 90 秒停頓 2–7 秒。卡片顯示現會沿用主機最近 10 秒內的回應（約每秒 0.4 次連線）。主機停止運作時仍會在 10 秒內被察覺，傳送訊息時亦仍會直接檢查（PR #933）。
- 停頓診斷：每次停頓探測會回報該次停頓本身的長度，過去會從第一次停頓開始計算（PR #933）。

### 驗證及限制
- 由 GitHub CI 從 main 建置及發佈；此版本沒有在本機建置。
- 「Let the model judge」：已由從不回應的審查者，以及無法就螢幕工具作出決定的審查者的測試涵蓋（511 項測試通過）。上述情況是透過閱讀程式碼找出的，並非在實際運行中捕捉到（PR #932）。
- 停滯恢復已由中斷未生效、控制器遺失，以及停止看似完成但卡片回合仍卡住的測試涵蓋，尚未在已安裝的應用程式中實際觀察到卡住的對話自行恢復（PR #930）。
- 包含 0.8.54 的所有內容。
