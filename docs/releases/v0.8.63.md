# Coding Tools 0.8.63

## English

### Chats
- A turn that says "waiting for you" now has a button beside its time. **Answer** scrolls the request it waits on into view and focuses its first choice. In a narrow split pane that request could sit below the fold, so the chat looked stuck on nothing.
- A turn can also wait on a request the chat can no longer show. This happens after Agent Orchestrator restarts under a running chat: the agent loses its link while asking. Once nothing has been shown for two minutes, the button reads **Continue**. It restarts the agent with "Continue." so it asks again. Seen on 2026-11-02, when two chats sat "waiting for you" for an hour on requests the reviewer had already allowed.
- A stuck turn now recovers by itself when it waits on a request that nobody can answer: AO no longer lists the request, and the agent has lost its link to AO. After the usual stall time, the watchdog shuts that agent down so the step can go on. This happens even when "Retry automatically" is off. A request that AO still lists is never touched; it stays yours to answer.
- "Keep going" on such a turn no longer waits behind it forever. When the turn has been quiet past the stall limit, or you pressed Continue, its agent is shut down and your message starts the next turn.
- The "Restarting — The agent stopped responding…" box under the chat box is gone. The turn's own row already says what is happening.

### Verification and limitations
- Tests: 451 workflow tests, 58 chat UI, 67 chat view, 242 chat model and 9 DeepSeek visibility tests pass, and the renderer type-checks. The new tests cover several cases:
  - The watchdog releases an orphaned request with Retry off, and leaves a listed request alone.
  - A steer releases a gone agent's held turn after 70 quiet minutes, or at once with Continue, but not after one quiet minute.
  - Answer and Continue each appear in their case.
- Measured on a test page with the app's stylesheets, in the transcript's own layout at 260, 360 and 560 px. The row stays one line, the button sits right after the time, and in narrow panes the text ends in "…" while the button stays in view. Continue sends once, then reads "Continuing…".
- Not yet checked in the installed app.
- Built and published by GitHub CI from main; no local build was made for this version.
- Everything in 0.8.62 is included.

## 繁體中文

### 對話
- 顯示「waiting for you」的回合，現在會在時間旁邊多一個按鈕。**Answer** 會把它在等待的請求捲動到畫面中，並聚焦在第一個選項。在狹窄的分割窗格中，這個請求可能位於畫面下方看不到的地方，令對話看起來像是無故卡住。
- 回合也可能在等待一個對話已無法顯示的請求。這會在 Agent Orchestrator 於對話執行期間重新啟動時發生：代理在提問期間失去了連線。當兩分鐘內都沒有顯示任何請求時，按鈕會變成 **Continue**，它會以「Continue.」重新啟動代理，讓代理再問一次。2026-11-02 曾出現兩個對話因此停在「waiting for you」一小時，而它們的請求其實早已被審查者允許。
- 卡住的回合如果在等待一個沒有人能回答的請求，現在會自行恢復：AO 已不再列出該請求，代理也已失去與 AO 的連線。經過一般的停滯時間後，監察程序會關閉該代理，讓步驟可以繼續。即使「Retry automatically」已關閉也會如此。AO 仍然列出的請求永遠不會被動到，依然由你回答。
- 對這類回合送出「keep going」不再永遠排在它後面等待。如果回合已安靜超過停滯上限，或你按了 Continue，它的代理會被關閉，你的訊息會作為下一個回合開始。
- 對話框下方的「Restarting — The agent stopped responding…」方塊已移除。回合本身那一行已經會說明正在發生甚麼。

### 驗證及限制
- 測試：451 項工作流程測試、58 項對話介面測試、67 項對話檢視測試、242 項對話模型測試及 9 項 DeepSeek 顯示測試全部通過，渲染程式的型別檢查亦通過。新測試涵蓋以下情況：
  - 監察程序在「Retry automatically」關閉時仍會釋放孤立的請求，但不會動到仍被列出的請求。
  - 送出訊息時，已失去連線的代理所卡住的回合會在安靜 70 分鐘後被釋放，按下 Continue 則會即時釋放；只安靜一分鐘則不會。
  - Answer 和 Continue 各自在對應的情況下出現。
- 在使用應用程式樣式表的測試頁面上，以對話紀錄本身的版面在 260、360 及 560 px 量測：該行保持單行，按鈕緊接在時間後面。在狹窄窗格中文字會以「…」結尾，按鈕則保持可見。Continue 只會送出一次，之後顯示「Continuing…」。
- 尚未在已安裝的應用程式中檢查。
- 由 GitHub CI 從 main 建置及發佈；此版本沒有在本機建置。
- 包含 0.8.62 的所有內容。
