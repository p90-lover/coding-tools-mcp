# Coding Tools 0.8.117

## English

### Chats (#1292, #1277)
- **The chat box's permission menu looks like Codex's (#1292).** It is a slimmer frosted list: 12 px rows with 11 px descriptions, Codex's own icons, a tick on the chosen level, and Full access in orange. It closes as soon as you pick a level.
- **Choosing Full access asks in Codex's "Turn on Full Access?" dialog (#1292),** not a plain system OK/Cancel box. The dialog lists what the agents can then do (files and folders, terminal commands, internet and connected apps), with Cancel and a red Confirm. Cancel, Escape or a click outside changes nothing.
- **Chats recover faster after Agent Orchestrator restarts (#1277),** for example during an app update. A chat that kept running reconnects by reading only its turns. A chat whose agent had stopped resumes without loading every tool output and attached image. On a busy disk the old full reads could exceed the recovery time limit, so a chat showed as unavailable or its resume failed, and AO could stall for minutes.

### Approve for me (#1291)
- **When Auto Review can't answer a permission review, the Activity log and the request's card now say why, in Auto Review's own words (#1291).** For example, both review accounts may be at their usage limit. A request denied because nothing could judge it is logged as "reviewer unavailable", not as a model's decision.

### CPA (#1294)
- **CPA's Provider Manager plugin is updated to 0.7.0, with smart routing (#1294).** Each request goes to the account whose quota would otherwise go unused soonest: the least quota left in any of its windows, per hour until that window resets.
  - Codex accounts are ordered this way within each priority tier.
  - Pooled API-key accounts such as OpenCode Go fail over in the same order.
  - The 0.6.0 plugin is moved to Trash on first start.

### Under the hood (#1290)
- **The app now talks to Agent Orchestrator through one versioned handler (#1290),** so the chat engine behind it can be replaced later without touching the rest of the app. Chats, their history, storage and permissions work as before, and nothing changes on screen.

## 繁體中文

### 對話（#1292、#1277）
- **聊天框的權限選單現在與 Codex 相同（#1292）。**更窄的半透明清單：12 px 項目、11 px 說明、Codex 原生圖示、所選等級打勾、完整存取以橘色顯示。選擇後立即關閉。
- **選擇「完整存取」時改用 Codex 的「Turn on Full Access?」對話框確認（#1292），**不再跳出系統的「確定／取消」對話框。對話框列出代理程式屆時可做的事（檔案與資料夾、終端機指令、網際網路與已連接的應用程式），並提供「取消」與紅色「確認」按鈕。按「取消」、Esc 或點擊外部都不會改變任何設定。
- **Agent Orchestrator 重新啟動後（例如更新 App 期間），聊天恢復得更快（#1277）。**仍在執行的聊天只讀取其回合即可重新連線；代理程式已停止的聊天，恢復時不再載入所有工具輸出與附加圖片。在忙碌的磁碟上，舊的完整讀取可能超過復原時限，導致聊天顯示為無法使用或恢復失敗，AO 也可能停頓數分鐘。

### 幫我核准（#1291）
- **Auto Review 無法回覆權限審查時，活動記錄與該請求的卡片現在會以 Auto Review 自己的說法說明原因（#1291）。**例如兩個審查帳號都已用完額度。因無法審查而被拒絕的請求，記錄為「審查者無法使用」，不再記為模型的決定。

### CPA（#1294）
- **CPA 的 Provider Manager 外掛更新至 0.7.0，加入智慧路由（#1294）。**每個請求會送往額度最快會浪費掉的帳號：以各時段中剩餘最少的額度，除以距離該時段重置的小時數計算。
  - Codex 帳號在同一優先層級內依此排序。
  - OpenCode Go 等共用 API 金鑰的帳號池也依相同順序切換。
  - 首次啟動時，0.6.0 版外掛會移至垃圾桶。

### 內部改動（#1290）
- **App 現在透過單一、有版本的處理層與 Agent Orchestrator 溝通（#1290），**日後可替換背後的聊天引擎而不必改動 App 其他部分。聊天、歷史記錄、儲存與權限的運作方式不變，畫面上也沒有任何改變。
