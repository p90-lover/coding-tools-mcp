# Coding Tools v0.8.167

## English

### Permissions
- **opencode and Pi chats can run in Ask for approval and Approve for me.** Both used to run in Full access only, because neither asked the chat before a tool.
  - opencode allows every tool by its own default. AO's opencode agents now ask about the shell, web fetch, web search and subagents, and about edits in AO's default mode. A rule you or a repository wrote in opencode's own config still decides first: a command you denied there stays denied and is never turned into a question.
  - Pi's pi-acp sends no approval requests. AO's managed Pi extension now puts each Pi tool call except reads and searches to the chat, and blocks it unless the chat allows it.
  - In both, the request shows as the usual approval card under Ask for approval and goes to this app's reviewer under Approve for me.
  - Checked against real opencode 1.19.5 and pi-acp 0.17.1, each on a local stand-in model: a `git status` reached the chat as a request, and denying it kept the command from running.

### Chats
- **Chats keep going after request timeouts and expired grants.**
  - Local request timeouts (`AbortSignal.timeout` / `TimeoutError` and deadline errors) now back off and resume automatically, in chat runs and goal rounds alike.
  - A running card whose grant expired, or came from an earlier build, is observed first. Its interrupted turn then settles and retries on a fresh grant instead of stopping with "no matching background grant".
  - An orphaned running card that settles into held checks **Retry automatically** at once.

### Subagents
- **Subagents can pick Codex own-account models.** When **Codex (own account)** is enabled on the Subagents page, `subagent_models` and `subagent_start` list and run `ao:codex` own-account models such as `gpt-6.2-sol`.

Includes all changes from v0.8.166.

## 繁體中文

### 權限
- **opencode 與 Pi 對話可使用「要求核准」與「替我核准」。** 兩者先前只能使用「完全存取」，因為它們在執行工具前都不會詢問對話。
  - opencode 預設允許所有工具。AO 的 opencode 代理現在會在執行 shell、網頁擷取、網頁搜尋與子代理前詢問，在 AO 的預設模式下編輯也會詢問。你或儲存庫在 opencode 設定中自行寫下的規則仍優先決定：你在那裡拒絕的指令仍維持拒絕，不會變成詢問。
  - Pi 的 pi-acp 不會送出核准請求。AO 管理的 Pi 擴充功能現在會把讀取與搜尋以外的每個 Pi 工具呼叫交給對話，除非對話允許，否則會阻擋該工具。
  - 兩者的請求在「要求核准」下會顯示為一般的核准卡片，在「替我核准」下則交由本應用程式的審查者處理。
  - 已分別以本機替代模型對實際的 opencode 1.19.5 與 pi-acp 0.17.1 驗證：`git status` 以請求的形式送達對話，拒絕後指令沒有執行。

### 對話
- **對話在請求逾時與授權過期後會自動繼續。**
  - 本機請求逾時（`AbortSignal.timeout`／`TimeoutError` 與期限錯誤）現在會在一般對話與目標回合中自動退避並繼續執行。
  - 授權已過期或來自舊版本的執行中卡片會先進行觀測，讓中斷的回合落地並以新授權自動重試，而不再因「no matching background grant」停住。
  - 孤立的執行中卡片轉為暫停時，會立即檢查**自動重試**。

### 子代理
- **子代理可選用 Codex 自有帳號模型。** 當「子代理」頁面啟用 **Codex（自有帳號）** 時，`subagent_models` 與 `subagent_start` 會列出並以 `ao:codex` 執行 `gpt-6.2-sol` 等自有帳號模型。

包含 v0.8.166 的所有變更。
