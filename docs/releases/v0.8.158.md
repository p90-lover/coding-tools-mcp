# Coding Tools v0.8.158

## English

- **CPA starts again.** Since 0.8.154, CPA stopped at every start with "failed to load config: yaml: did not find expected ',' or '}'", and the app restarted it every 5 minutes. Everything that goes through CPA failed, and the proxy page's per-account routing couldn't reach CPA ("proxy.cpa_credentials_sync_failed").
  - **Why:** the app re-writes CPA's saved config at each start. Its writer left the Antigravity prompt filter's patterns (added in 0.8.154) unquoted, in a form CPA's YAML parser cannot read.
  - **What changed:** the config is now written so that every string is quoted, which CPA reads. Your saved CPA settings stay as they are.
- **Verification:** on a copy of the live config, run with the app's own runtime, the old writer's output fails in CPA's YAML parser exactly as CPA did, and the new output parses. A new test covers the writer on that runtime; it fails without the fix. The other CPA test files show the same results with and without the change. Not checked in the installed app before release.

Everything in 0.8.157 is included.

## 繁體中文

- **CPA 恢復啟動。** 自 0.8.154 起，CPA 每次啟動都會因「failed to load config: yaml: did not find expected ',' or '}'」而停止，App 每 5 分鐘重新啟動它一次。所有經由 CPA 的功能都會失敗，代理頁面的各帳號路由也無法連到 CPA（「proxy.cpa_credentials_sync_failed」）。
  - **原因：** App 每次啟動都會重新寫入 CPA 已儲存的設定。寫入時，Antigravity 提示詞過濾器的樣式（0.8.154 新增）沒有加上引號，CPA 的 YAML 解析器無法讀取這種格式。
  - **變更：** 設定現在以所有字串都加上引號的格式寫入，CPA 可以正常讀取。你已儲存的 CPA 設定維持不變。
- **驗證：** 以 App 自己的執行環境處理即時設定的副本：舊寫入方式的結果在 CPA 的 YAML 解析器中失敗，與 CPA 的錯誤相同；新的結果可正常解析。新增的測試涵蓋該執行環境下的寫入，沒有此修正時會失敗。其他 CPA 測試檔在變更前後結果相同。發佈前沒有在已安裝的應用程式中檢查。

包含 0.8.157 的所有變更。
