# Coding Tools v0.8.164

## English

### Chats & Approvals
- **Automatic retry and continuation after local, Guardian, and goal timeouts.** A newly launched agent is no longer stopped when `/api/v1/ao/external/submitted` times out after launch while the run is still active, and orphaned reserved external cards are observed and moved to held for automatic retry. `start_run` backs off and retries on local headless timeouts instead of marking the run failed, `control_run` retry reconciles cards already reset to pending with prior attempt history, and `scheduleAutoRetry` recovers when `start_run` fails or times out. Native Codex Guardian queue, account-read, and server timeouts or repeated server crashes now report `guardianUnavailable` and `guardianTimedOut` (while protocol violations and missing verdicts remain manual), retrying timed-out Guardian reviews when paid CPA reviews are off and retrying transient CPA fallback judge failures up to 3 times. Goal round startup defers on transient timeouts or revision races and re-arms `armGoalRetry` when reading workspace runs fails.
- **A request in a chat set to Ask for approval says why it waits, with an Approve for me button.** A request in a chat set to Ask for approval now says on its card that the reviewer doesn't check this chat, with an Approve for me button. One click switches the chat, and the waiting request and the rest of the running turn are reviewed at once. Let the model judge and quota-based reviews only apply to chats on Approve for me.
- **New chats start in Approve for me.** New chats start in Approve for me on Claude Code, Codex and Antigravity, keeping the last chat's model, instead of taking the last chat's mode. Ask for approval and Full access are picked per chat.

Includes all changes from v0.8.163.

## 繁體中文

### 對話與核准
- **本機、Guardian 與目標回合逾時後自動重試並繼續執行。** 當代理啟動後 `/api/v1/ao/external/submitted` 發生逾時但回合仍在執行時，不再誤停剛啟動的代理；滯留於 `reserved` 狀態的外部卡片會被觀測並轉為 `held` 以自動重試。`start_run` 遇到本機無頭服務逾時時會自動退避重試，不再將回合標記為失敗；當重試已先將卡片重設為 `pending` 時，`control_run` 與 `scheduleAutoRetry` 會自動銜接並在 `start_run` 失敗或逾時後繼續重試。Native Codex Guardian 的佇列、帳號讀取、伺服器逾時或重複崩潰現在會回報 `guardianUnavailable` 與 `guardianTimedOut`（協定違規與缺失裁決仍維持人工確認），在未開啟付費 CPA 審查時自動重試逾時的 Guardian 審查，並在 CPA 備援模型審查發生暫時性失敗時最多重試 3 次。目標回合啟動遇到暫時性逾時或版本競爭時會延後重試，且 `armGoalRetry` 在讀取工作區回合失敗時會重新排程。
- **設為「要求核准」的對話中，請求卡片會說明等待原因並提供「替我核准」按鈕。** 設為「要求核准」的對話中，請求卡片現在會說明審查者不會檢查此對話的請求，並提供「替我核准」按鈕。按一下即可切換對話，等待中的請求與目前回合的其餘請求會立即接受審查。「讓模型判斷」與依配額的審查只適用於設為「替我核准」的對話。
- **新對話預設以「替我核准」開始。** 在 Claude Code、Codex 與 Antigravity 上，新對話現在一律以「替我核准」開始，並沿用上一個對話的模型，不再沿用上一個對話的模式。「要求核准」與「完整存取」需在各對話中自行選擇。

包含 v0.8.163 的所有變更。
