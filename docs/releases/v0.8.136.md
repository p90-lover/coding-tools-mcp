# Coding Tools v0.8.136

## English

### Provider Manager: all CPA accounts and remaining API balance

- **The problem.** Provider Center and `listProviders` only listed accounts already saved in the local provider-network store. Live CPA auth-dir accounts (Codex, Antigravity, API-key upstreams, and others) therefore did not appear, except for the few that had already been linked. API-key remaining balance was also dropped, so a Provider Manager card never showed credit or key budget even when the provider reported it.
- **What changed.** Provider Center and `listProviders` now overlay every CPA auth-dir account as a display-only row. An already-linked account, including the existing Antigravity account, stays in place and is only annotated with remaining balance when that value is already known. Overlay rows cannot overwrite the store. Auth Files injection now keeps and renders remaining balance / key budget, and a failed refresh keeps the last good reading. Account rows show a From CPA tag and remaining balance when present.
- **Not changed.** Official OpenAI keys with usage reporting off still have no prepaid balance endpoint, so those cards correctly stay at "Balance not reported" until a usage/balance source is configured.

### Antigravity: a different account starts from an empty isolated auth home

- **The problem.** Agent Orchestrator and the managed Antigravity CLI started `agy` under the machine's default `USERPROFILE`/`HOME`, so a different account silently reused the already signed-in CLI session.
- **What changed.** Each managed launch now gets a per-account auth home under the tools root, or an empty profile when no account is given. The `agy` shim applies that home only to the CLI process. Antigravity Google sign-in opens in the isolated auth browser instead of the system browser, so it does not reuse the default Google session's cookies. Auth homes are created without blocking Electron's main thread.
- **Not changed.** This does not start a new sign-in or change a stored Antigravity account. Until a managed worker's credentials are confirmed file-only, `cpa/gemini-…` models on Native Codex remain the safe path.

## 繁體中文

### Provider Manager：顯示所有 CPA 帳號與 API 剩餘額度

- **問題。** Provider Center 和 `listProviders` 只列出已存在本機 provider-network 儲存中的帳號。因此 CPA 授權目錄裡實際存在的帳號（Codex、Antigravity、API 金鑰上游等）不會出現，除非少數已經被連結過。API 金鑰的剩餘額度也會被丟掉，即使供應商有回報點數或金鑰預算，Provider Manager 卡片也不會顯示。
- **改了什麼。** Provider Center 和 `listProviders` 現在會把 CPA 授權目錄裡的每個帳號疊加為僅供顯示的列。已經連結的帳號（包括既有的 Antigravity 帳號）會留在原位，只有在已經知道剩餘額度時才會補上註記。這些疊加列不能覆寫儲存內容。Auth Files 注入現在會保留並顯示剩餘額度／金鑰預算，重新整理失敗時也會留下上次的有效讀數。帳號列會在有資料時顯示 From CPA 標籤和剩餘額度。
- **沒有改變的部分。** 關閉用量回報的官方 OpenAI 金鑰仍然沒有預付餘額端點，這些卡片會正確保持「Balance not reported」，直到設定了用量或餘額來源。

### Antigravity：不同帳號會從空白、隔離的授權主目錄啟動

- **問題。** Agent Orchestrator 和受管理的 Antigravity CLI 會在機器預設的 `USERPROFILE`／`HOME` 下啟動 `agy`，因此換一個帳號時，仍會默默沿用已經登入的 CLI 工作階段。
- **改了什麼。** 每次受管理的啟動現在都會在工具根目錄下取得該帳號專用的授權主目錄；沒有指定帳號時則使用空白設定檔。`agy` 的 shim 只把這個主目錄套用到 CLI 行程。Antigravity 的 Google 登入會在隔離的授權瀏覽器中開啟，而不是系統瀏覽器，因此不會重用預設 Google 工作階段的 cookie。建立授權主目錄時不會阻塞 Electron 主執行緒。
- **沒有改變的部分。** 這不會開始新的登入，也不會改動已儲存的 Antigravity 帳號。在確認受管理工作者的憑證只存在檔案中之前，Native Codex 上的 `cpa/gemini-…` 模型仍是較安全的路徑。
