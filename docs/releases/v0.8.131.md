# Coding Tools v0.8.131

## English

### Chats

- **A chat whose agent stopped responding now says so.** When a turn shows nothing for 10 minutes (longer while a tool call runs), the app stops it so the step can be retried. When that stop had to shut the agent down, the chat showed the step as failed with `ACP session/prompt: {"code":-32800,"message":"Request cancelled","data":{"error":"context canceled"}}`. The step now says "The agent stopped responding, so its turn was stopped." Automatic retry works as before.
- **Agent Orchestrator records such a turn correctly.** A turn that was running when AO stopped its agent is recorded as interrupted, not as failed with the protocol's own cancel error. AO also reports the turn's end before the agent goes. Before, that report could be lost, and the turn then showed as running with no agent behind it.

### CPA

- **Two OpenAI API-key providers with the same name each keep their "… (Responses)" entry.** 0.8.128 matched a "… (Responses)" entry to its provider by name. With two providers of one name, each with its own key, the first settings write gave each key an entry and the next write folded both into the first provider, so the second key no longer served GPT-5 and later models. A provider renamed in CPA's page lost those models altogether. The app now matches an entry to the provider that holds its key.
- **If the second provider already lost those models** (possible if 0.8.128, 0.8.129 or 0.8.130 wrote CPA's settings twice with such a setup), fetch its model list again in Provider Manager. The app splits the list again the next time it writes CPA's settings.

## 繁體中文

### 對話

- **代理程式停止回應的對話，現在會說明原因。** 當一個回合 10 分鐘沒有任何動靜（工具呼叫執行中則更久），應用程式會停止它，讓步驟可以重試。如果這次停止必須關閉代理程式，對話會把步驟顯示為失敗，內容是 `ACP session/prompt: {"code":-32800,"message":"Request cancelled","data":{"error":"context canceled"}}`。現在步驟會顯示「The agent stopped responding, so its turn was stopped.」。自動重試照常運作。
- **Agent Orchestrator 會正確記錄這種回合。** AO 停止代理程式時仍在執行的回合，會記錄為已中斷，而不是以通訊協定本身的取消錯誤記錄為失敗。AO 也會在代理程式結束前回報回合已結束。以前這個回報可能遺失，回合就會一直顯示為執行中，背後卻沒有代理程式。

### CPA

- **兩個同名的 OpenAI API 金鑰供應商，各自保留自己的「…(Responses)」項目。** 0.8.128 以名稱把「…(Responses)」項目對應到供應商。如果有兩個同名的供應商、各有自己的金鑰，第一次寫入設定時每把金鑰都有一個項目，下一次寫入卻把兩個項目都併回第一個供應商，第二把金鑰就不再提供 GPT-5 以後的模型。在 CPA 頁面改名的供應商，則會完全失去這些模型。現在應用程式會把項目對應到持有該金鑰的供應商。
- **如果第二個供應商已經失去這些模型**（若 0.8.128、0.8.129 或 0.8.130 在這種設定下寫入了兩次 CPA 設定，就可能發生），請在 Provider Manager 重新抓取它的模型清單。應用程式下次寫入 CPA 設定時會再次拆分。
