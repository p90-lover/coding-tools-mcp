# Coding Tools 0.8.113

## English

### Agent Orchestrator: CPA models, start time and saves (#1231, #1233)
- **CPA models work even when Agent Orchestrator started before CPA was ready (#1231).** AO received CPA's key only at its own start. Started during a CPA install or update it had none, and every new CPA chat failed with "agent requires authentication" until the app was restarted (every new CPA chat on the morning of 2026-11-12). The app now starts AO again with the key when no agent is mid-turn, and otherwise says why a CPA chat cannot start yet.
- **AO starts in seconds after a restart, and chat saves no longer stall on database upkeep (#1233, agent-orchestrator#29).** AO used to copy its whole write-ahead log into the database inside an ordinary save. After a restart that was its first save, before it answered anything: 4.5 minutes on 2026-11-11. The copy now runs in the background.
- **A chat whose agent fails to start for a passing reason gets three tries (#1231),** the second after 5 seconds and the third after 20, instead of one immediate retry. The chat shows it waiting meanwhile.
- **A "signed out" answer is checked again before a launch is refused (#1233, agent-orchestrator#32):** after 2 seconds and after 5.
- **Every AO start records how long it took (#1231),** and whether AO holds CPA's key.

### Activity log (#1234)
- **A CPA outage no longer floods the activity log.** While CPA could not be reached, every chat's usage line retried and logged its failure: 264 entries in three minutes in a log that holds 300, which erased the record of what had gone wrong before. Reads now pause, and the outage is logged once.

### Verification and limitations
- GitHub Actions is unavailable for this repository. This release was built, tested and published locally from the merged `main`, following the release workflow's steps. Packaging is gated on the full desktop suite and both typechecks.
- #1231: `agent-orchestrator-lifecycle` 49/49, with five new tests; 213/213 across five suites. That AO's key was empty on 2026-11-12 is read from the code and from two timestamps (AO started 01:40:34, CPA's configuration written 01:43:22); the app's log of that morning was gone. Not checked in the running app.
- #1233: AO's merged main is the same tree as the integration built beforehand: it builds, `go vet` is clean for the touched packages, and the Claude adapter, `storage/sqlite` and the store's checkpoint, maintenance and change-log tests pass. The 288 s to 0.4 s measurement is agent-orchestrator#29's author's, on this machine's disk. App: 214/214 across seven suites on main with the pin. AO's start time in the installed app has not been measured yet; `ao.started` will show it.
- #1234: `cpa-usage` 17/17, with two new tests.
- The wait for a starting AO is still up to 15 minutes. It will be lowered once `ao.started` shows real start times with this AO.
- Includes everything in 0.8.112.

## 繁體中文

### Agent Orchestrator：CPA 模型、啟動時間與儲存（#1231、#1233）
- **即使 Agent Orchestrator 在 CPA 就緒前啟動，CPA 模型仍可使用（#1231）。**AO 只在自己啟動時取得 CPA 的金鑰。若在 CPA 安裝或更新期間啟動就沒有金鑰，之後每個新的 CPA 對話都會以「agent requires authentication」失敗，直到重新啟動程式（2026-11-12 早上所有新的 CPA 對話都是如此）。現在程式會在沒有代理執行回合時重新啟動 AO 並帶入金鑰，否則會說明 CPA 對話暫時無法開始的原因。
- **AO 重新啟動後數秒內即可就緒，對話儲存也不再因資料庫維護而停頓（#1233、agent-orchestrator#29）。**AO 以前會在一般的儲存動作中把整個預寫日誌複製進資料庫。重新啟動後的第一次儲存就是如此，而且發生在它開始回應之前：2026-11-11 花了 4.5 分鐘。現在複製改在背景進行。
- **代理因暫時性原因無法啟動時，對話會嘗試三次（#1231），**第二次在 5 秒後、第三次在 20 秒後，而不是只立即重試一次。期間對話顯示為等待中。
- **拒絕啟動前會再次確認「已登出」的結果（#1233、agent-orchestrator#32）：**2 秒後與 5 秒後各確認一次。
- **每次 AO 啟動都會記錄花費的時間（#1231），**以及 AO 是否持有 CPA 的金鑰。

### 活動記錄（#1234）
- **CPA 中斷時不再洗掉活動記錄。**無法連上 CPA 時，每個對話的用量列都會重試並記錄失敗：三分鐘內 264 筆，而記錄只能保留 300 筆，先前出錯的紀錄因此被擠掉。現在讀取會暫停，整段中斷只記錄一次。
