# Coding Tools 0.8.74

## English

### Browser
- After you sign in to ChatGPT, the Browser tab no longer keeps refreshing itself into "Too many requests" (429). The app checks the sign-in from inside the ChatGPT page, and a 429 from that check counted as signed out. The next good answer then counted as a new sign-in. That started the bridge connect, which reloads the page, so ChatGPT got more requests and answered with more 429s. Now a check that gets no real answer (a 429, a server error, a security check or a timeout) leaves a signed-in page signed in. A real signed-out answer still signs it out (PR #1017).

### Chats
- Erase in the image preview keeps the image and its mask together and first, even near the attachment limit. If the chat box is full, uploading or has changed, the edit is refused without dropping anything (PR #1013).
- The numbers under a finished reply keep retrying when the first read comes back empty, and numbers already shown stay (PR #1013).
- A queued message waiting for a compaction is read again once the compaction ends, so a message you cleared, edited or replaced in the meantime is not sent in its old form (PR #1014).

### Setup
- CPA setup reports ready only when CPA's final health check passes. Before, a refused health check could still end as ready (PR #1012).

### Verification and limitations
- Browser: 7 new tests cover the 429 loop (429, 502, a failed fetch and a security check keep the sign-in; an empty session and a 401 still sign out). All 174 tests in the 11 other files that load the browser code pass. The fix has not been checked against a live 429 in the installed app yet.
- Chats: 262 chat tests and 15 image tests pass (PR #1013), and 469 workflow tests pass (PR #1014). Setup: 33 bootstrap tests pass (PR #1012).
- Built and published by GitHub CI from main; no local build was made for this version.
- Everything in 0.8.73 is included.

## 繁體中文

### 瀏覽器
- 登入 ChatGPT 後，「瀏覽器」分頁不會再不停自行重新整理，直至出現「Too many requests」（429）。應用程式在 ChatGPT 頁面內檢查登入狀態，而該檢查收到 429 時會被當作已登出。下一次正常回應便被當作新的登入，觸發橋接連線，而橋接連線會重新載入頁面，令 ChatGPT 收到更多請求，回應更多 429。現在若檢查得不到真正的回應（429、伺服器錯誤、安全檢查或逾時），已登入的頁面會保持登入。真正的已登出回應仍會令頁面登出（PR #1017）。

### 對話
- 圖片預覽中的「擦除」會把圖片及其遮罩放在一起並排在最前，即使接近附件上限亦然。若對話框已滿、正在上載或已更改，編輯會被拒絕，但不會丟失任何內容（PR #1013）。
- 已完成回覆下方的數字在首次讀取為空時會繼續重試，已顯示的數字會保留（PR #1013）。
- 等待壓縮的排隊訊息會在壓縮完成後重新讀取，因此期間你清除、編輯或取代的訊息不會以舊內容送出（PR #1014）。

### 設定
- CPA 設定只在 CPA 最後的健康檢查通過後才回報就緒。過去健康檢查被拒絕時仍可能以就緒結束（PR #1012）。

### 驗證及限制
- 瀏覽器：7 項新測試涵蓋 429 迴圈（429、502、請求失敗及安全檢查都保持登入；空的工作階段及 401 仍會登出）。載入瀏覽器程式碼的其餘 11 個測試檔案共 174 項測試均通過。修正尚未在已安裝的應用程式中以真實的 429 檢查。
- 對話：262 項對話測試及 15 項圖片測試通過（PR #1013），469 項工作流程測試通過（PR #1014）。設定：33 項啟動測試通過（PR #1012）。
- 由 GitHub CI 從 main 建置及發佈；此版本沒有在本機建置。
- 包含 0.8.73 的所有內容。
