# Coding Tools 0.8.79

## English

### Chats
- **No more "HEADLESS_CAPACITY: request admission is full" when many chats are open.** Eight split-view chats refreshing at once used to fill the local service's queue, and 25 background calls failed in three seconds, each a "Something went wrong" toast or a red line under its chat (#1045).
  - The local service now takes 32 requests at once (was 16), and the app sends up to 24 (was 12). Two are still kept for Stop and other controls.
  - A waiting request fails only once nothing has finished for 15 s, or after 60 s in total. Before, it failed after 15 s even while the queue kept moving.
- A background refresh the service had no room for retries after a short pause, with a random spread so panes turned away together don't return together. It no longer shows a toast; the next refresh reads again. Sending a message and anything else that could act is never retried (#1045).
- The run status and harness status refreshes of open chats drift apart instead of asking at the same moment, and panes asking the same status at once share one call (#1045).

### Verification and limitations
- 141 headless queue tests pass, including new ones: a moving queue never times out, and a request passed over still fails at the 60 s limit. 269 chat tests pass, including new ones for the quiet retry, its limits and shared reads. The service's Rust tests pass on Windows, Linux and macOS (#1045).
- The cause was read from the installed 0.8.75's in-memory activity log: 25 failed background calls between 10:16:55 and 10:16:58 UTC, with no main-thread freeze at that time.
- Not yet checked in the installed app.
- Built and published by GitHub CI from main; no local build was made for this version.
- Includes all changes in 0.8.78.

## 繁體中文

### 對話
- **開啟多個對話時，不會再出現「HEADLESS_CAPACITY: request admission is full」。** 過去分割檢視中八個對話同時重新整理，會塞滿本機服務的佇列，三秒內有 25 個背景呼叫失敗，每個都變成「發生錯誤」提示或對話下方的紅字（#1045）。
  - 本機服務現可同時處理 32 個請求（原為 16），應用程式最多同時送出 24 個（原為 12），仍保留 2 個給「停止」及其他控制。
  - 等候中的請求只會在 15 秒內沒有任何請求完成、或總共等候 60 秒後才失敗。過去即使佇列仍在前進，15 秒後也會失敗。
- 服務暫時沒有空間的背景重新整理，會在短暫等候後重試，等候時間隨機錯開，令一同被拒的窗格不會一同回來。它不再顯示提示；下一次重新整理會再讀取。傳送訊息及其他可能產生動作的操作永不重試（#1045）。
- 已開啟對話的執行狀態及代理程式狀態重新整理會互相錯開，不再於同一刻查詢；同時查詢相同狀態的窗格會共用一次呼叫（#1045）。

### 驗證及限制
- 141 項 headless 佇列測試均通過，包括新測試：前進中的佇列永不逾時，而被略過的請求仍會在 60 秒上限失敗。269 項對話測試均通過，包括安靜重試、其限制及共用讀取的新測試。服務的 Rust 測試在 Windows、Linux 及 macOS 上均通過（#1045）。
- 原因取自已安裝 0.8.75 的記憶體內活動記錄：UTC 10:16:55 至 10:16:58 之間有 25 個背景呼叫失敗，當時主執行緒沒有停頓。
- 尚未在已安裝的應用程式中檢查。
- 由 GitHub CI 從 main 建置及發佈；此版本沒有在本機建置。
- 包含 0.8.78 的所有內容。
