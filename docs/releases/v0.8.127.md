# Coding Tools v0.8.127

## English

### Chats

- **A request the provider refused is no longer retried eight times.** When Claude Code printed the provider's error ("API Error: 400 …") and its turn ended, the failed step read "The agent exited before it gave a final answer", and "Retry automatically" ran the same request up to eight times, with waits of up to 15 minutes; after an app restart many chats did this at once. The step now keeps the provider's own words, so it shows "The provider refused this request (…), since retrying won't fix it" and waits for you, and a goal pauses on it. A spent quota reported this way is recognised too.

### Updates

- **The Update button answers the click.** It now reads "Updating" as soon as you click. Before, the app first waited for whatever was using the built-in browser, up to a minute, and the button still read "Update to v…" with nothing happening.
- **A background ChatGPT connector setup no longer blocks the update.** It is stopped for the update and runs again afterwards. Before, a setup that was timing out made every click wait a minute and then refuse with "Wait for MCP connector creation to finish".

### Computer use

- **The computer is released between an agent's computer-use calls.** Each native computer-use turn now ends after its call completes, including after an error the agent can recover from, so the long-lived helper no longer keeps the input lock, the cursor and the on-screen overlay while it is idle. The cleanup is limited to one second, and it is never sent after Escape, a policy stop, a lost helper or a shutdown, because that could restart a helper that was stopped.
- **The Stop button on the computer-control bar works while a click or typing step is slow.** During such a step the bar lets clicks pass through to the controlled window until the step ends, and a step waiting on the computer-use engine can take up to 2 minutes. For that whole time Stop could not be clicked. Each step now lets clicks through for at most 5 seconds; after that Stop takes clicks again and ends control.

### Agent Orchestrator

- **Releasing idle agents is gentler after a start.** The check now asks about four chats at a time instead of every idle chat at once (355 requests in one moment on a large history), and it no longer asks again, with a warning each time, about chats that have already ended.

### Known issue, not fixed here

- Chats on a model served by an OpenAI API key through CPA (for example GPT-6 Astra or GPT-6.1 Sol once the ChatGPT accounts' quota is used up) can still be refused by OpenAI: more than 128 tools in one request, or tools together with a reasoning level, are not accepted on the endpoint CPA uses for such keys. From this version those refusals are shown once instead of being retried. Until that route is changed, pick another model for those chats.

## 繁體中文

### 對話

- **供應商拒絕的要求不會再重試八次。** 當 Claude Code 印出供應商的錯誤（「API Error: 400 …」）後回合結束，失敗的步驟只顯示「The agent exited before it gave a final answer」，而「自動重試」會把同一個要求最多重試八次，每次等待最長 15 分鐘；應用程式重新啟動後，許多對話會同時這樣做。現在步驟會保留供應商的原話，顯示「The provider refused this request (…), since retrying won't fix it」並等待你處理，目標也會因此暫停。以這種方式回報的配額用盡同樣能辨識。

### 更新

- **按下「更新」按鈕會立即有反應。** 現在一按下就顯示「更新中」。以前應用程式會先等待正在使用內建瀏覽器的工作，最長一分鐘，而按鈕仍顯示「更新至 v…」，看起來毫無動靜。
- **背景的 ChatGPT 連接器設定不會再擋住更新。** 更新時會先停止它，更新後再重新執行。以前如果設定正在逾時，每次按下都要等一分鐘，然後以「Wait for MCP connector creation to finish」拒絕。

### 電腦操作

- **代理程式的電腦操作呼叫之間會釋放電腦。** 每個原生電腦操作回合現在會在呼叫完成後結束，包括代理程式可以復原的錯誤之後，所以長時間執行的輔助程式在閒置時不會再持有輸入鎖定、游標和螢幕上的覆蓋層。清理動作最多一秒；在按下 Escape、政策停止、輔助程式遺失或關閉之後絕不會送出清理，因為那可能會重新啟動已停止的輔助程式。
- **點擊或輸入步驟很慢時，電腦控制列上的「停止」按鈕現在可以正常使用。** 這類步驟執行期間，控制列會讓點擊穿透到被控制的視窗，直到步驟結束；而等待電腦操作引擎的步驟最長可達 2 分鐘。在這段時間裡「停止」都無法點擊。現在每個步驟最多只讓點擊穿透 5 秒，之後「停止」就能再次點擊並結束控制。

### Agent Orchestrator

- **啟動後釋放閒置代理程式的動作更溫和。** 檢查時一次只查詢四個對話，不再同時查詢所有閒置對話（歷史紀錄很多時，一瞬間送出 355 個要求）；對於已經結束的對話，也不會每次都再查詢並記錄一則警告。

### 已知問題，此版本尚未修正

- 透過 CPA 使用 OpenAI API 金鑰的模型（例如 ChatGPT 帳號配額用完後的 GPT-6 Astra 或 GPT-6.1 Sol），對話仍可能被 OpenAI 拒絕：CPA 為這類金鑰使用的端點不接受單一要求超過 128 個工具，也不接受工具與推理等級同時使用。從此版本起，這些拒絕只會顯示一次，不再重試。在該路由變更之前，請為這些對話選擇其他模型。
