# v0.4.9 — ordinary unlimited-duration commands, bounded RAM cache

## English

This release retains the unbounded ordinary-command execution and RAM-cache design
from v0.4.7 and the self-contained native release fixtures from v0.4.8. Those older
tags and failed build evidence are preserved; no release tag is rewritten.

Ordinary `exec_command` has no automatic runtime deadline when `timeout_ms` is
omitted, null, or zero. There is no separate long-run mode, and seven days is not a
ceiling. A positive timeout is an explicit caller-requested stop condition. Short
HTTP response waits, manual cancellation, permission revocation and resource
admission remain separate and enforced. Poll the returned command handle rather
than relaunching work after a transport timeout.

Disposable command output stays in RAM, with a 90-minute maximum payload age and
oldest-payload-first eviction. The shared output payload budget is 64 MiB, with
1 MiB per stream. Cache expiry never expires an active command or its ownership
and write leases. Durable history, authentication, source files and compiler
caches are not disposable output cache.

Four legacy storage tests are now isolated to their own retained `aiTemp` fixture
stores. Previously they could replace the process-wide trusted-origin snapshot
while the parallel OAuth rotation test was running. The actual OAuth checks,
permission rules and trusted-origin implementation are unchanged. The Windows
pixel conversion loop uses fixed-size chunks to satisfy the release toolchain's
strict lint; its conversion and capture-permission behavior are unchanged.

The application/server must remain running. This release does not implement a
restart-surviving supervisor and does not claim a seven-day wall-clock endurance
test, complete provider-policy equivalence, or full provider orchestration.
No provider/model calls are needed for the verification. Installer publication
requires the existing native, frontend, audit and asset-verification gates to pass.

## 繁體中文

本版保留 v0.4.7 嘅一般指令無時限執行及 RAM 快取設計，以及 v0.4.8 可自行建立嘅
原生測試元件。舊 tag 同失敗建置證據會保留，唔會重寫任何發佈 tag。

一般 `exec_command` 省略 `timeout_ms`、設為 null 或零時，冇自動運行期限。
冇獨立長任務模式，七日亦唔係上限。明確提供正數先會設定呼叫端要求嘅停止條件。
短 HTTP 回應等待、手動取消、權限撤銷同資源准入仍然分開並保留。遇到傳輸逾時，
應查詢原有 command handle，唔係重新啟動同一工作。

可丟棄嘅指令輸出只存於 RAM，最多保留 90 分鐘，並優先移除最舊資料。
共用輸出資料容量為 64 MiB，每個串流 1 MiB。快取到期唔會令運行中指令、程序管理
紀錄或寫入鎖到期。持久化歷史、認證、原始碼同編譯工具快取唔屬於可丟棄輸出快取。

四項舊有儲存測試已改用各自保留喺 `aiTemp` 嘅測試儲存位置，避免喺並行 OAuth
來源輪替測試期間覆蓋共用可信來源快照。正式 OAuth 檢查、權限規則同可信來源實作
保持不變。Windows 像素轉換迴圈改用固定大小區塊以通過發佈工具鏈嚴格 lint，
轉換結果同擷取權限行為不變。

應用程式／伺服器仍須保持運行。本版未提供跨重啟持久化程序監督器，亦唔聲稱已完成
七日實際耐久測試、等同全部供應商政策，或完成全部供應商任務編排。
驗證毋須供應商／模型呼叫；安裝程式必須通過現有原生、前端、審計同檔案校驗流程，
先可以正式公開。
