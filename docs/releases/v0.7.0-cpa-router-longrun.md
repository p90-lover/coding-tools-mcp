# CPA / Codex Router 7-day long-run durability

This increment sits on `0.7.0-rc.10` (`release/codex-router-multiprovider-0.7.0-rc.8` after #177 / #180 / #189). It does **not** claim `0.7.0-rc.11`; that slot is left for the parallel five-stack lane.

Scope is **CPA (CLI Proxy API)** and **Codex Router** only.

## Why

rc.10 restored the original CPA `management.html` panel and Codex Router Control Center. Those runtimes were still tuned for short desktop sessions:

- Codex Router’s request execution deadline defaulted to **24 hours**, so a ~7-day task was canceled mid-flight.
- LiteLLM’s generated `request_timeout` was **600 seconds**.
- Gateway crash restarts were bounded at 5 failures / 10 minutes; Coding Tools did not keep desired-run across a crash or app relaunch.
- CPA had no SSE / non-stream keep-alives, so idle proxies could drop a live turn.
- Original UI iframes did not reconnect after a health blip.

## What changed

- Durable desired-run supervisor for CPA and Codex Router: crash recovery, loopback health-blip reconnect, 45s keep-alive, exponential backoff capped at 5 minutes, **never auto-abandoned**.
- `prevent-app-suspension` while either runtime is desired-running.
- CPA config: original control panel stays on loopback; streaming keep-alive 15s; non-stream keep-alive 30s; retries; 256 MB log cap; error-log file cap; cooldown persisted; management panel auto-update disabled during a long run.
- Codex Router env: 8-day execution and activity retention; longer Grok stall; more in-process gateway restarts; LiteLLM `request_timeout` patched to match.
- Original CPA iframe reloads only on a real reconnect generation (`?lr=`), not on every poll.

## Handoff / non-goals

CommandCode Proxy, Paseo, Anneal, Chrome extension, and the main Desktop shell are untouched aside from a small `main.cjs` original-UI constructor argument and `package.json` `asarUnpack` for the new helper. Identity / installer version remains `0.7.0-rc.10` so this can merge without colliding with an rc.11 five-stack identity bump.

Long-run durability (manual, Windows rc.10+ build):

1. More → CPA → Install / start original UI. Confirm `management.html` fills the page (dashboard through plugins). Copy management key and log in.
2. More → Codex Router → Open original UI. Confirm Control Center chrome (Usage / Status / Models / Local / Harness / Context / Settings).
3. Start a routed Codex / CPA job. Lock the machine, flap the LAN for ~30s, and confirm the iframe reconnects without spawning extra panels or restarting a healthy PID.
4. Kill the CPA process once. Confirm Coding Tools brings it back with backoff and the original UI reconnects; the job’s proxy keep-alives continue after ready.
5. Quit and relaunch Coding Tools (keep running on close if used). CPA and Codex Router resume because desired-run is durable.
6. Confirm `state/*/logs` stays under the 256 MB cap after extended debug-off operation.
7. Regression: shell from #177, CommandCode / Paseo / Anneal, Provider Hub, and installer identity stay unchanged.
