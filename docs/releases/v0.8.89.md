# Coding Tools 0.8.89

## English

### Approvals
- **"Let the model judge" now reviews pushes it used to deny unread.** A `git push` the app could not check by itself, such as one through `git -C <folder>`, was answered "check it yourself" before any model saw it. With the judge on, that became an automatic deny; with it off, the request waited for you. Now:
  - A push through one absolute `git -C <folder>` is reviewed normally, with the repository read in that folder.
  - With the judge on, any other push the app cannot verify goes to the model, which is told why it could not be verified.
  - Pushes to main or master, force pushes, and branch deletions still never go through on their own.
- **Turning the judge on from a waiting request's card now judges that request.** Before, a request already left to you stayed waiting after you turned the judge on. Each request is judged once.
- **A turn held by a request the reviewer already answered restarts by itself.** If the agent stays silent after its request was answered, "Retry automatically" restarts the turn. Seen on 2026-11-04: a chat said "waiting for approval" for an hour while its tool calls showed "Allowed".

### Verification and limitations
- Five new tests cover the `-C` push rules, a judged push, the judge turned on later, and the restart of an answered-but-held turn. Four failed on 0.8.88 and pass now; the fifth checks that a push still waits for you when the judge is off. The workflow, chat, subagent and git test suites pass.
- Not yet checked in the installed app. The hour-long wait came from AO's record of that chat: the push was waiting, and the Reads behind it were allowed. Why the chat offered "Continue" instead of "Answer" for that push couldn't be confirmed, because the app's in-memory log had already rolled past it.
- Built and published by GitHub CI from main; no local build was made for this version.
- Includes all changes in 0.8.88.

## 繁體中文

### 審批
- **「讓模型判斷」現在會審查以往未讀就拒絕的推送。** 應用程式無法自行核實的 `git push`（例如經 `git -C <資料夾>` 的推送），以往在任何模型看到之前就被標為「請自行檢查」。開啟判斷時，這會變成自動拒絕；關閉時，請求就等你處理。現在：
  - 經單一絕對路徑 `git -C <資料夾>` 的推送會正常審查，並在該資料夾讀取儲存庫資料。
  - 開啟判斷時，其他無法核實的推送會交給模型，並告訴模型為何無法核實。
  - 推送到 main 或 master、強制推送及刪除分支仍然不會自動放行。
- **從等待中請求的卡片開啟判斷，現在會判斷該請求。** 以往已交給你的請求，在開啟判斷後仍然繼續等待。每個請求只判斷一次。
- **被已獲審查員答覆的請求卡住的回合會自行重新開始。** 如果請求已獲答覆而代理仍然沒有動靜，「自動重試」會重新開始該回合。2026-11-04 曾出現：某對話顯示「等待審批」一小時，而其工具呼叫已標示「已允許」。

### 驗證及限制
- 五項新測試涵蓋 `-C` 推送規則、經判斷的推送、之後才開啟判斷，以及已答覆但仍被卡住的回合的重新開始。其中四項在 0.8.88 上失敗，現已通過；第五項確認關閉判斷時推送仍會等你處理。工作流程、對話、子代理及 git 測試組全部通過。
- 尚未在已安裝的應用程式中確認。一小時的等待來自 AO 對該對話的記錄：推送在等待中，其後的讀取已獲允許。至於該對話為何對這個推送顯示「繼續」而非「回答」，未能確認，因為應用程式的記憶體日誌已滾動覆蓋了那段時間。
- 由 GitHub CI 從 main 建置及發佈；此版本沒有在本機建置。
- 包含 0.8.88 的所有內容。
