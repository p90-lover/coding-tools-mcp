# Coding Tools v0.8.159

## English

- **Antigravity runs as a chat**, the way T3 Code does: through Google's own `agy acp` agent and its own Google sign-in, which Google says is permitted for personal use. (AO#61)
  - Its approval requests now appear in the chat, so Ask and Approve for me work on Antigravity.
  - Sign in once on the Antigravity page, with a Google account Antigravity accepts where you are, and its own models are listed beside CPA's. CPA's models work without that sign-in.
  - A message sent while an Antigravity turn is running waits until the turn ends.
- **Native Guardian reviews on Codex's own auto-review model** (codex-auto-review), the one Codex Desktop's Guardian uses, instead of Codex's default chat model. Measured cost is unchanged: about 0.5% of a Plus 5-hour window per 100 reviews.
- **Approve for me no longer spends a second native Guardian review on a command it just allowed.** The same command, in the same folder and chat, is allowed again for 10 minutes without another review. A new message from you, another command or folder, and anything Guardian refused or left to you are still reviewed every time.
- **An account's MCP check no longer fails as "context changed" when ChatGPT tidies its plugins page address while the check runs.**
  - ChatGPT rewrites the plugins page's address in place as the page settles (`?view=personal` becomes `?directoryTab=personal`). When that landed during the check's session read, the check stopped with "The MCP authentication or workspace context changed", even on a signed-in workspace owner.
  - A move to another page, a new page load or an account switch still stops the check. When it stops, the log now names which check moved.
- **"New sessions start on: The least busy account" skips accounts that cannot answer.** It used to pick among all accounts that take new sessions, including signed-out ones and ones whose sign-in ChatGPT rejected. It now picks among signed-in accounts whose sign-in ChatGPT accepts. With none left, it keeps the account in use.
- **A team agent's conversation, opened from the Team graph, no longer floods the app with reads.**
  - For an agent running in Terminal UI mode it asked every 2 seconds and failed every time, taking request slots other chats needed. It now says the agent runs in a terminal and stops asking.
  - Reads no longer overlap on a slow service, and a failed read waits longer each time (up to a minute).
- **Older turns of chats with an edited or retried prompt open fast too.** (AO#60)
  - 0.8.155 (AO#59) made AO record where each new turn starts in its chat. Turns from before that update had no starting point, so in a chat with an edited or retried prompt each timeline page still searched the chat from its beginning for every such turn.
  - About 10 minutes after AO starts, it now reads each chat once in the background and records where its older turns start. Chats with an edited or retried prompt go first, then the most recently used. In the test chat, one page went from 1.06 s to 16 ms.
  - The background pass pauses after each step for as long as that step took, and gives way to chat writes. It runs once; later starts only check that it is done.
- **Verification:** each change's new tests fail without it (control runs) and pass with it. Antigravity: the app suites for providers, permissions, the workflow, Antigravity and Auto Review quota pass (740), AO builds at the new pin and its agy, ACP, registry and gateway tests pass, and a real Antigravity turn on the CPA gateway asked for permission before a file write. Guardian: the review and Auto Review quota suites pass, and requests now go out on codex-auto-review (checked through a logging proxy). MCP and accounts: the connector, workspace, account and chat suites pass, and TypeScript is clean. AO#60: the AO store and cdc packages pass. Not checked in the installed app before release.

Everything in 0.8.158 is included.

## 繁體中文

- **Antigravity 改以聊天方式執行**，做法與 T3 Code 相同：透過 Google 官方的 `agy acp` 代理程式及其本身的 Google 登入，Google 表示個人使用是允許的。（AO#61）
  - 它的核准請求現在會顯示在聊天中，因此 Antigravity 也能使用「詢問」與「代我核准」。
  - 在 Antigravity 頁面以一個 Antigravity 在你所在地區接受的 Google 帳號登入一次，就會在 CPA 模型旁列出它自己的模型；不登入也能使用 CPA 的模型。
  - Antigravity 回合進行中送出的訊息，會等該回合結束後才處理。
- **原生 Guardian 現在改用 Codex 自己的自動審查模型**（codex-auto-review）進行審查，與 Codex Desktop 的 Guardian 相同，不再使用 Codex 的預設聊天模型。實測額度用量不變：每 100 次審查約占 Plus 5 小時額度的 0.5%。
- **「替我核准」不再為剛核准過的指令再做一次原生 Guardian 審查。** 同一個聊天、同一個資料夾中的相同指令，在 10 分鐘內會直接再次核准，不必重新審查。你傳送新訊息、換成其他指令或資料夾，或 Guardian 拒絕或交由你決定的請求，仍然每次都會審查。
- **ChatGPT 在檢查進行中自行整理外掛頁面網址時，帳號的 MCP 檢查不再誤判為「內容已變更」而失敗。**
  - ChatGPT 會在頁面載入完成時就地改寫外掛頁面的網址（`?view=personal` 變成 `?directoryTab=personal`）。若這發生在檢查讀取登入狀態的期間，檢查就會以「The MCP authentication or workspace context changed」停止，即使是已登入的工作區擁有者也一樣。
  - 移到其他頁面、重新載入頁面或切換帳號，仍會停止檢查。檢查停止時，記錄會寫明是哪一項檢查有變動。
- **「新工作階段開始於：最不忙的帳號」會略過無法回應的帳號。** 過去它會在所有接受新工作階段的帳號中挑選，包括已登出、或登入已被 ChatGPT 拒絕的帳號。現在只會在已登入且登入仍被 ChatGPT 接受的帳號中挑選；若沒有符合的帳號，就沿用目前使用中的帳號。
- **從團隊圖開啟的團隊代理對話，不再對應用程式發出大量讀取。**
  - 對於以終端機介面（Terminal UI）模式執行的代理，它每 2 秒讀取一次且每次都失敗，佔用其他聊天需要的請求名額。現在它會說明該代理在終端機中執行，並停止讀取。
  - 服務緩慢時讀取不再重疊，讀取失敗後的等待時間會逐次加長（最多一分鐘）。
- **曾編輯或重試過提示的對話，較舊的回合也能快速開啟。**（AO#60）
  - 0.8.155（AO#59）讓 AO 記錄每個新回合在對話中的起點。那次更新之前的回合沒有起點，所以在曾編輯或重試過提示的對話中，時間軸的每一頁仍要為每個這類回合，從對話開頭搜尋一次。
  - 現在 AO 啟動約 10 分鐘後，會在背景把每個對話讀一次，記下較舊回合的起點。曾編輯或重試過提示的對話優先，其次是最近使用的對話。在測試對話中，一頁從 1.06 秒降到 16 毫秒。
  - 背景作業每做完一步，就暫停與該步相同的時間，並讓出位置給對話的寫入。它只執行一次，之後的啟動只會確認已經完成。
- **驗證：** 每項變更的新測試在沒有該變更時會失敗（對照執行），加入後通過。Antigravity：供應者、權限、工作流程、Antigravity 與自動審查額度的 App 測試通過（740 項），AO 在新版本上可建置，其 agy、ACP、registry 與 gateway 測試通過，在 CPA gateway 上的實際 Antigravity 回合於寫入檔案前先要求權限。Guardian：審查與自動審查額度測試通過，請求現在以 codex-auto-review 送出（經記錄代理確認）。MCP 與帳號：連接器、工作區、帳號與聊天測試通過，TypeScript 檢查無誤。AO#60：AO 的 store 與 cdc 套件測試通過。發佈前沒有在已安裝的應用程式中檢查。
