# Coding Tools 0.8.56

## English

### Chats
- Running chats show as running in the chat list. Another project's chats were read only once a minute, so a chat running in another split pane looked done for up to a minute. They are now read again as soon as AO reports a change to their runs. The open chat also keeps its spinner after you click it, and paused chats get a dot (PR #940).
- A running chat goes to the top, and a chat you drag stays where you put it until its next run. A dragged chat was released only while its project was the open one, so it could stay off the top for good. A chat dropped above running ones now stays there; they jumped straight back above it, so the drag looked like it did nothing. "Reset to newest first" also clears dragged chats (PR #940).
- Ctrl+Shift+A (archive) and the new Ctrl+Shift+Backspace (delete) work while you type in the chat box. They act on the focused split pane's chat, whichever project it is in (PR #940).
- Another project's chats have their own menu: Open, Open in split view, Pin, Mark unread, Archive and Delete. Every project's pinned chats show under Pinned; another project's chat used to vanish once pinned (PR #940).
- Archive and delete take the chat out of the list as soon as the change is saved, and close a split pane showing it. "Archive chats" no longer does nothing while something else is busy (PR #940).
- Every message you send shows whether the model has read it. Under the message:
  - a fading check ("Sending…") while it is on its way to an agent;
  - one check ("Unread") once an agent has it;
  - two checks ("Read by GPT-6.1 Sol", or whichever model answers) once the model has written anything.

  Messages sent mid-turn already had these marks; now the message that starts a turn has them too. A turn stopped before its model wrote anything gets no mark, and a retried card's earlier reply doesn't count as reading the new message (PR #941).
- A chat no longer says "waiting for the model" while no agent has your message yet. When an agent has to be started fresh, Agent Orchestrator keeps the turn queued until one takes it. Seen today: two fresh agents took 7 minutes to come up while the chat said "waiting for the model", and the model then answered in 7 seconds. Such a turn now reads "waiting for the agent to take the message", and after 10 minutes it shows "May be stuck" (PR #941).

### Auto-archive and auto-delete
- A chat you restore counts as used, so the idle sweep no longer archives it again within seconds (PR #940).
- A chat whose run is stuck with nothing working (a held card, a pause, a start that never got going) is archived once idle. One old stuck card used to keep a chat open for good (PR #940).
- The sweep also runs every hour from the app itself, so the app archives while it sits in the tray (PR #940).
- Archived chats whose runs have left the project's read still count down to Recently deleted. A chat archived for being idle keeps its title (PR #940).

### Settings
- Settings › Chat has three new groups (PR #940):
  - Chat list: chats shown per project, and keep running chats on top.
  - Archive and delete: archive inactive chats after, and delete archived chats after.
  - Keyboard shortcuts.
- The chat list's popover uses the same choices and follows changes made in Settings. A number typed into the popover was lost when it closed (PR #940).

### Web GPT
- WebGPT's bundled runtime moves from codex-chatgpt-web v5.0.6 to the latest v6.1.17, and Coding Tools' own WebGPT fixes are kept. New from upstream (PR #912):
  - separate GPT-6 Sol and GPT-5.6 Sol rows with selectable effort;
  - a Zero Risk mode;
  - a "New browser chat for each turn" option;
  - tunnel-client 0.0.16, which bundles cloudflared 2026.8.2.
- Task turns still run in saved ChatGPT chats by default, because ChatGPT refuses connectors in Temporary Chat (PR #912).
- A "Something went wrong" retry in a fresh conversation now counts toward the turn's three automatic retries, so a ChatGPT outage costs at most four sends (PR #912).

### Performance
- The chat list no longer redraws on every activity read, about once a second. Another project's unchanged read keeps its list (PR #940).
- Every split pane polled and read the same runs and board on each push. A read asked for again while one is on its way now shares that call (PR #940).
- Chat pages share what one list saves (sections, order, folded projects) instead of overwriting each other (PR #940).
- Freeze records name the main thread's own CPU next to the whole app's, so a freeze where main was waiting is no longer mistaken for one where it was computing (PR #937).

### Also in this version (0.8.55 was not published on its own)
- A chat stuck on "may be stuck" recovers by itself when Retry automatically is on (PR #930).
- Fewer freezes with several chats working: running cards stopped opening a new connection to their chat host about twice a second (PR #933).
- "Let the model judge" no longer leaves a request waiting for you (PR #932).
- Stop, Pause and approvals stay responsive while several long chats load (PR #928). Stop and retry work on an agent that is still exiting (PR #931).
- Long chats keep going instead of stopping at their record's size (PR #935). Browser automation works after a slow start (PR #924).
- In split panes the chat box uses two rows, and Single | Team is a two-logo toggle (PR #934).
- The full 0.8.55 notes are in `docs/releases/v0.8.55.md`.

### Agent Orchestrator
- Agent Orchestrator now runs the fork's main branch. It includes upstream AO through 2026-10-01 alongside every Coding Tools change:
  - automations and cues;
  - rich session links, and PR references reported by workers;
  - the fx, Gemini, MiMo Code, DeepSeek and OpenCode v2 harnesses.

  On first start, AO's database moves the Coding Tools migrations it already applied to their new numbers, then adds upstream's (PR #909, AO fork PR #16).
- If AO stops while that first start is rebuilding its change triggers, the next start finishes the job instead of recording it as done with three triggers missing (AO fork PR #17).
- Verification: the fork's migration tests cover a database as 0.8.x left it, a fresh upstream database, and a start interrupted mid-migration. The upgrade hasn't yet been watched on an installed app's own database.

### Verification and limitations
- Built and published by GitHub CI from main; no local build was made for this version.
- Covered by tests: 868 tests pass in the changed areas, including 10 new ones. The list was also checked in a browser harness with a fake AO:
  - a clicked running chat keeps its spinner;
  - both shortcuts work from the chat box;
  - a dragged chat stays put until its next run;
  - another project's running chat shows within a second of a push;
  - the Settings groups save.

  None of this has been watched in the installed app yet.
- "Delete archived chats after" moves chats to Recently deleted, where they can still be restored. AO has no way to erase a chat for good.
- Read receipts and the queued-turn label: covered by new tests (a fresh agent still coming up, an agent that has the message, model output, a finished answer, a retried card, a stopped turn). The marks were checked in a browser preview with the chat's own styles, not yet in the installed app. What held the two agents' turns in Agent Orchestrator for 7 minutes is not found yet; this release only makes the wait visible (PR #941).
- Everything in 0.8.55 is included.

## 繁體中文

### 對話
- 執行中的對話會在對話列表中顯示為執行中。過去其他專案的對話每分鐘才讀取一次，因此在另一個分割窗格中執行的對話，最多會有一分鐘看似已完成。現在只要 AO 回報其執行有變化，便會立即重新讀取。開啟中的對話在你點按後亦會保留轉圈圖示，已暫停的對話則會顯示圓點（PR #940）。
- 執行中的對話會移到最上方；你拖曳過的對話會留在你放置的位置，直到它下次執行為止。過去只有在其專案為目前開啟的專案時，拖曳過的對話才會被釋放，因此它可能永遠不會回到最上方。現在放在執行中對話上方的對話會留在原位；過去那些執行中的對話會立即跳回它上方，看起來就像拖曳沒有作用。「Reset to newest first」亦會清除拖曳過的對話（PR #940）。
- 在對話框中輸入時，Ctrl+Shift+A（封存）及新增的 Ctrl+Shift+Backspace（刪除）都能使用，並會作用於目前聚焦的分割窗格中的對話，不論它屬於哪個專案（PR #940）。
- 其他專案的對話現在有自己的選單：開啟、在分割檢視中開啟、釘選、標示為未讀、封存及刪除。所有專案的已釘選對話都會顯示在「已釘選」下；過去其他專案的對話一經釘選便會消失（PR #940）。
- 封存及刪除在變更儲存後會立即從列表中移除該對話，並關閉顯示它的分割窗格。「封存對話」不會再在其他操作進行中時毫無作用（PR #940）。
- 你傳送的每則訊息都會顯示模型是否已讀取。訊息下方會顯示：
  - 訊息正送往代理時，顯示淡入淡出的勾號（「Sending…」）；
  - 代理收到後，顯示一個勾號（「Unread」）；
  - 模型寫出任何內容後，顯示兩個勾號（「Read by GPT-6.1 Sol」，或實際回答的模型）。

  回合進行中傳送的訊息原本已有這些標記，現在開啟回合的訊息也有。模型寫出任何內容前已停止的回合不會顯示標記；重試卡片沿用的舊回覆不會算作已讀取新訊息（PR #941）。
- 尚未有代理收到你的訊息時，對話不再顯示「waiting for the model」。需要重新啟動代理時，Agent Orchestrator 會把回合保持在佇列中，直到有代理接手。今天曾見到兩個新代理花了 7 分鐘才啟動，期間對話一直顯示「waiting for the model」，而模型收到訊息後 7 秒便回答。這類回合現在會顯示「waiting for the agent to take the message」，10 分鐘後顯示「May be stuck」（PR #941）。

### 自動封存及自動刪除
- 你還原的對話會視為已使用，閒置清理不會再在數秒內再次封存它（PR #940）。
- 執行卡住而沒有任何工作進行的對話（被暫留的卡片、暫停、從未真正開始的啟動）在閒置後會被封存。過去一張舊的卡住卡片會令對話永遠保持開啟（PR #940）。
- 清理現在亦會由應用程式本身每小時執行一次，因此應用程式在系統匣中時也會封存（PR #940）。
- 執行已不在專案讀取範圍內的已封存對話，仍會倒數計時移至「最近刪除」。因閒置而封存的對話會保留其標題（PR #940）。

### 設定
- 「設定 › 對話」新增三個群組（PR #940）：
  - 對話列表：每個專案顯示的對話數目，以及將執行中的對話保持在最上方。
  - 封存及刪除：閒置多久後封存對話，以及封存多久後刪除對話。
  - 鍵盤快速鍵。
- 對話列表的彈出視窗使用相同的選項，並會跟隨在「設定」中所作的變更。過去在彈出視窗中輸入的數字會在關閉時遺失（PR #940）。

### Web GPT
- WebGPT 內附的執行環境由 codex-chatgpt-web v5.0.6 更新至最新的 v6.1.17，同時保留 Coding Tools 自己的 WebGPT 修正。上游新增（PR #912）：
  - 可選擇推理強度的 GPT-6 Sol 與 GPT-5.6 Sol 獨立項目；
  - Zero Risk 模式；
  - 「每個回合使用新的瀏覽器對話」選項；
  - 升級至 0.0.16 的 tunnel-client（內附 cloudflared 2026.8.2）。
- 任務回合預設仍在已儲存的 ChatGPT 對話中執行，因為 ChatGPT 不允許在臨時對話中使用連接器（PR #912）。
- 在新對話中重試「Something went wrong」現在會計入該回合的三次自動重試，因此 ChatGPT 故障時最多只會傳送四次（PR #912）。

### 效能
- 對話列表不會再在每次活動讀取（約每秒一次）時重新繪製。其他專案的讀取沒有變化時，會保留其列表（PR #940）。
- 過去每個分割窗格在每次推送時都會輪詢並讀取相同的執行及看板資料。現在進行中的讀取若再次被要求，會共用同一個呼叫（PR #940）。
- 各對話頁面會共用同一個列表所儲存的內容（分組、排序、摺疊的專案），而不是互相覆寫（PR #940）。
- 停頓記錄會在整個應用程式的 CPU 之外，另列主執行緒本身的 CPU，因此主程序在等待的停頓不會再被誤認為它在運算（PR #937）。

### 此版本亦包含（0.8.55 沒有單獨發佈）
- 開啟「自動重試」時，顯示「可能卡住」的對話會自行恢復（PR #930）。
- 多個對話同時運作時減少停頓：執行中的卡片不再約每秒兩次開啟新的連線至其對話主機（PR #933）。
- 「Let the model judge」不再讓請求等候你處理（PR #932）。
- 多個長對話載入時，「停止」、「暫停」及審批仍能即時回應（PR #928）。「停止」及重試能處理仍在結束中的代理（PR #931）。
- 長對話可以持續進行，不會因記錄大小而停止（PR #935）。啟動較慢時瀏覽器自動化仍可運作（PR #924）。
- 在分割窗格中，對話框分為兩行，Single | Team 改為雙圖示切換（PR #934）。
- 0.8.55 的完整說明見 `docs/releases/v0.8.55.md`。

### Agent Orchestrator
- Agent Orchestrator 現在執行分支版本的 main 分支，當中包含截至 2026-10-01 的上游 AO 及所有 Coding Tools 變更：
  - 自動化及提示（cues）；
  - 豐富的工作階段連結，以及由工作者回報的 PR 參照；
  - fx、Gemini、MiMo Code、DeepSeek 與 OpenCode v2 執行環境。

  首次啟動時，AO 的資料庫會先把已套用的 Coding Tools 遷移改為新編號，再加入上游的遷移（PR #909，AO 分支 PR #16）。
- 若 AO 在首次啟動重建變更觸發器期間停止，下次啟動會完成這項工作，而不會在缺少三個觸發器的情況下將其記錄為已完成（AO 分支 PR #17）。
- 驗證：分支的遷移測試涵蓋 0.8.x 留下的資料庫、全新的上游資料庫，以及在遷移中途中斷的啟動。尚未在已安裝應用程式自身的資料庫上實際觀察升級過程。

### 驗證及限制
- 由 GitHub CI 從 main 建置及發佈；此版本沒有在本機建置。
- 已由測試涵蓋：變更範圍內 868 項測試通過，其中 10 項為新增。列表亦已在使用模擬 AO 的瀏覽器測試環境中檢查：
  - 點按後的執行中對話保留轉圈圖示；
  - 兩個快速鍵都能在對話框中使用；
  - 拖曳過的對話會留在原位，直到下次執行；
  - 其他專案的執行中對話會在推送後一秒內顯示；
  - 「設定」中的群組能夠儲存。

  以上尚未在已安裝的應用程式中實際觀察。
- 「封存多久後刪除對話」會將對話移至「最近刪除」，在那裡仍可還原。AO 沒有永久清除對話的方法。
- 已讀標記及佇列回合的狀態文字：已由新測試涵蓋（新代理仍在啟動、代理已收到訊息、模型輸出、已完成的回答、重試的卡片、已停止的回合）。標記已在使用對話本身樣式的瀏覽器預覽中檢查，尚未在已安裝的應用程式中檢查。尚未找出 Agent Orchestrator 為何把兩個代理的回合保留了 7 分鐘；此版本只令這段等待變得可見（PR #941）。
- 包含 0.8.55 的所有內容。
