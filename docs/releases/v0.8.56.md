# Coding Tools 0.8.56

## English

### Chats
- Running chats show as running in the chat list. Another project's chats were read only once a minute, so a chat running in another split pane looked done for up to a minute. They are now read again as soon as AO reports a change to their runs. The open chat also keeps its spinner after you click it, and paused chats get a dot.
- A running chat goes to the top, and a chat you drag stays where you put it until its next run. A dragged chat was released only while its project was the open one, so it could stay off the top for good. A chat dropped above running ones now stays there; they jumped straight back above it, so the drag looked like it did nothing. "Reset to newest first" also clears dragged chats.
- Ctrl+Shift+A (archive) and the new Ctrl+Shift+Backspace (delete) work while you type in the chat box. They act on the focused split pane's chat, whichever project it is in.
- Another project's chats have their own menu: Open, Open in split view, Pin, Mark unread, Archive and Delete. Every project's pinned chats show under Pinned; another project's chat used to vanish once pinned.
- Archive and delete take the chat out of the list as soon as the change is saved, and close a split pane showing it. "Archive chats" no longer does nothing while something else is busy.

### Auto-archive and auto-delete
- A chat you restore counts as used, so the idle sweep no longer archives it again within seconds.
- A chat whose run is stuck with nothing working (a held card, a pause, a start that never got going) is archived once idle. One old stuck card used to keep a chat open for good.
- The sweep also runs every hour from the app itself, so the app archives while it sits in the tray.
- Archived chats whose runs have left the project's read still count down to Recently deleted. A chat archived for being idle keeps its title.

### Settings
- Settings › Chat has three new groups:
  - Chat list: chats shown per project, and keep running chats on top.
  - Archive and delete: archive inactive chats after, and delete archived chats after.
  - Keyboard shortcuts.
- The chat list's popover uses the same choices and follows changes made in Settings. A number typed into the popover was lost when it closed.

### Performance
- The chat list no longer redraws on every activity read, about once a second. Another project's unchanged read keeps its list.
- Every split pane polled and read the same runs and board on each push. A read asked for again while one is on its way now shares that call.
- Chat pages share what one list saves (sections, order, folded projects) instead of overwriting each other.

### Verification and limitations
- Built and published by GitHub CI from main; no local build was made for this version.
- Covered by tests: 868 tests pass in the changed areas, including 10 new ones. The list was also checked in a browser harness with a fake AO:
  - a clicked running chat keeps its spinner;
  - both shortcuts work from the chat box;
  - a dragged chat stays put until its next run;
  - another project's running chat shows within a second of a push;
  - the Settings groups save.

  None of this has been watched in the installed app yet.
- "Delete archived chats after" moves chats to Recently deleted, where they can still be restored. AO has no way to erase a chat for good.
- Everything in 0.8.55 is included.

## 繁體中文

### 對話
- 執行中的對話會在對話列表中顯示為執行中。過去其他專案的對話每分鐘才讀取一次，因此在另一個分割窗格中執行的對話，最多會有一分鐘看似已完成。現在只要 AO 回報其執行有變化，便會立即重新讀取。開啟中的對話在你點按後亦會保留轉圈圖示，已暫停的對話則會顯示圓點。
- 執行中的對話會移到最上方；你拖曳過的對話會留在你放置的位置，直到它下次執行為止。過去只有在其專案為目前開啟的專案時，拖曳過的對話才會被釋放，因此它可能永遠不會回到最上方。現在放在執行中對話上方的對話會留在原位；過去那些執行中的對話會立即跳回它上方，看起來就像拖曳沒有作用。「Reset to newest first」亦會清除拖曳過的對話。
- 在對話框中輸入時，Ctrl+Shift+A（封存）及新增的 Ctrl+Shift+Backspace（刪除）都能使用，並會作用於目前聚焦的分割窗格中的對話，不論它屬於哪個專案。
- 其他專案的對話現在有自己的選單：開啟、在分割檢視中開啟、釘選、標示為未讀、封存及刪除。所有專案的已釘選對話都會顯示在「已釘選」下；過去其他專案的對話一經釘選便會消失。
- 封存及刪除在變更儲存後會立即從列表中移除該對話，並關閉顯示它的分割窗格。「封存對話」不會再在其他操作進行中時毫無作用。

### 自動封存及自動刪除
- 你還原的對話會視為已使用，閒置清理不會再在數秒內再次封存它。
- 執行卡住而沒有任何工作進行的對話（被暫留的卡片、暫停、從未真正開始的啟動）在閒置後會被封存。過去一張舊的卡住卡片會令對話永遠保持開啟。
- 清理現在亦會由應用程式本身每小時執行一次，因此應用程式在系統匣中時也會封存。
- 執行已不在專案讀取範圍內的已封存對話，仍會倒數計時移至「最近刪除」。因閒置而封存的對話會保留其標題。

### 設定
- 「設定 › 對話」新增三個群組：
  - 對話列表：每個專案顯示的對話數目，以及將執行中的對話保持在最上方。
  - 封存及刪除：閒置多久後封存對話，以及封存多久後刪除對話。
  - 鍵盤快速鍵。
- 對話列表的彈出視窗使用相同的選項，並會跟隨在「設定」中所作的變更。過去在彈出視窗中輸入的數字會在關閉時遺失。

### 效能
- 對話列表不會再在每次活動讀取（約每秒一次）時重新繪製。其他專案的讀取沒有變化時，會保留其列表。
- 過去每個分割窗格在每次推送時都會輪詢並讀取相同的執行及看板資料。現在進行中的讀取若再次被要求，會共用同一個呼叫。
- 各對話頁面會共用同一個列表所儲存的內容（分組、排序、摺疊的專案），而不是互相覆寫。

### 驗證及限制
- 由 GitHub CI 從 main 建置及發佈；此版本沒有在本機建置。
- 已由測試涵蓋：變更範圍內 868 項測試通過，其中 10 項為新增。列表亦已在使用模擬 AO 的瀏覽器測試環境中檢查：
  - 點按後的執行中對話保留轉圈圖示；
  - 兩個快速鍵都能在對話框中使用；
  - 拖曳過的對話會留在原位，直到下次執行；
  - 其他專案的執行中對話會在推送後一秒內顯示；
  - 「設定」中的群組能夠儲存。

  以上尚未在已安裝的應用程式中實際觀察。
- 「封存多久後刪除對話」會將對話移至「最近刪除」，在那裡仍可還原。AO 沒有永久清除對話的方法。
- 包含 0.8.55 的所有內容。
