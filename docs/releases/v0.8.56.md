# Coding Tools 0.8.56

## English

### Chats
- Every message you send shows whether the model has read it. Under the message:
  - a fading check ("Sending…") while it is on its way to an agent;
  - one check ("Unread") once an agent has it;
  - two checks ("Read by GPT-6.1 Sol", or whichever model answers) once the model has written anything.

  Messages sent mid-turn already had these marks; now the message that starts a turn has them too. A turn stopped before its model wrote anything gets no mark, and a retried card's earlier reply doesn't count as reading the new message (PR #941).
- A chat no longer says "waiting for the model" while no agent has your message yet. When an agent had to be started fresh, Agent Orchestrator keeps the turn queued until one takes it. Seen today: two fresh agents took 7 minutes to come up while the chat said "waiting for the model", and the model then answered in 7 seconds. Such a turn now reads "waiting for the agent to take the message", and after 10 minutes it shows "May be stuck" (PR #941).

### Verification and limitations
- The receipts and the queued-turn label are covered by new tests (a fresh agent still coming up, an agent that has the message, model output, a finished answer, a retried card, a stopped turn). The four chat suites pass locally: 242, 398 of 399 (the one left needs files the local check-out didn't include), 63 and 56. The marks were checked in a browser preview of the chat's own styles, not yet in the installed app (PR #941).
- What held the two agents' turns in Agent Orchestrator for 7 minutes is not found yet; this release only makes the wait visible.
- Built and published by GitHub CI from main; no local build was made for this version.
- Everything in 0.8.55 is included.

## 繁體中文

### 對話
- 你傳送的每則訊息都會顯示模型是否已讀取。訊息下方會顯示：
  - 訊息正送往代理時，顯示淡入淡出的勾號（「Sending…」）；
  - 代理收到後，顯示一個勾號（「Unread」）；
  - 模型寫出任何內容後，顯示兩個勾號（「Read by GPT-6.1 Sol」，或實際回答的模型）。

  回合進行中傳送的訊息原本已有這些標記，現在開啟回合的訊息也有。模型寫出任何內容前已停止的回合不會顯示標記；重試卡片沿用的舊回覆不會算作已讀取新訊息（PR #941）。
- 尚未有代理收到你的訊息時，對話不再顯示「waiting for the model」。需要重新啟動代理時，Agent Orchestrator 會把回合保持在佇列中，直到有代理接手。今天曾見到兩個新代理花了 7 分鐘才啟動，期間對話一直顯示「waiting for the model」，而模型收到訊息後 7 秒便回答。這類回合現在會顯示「waiting for the agent to take the message」，10 分鐘後顯示「May be stuck」（PR #941）。

### 驗證及限制
- 已讀標記及佇列回合的狀態文字已由新測試涵蓋（新代理仍在啟動、代理已收到訊息、模型輸出、已完成的回答、重試的卡片、已停止的回合）。四組對話測試在本機通過：242、399 項中的 398 項（餘下一項需要本機簽出未包含的檔案）、63 及 56。標記已在使用對話本身樣式的瀏覽器預覽中檢查，尚未在已安裝的應用程式中檢查（PR #941）。
- 尚未找出 Agent Orchestrator 為何把兩個代理的回合保留了 7 分鐘；此版本只令這段等待變得可見。
- 由 GitHub CI 從 main 建置及發佈；此版本沒有在本機建置。
- 包含 0.8.55 的所有內容。
