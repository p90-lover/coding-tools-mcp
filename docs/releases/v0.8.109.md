# Coding Tools 0.8.109

## English

### Updates: automatic updates install again (#1175)
- **With Automatic updates on, an update never installed while Coding Tools was open.** The app counted its own startup (bringing up the bridge and the MCP runtime) as still running for as long as it stayed open, so every idle check answered "busy". This has been so since automatic installs arrived (#322, October 17). An update arrived only when you clicked Update or restarted the app.
- **The same mistake stopped two other automatic steps:**
  - a new version that failed its health check never rolled itself back (#698);
  - a downloaded CPA update waited for the next start instead of switching while the app was idle (#661).
- **The startup now counts only while it runs.**
- ⚠️ **An idle Coding Tools with Automatic updates on now installs an available update by itself, and that restarts the app.** It still waits:
  - for the idle time set in Settings;
  - for running chats, when "Wait for chats to finish" is on;
  - for any browser or runtime work that is still running.
  
  To keep updating by hand, turn Automatic updates off in Settings.
- Reconnecting an MCP tunnel works as before. When the startup it waited for left the runtime not ready, it still starts the runtime once more.

### Sidebar: the Claude desktop look, and a pin keeps "More" open (#1176)
- **The sidebar now looks like the Claude desktop app's:**
  - a warm dark surface;
  - 32 px rows with rounded corners and soft hover and selected fills;
  - quiet section names, and a clay-coloured update row and keyboard focus ring.
  - Only the sidebar changes; the pages keep their look.
- **"More" can stay open.** It used to open only while one of its pages was showing, and folded away as soon as you left one.
  - A pin on the right of its heading ("Always show More") now keeps it open on every page and across restarts.
  - Click the pin again to go back to the old behaviour. While pinned, the heading no longer folds the section.
  - Without the pin, the heading opens and folds it as before.

### Performance: changing an external service's settings no longer freezes the window (#1170)
- **Each CPA start, install, repair or update froze every window for up to 2.2 s** (2026-11-10, 0.8.106). That is also true of each change on the external services settings screen. The app saved `external-services.json` with a flushed write on its main thread, and on the busy hard disk the flush alone took seconds.
- **The file is now saved off the main thread.** Several changes in a row become one write, and quitting waits for a save in progress.
- **A save that fails keeps the old file and is logged.** The next change writes it again, and a change made on the settings screen still reports the error there.

### Performance: starting the MCP tunnel no longer freezes the window (#1172)
- **Starting the MCP tunnel froze every window for 6.6 s** (2026-11-10, 0.8.106). The app checked that the tunnel program and its key exist on its main thread, and on the busy hard disk one check took seconds. The tunnel starts with the runtime, and again on each restart and recovery.
- **Both checks now run off the main thread.** A missing program or key still stops the start with the same message, before any tunnel command runs.

### Performance: Coding Tools no longer rewrites an unchanged file at every start (#1173)
- **Every launch froze every window for about 0.7 s** (2026-11-10, 0.8.107). The app rewrote the list of local service addresses (`loopback-mesh.json`) with a flushed write, even when nothing in it had changed.
- **The file on disk is now read off the main thread at launch.** An unchanged list is no longer rewritten. A real change is still written at once, before any other program can read the file.

## 繁體中文

### 更新：自動更新恢復安裝（#1175）
- **開啟「自動更新」時，只要 Coding Tools 開著，更新就從未安裝。** 程式在整段執行期間都把自己的啟動程序（啟動橋接程式與 MCP 執行環境）視為仍在執行，因此每次閒置檢查都回答「忙碌」。自動安裝功能推出以來（#322，10 月 17 日）一直如此；只有在你按下「更新」或重新啟動程式時，更新才會安裝。
- **同一個錯誤也讓另外兩項自動步驟無法執行：**
  - 未通過健康檢查的新版本從未自動還原（#698）；
  - 已下載的 CPA 更新一直等到下次啟動，而不是在程式閒置時切換（#661）。
- **現在啟動程序只在執行期間才算數。**
- ⚠️ **開啟「自動更新」時，閒置的 Coding Tools 現在會自行安裝可用的更新，並因此重新啟動程式。** 它仍會等待：
  - 設定中的閒置時間；
  - 開啟「等待對話完成」時，等待執行中的對話；
  - 仍在執行的瀏覽器或執行環境工作。
  
  若想繼續手動更新，請在設定中關閉「自動更新」。
- 重新連接 MCP 通道的行為不變：若它等待的啟動程序結束後執行環境仍未就緒，仍會再啟動一次執行環境。

### 側邊欄：改為 Claude 桌面版的外觀，並可釘選「更多」保持展開（#1176）
- **側邊欄改為 Claude 桌面版的外觀：**
  - 溫暖的深色底；
  - 32 px 高的圓角列，滑過與選取時有柔和的底色；
  - 低調的分區名稱，更新列與鍵盤焦點框改用陶土色。
  - 只有側邊欄改變，各頁面維持原樣。
- **「更多」可以保持展開。** 以前只有在顯示其中某一頁時才會展開，一離開就收起。
  - 現在標題右側的圖釘（「一律顯示「更多」」）能讓它在每一頁都保持展開，重新啟動後依然如此。
  - 再按一次圖釘即回到原本的行為。釘選時，標題不再收起此區。
  - 未釘選時，標題照舊可展開或收起此區。

### 效能：變更外部服務設定時不再凍結視窗（#1170）
- **每次啟動、安裝、修復或更新 CPA，所有視窗都會凍結最多 2.2 秒**（2026-11-10，0.8.106）。在外部服務設定畫面做的每次變更也是如此。程式在主執行緒上以強制寫入磁碟的方式儲存 `external-services.json`，在忙碌的硬碟上，光是寫入磁碟就要數秒。
- **現在改在主執行緒之外儲存。** 連續多次變更只寫入一次，結束程式時會等待進行中的儲存。
- **儲存失敗時保留舊檔並記錄。** 下一次變更會再寫入；在設定畫面上做的變更，仍會在畫面上顯示錯誤。

### 效能：啟動 MCP 通道時不再凍結視窗（#1172）
- **啟動 MCP 通道時，所有視窗凍結 6.6 秒**（2026-11-10，0.8.106）。程式在主執行緒上檢查通道程式與其金鑰是否存在，在忙碌的硬碟上，一次檢查就要數秒。通道會隨執行環境啟動，每次重新啟動與復原時也會再啟動。
- **兩項檢查現在都在主執行緒之外進行。** 程式或金鑰不存在時，仍會以相同訊息停止啟動，且不會執行任何通道指令。

### 效能：Coding Tools 啟動時不再重寫未變更的檔案（#1173）
- **每次啟動，所有視窗都會凍結約 0.7 秒**（2026-11-10，0.8.107）。程式以強制寫入磁碟的方式重寫本機服務位址清單（`loopback-mesh.json`），即使內容完全沒變。
- **現在啟動時會在主執行緒之外讀取磁碟上的檔案。** 未變更的清單不再重寫；真正的變更仍會立即寫入，搶在其他程式讀取之前。
