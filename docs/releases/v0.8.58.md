# Coding Tools 0.8.58

## English

### Performance
- Fewer freezes on a busy disk. When a folder the app watches changed (CPA's accounts, the Codex homes, provider and CPA settings, the runtime config), Windows' handling of that change looked the file up on disk on the app's main thread first. All of those folders are on the hard disk with the app's data, so one change could hold every window for seconds: 5.2 s with almost no CPU was seen today. The watches now run in a background thread, and the app only hears about the change (PR #951).
- Agent Orchestrator reads far less from disk while chats are working. For each model reply's token usage, AO checks whether another chat continuing the same transcript has already recorded it. No index answered that check, so SQLite read through every usage record AO had ever stored, once per reply. With six chats working this was over a third of AO's database read time, and it grew with the usage history. An index now answers it in a few page reads (PR #953, AO fork PR #18).
- Old runtime copies are cleaned up. A runtime installed beside a busy version folder got a name the cleanup didn't recognise, so it stayed on disk after a newer version took over (PR #952).

### Chats
- DeepSeek at max effort is sent at max. Through CPA, Claude Code's requests went out at low effort whatever you picked; the effort is now part of the model name CPA receives (PR #946).
- After a chat restart, the chat's history pairs each message with its own reply. A restarted run's reply could be shown under the next message (PR #950).
- Text cut to fit a size limit stays within the limit, and the "omitted" marker gives the real number of characters left out (PR #950).

### Verification and limitations
- Built and published by GitHub CI from main; no local build was made for this version.
- Folder watches: all 19 test files that use the changed code pass, including new tests that the watch runs off the main thread, that a missing folder reports an error instead of failing, and that it still works where no background thread can start. Not yet watched in the installed app: whether the freezes stop will show in the app's freeze records (PR #951).
- AO usage check, before: on the installed 0.8.51 with six of 593 chats working, Windows I/O counters showed AO reading 89,000–101,000 times a minute (5.6–6.5 MB/s). A CPU profile put 37.5% of AO's database read time in this check.
- AO usage check, after: replaying AO's per-reply transaction on a database built from AO's own migrations, with 200,000 usage records, took about 5,040 disk reads per reply without the index and 4–5 with it. A new test checks that SQLite finds both tables through an index. Not yet measured in an installed build; under the same load, AO's reads should drop by about a third. The rest is mostly open chats reading their pages (PR #953).
- Everything in 0.8.57 is included.

## 繁體中文

### 效能
- 磁碟繁忙時減少停頓。應用程式監看的資料夾（CPA 帳號、Codex 主目錄、供應商及 CPA 設定、執行環境設定）有變化時，Windows 處理該變化前會先在應用程式的主執行緒上於磁碟查詢該檔案。這些資料夾都位於存放應用程式資料的硬碟上，因此一次變化便可能令所有視窗停頓數秒：今天曾見到 5.2 秒，而 CPU 幾乎沒有使用。現在監看改在背景執行緒進行，應用程式只會收到變化通知（PR #951）。
- 對話執行期間，Agent Orchestrator 從磁碟讀取的次數大幅減少。每當模型回覆的 token 用量送達，AO 都會檢查延續同一份對話記錄的另一個對話是否已記錄過它。過去沒有索引能回答這項檢查，因此 SQLite 每次回覆都會讀遍 AO 曾儲存的所有用量記錄。在六個對話執行時，這佔了 AO 資料庫讀取時間的三分之一以上，而且會隨用量記錄增加而變慢。現在由一個索引以少數幾頁讀取回答這項檢查（PR #953，AO 分支 PR #18）。
- 會清理舊的執行環境副本。安裝在忙碌版本資料夾旁的執行環境，名稱過去無法被清理程序辨認，因此較新版本接手後仍會留在磁碟上（PR #952）。

### 對話
- 以最高推理強度使用 DeepSeek 時會以最高強度送出。過去經 CPA 送出的 Claude Code 請求不論你選擇什麼都以低強度送出；現在推理強度會包含在 CPA 收到的模型名稱中（PR #946）。
- 對話重新啟動後，對話記錄中每則訊息都會與其自身的回覆配對。過去重新啟動的執行所產生的回覆可能顯示在下一則訊息之下（PR #950）。
- 為符合大小上限而截斷的文字會保持在上限內，「已省略」標記亦會顯示實際省略的字元數（PR #950）。

### 驗證及限制
- 由 GitHub CI 從 main 建置及發佈；此版本沒有在本機建置。
- 資料夾監看：使用已變更程式碼的全部 19 個測試檔案均通過，包括新增的測試：監看在主執行緒以外執行、缺少的資料夾會回報錯誤而非失敗，以及無法啟動背景執行緒時仍可運作。尚未在已安裝的應用程式中觀察：停頓是否消失，將在應用程式的停頓記錄中顯示（PR #951）。
- AO 用量檢查，修正前：在已安裝的 0.8.51 上，593 個對話中有六個執行時，Windows I/O 計數器顯示 AO 每分鐘讀取 89,000–101,000 次（5.6–6.5 MB/s）。CPU 剖析顯示 AO 資料庫讀取時間的 37.5% 花在這項檢查上。
- AO 用量檢查，修正後：在以 AO 自身遷移建立、含 200,000 筆用量記錄的資料庫上重播 AO 每次回覆的交易，沒有索引時每次回覆約讀取磁碟 5,040 次，有索引時為 4–5 次。新測試會檢查 SQLite 透過索引尋找兩個資料表。尚未在已安裝的版本中實際量測；在相同負載下，AO 的讀取次數預計減少約三分之一，其餘主要是開啟中的對話讀取其頁面（PR #953）。
- 包含 0.8.57 的所有內容。
