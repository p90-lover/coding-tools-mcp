# Coding Tools 0.8.58

## English

### Performance
- Agent Orchestrator reads far less from disk while chats are working. For each model reply's token usage, AO checks whether another chat continuing the same transcript has already recorded it. No index answered that check, so SQLite read through every usage record AO had ever stored, once per reply. With six chats working this was over a third of AO's database read time, and it grew with the usage history. An index now answers it in a few page reads (PR #953, AO fork PR #18).

### Verification and limitations
- Before: on the installed 0.8.51 with six of 593 chats working, Windows I/O counters showed AO reading 89,000–101,000 times a minute (5.6–6.5 MB/s). A CPU profile put 37.5% of AO's database read time in this check.
- After: replaying AO's per-reply transaction on a database built from AO's own migrations, with 200,000 usage records, took about 5,040 disk reads per reply without the index and 4–5 with it. A new test checks that SQLite finds both tables through an index.
- Not yet measured in an installed build. Under the same load, AO's reads should drop by about a third. The rest is mostly open chats reading their pages.
- Everything in 0.8.57 is included.

## 繁體中文

### 效能
- 對話執行期間，Agent Orchestrator 從磁碟讀取的次數大幅減少。每當模型回覆的 token 用量送達，AO 都會檢查延續同一份對話記錄的另一個對話是否已記錄過它。過去沒有索引能回答這項檢查，因此 SQLite 每次回覆都會讀遍 AO 曾儲存的所有用量記錄。在六個對話執行時，這佔了 AO 資料庫讀取時間的三分之一以上，而且會隨用量記錄增加而變慢。現在由一個索引以少數幾頁讀取回答這項檢查（PR #953，AO 分支 PR #18）。

### 驗證及限制
- 修正前：在已安裝的 0.8.51 上，593 個對話中有六個執行時，Windows I/O 計數器顯示 AO 每分鐘讀取 89,000–101,000 次（5.6–6.5 MB/s）。CPU 剖析顯示 AO 資料庫讀取時間的 37.5% 花在這項檢查上。
- 修正後：在以 AO 自身遷移建立、含 200,000 筆用量記錄的資料庫上重播 AO 每次回覆的交易，沒有索引時每次回覆約讀取磁碟 5,040 次，有索引時為 4–5 次。新測試會檢查 SQLite 透過索引尋找兩個資料表。
- 尚未在已安裝的版本中實際量測。在相同負載下，AO 的讀取次數預計減少約三分之一；其餘主要是開啟中的對話讀取其頁面。
- 包含 0.8.57 的所有內容。
