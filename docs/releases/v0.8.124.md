# Coding Tools v0.8.124

## English

### Permissions

- **Approve for me now takes effect in a turn that's already running (#1315).** Picking a permission mode while an agent was working only saved it for the agent's next turn: the chip said "Applies from the next turn" and "Active permissions not confirmed yet". After Auto Review came back from a server error, choosing Approve for me again did nothing for a turn that had been running for hours, so every request kept waiting for you.
  - Requests from the running turn now follow your latest choice as soon as you make it, and the chip says "Active now".
  - When the agent answers its own requests (Codex with its own auto-review, or Full access), the chip says "This turn: …" and that your change applies from the next turn.

### Approvals and follow-ups

- **Switching "Let the model judge" during an approval review takes effect at once (#1213).** A review already in flight now reads the setting when it settles, not when it started.
- **Scheduled wake-ups and command-completion follow-ups are no longer lost or left on "Sending" (#1213).** A temporary failure while one was being delivered could drop it or leave it stuck; it is now retried or cleaned up.

### Chats

- **A chat's live view no longer freezes on one slow read (#1318).** After a stopped chat was continued with "keep going", its agent kept the task and its context, but the view stayed on "checking", then "reconnecting to the chat's agent", for about 8 minutes. That hid the approval the agent was waiting for.
  - The chat refreshes its live view every second and waited for every refresh to finish before starting the next, so one refresh that never finished stopped them all. A refresh that takes longer than 10 seconds no longer holds the others: the chat keeps what it had and asks again on the next tick.
  - The app logs which step held a slow refresh (`ao.activity_frame_stalled`, `ao.activity_frame_slow`, `ao.activity_read_slow`).
- **Clicking a working agent on the Team graph opens its conversation (#1246):** its request, thinking, tool calls and replies. "Edit role" and the card menu's Edit still open the role editor.
- **Chats use less GPU while an agent works (#1316).** The pulsing dots in a running turn's stats line now update 10 times a second, like the other status marks, instead of redrawing the window on every screen refresh. This shipped in 0.8.123, whose notes did not list it.

### Agent Orchestrator

Agent Orchestrator is pinned at db4fa47cf (AO#46, AO#47, AO#48 and AO#41, on top of 0.8.123's 50b709c03).

- **A chat that was starting when the app restarted no longer stays unreachable (AO#46).** Its background host was left running with no session, and every later attempt to open the chat failed. The chat now starts on a new host, and a host left like this ends itself after 2 minutes.
- **A chat no longer refuses to start after a reboot because of an old lock (AO#46).** A leftover `host.lock` named a process id that Windows had given to another program. The lock now also checks when its owner started.
- **A Claude Code chat whose session was dropped during a turn recovers on the next message (AO#46),** instead of every later turn failing the same way.
- **Open chats no longer keep the hard disk busy (AO#47).** Each working chat card's timeline refresh, about every second, opened every recent activity's saved output and every turn the chat ever had. With several chats working, the disk stayed 100% busy. The refresh now reads two small indexes, built once on the first start after this update.
- **Usage tracking no longer keeps looking for a chat history file that is gone (AO#48).** It now gives up on such a file after about 4 minutes and keeps the usage it had read (marked partial if the file was not read to its end). A chat that ended without ever writing a history file no longer keeps the usage scan running.
- **A chat's agent connection is no longer closed when AO's event writer stalls (AO#41).** On 2026-11-13, with the disk saturated, AO's notification queue filled, AO closed the agent connection, and the chat's resume failed with "peer disconnected before response". Events that arrive while the writer is stalled now wait instead of overflowing the queue.
- **AO's startup is gentler after a hard stop (#1214).** AO no longer runs database maintenance at startup while its write-ahead log holds more than 64 MB (it copies that backlog in the background instead), and a slow AO start reports its progress every minute instead of once.

### Computer use

- **When Codex stops computer use for the current turn, control ends at once (#1199).** For example, when it cannot verify that the current browser URL is allowed. Queued input is discarded, instead of the app reporting that control is still usable.

### MCP connectors

- **A failed automatic MCP connector setup records what the ChatGPT page showed (#1239):** how many tabs it had and how many were visible, whether the plugin list was still loading, how long setup waited, and whether the hidden window was still drawing. No tab names or account details are recorded, and the message you see is unchanged.

## 繁體中文

### 權限

- **「替我核准」現在也會在已經執行中的回合生效（#1315）。** 以前在代理程式工作時選擇權限模式，只會儲存到代理程式的下一個回合：晶片顯示「從下一個回合開始套用」和「尚未確認目前的權限」。自動審查（Auto Review）從伺服器錯誤恢復後，再次選擇「替我核准」對已執行數小時的回合毫無作用，每個要求仍然等待你處理。
  - 現在，執行中回合的要求會在你做出選擇後立即依照你最新的選擇處理，晶片會顯示「立即生效」。
  - 若代理程式自行回應自己的要求（Codex 使用其內建的自動審查，或「完全存取」），晶片會顯示「本回合：…」，並說明你的變更從下一個回合開始套用。

### 審批與後續訊息

- **在核准審查進行中切換「讓模型判斷」會立即生效（#1213）。** 進行中的審查現在會在結束時讀取當下的設定，而不是開始時的設定。
- **排程喚醒與指令完成後的後續訊息不再遺失，也不會一直停在「傳送中」（#1213）。** 以前傳送過程中的暫時性失敗可能讓它遺失或卡住；現在會重試或清理。

### 對話

- **對話的即時畫面不會再因一次緩慢的讀取而卡住（#1318）。** 停止的對話用「keep going」繼續後，代理程式仍保有原本的任務與上下文，但畫面約有 8 分鐘停在「checking」，接著是「reconnecting to the chat's agent」，蓋住了代理程式正在等待的核准。
  - 對話每秒更新一次即時畫面，而且要等每次更新完成才開始下一次，所以只要有一次更新沒有完成，之後的更新就全部停住。現在超過 10 秒仍未完成的更新不會再擋住其他更新：對話會繼續顯示原本的內容，並在下一次更新時再讀一次。
  - App 會記錄是哪個步驟拖慢了更新（`ao.activity_frame_stalled`、`ao.activity_frame_slow`、`ao.activity_read_slow`）。
- **在團隊圖上點擊正在工作的代理，現在會開啟它的對話（#1246）：** 它收到的請求、思考、工具呼叫與回覆。「Edit role」與卡片選單的「Edit」仍會開啟角色編輯器。
- **代理執行時，對話更省 GPU（#1316）。** 執行中回合統計列的脈動圓點現在與其他狀態標記一樣，每秒更新 10 次，不再於每次螢幕刷新時重繪視窗。此變更已隨 0.8.123 發佈，但當時的說明未列出。

### Agent Orchestrator

Agent Orchestrator 固定於 db4fa47cf（在 0.8.123 的 50b709c03 之上加入 AO#46、AO#47、AO#48 與 AO#41）。

- **App 重新啟動時正在啟動的對話，不會再一直無法使用（AO#46）。** 以前該對話的背景主機會留在執行中但沒有工作階段，之後每次開啟對話都會失敗。現在對話會改用新的主機啟動，而這種被留下的主機會在 2 分鐘後自行結束。
- **重新開機後，對話不會再因為舊的鎖定檔而無法啟動（AO#46）。** 留下來的 `host.lock` 記錄的處理程序 ID 已被 Windows 分配給其他程式。現在鎖定檔也會檢查擁有者的啟動時間。
- **Claude Code 對話在回合進行中被丟棄工作階段時，會在下一則訊息復原（AO#46），** 不再讓之後每個回合都以相同方式失敗。
- **開著的對話不會再讓硬碟一直忙碌（AO#47）。** 每張進行中的對話卡大約每秒更新一次時間軸，以前每次都會開啟每個近期活動儲存的輸出，以及該對話所有回合。有好幾個對話同時進行時，硬碟會持續 100% 忙碌。現在更新改為讀取兩個小型索引，更新後第一次啟動時建立一次。
- **用量追蹤不會再一直尋找已消失的對話記錄檔（AO#48）。** 現在大約 4 分鐘後就會放棄該檔案，並保留已讀取的用量（若檔案尚未讀完，會標示為不完整）。結束時從未寫入記錄檔的對話，也不會再讓用量掃描持續執行。
- **AO 的事件寫入停滯時，對話的代理連線不會再被關閉（AO#41）。** 2026-11-13 磁碟滿載時，AO 的通知佇列被塞滿，AO 關閉了代理連線，對話的恢復因「peer disconnected before response」而失敗。現在寫入停滯期間收到的事件會等待，不再讓佇列溢位。
- **強制停止後，AO 啟動時更溫和（#1214）。** 預寫日誌超過 64 MB 時，AO 啟動不再執行資料庫維護（改由背景複製這些積壓），AO 啟動緩慢時會每分鐘回報一次進度，而不是只回報一次。

### 電腦控制

- **當 Codex 在本輪停止電腦控制時，控制會立即結束（#1199）。** 例如無法確認目前瀏覽器網址是否允許時，會捨棄排隊中的輸入，不再回報控制仍可使用。

### MCP 連接器

- **自動建立 MCP 連接器失敗時，現在會記錄 ChatGPT 頁面當時的狀態（#1239）：** 頁面有幾個分頁、其中幾個可見、外掛清單是否仍在載入、設定等了多久，以及隱藏視窗是否仍在繪製。不記錄分頁名稱或帳號資料，畫面上的訊息不變。
