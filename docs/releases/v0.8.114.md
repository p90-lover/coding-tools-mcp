# Coding Tools 0.8.114

## English

### CPA runs one plugin: Provider Manager 0.6.0 (#1251)
- **Every CPA plugin's work is now inside Provider Manager.** CPA Helper (usage, prices, the Codex quota scheduler), CPA Auto Review, Cline Pass, CommandCode Go, CommandCode and Grok are its parts, so CPA loads a single plugin.
  - On the first start, the old plugins move to Trash.
  - Cline, CommandCode and Grok accounts become Provider Manager accounts, with each original copied to Trash first.
  - Settings and data move over, and your Provider Manager upstreams and keys stay where they were.
  - Model ids, routes and logins are unchanged.
- **A new Provider Manager console:**
  - Overview: live numbers, a traffic chart, models, upstream health and a live feed.
  - Logs, Providers, Models and pricing, Routing, Accounts by kind, Auto Review, Cline Pass, AI Studio and Parts.
  - Light and dark themes, with animation that stops while the page is idle.
- **Codex accounts with quota left are used again** when the preferred priority tier is spent. One spent tier no longer refuses every Codex request with "quota_exceeded".
- **Grok** now receives chat-completions requests only. Responses-only features, such as the hosted `web_search`/`x_search` tools and `previous_response_id`, are no longer available on Grok models.

### Chats (#1243, #1253)
- **The chat keeps following new output until you scroll up, as in Codex (#1243).** A click, a touch or a wheel down that moved nothing used to stop it. A send now always jumps to the newest message.
- **Switching model or harness during "Retry automatically" cancels the retry (#1253),** and your next message uses the new setup. Before, the retry ran on the old setup and your message waited behind it.
- **Queued messages are never lost (#1253).**
  - A message stays queued until it is sent.
  - A failed send shows "Not sent yet" with the reason.
  - A message that can't be sent or queued goes back into the chat's input box.
- **Faster chats (#1253).**
  - A stuck follow-up gives up after 30 seconds instead of 3 minutes.
  - A hung agent start is caught in about 90 seconds instead of 4 minutes.
  - A broken setup is no longer retried for half an hour.
  - Failures that never reached the provider retry after 2 seconds.
  - Stop, send and queue make fewer waits in a row.

  Retries after provider errors (rate limits, 5xx) keep their full pauses.
- **A chat resumed after a restart no longer stalls when focus moves for a moment (#1238).** The refused step runs again when you return to the window.
- **Rewind waits for the chat to stop (#1238).** While a chat works, Rewind is turned off and says to stop the chat first, instead of failing.
- **A retried chat's earlier attempt no longer shows below the new one (#1242).**
- **A chat no longer fails when the agent's version check can't run (#1250).** On a busy machine, a start could fail with "read Codex version: exit status 1" although the agent was fine. It is now retried twice, and only an agent that is really too old is refused.
- **A subagent cut short by a restart or a dead agent process carries on instead of failing (#1249).**

### Clicks and focus (#1247)
- **The first click after the app was busy works again.** Buttons outside the chat (App plugins Update, Browser accounts, Email, MCP tunnels, services) could refuse a click with "Click into the Coding Tools window". They now wait a moment for the window's focus.
- **Approving an agent's request right after a pause works.**
- **A message sent as you switched away is no longer lost.** It comes back into the chat box with the reason; Send now on a queued message does the same.
- **No more 40-second freezes from CPA requests.** Image generation, the Gemini sign-in check and provider account checks no longer ask CPA from the app's main thread.

### App plugins (#1241)
- **Update works again for CPA plugins.** It failed with "Invalid URL".
- **Two auto-update switches flipped together are both saved.**

### Clawd (#1245)
- **Clawd's house is back above Settings in split view.**
- **Clawd walks turned toward where it goes, turns round,** and waves, stretches, dances and peers.

### Verification and limitations
- #1251 and Provider Manager 0.6.0:
  - Provider Manager's full Go suite passes, and its console tests pass 64/64.
  - Each part's tests pass, including a live Cline Pass run under Bun.
  - The app's CPA tests: 124 pass, 0 fail.
  - The account migration and the console have not been checked in the running app.
- #1243 and #1253:
  - The touched test files pass 1,060/1,060 and 351/351.
  - `tsc` is clean.
  - Not checked in the running app.
  - The new `ao.send_timing`, `ao.stop_timing` and `ao.review_timing` logs will show the real gains.
- Built from the merged `main` after the full desktop suite and both typechecks.
- Includes everything in 0.8.113.

## 繁體中文

### CPA 只執行一個外掛：Provider Manager 0.6.0（#1251）
- **所有 CPA 外掛的功能現在都在 Provider Manager 內。**CPA Helper（用量、價格、Codex 配額排程）、CPA Auto Review、Cline Pass、CommandCode Go、CommandCode 與 Grok 都成為它的部件，CPA 只需載入一個外掛。
  - 首次啟動時，舊外掛會移至垃圾桶。
  - Cline、CommandCode 與 Grok 帳號會轉為 Provider Manager 帳號，每個原始檔案都會先複製到垃圾桶。
  - 設定與資料會一併轉移，原有的 Provider Manager 上游與金鑰保持不變。
  - 模型 ID、路由與登入方式不變。
- **全新的 Provider Manager 主控台：**
  - 總覽：即時數據、流量圖、模型、上游狀態與即時動態。
  - 記錄、供應商、模型與價格、路由、依類型分組的帳號、Auto Review、Cline Pass、AI Studio 與部件。
  - 支援淺色與深色主題，動畫在頁面閒置時會停止。
- **偏好的優先級用完時，會改用仍有配額的 Codex 帳號。**不會再因一個優先級用完就以「quota_exceeded」拒絕所有 Codex 請求。
- **Grok** 現在只接收 chat completions 請求。Grok 模型不再支援 Responses 專屬功能，例如內建的 `web_search`/`x_search` 工具與 `previous_response_id`。

### 對話（#1243、#1253）
- **對話會持續跟隨新輸出，直到你向上捲動，與 Codex 相同（#1243）。**以前只要點擊、觸控或向下捲動（即使畫面沒動）就會停止跟隨。現在送出訊息後一定會跳到最新內容。
- **在「自動重試」期間切換模型或 Harness 會取消重試（#1253），**下一則訊息會使用新設定。以前重試會沿用舊設定，你的訊息則排在它後面。
- **排隊中的訊息不會再遺失（#1253）。**
  - 訊息會留在佇列中直到送出。
  - 送出失敗時會顯示「尚未送出」及原因。
  - 無法送出也無法排隊的訊息會放回該對話的輸入框。
- **對話更快（#1253）。**
  - 卡住的後續訊息 30 秒（原為 3 分鐘）就會放棄。
  - 卡住的代理啟動約 90 秒（原為 4 分鐘）內就會被偵測。
  - 設定錯誤不會再重試半小時。
  - 尚未送達供應商的失敗 2 秒後就重試。
  - 停止、送出與排隊時，接連的等待步驟減少了。

  供應商錯誤（限流、5xx）後的重試仍維持完整間隔。
- **重新啟動後恢復的對話，不再因焦點短暫移開而停住（#1238）。**被拒的步驟會在你回到視窗時再執行一次。
- **倒回會等對話停止後才可使用（#1238）。**對話執行期間，「倒回」會停用並提示先停止對話，而不是失敗。
- **重試的對話不再把先前的嘗試顯示在新嘗試下方（#1242）。**
- **代理的版本檢查無法執行時，對話不再失敗（#1250）。**電腦忙碌時，開始對話可能會以「read Codex version: exit status 1」失敗，即使代理沒有問題。現在會重試兩次，只有版本真的過舊的代理才會被拒絕。
- **因重新啟動或代理程序結束而中斷的子代理會繼續執行，而不是失敗（#1249）。**

### 點擊與焦點（#1247）
- **應用程式忙碌後的第一下點擊恢復正常。**聊天以外的按鈕（App plugins 更新、瀏覽器帳號、電子郵件、MCP 通道、服務）可能會以「Click into the Coding Tools window」拒絕點擊。現在它們會稍候視窗取得焦點。
- **應用程式暫停後立即批准代理的請求恢復正常。**
- **切換到其他應用程式時送出的訊息不再遺失。**訊息會連同原因回到輸入框；佇列訊息的「立即傳送」也一樣。
- **不再因 CPA 請求凍結 40 秒。**生成圖片、Gemini 登入檢查與供應商帳號檢查不再從應用程式的主執行緒向 CPA 發出請求。

### 應用程式外掛（#1241）
- **CPA 外掛的「更新」恢復正常。**先前會以「Invalid URL」失敗。
- **同時切換兩個自動更新開關時，兩者都會儲存。**

### Clawd（#1245）
- **分割檢視中，Clawd 的小屋回到「設定」上方。**
- **Clawd 走路時會轉向前進方向、會轉身，**還會揮手、伸懶腰、跳舞與探頭。
