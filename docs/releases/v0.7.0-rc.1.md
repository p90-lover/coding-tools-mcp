# Coding Tools v0.7.0-rc.1

## English

This release candidate introduces the next-generation multi-provider Codex subagent architecture and ships it through the Electron-first Coding Tools harness.

### Highlights

- Adds Codex Router as the provider-routing plane while preserving the existing native and ChatGPT Web root path.
- Supports scalable native V2 subagents through generated, managed `agent_type` definitions instead of a bounded model-override roster.
- Supports namespaced direct models such as `codex-router/<router-slug>` and first-class generic providers such as `commandcode-proxy`.
- Adds restricted loopback Responses ingress so Coding Tools Web can be exported into Codex Router without exposing native/OpenAI routes or creating a routing loop.
- Preserves official Codex `/goal` `goal.internal_context` turns through Coding Tools Web.
- Reduces routed-request overhead by performing one bounded, encoding-aware request-body decode and reusing the parsed JSON.
- Includes the authenticated headless Rust service, Electron packaging contracts, package-content verification, and packaged launcher smoke checks.

### Safety and release integrity

- Provider credentials are not bundled into Coding Tools; authentication and protocol translation remain owned by Codex Router and the selected provider.
- Managed stale or replaced agent definitions are retained under `Trash/` rather than deleted. Temporary build and validation material stays under `aiTemp/`.
- The Windows installer remains per-user and does not request elevation.
- Publication is bound to one exact tested source SHA. The release includes `SHA256SUMS.txt`, `provenance.json`, and `validation-evidence.json`; assets are downloaded and hashed again before the prerelease is published.

### Validation boundary

Automated release gates cover frontend checks and audit, Linux/macOS/Windows Rust tests and strict Clippy, focused `/goal` and ingress regressions, TypeScript checks, the release identity contract, the locked headless Rust build, Electron package-content verification, and packaged smoke tests.

Live acceptance using real paid-provider accounts and credentials is intentionally disclosed as `pending_manual`; no paid-provider, OpenAI, or ChatGPT request is required by the model-free automated proof.

## 繁體中文

呢個 release candidate 帶來下一代多 provider Codex subagent 架構，並透過 Electron-first Coding Tools harness 發佈。

### 主要更新

- 加入 Codex Router 作為 provider routing plane，同時保留原本 native 同 ChatGPT Web root 路線。
- 透過自動產生、由專案管理嘅 `agent_type` 定義支援可擴展 native V2 subagent，避免受限於固定 model-override roster。
- 支援 `codex-router/<router-slug>` 命名空間直接 model，亦支援 `commandcode-proxy` 呢類一級 generic provider。
- 加入受限制嘅 loopback Responses ingress，令 Coding Tools Web 可以匯出到 Codex Router，同時唔會暴露 native／OpenAI route 或造成 routing loop。
- 完整保留官方 Codex `/goal` 嘅 `goal.internal_context` turn，並可經 Coding Tools Web 傳送。
- Routed request 只會做一次有大小限制、識別 encoding 嘅 body decode，再重用已解析 JSON，減少重複處理延遲。
- 包含經驗證嘅 headless Rust service、Electron packaging contract、package content 驗證同 packaged launcher smoke check。

### 安全同 release 完整性

- Coding Tools 唔會內置 provider credential；authentication 同 protocol translation 繼續由 Codex Router 同所選 provider 負責。
- 過期或被取代嘅 managed agent definition 會保留喺 `Trash/`，唔會刪除；臨時 build 同驗證資料會留喺 `aiTemp/`。
- Windows installer 維持 per-user 安裝，唔會要求提升權限。
- 發佈流程會綁定一個已測試嘅精確 source SHA。Release 會附有 `SHA256SUMS.txt`、`provenance.json` 同 `validation-evidence.json`；所有 asset 會喺正式發佈前重新下載同核對 hash。

### 驗證範圍

自動 release gate 包括 frontend check 同 audit、Linux／macOS／Windows Rust test 同嚴格 Clippy、聚焦 `/goal` 同 ingress regression、TypeScript check、release identity contract、locked headless Rust build、Electron package-content 驗證，以及 packaged smoke test。

使用真實付費 provider 帳戶同 credential 嘅 live acceptance 會清楚標記為 `pending_manual`；model-free 自動 proof 唔需要發出任何付費 provider、OpenAI 或 ChatGPT request。
