# Coding Tools 0.8.103

## English

### /schedule: a chat continues by itself later
- **`/schedule <when> [message]` makes the chat go on by itself at a later time.** For example, use it when a usage limit resets in five hours, when a long job will be done later, or to pick the work up the next morning.
  - **Durations:** `5h` means 5 hours. `90m`, `1h30m`, `1.5h`, `2 days and 3 hours` and `1w` work too.
  - **Clock times:** `9:30`, `9pm`, `tomorrow 9am`, `tonight 11:30`. A clock time means its next occurrence, in your time zone.
  - **Limits:** from 1 minute to 30 days ahead. A bare number like `5` is refused, and the error shows how to write it.
- **What it sends:** the words after the time, exactly as you wrote them (`/schedule 2h30m run the tests again`). With no words, the chat is told to continue and how long ago that was scheduled, so it checks what changed in between.
- **It's yours:**
  - Messages you send in the meantime don't cancel it.
  - If a turn is running when it's due, it waits for that turn to end.
  - It's sent once, then removed.
  - It moves with the chat to another project.
  - It survives an app restart.
  - It's dropped if the chat is archived or deleted.
- **Seeing and deleting it:**
  - A bar above the composer counts down to it.
  - Chat details has a **Schedule** row: right-click it and choose **Delete schedule**.
  - `/clearschedule` and the bar's trash button delete it too.
  - `/schedule` with nothing after it shows the current schedule.
  - A chat has one schedule, and setting a new one asks before replacing it.

### Goals stop when they make no progress
- **A goal now stalls after three rounds in a row without progress.** Before, a goal whose agent was blocked never stopped: three goals in one project had run 154, 281 and 480 rounds over 14 days, each round only repeating the same blocker.
- The goal checker now says whether each round made progress, and it sees the previous round's verdict. After 3 rounds in a row without progress the goal stops as **Goal stalled** and says what blocks it ("No progress in 3 rounds in a row: …"), whether or not "Let the model judge" is on. Clear what blocks it, then `/goal resume`.
- **Goal rounds that end at once are paced (#1111).** A round judged "not met" that ends within 2 minutes counts as quick. After the first quick round, the next one waits 30 s, then 2, 5, 10 and 15 minutes, and the goal's note says why. Eight quick rounds in a row stall the goal. A round that works longer resets the count.

### Settings › Instructions: AGENTS.md for every agent (#1111)
- **Settings has a new Instructions section, like Codex's custom instructions.**
  - **Global AGENTS.md** applies to every agent in every project.
  - **Workspace AGENTS.md** is the `AGENTS.md` at the project's root; a picker chooses the project.
  - Save with **Save** or Ctrl+S.
- **New agents** get both files at the start of their first message, global first, and your request is never cut to make room. **Running agents** get them again before their next message after either file changes.

### Smoother chat
- **Scroll-to-bottom button (#1114):** a round button above the composer jumps to the latest message. It shows three dots while an agent works and rises above an approval card instead of covering it. Only your own scrolling stops the chat following new output.
- **Slimmer model list (#1132):** tighter rows and a smaller search box, while keeping provider logos, selection checks and scrolling.
- **A message is no longer sent twice (#1111):** a message refused because a goal round had just started could be steered into that round twice. A repeat of the same text into the same turn is now skipped.
- **Fewer freezes:**
  - **Bridge re-checks (#1111):** the app no longer rewrites, and flushes to disk, the same bridge state on every 20–40 minute re-check. Each rewrite froze every window for up to 1.5 s.
  - **Services snapshots (#1109):** these no longer read or write files on the main thread; a single file check there had frozen the app for up to 29 s.
  - **/schedule (#1111):** its saves happen off the main thread too.

### Account tunnels reconnect (#1129)
- **Saved account tunnels reconnect even when the runtime was stopped or an old bridge setup blocked its start.** Reconnecting now starts the runtime the usual way first, or waits for a start already under way.

### MCP Connect works again (#1133)
- **ChatGPT's new plugins page is understood.** Connect and Refresh confirm the workspace from the page's new list request. Before, each one stopped at "ChatGPT did not confirm the selected workspace."
- **Cloudflare's check no longer stops hidden windows.** They wait up to 60 s for the check to pass and send the Browser tab's user agent. A check that doesn't pass says to open the account in the Browser tab and retry.
- **No more dead-end "Refresh required".** Connect reads stale workspace details again itself, then connects.
- **Errors name the step that failed** instead of "Connector creation failed".
- **"Restart Codex" shows while it's needed:** when a running Codex app lists no WebGPT models. It clears once it does.
- **Cleaner account cards:** 4 rows instead of 9.

### Every chat stays on the list (#1130)
- Busy goal or loop chats no longer push other chats off the chat list and out of Archived. Before, a project listed only the chats in its newest 100 runs: 4 of 49 in one project. Each missing chat is read once, in the background.

## 繁體中文

### /schedule：對話稍後自行繼續
- **`/schedule <時間> [訊息]` 讓對話在稍後的時間自行繼續。** 例如用量上限五小時後重置、長時間的工作稍後才會完成，或想在隔天早上接著做時使用。
  - **時長：** `5h` 代表 5 小時。`90m`、`1h30m`、`1.5h`、`2 days and 3 hours` 和 `1w` 也都可以。
  - **時刻：** `9:30`、`9pm`、`tomorrow 9am`、`tonight 11:30`。時刻指的是下一次到達的那個時間，以您的時區為準。
  - **範圍：** 1 分鐘到 30 天之後。單獨的數字（例如 `5`）會被拒絕，錯誤訊息會說明正確寫法。
- **送出的內容：** 時間後面的文字，完全照您寫的送出（`/schedule 2h30m run the tests again`）。若沒有文字，對話會被告知繼續，並說明這是多久以前排定的，讓它先確認這段期間有什麼變化。
- **排程屬於您：**
  - 期間您送出的訊息不會取消它。
  - 到時若有回合正在執行，會等那個回合結束。
  - 只會送出一次，送出後即移除。
  - 對話移到其他專案時會一起移動。
  - 應用程式重新啟動後仍會保留。
  - 對話被封存或刪除時會一併取消。
- **查看與刪除：**
  - 輸入框上方的列會倒數計時。
  - 對話詳細資料中有 **Schedule** 一列：在上面按右鍵並選擇 **Delete schedule**。
  - `/clearschedule` 和該列的垃圾桶按鈕也能刪除。
  - 只輸入 `/schedule` 會顯示目前的排程。
  - 每個對話只有一個排程，設定新排程時會先詢問是否取代。

### 目標沒有進展時會停下
- **目標現在連續三輪沒有進展就會停下。** 以前，代理被卡住的目標永遠不會停：同一個專案中有三個目標在 14 天內跑了 154、281 和 480 輪，每一輪都只是重複同一個阻礙。
- 目標檢查現在會判斷每一輪是否有進展，並能看到上一輪的判定。連續 3 輪沒有進展後，目標會停為 **Goal stalled**，並說明是什麼擋住了它（「No progress in 3 rounds in a row: …」），不論「Let the model judge」是否開啟。排除阻礙後，執行 `/goal resume`。
- **很快結束的目標回合會放慢（#1111）。** 判定為「未達成」、且在 2 分鐘內結束的回合算作快速回合。第一個快速回合之後，下一回合會先等待 30 秒，之後依序是 2、5、10 和 15 分鐘，目標的備註會說明原因。連續 8 個快速回合會讓目標停下。執行較久的回合會重新計數。

### Settings › Instructions：給所有代理的 AGENTS.md（#1111）
- **設定新增 Instructions 區塊，類似 Codex 的自訂指示。**
  - **全域 AGENTS.md** 適用於所有專案中的每個代理。
  - **工作區 AGENTS.md** 是專案根目錄的 `AGENTS.md`，可用選單選擇專案。
  - 用 **Save** 或 Ctrl+S 儲存。
- **新的代理**會在第一則訊息開頭收到這兩個檔案，全域的在前，而且您的請求不會為了騰出空間被截斷。**執行中的代理**在任一檔案變更後，會在下一則訊息前再次收到。

### 對話更順暢
- **捲到底部按鈕（#1114）：** 輸入框上方的圓形按鈕可跳到最新訊息。代理工作時顯示三個點，遇到核准卡片時會移到卡片上方，不會擋住它。只有您自己捲動時，對話才會停止跟隨新輸出。
- **更精簡的模型清單（#1132）：** 縮窄模型清單、壓縮列高與搜尋框，同時保留供應商圖示、選取勾號及捲動功能。
- **訊息不再送出兩次（#1111）：** 目標回合剛開始時被拒絕的訊息，可能被插入該回合兩次。現在同一段文字重複插入同一回合時會略過。
- **減少卡頓：**
  - **橋接器重新檢查（#1111）：** 應用程式不再於每 20–40 分鐘的重新檢查時，重寫相同的橋接器狀態並寫入磁碟。每次重寫曾讓所有視窗凍結最多 1.5 秒。
  - **服務快照（#1109）：** 不再於主執行緒讀寫檔案；那裡的一次檔案檢查曾讓應用程式凍結最多 29 秒。
  - **/schedule（#1111）：** 儲存也不在主執行緒進行。

### 帳號通道重新連線（#1129）
- **即使 runtime 已停止，或舊的橋接器設定擋住了啟動，已儲存的帳號通道也能重新連線。** 重新連線現在會先以一般方式啟動 runtime，或等待已在進行中的啟動。

### MCP 連線恢復正常（#1133）
- **支援 ChatGPT 新的外掛頁面。** 「連線」與「重新整理」會從頁面新的清單請求確認工作區。之前每次都停在「ChatGPT did not confirm the selected workspace.」。
- **Cloudflare 檢查不再擋住隱藏視窗。** 隱藏視窗會等待檢查通過最多 60 秒，並使用與瀏覽器分頁相同的使用者代理。若檢查未通過，會提示在瀏覽器分頁中開啟該帳號後重試。
- **「需要重新整理」不再卡住。** 「連線」會自行重新讀取過期的工作區資料，再進行連線。
- **錯誤訊息會指出失敗的步驟**，而不是只顯示「Connector creation failed」。
- **需要時才顯示「Restart Codex」：** 執行中的 Codex 應用程式未列出 WebGPT 模型時顯示，列出後即清除。
- **更簡潔的帳號卡片：** 由 9 列減為 4 列。

### 每個對話都留在清單上（#1130）
- 忙碌的目標或循環對話不再把其他對話擠出對話清單與「已封存」。之前，專案只列出最新 100 次執行中的對話：某個專案 49 個中只列出 4 個。每個缺少的對話會在背景讀取一次。
