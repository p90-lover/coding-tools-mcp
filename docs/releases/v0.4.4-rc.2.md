# v0.4.4-rc.2 — Tool result contracts and integration lifecycle

## English

This release extends the verified rc.1 snapshot sandbox; it is not a claim that all Codex, Paseo or Anneal upstream functionality has been ported. The native helper, OAuth guard, PKCE/consent behavior and existing execution-permission boundaries are preserved. No model inference or Codex executable is invoked by release verification.

All 70 registered MCP tools now advertise an object outputSchema for their structuredContent. The shared success/error envelope remains compatible with additive workspace and policy metadata. Task events, pagination, file reads, plans, catalog discovery and other common results have additional field contracts. list_task_events specifies event records and a nonnegative next_cursor, and requires those fields for successful responses. Existing text compatibility blocks and separate image content blocks remain; an output schema is not a new permission and does not repair ChatGPT's conversation-level developer-MCP rejection. After upgrading, refresh the connector's saved tool metadata to see the new schemas.

The verification inventory calls all 70 registered tools against retained synthetic workspaces or disabled-consent boundaries and records the exact scope per tool. Safe file/git/history/task/plan/image-metadata operations execute against fixtures; image tests read the already-present application icon, not a generated or user screenshot. GUI/provider/native-agent operations that lack local consent are marked guard-or-status-only, NOT successful live acceptance. Six native agent control operations are also denied against a disabled bridge. The resulting output-contract-proof.json distinguishes these modes; it must not be described as every function successfully executed on the user's computer. JSON Schema validation checks actual structuredContent, text parity and malformed event-pagination negatives. Existing real snapshot execution/revocation, OAuth browser-to-Rust, integration-adapter and board tests remain release gates.

Paseo/Anneal state reads now reject stale responses after changing an endpoint or clearing its view. Late errors/finally handlers cannot erase a newer request's busy/error state. A failed refresh no longer leaves an old successful snapshot presented as current. Tokens remain memory-only; fixed loopback routes, timeouts and request correlation are unchanged.

Invalid, missing or duplicate sandbox input selections are now validated and bounded-read before allocating retained slots. Partial I/O setup stays in application aiTemp staging instead of consuming the 32-run quota. A new visible-local Archive retained snapshots control moves the entire shared inactive run directory into application aiTemp/sandbox-snapshots/Trash/retained-snapshots/<id>. The user explicitly confirms ALL inactive runs, not just one workspace. Active execution blocks archival; original project files and approvals do not change. There is no remote archive tool, automatic cleanup, import or deletion. Staging failures and archives may still occupy disk; this is not a disk-space reclamation feature or hard storage quota.

Scope ledger: embedded model-free local tools, custom offline AppContainer, scoped native App Server bridge and local board are present. Paseo's observed agent list and Anneal's fixed board read are adapters, not full autonomous engines. Native agent model operations remain opt-in and were not run with real providers. Full upstream engine orchestration, mobile/voice/relay surfaces, official complete Codex sandbox parity and live-user acceptance remain unverified/unimplemented as appropriate. The inspected Paseo reference is d7c7044dfc91d1d18721dc8757ac3bb913d8c232; its changes since the retained f7e68e3 snapshot are release/package metadata, not the inspected protocol implementation. Anneal reference is 6c5d2f6f17f75ee11079a510bbd4d87fcaaa126c. These references do not mean their entire sources were bundled or executed.

Windows x64, publisher-unsigned, prerelease. Exact tested source, main and release tag must agree. Prior releases and unfinished branches remain. Tests/build artifacts stay in aiTemp; replaced local copies are kept in Trash. No deletion command, user account, game, remote model run, or hidden permission escalation is part of verification. This does not install the EXE on the user's PC.

## 繁體中文

本版在已驗證的 rc.1 快照沙箱上繼續整合，並非宣稱已移植全部 Codex、Paseo 或 Anneal 上游功能。保留原生 helper、OAuth 防護、PKCE／同意流程及執行權限邊界；發佈驗證不呼叫模型推論或 Codex 執行檔。

全部 70 個已註冊 MCP 工具現在為 structuredContent 提供 object outputSchema。共用成功／錯誤結構保留可擴充的工作區及權限資料；任務事件、分頁、檔案讀取、計畫、工具目錄等另有欄位契約。list_task_events 定義事件紀錄及非負 next_cursor，成功回應必須提供這些欄位。保留相容文字區塊及獨立影像區塊；outputSchema 不授予新權限，也不能修復 ChatGPT 對話層的 developer-MCP 拒絕。升級後更新連接器儲存的工具資料，才會看到新結構。

驗證清單對全部 70 個已註冊工具執行保留測試工作區或未授權邊界檢查，逐項記錄範圍。安全的檔案／Git／歷史／任務／計畫／影像資料操作使用測試檔；影像測試讀取既有應用程式圖示，不產生影像或使用使用者截圖。未獲本機同意的 GUI／供應商／原生 Agent 操作標示為僅拒絕／狀態檢查，不冒稱真實執行成功；另核對六項原生 Agent 控制在 bridge 未啟用時均被拒絕。output-contract-proof.json 明確区分驗證方式，不能解讀為所有功能已在使用者電腦成功執行。JSON Schema 檢查真正 structuredContent、文字一致性及錯誤事件分頁案例；既有原生快照／撤銷、OAuth 瀏覽器至 Rust、整合介接及看板測試仍是發佈關卡。

Paseo／Anneal 更換端點或清除畫面後，會丟棄舊請求回應。遲到的錯誤／finally 不會覆蓋新請求狀態；更新失敗亦不再把舊的成功快照當成最新狀態。Token 仍只保留於記憶體，固定 loopback 路由、時限及請求關聯不變。

沙箱會先驗證並有界讀取全部輸入，再配置保留紀錄，所以無效／遺失／重複的输入選擇不再消耗 32 次額度。I/O 初始化失敗的局部資料保留於應用程式 aiTemp staging，不佔用執行紀錄額度。新增本機「封存保留快照」控制，把共用的全部非執行中紀錄目錄移到應用程式 aiTemp/sandbox-snapshots/Trash/retained-snapshots/<id>。使用者須明確確認全部非執行中紀錄，而不只是當前工作區；有工作執行時拒絕封存，原專案及授權不變。沒有遠端封存工具、自動清理、匯入或刪除。失敗 staging 及封存仍可能佔用磁碟，這不是釋放容量功能或硬性磁碟配額。

範圍清單：已有內嵌無模型工具、自訂離線 AppContainer、有範圍限制的原生 App Server bridge 及本機看板。Paseo Agent 清單與 Anneal 固定看板讀取仍是介接器，不是完整自主引擎。原生 Agent 模型操作仍須主動同意，本次未使用真實供應商執行。完整上游引擎調度、手機／語音／relay、官方完整 Codex 沙箱對等能力及真實使用者驗收，仍按實際情況標示為未實作／未驗證。已檢查的 Paseo 原始碼為 d7c7044dfc91d1d18721dc8757ac3bb913d8c232，較保留的 f7e68e3 快照只變更發佈／套件資料，沒有改動所查協議實作。Anneal 為 6c5d2f6f17f75ee11079a510bbd4d87fcaaa126c；列出版本不代表已打包或執行其全部原始碼。

提供 Windows x64、未簽章預發佈版。真正測試的原始碼、main 及 tag 必須一致；保留舊 Release 及未完成分支。測試／建置資料放 aiTemp，替換原件保留於 Trash。驗證不使用刪除指令、真實帳戶、遊戲、遠端模型或隱藏的權限提升，也不會自行安裝至使用者電腦。
