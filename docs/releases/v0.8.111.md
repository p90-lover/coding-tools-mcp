# Coding Tools 0.8.111

## English

### Performance: change-log cleanup leaves the chat writer free when there is nothing to delete (#1190)
- Agent Orchestrator now discovers each bounded cleanup batch through a reader connection, then takes SQLite's foreground writer only to delete that fixed list. A no-op pass no longer waits in the writer queue.
- The row-cap search uses a sequence boundary rather than counting the entire backlog. Sequence gaps, concurrent cleanup and newly appended events cannot shift the selected batch into newer history. Negative limits do not delete events; a zero row cap still works.
- The app pins the merged AO source `1a58d3a16a0ce29a90c9df09fa1f937335c38c6a`. The release rebuilds the daemon and checks its source manifest and SHA-256, not a scratch verification binary.

### Performance: bridge starts and GitHub update checks avoid main-thread freezes (#1196)
- The bundled bridge's version is read once per runtime folder instead of on every start or recovery. A missing or invalid file is not cached; development runs still read the current source version.
- GitHub release checks and downloads for CPA, app plugins and the Antigravity CLI use Chromium's network service rather than connecting from Node on Electron main. A live update check on 0.8.108 held main for 88 seconds.
- Redirects preserve fetch's normal follow behavior, stop after five hops and remain on HTTPS. Local CPA health checks retain their existing transport.
- A watchdog that misses two short health checks gives a running bridge another 15 seconds to answer before deciding it needs a restart. A busy disk no longer makes those two misses alone sufficient to restart a live daemon.

### Storage: temporary files and rtk history stay off the system drive (#1198)
- On Windows, when the app's data root is on another drive, children inherit a temporary folder there and rtk writes its history there too. Explicit off-system-drive settings are preserved; `CODING_TOOLS_TEMP_DIR` can choose another folder.
- Sandboxed agents still receive a writable temporary folder. Updates are unchanged: their staging already lives beside the installed app or in app data, not in TEMP.
- A bounded asynchronous cleanup removes entries untouched for seven days, without following links or deleting a folder with recent contents. The old rtk database remains where it was; savings count from the new database.
- Shared agent homes such as `.claude` and `.codex` are not relocated, so existing sign-ins and chat-resume paths are preserved.

### Images: image requests do not inherit the text chat's reasoning effort (#1200)
- A session-scoped `generate_image` tool uses CPA's standalone Images API with its own image model, size and quality. It does not accept or inherit chat reasoning effort or complexity, avoiding the confirmed hosted-image rejection of `xhigh` without lowering text reasoning.
- Validated image bytes return inline, without disk persistence. Failed or interrupted billable calls are not automatically retried; redirects and arbitrary provider image URLs are not followed. Tool opt-out, session isolation and credential privacy are preserved.
- The required backend bundle includes the image service. Bundled CPA is pinned to official 8.0.63 with checksums for all six supported platform archives.

  - The broader migration test `TestMigrateRepairsRenumberedAgentInventoryHistory` fails with a NULL plan-status scan identically on the exact original source. That pre-existing failure is disclosed, not fixed here. Windows race instrumentation, Linux and full-backend CI were not run.
  - This fixes a reproduced maintenance-contention path, not every native Electron stall or other writer wait. Live samples did not establish a monotonic memory leak.
- #1196: the final related suites pass 250/250. New regressions fail on the previous code. The updated transport and patient watchdog were not checked live in the installed app.
- #1198: five dedicated tests cover redirection, overrides, other system drives, non-Windows/no-op cases, pruning bounds, links and startup order. ## 繁體中文

### 效能：無需刪除變更記錄時，不再等待聊天寫入連線（#1190）
- Agent Orchestrator 先透過讀取連線找出有限的清理批次，只有刪除固定清單時才取得 SQLite 的前景寫入連線。沒有內容可清理時，不再排隊等待寫入。
- 保留筆數的搜尋使用序號邊界，不再計算整份積壓記錄。序號空缺、同時清理與新加入的事件，都不會讓批次移到較新的歷史。負數限制不會刪除事件，零筆保留上限仍可使用。
- 程式固定使用已合併的 AO 來源 `1a58d3a16a0ce29a90c9df09fa1f937335c38c6a`。發佈會重新編譯 daemon，並檢查來源資訊與 SHA-256，不會直接使用臨時驗證執行檔。

### 效能：bridge 啟動與 GitHub 更新檢查避免卡住主執行緒（#1196）
- 內建 bridge 的版本對每個執行環境資料夾只讀取一次，不再於每次啟動或復原時讀取。不存在或無效的檔案不會快取；開發模式仍會讀取目前的來源版本。
- CPA、應用程式外掛與 Antigravity CLI 的 GitHub 版本檢查及下載，改用 Chromium 網路服務，不再從 Electron 主執行緒的 Node 連線。0.8.108 的一次實際更新檢查曾讓主執行緒停住 88 秒。
- 重新導向保留 fetch 的一般跟隨行為，最多五次，且全程維持 HTTPS。本機 CPA 健康檢查維持原有傳輸方式。
- 看門狗連續兩次短暫健康檢查失敗後，會再給執行中的 bridge 15 秒回應，才決定是否需要重啟。磁碟忙碌造成的兩次短暫失敗，不再足以直接重啟仍存活的 daemon。

### 儲存：暫存檔與 rtk 歷史記錄不再寫入系統磁碟（#1198）
- 在 Windows 上，若程式資料位於其他磁碟，子程序會沿用該處的暫存資料夾，rtk 歷史記錄也移到該處。保留已指定的非系統磁碟設定；可用 `CODING_TOOLS_TEMP_DIR` 選擇其他位置。
- 沙箱代理仍取得可寫入的暫存資料夾。更新不受影響：更新原本就在安裝位置旁或程式資料中準備，不使用 TEMP。
- 有上限的非同步清理會移除七天未使用的項目，不追蹤連結，也不刪除含有近期內容的資料夾。舊 rtk 資料庫保留原處，節省統計從新資料庫開始。
- 不搬移 `.claude`、`.codex` 等共用代理資料夾，保留現有登入與對話恢復路徑。

### 圖片：圖片請求不沿用文字聊天的推理強度（#1200）
- 綁定工作階段的 `generate_image` 工具，透過 CPA 的獨立 Images API 傳送圖片模型、尺寸與品質。不接受或沿用聊天的 reasoning effort／complexity，因此可避免已重現的 `xhigh` 圖片模型錯誤，而不降低文字推理強度。
- 驗證後的圖片以內嵌位元組回傳，不寫入磁碟。失敗或中斷的計費請求不會自動重送，也不追蹤重新導向或任意供應商圖片網址。保留停用工具、工作階段隔離與憑證保密機制。
- 必要後端套件包含圖片服務；內建 CPA 固定為官方 8.0.63，六種支援平台的封存檔均有固定校驗值。
