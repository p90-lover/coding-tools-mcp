# Coding Tools 0.8.111

## English

### Agents start again when the disk is busy (#1212)
- **AO's background cleanup no longer blocks chats.** Cleanup held Agent Orchestrator's only database writer for 2 to 5 minutes at a time, so approval answers, messages and new agents waited, and starts took 5 to 6 minutes and then failed. Cleanup now gives the writer back as soon as a chat needs it and retries a minute later in smaller steps.
- **AO is given time to start instead of being restarted.** A slow start (4.5 minutes after the 0.8.110 update) was killed at 90, 180 and 360 seconds and began again each time: 5 starts, 28 minutes. A running AO is now waited for up to 15 minutes, and a failed start pauses before the next one.
- **A chat is no longer cut off from its agent by one slow save.** Three failed saves within 60 ms used to detach the chat while the agent worked on unseen. A busy database is now retried for about a minute.
- **The window no longer freezes while a service restarts.** Each restart of CPA read the saved proxy settings on the main thread; on a busy disk one read froze the app for 46 seconds and every chat call timed out. A restart now uses the settings already held in memory.
- **A backend update waits for running chats** (up to 30 minutes) before it restarts AO.

### Fewer whole-app freezes on a busy disk (#1196, #1205, #1216, #1217)
- **Bridge version and GitHub checks (#1196).** The bundled bridge's version is read once per runtime folder. GitHub release checks and downloads for CPA, app plugins and the Antigravity CLI use Chromium's network service instead of connecting from the main process. A bridge that misses two short health checks gets 15 more seconds before it is restarted.
- **Update (#1205).** The update worker is started off the main thread; starting it had frozen the app for 12.7 seconds.
- **Stopping processes (#1216).** Ending a process tree starts `taskkill` from a worker. Starting it on the main thread held every window for 88.5 seconds once.
- **Antigravity CLI (#1217).** Its proxy settings are read without blocking the main thread.

### Chats (#1204, #1207, #1208, #1209, #1210, #1211, #1215)
- **A send that loses a race with another chat is redone, not dropped (#1204).** Sending, starting a chat, steering and renaming read the board again after "Workflow revision changed".
- **A refusal with no status is not retried (#1207).** "Complexity 'xhigh' is not supported for this image model" was retried 8 times. An update whose files are briefly held by another program now waits up to 2 minutes instead of rolling back.
- **Sends are no longer refused after a stall (#1208).** The wait for the window to settle counts only time the main process was free.
- **The harness list fills in however long AO takes to start (#1209),** and Claude Code's mark has no dark tile.
- **Native Codex shows ChatGPT's mark (#1210)** in the harness list.
- **The context-window menu is a slim, see-through list (#1211).** GPT-6, GPT-5.6 and Fable 5 can be set to 1M.
- **A subagent's work opens in the side panel again (#1215).**

### Smaller fixes (#1198, #1200, #1203, #1206)
- **Temporary files and rtk's history stay off the system drive (#1198)** when the app's data is on another drive.
- **Image requests no longer inherit the chat's reasoning effort (#1200).** A `generate_image` tool uses CPA's Images API with its own model, size and quality. Bundled CPA is 8.0.63.
- **The sidebar's attention dot pulses three times, not forever (#1203).** The endless pulse cost the GPU process about 15% of a core.
- **A saved CPA process id that Windows gave to another program is neither adopted nor ended (#1206).**

## 繁體中文

### 磁碟忙碌時代理可以再次啟動（#1212）
- **AO 的背景清理不再阻擋對話。**清理工作每次佔用 Agent Orchestrator 唯一的資料庫寫入通道 2 至 5 分鐘，審批答覆、訊息與新代理都得等待，啟動要 5 至 6 分鐘後才失敗。現在只要對話需要寫入，清理就會立即讓出，並在一分鐘後以較小的批次重試。
- **給 AO 足夠的啟動時間，而不是重新啟動它。**啟動較慢時（0.8.110 更新後需 4.5 分鐘），AO 會在 90、180、360 秒被終止並重新開始：共 5 次、28 分鐘。現在只要 AO 仍在執行就會等待最多 15 分鐘，啟動失敗後也會先暫停再重試。
- **一次緩慢的儲存不再讓對話與代理斷開。**以前 60 毫秒內三次儲存失敗就會讓對話脫離，而代理仍在背景繼續工作。現在資料庫忙碌時會重試約一分鐘。
- **服務重新啟動時視窗不再凍結。**CPA 每次重新啟動都會在主執行緒讀取已儲存的代理伺服器設定；磁碟忙碌時一次讀取曾讓程式凍結 46 秒，所有對話呼叫都逾時。現在重新啟動會使用記憶體中已有的設定。
- **後端更新會等待執行中的對話**（最多 30 分鐘）才重新啟動 AO。

### 磁碟忙碌時減少整個程式凍結（#1196、#1205、#1216、#1217）
- **橋接版本與 GitHub 檢查（#1196）。**內建橋接的版本每個執行階段資料夾只讀取一次。CPA、應用程式外掛與 Antigravity CLI 的 GitHub 版本檢查及下載改用 Chromium 的網路服務，不再由主行程連線。橋接錯過兩次短暫的健康檢查時，會再多等 15 秒才重新啟動。
- **更新（#1205）。**更新工作程式改在主執行緒之外啟動；以前啟動它曾讓程式凍結 12.7 秒。
- **停止程序（#1216）。**結束程序樹時改由工作執行緒啟動 `taskkill`。在主執行緒啟動曾讓所有視窗停住 88.5 秒。
- **Antigravity CLI（#1217）。**讀取其代理伺服器設定時不再阻擋主執行緒。

### 對話（#1204、#1207、#1208、#1209、#1210、#1211、#1215）
- **與另一個對話競爭失敗的傳送會重做，而不是遺失（#1204）。**傳送、開始對話、引導及重新命名在出現「Workflow revision changed」後會重新讀取看板。
- **沒有狀態碼的拒絕不再重試（#1207）。**「Complexity 'xhigh' is not supported for this image model」曾被重試 8 次。更新時檔案若被其他程式短暫佔用，現在會等待最多 2 分鐘，而不是回復舊版。
- **停頓之後傳送不再被拒絕（#1208）。**等待視窗穩定時，只計算主行程空閒的時間。
- **無論 AO 啟動多久，代理程式清單都會填入（#1209），**Claude Code 的標誌也不再有深色底。
- **Native Codex 在清單中顯示 ChatGPT 的標誌（#1210）。**
- **內容視窗選單改為精簡的半透明清單（#1211）。**GPT-6、GPT-5.6 與 Fable 5 可設為 1M。
- **子代理的工作可以再次在側邊面板開啟（#1215）。**

### 其他修正（#1198、#1200、#1203、#1206）
- **暫存檔與 rtk 的記錄不再寫入系統磁碟（#1198）**（當應用程式資料位於其他磁碟時）。
- **圖片請求不再沿用對話的推理強度（#1200）。**`generate_image` 工具使用 CPA 的 Images API，並有自己的模型、尺寸與品質。內建 CPA 為 8.0.63。
- **側邊欄的提醒圓點只閃動三次，不再持續閃動（#1203）。**持續閃動曾讓 GPU 行程佔用約 15% 的單一核心。
- **已儲存的 CPA 程序識別碼若被 Windows 分配給其他程式，既不接管也不結束它（#1206）。**
