# Coding Tools 0.8.119

## English

### Chat agents (monitor tools)
- **A chat's agent can watch a command and be told when something needs attention, like Claude Code's Monitor tool.** `monitor` takes Claude Code's three inputs: a description, a deadline (5 minutes by default, at most 30) and a command.
  - The command runs through the chat's own terminal tools: it is reviewed and sandboxed like any other command, and shows in the chat's Terminal pane.
  - Each line it prints is an event. Events reach the chat as a tool notification after its current turn ends, several at a time, so the agent keeps working instead of polling. A line repeated many times in a row arrives once, with its count.
  - The command's exit, the deadline, more than 200 events in a minute, or output that cannot be read ends the watch, and the chat is told which. `list_monitors` and `stop_monitor` manage them; a chat can run 8 at a time.
- **`push_notification`, like Claude Code's.** An agent can send you a desktop notification when something needs you. The app's window flashes when it is not in front, and a chat can notify at most once every 10 seconds.
- **`sleep`, like Codex's.** An agent can wait up to 100 seconds inside its turn. It stops at once when you send the chat a message.
- `monitor` and `sleep` come with the terminal tools, which are on by default when Codex's sandbox is installed. `push_notification` is on for every chat. "Approve for me" reviews `monitor` like any command and treats the other two as routine.

### Chats (#1300)
- **An unsent message is no longer lost when the app crashes or restarts (#1300).** What you typed, attached (images and files) and annotated in a chat's box is saved as you write it. It comes back when the chat opens again, also for a message that was being sent.

### Approve for me (#1301)
- **The reviewer now sees your standing instructions (#1301).** "Approve for me" refused routine pushes, pull requests, merges and releases as "not authorized by the user", even when your AGENTS.md authorizes them: the reviewer was never shown it.
  - It now gets your global and workspace AGENTS.md, the same text the chat's agent is given.
  - The reviewer still decides, and the hard safety rules are unchanged. Nothing is allowed without a review.
  - The project's own AGENTS.md is a file an agent can edit, so the reviewer is told it covers the project's routine delivery steps only. It never widens access to secrets, other destinations or destructive actions.
- **`git -C <folder> status`, `diff` and `log` run without a review (#1301),** like the same commands without `-C`, when the folder is inside the workspace. `--no-pager` is accepted too.
- **Safer:** `git grep -O<program>`, `--open-files-in-pager` and `--ext-diff` start a program, so they now go to the reviewer. They used to pass as read-only.

## 繁體中文

### 聊天代理（監看工具）
- **聊天的代理可以監看指令，並在有事需要處理時收到通知，就像 Claude Code 的 Monitor 工具。** `monitor` 使用與 Claude Code 相同的三個輸入：說明、期限（預設 5 分鐘，最長 30 分鐘）與指令。
  - 指令透過聊天自己的終端工具執行：與其他指令一樣經過審查並在沙箱中執行，也會顯示在聊天的終端窗格。
  - 指令輸出的每一行都是一個事件。事件會在目前回合結束後以工具通知的形式送達聊天，一次可包含數則，因此代理可以繼續工作而不必輪詢。連續重複多次的同一行只送一次，並附上次數。
  - 指令結束、期限到期、一分鐘內超過 200 個事件，或輸出無法讀取時，監看就會結束，並告知聊天原因。可用 `list_monitors` 與 `stop_monitor` 管理；每個聊天最多同時執行 8 個。
- **`push_notification`，如同 Claude Code 的同名工具。** 有事需要你處理時，代理可以傳送桌面通知給你。應用程式視窗不在最前面時會閃爍提示；每個聊天最多每 10 秒通知一次。
- **`sleep`，如同 Codex 的同名工具。** 代理可以在回合中等待最多 100 秒；你一傳訊息給該聊天，它就會立即停止等待。
- `monitor` 與 `sleep` 隨終端工具一起提供；安裝 Codex 沙箱時，終端工具預設開啟。`push_notification` 在所有聊天中皆可使用。「幫我核准」會像審查其他指令一樣審查 `monitor`，另外兩個工具則視為例行操作。

### 聊天（#1300）
- **應用程式當機或重新啟動時，未送出的訊息不會再遺失（#1300）。** 你在對話框中輸入的文字、附加的圖片與檔案以及標註，會在輸入時自動儲存，重新開啟聊天時會恢復；正在送出中的訊息也一樣。

### 「幫我核准」（#1301）
- **審查者現在看得到你的常設指示（#1301）。** 先前即使你的 AGENTS.md 已授權，「幫我核准」仍把例行的推送、pull request、合併與發行判定為「使用者未授權」而拒絕，因為審查者從未看到該檔案。
  - 現在審查者會收到你的全域與工作區 AGENTS.md，與聊天代理收到的內容相同。
  - 仍由審查者決定，硬性安全規則不變；沒有任何操作可以略過審查。
  - 專案自己的 AGENTS.md 是代理可以編輯的檔案，因此審查者會被告知它只涵蓋該專案的例行交付步驟，不會擴大對機密、其他目的地或破壞性操作的存取。
- **`git -C <資料夾> status`、`diff`、`log` 不必審查即可執行（#1301），** 只要資料夾在工作區內，就和不帶 `-C` 的相同指令一樣。也接受 `--no-pager`。
- **更安全：** `git grep -O<程式>`、`--open-files-in-pager` 與 `--ext-diff` 會啟動程式，現在改為交給審查者；以前會被當成唯讀而直接通過。
