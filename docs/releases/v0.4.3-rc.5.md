# v0.4.3-rc.5 — Fix local OAuth consent Origin rejection

## English

Fixes a reproduced rc.4 regression: validated OAuth consent pages still carried `Referrer-Policy: no-referrer`. For a native HTML form POST, Chromium consequently sends `Origin: null`, even when the page and form destination are same-origin and the consent cookie is present. The HTTP guard correctly rejects that Origin before password verification. This affects both manual submission and the v0.0.7 extension's `requestSubmit()` flow; it is not repaired by adding chatgpt.com to a global allowlist.

The production change applies `Referrer-Policy: strict-origin` only to responses marked internally as validated OAuth consent forms. The same-origin POST retains its actual Origin, while Referer contains only the origin, never the OAuth path/query. All other responses, including the authorization-code redirect, retain no-referrer. The middleware still rejects null/unknown/duplicate origins. The trusted-origin list, Host/Forwarded distrust, callback CSP, passwords, nonce/cookie binding, PKCE and one-use codes remain unchanged.

The earlier fixture replay omitted Referrer-Policy, so it did not expose this browser behavior. Verification now forwards ALL response headers from an actual running Rust listener into Chromium, then forwards the browser-generated POST back to that same listener without replacing Origin. Manual submission and the exact released extension v0.0.7 helper must complete consent, PKCE/token exchange and authenticated tools/list against the real server. Restoring the old policy in the negative case must reproduce Origin:null and HTTP 403. Forged origins remain denied. Browser transport and extension IPC are explicitly synthetic; no live ChatGPT account or user's tunnel is contacted. External browser traffic is blocked, and only synthetic test credentials are used.

The extension source is pinned to `b0d4db553227fa3c7300050b8edff6e2eb9afee4`; no extension upgrade or connector recreation is required for this server-side bug when v0.0.7 is already installed. Completely exit Desktop, install rc.5 and reopen it. Close the failed authorization page and start Connect/Sign in again from ChatGPT to obtain a fresh complete authorization request. Do not refresh/repost the old failed form, strip its query, disable Origin checks, or change execution permissions. Keep existing workspace settings and OAuth data. A secret not shown in the extension is a separate condition: this fix does not invent or bypass confidential-client credentials.

Windows x64 installer, publisher-unsigned, prerelease. Source commit, release tag and main must match the tested build. SHA256SUMS, provenance and focused evidence are included. Existing rc.4 features/file-safety changes, released extension work and older releases are preserved; unrelated AppContainer/Paseo/Anneal work is not bundled. No Codex executable, agent/model inference or native computer input is invoked by verification. The user's actual installed executable and live account connection still require local acceptance.

References:
- https://fetch.spec.whatwg.org/#append-a-request-origin-header
- https://w3c.github.io/webappsec-referrer-policy/#referrer-policy-strict-origin

## 繁體中文

修正已重現的 rc.4 問題：經驗證的 OAuth 同意表單仍帶有 `Referrer-Policy: no-referrer`。Chromium 提交原生 HTML 表單 POST 時因此送出 `Origin: null`，即使頁面與提交目的地同源，而且有正確同意 Cookie。HTTP 防護會在密碼驗證之前拒絕此來源。手動提交及 v0.0.7 擴充功能的 `requestSubmit()` 都受影響；把 chatgpt.com 加入全域白名單並不能修復。

正式程式只對具有內部「已驗證 OAuth 同意表單」標記的回應採用 `Referrer-Policy: strict-origin`。同源 POST 保留真正 Origin，Referer 只含來源，不含 OAuth 路徑或查詢參數。其餘回應，包括授權碼轉址，仍保留 no-referrer。防護仍拒絕 null／未知／重複來源。可信來源清單、對 Host／Forwarded 的不信任、callback CSP、密碼、Nonce／Cookie 綁定、PKCE 及一次性授權碼均不變。

先前重播測試漏傳 Referrer-Policy，未能發現這個瀏覽器行為。現在會把真正運行的 Rust listener 的所有回應標頭傳給 Chromium，再把瀏覽器產生的 POST 原樣傳回同一 listener，不替換 Origin。手動及指定 v0.0.7 正式擴充功能助手均須完成真正伺服器的同意、PKCE／Token 交換及已驗證 tools/list。負向案例還原舊策略時，必須重現 Origin:null 及 HTTP 403；偽造來源亦仍被拒絕。瀏覽器傳輸及擴充功能訊息邊界明確使用模擬，不接觸真實 ChatGPT 帳戶或使用者隧道；封鎖對外瀏覽器流量，只使用測試憑證。

擴充功能原始碼固定為 `b0d4db553227fa3c7300050b8edff6e2eb9afee4`。已安裝 v0.0.7 時，此伺服器端修正不要求更新擴充功能或重新建立連接器。完全退出 Desktop、安裝 rc.5 後重新開啟，關閉失敗授權頁，再從 ChatGPT 的 Connect／Sign in 開始新授權，取得全新的完整請求。不要重新整理／重送舊表單、移除查詢参数、停用來源檢查或提高執行權限。保留工作區設定及 OAuth 資料。擴充功能沒有顯示 secret 屬另一狀況；本修正不會憑空建立或繞過機密用戶端憑證。

提供 Windows x64 安裝包，未有發行者簽章，屬預發佈版本。原始碼 commit、Release tag 及 main 必須與驗證建置一致，附 SHA256SUMS、來源紀錄及重點證據。保留 rc.4 功能／檔案安全修正、已發佈擴充功能工作及舊 Release，不混入其他 AppContainer／Paseo／Anneal 開發。驗證沒有呼叫 Codex 執行檔、Agent／模型推論或原生電腦輸入；使用者的實際安裝及真實帳戶連線仍須本機驗收。
