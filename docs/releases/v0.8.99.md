# Coding Tools 0.8.99

## English

### Computer control uses the installed Codex Windows engine
- **The real engine, not an imitation.** Computer snapshots and actions now run through the Codex desktop app's own Windows computer-use engine (`@oai/sky`) and its native helper, including its on-screen control feedback. Coding Tools starts its own private worker for each local grant. It never joins another Codex session, never copies Codex binaries into the app, and never launches a Codex agent or model.
- **Codex desktop is now required for computer control.** The previous independent SendInput path is removed. If a compatible Codex desktop app is not installed, computer actions fail with a clear message, and no other input engine is used. A non-standard install can be pointed to with `CODING_TOOLS_CODEX_RESOURCES` (its `app/resources` folder).
- **New documented window actions.** `computer_action` also accepts the documented Codex window methods (`get_window`, `get_window_state`, `click`, `press_key`, `type_text`, `scroll`, `set_value`, `drag`, `perform_secondary_action`, `activate_window`) as `method` + `params`. Existing `step` calls keep working. The legacy standalone pointer move is no longer available, because the Codex engine has none.
- **Your local approval stays in charge.** Every call still needs the local grant, the visible monitor and a unique request id, and must target the approved window and executable. Stop, pause, grant expiry, losing the monitor or a physical Escape stop the worker at once, even mid-action. An interrupted or unclear action is never replayed. Screenshots stay in memory. The monitor now says the Codex Windows engine is in control.

### Chat work steps in color, with details when opened
- **Each step shows what kind of work it was.** In a turn's work fold, thoughts, commands, reads, searches, edits, web lookups, plans, subagents, questions and tool calls each have their own glyph and color, in light and dark themes. A failed or denied step turns red.
- **How long each step took.** Finished thoughts and tool calls show their time ("1.8s", "42s"), and a group of steps shows its total. Running steps show no time yet. Native Codex steps carry no timestamps, so they show none.
- **Open a step for its details.** A command opens on a card with its status, its time, who approved it, the exact command and its output with a line count. An MCP tool names its server and tool, and JSON arguments read as names and values instead of raw JSON. Cards are drawn only when opened, so long chats stay light.
- **Edits name their files.** An edit card leads with each file's name, folder, lines added and removed and a small diff bar, then the diff.
- **An overview of the whole turn.** Opening **Worked for …** starts with chips counting each kind of step (for example "3 thoughts · 4 commands · 2 files +36 −3"), how many failed and the total step time, plus a strip of every step in order, sized by how long it took. The line is colored by how the turn ended: failed, stopped or waiting for input.

### Verification and limitations
- GitHub Actions remains unavailable. This release is gated on local checks: `cargo fmt --check`, `cargo test --lib` and `cargo clippy --all-targets -D warnings` for the desktop core, the Codex bridge tests, release identity tests and `bun run package:win`. CI is not claimed to have passed.
- Automated tests use a simulated Codex client and never send real input to the desktop. No live click or typing into a real application was performed during verification.
- Chat work steps: the full desktop suite ran 4,284 tests. 4,263 passed and 20 were skipped. One (`native-ao-tree`) failed only because the agent-orchestrator submodule is not checked out in the development worktree; the release build checks it out and runs it. The renderer type check is clean. The new look was previewed with a recorded turn in a renderer harness, in light and dark themes, not yet in the installed app.
- Includes everything in 0.8.98.

## 繁體中文

### 電腦操作改用已安裝的 Codex Windows 引擎
- **使用真正的引擎，而非仿製品。** 電腦截圖與操作現在透過 Codex 桌面應用程式自己的 Windows 電腦操作引擎（`@oai/sky`）及其原生輔助程式執行，包括它在畫面上的操作回饋。Coding Tools 會為每一次本機授權啟動自己的私有工作程序；不會加入其他 Codex 工作階段、不會把 Codex 執行檔複製到應用程式中，也不會啟動 Codex 代理或模型。
- **電腦操作現在需要 Codex 桌面版。** 原本獨立的 SendInput 路徑已移除。若未安裝相容的 Codex 桌面應用程式，電腦操作會以清楚的訊息失敗，且不會改用其他輸入引擎。非標準安裝位置可用 `CODING_TOOLS_CODEX_RESOURCES` 指向其 `app/resources` 資料夾。
- **新增已記載的視窗操作。** `computer_action` 也接受 Codex 已記載的視窗方法（`get_window`、`get_window_state`、`click`、`press_key`、`type_text`、`scroll`、`set_value`、`drag`、`perform_secondary_action`、`activate_window`），以 `method` + `params` 呼叫。原有的 `step` 呼叫照常可用。舊的單獨移動指標動作已無法使用，因為 Codex 引擎沒有這項功能。
- **本機授權仍然作主。** 每次呼叫仍需要本機授權、可見的監看視窗及唯一的請求 ID，且必須針對已批准的視窗及執行檔。停止、暫停、授權到期、監看視窗消失或實體按下 Escape 都會立即停止工作程序，即使動作進行中亦然。中斷或結果不明的動作絕不會自動重送。截圖只保存在記憶體中。監看視窗現在會顯示由 Codex Windows 引擎操作。

### 對話工作步驟改為彩色，展開可看詳情
- **每個步驟顯示它做了哪類工作。** 在回合的工作摺疊區中，思考、指令、讀取、搜尋、編輯、網頁查詢、計畫、子代理、提問及工具呼叫各有自己的圖示與顏色，淺色與深色主題皆適用。失敗或被拒絕的步驟會變成紅色。
- **每個步驟花了多久。** 已完成的思考與工具呼叫會顯示耗時（例如「1.8s」、「42s」），一組步驟會顯示總計。執行中的步驟暫不顯示時間；原生 Codex 步驟沒有時間戳記，因此不顯示。
- **展開步驟即可查看詳情。** 指令展開後是一張卡片，列出狀態、耗時、由誰批准、確切的指令及其輸出與行數。MCP 工具會標明伺服器與工具名稱，JSON 參數以名稱與值列出，而不是原始 JSON。卡片只在展開時才繪製，長對話依然輕快。
- **編輯會列出檔案。** 編輯卡片先列出每個檔案的名稱、資料夾、新增與刪除的行數及小型差異條，再顯示差異內容。
- **整個回合的總覽。** 展開「Worked for …」時，最上方會以標籤統計各類步驟（例如「3 thoughts · 4 commands · 2 files +36 −3」）、失敗數量及步驟總耗時，並以一條依時間比例排列的色條顯示每個步驟。這一行的顏色反映回合的結果：失敗、已停止或等待輸入。

### 驗證及限制
- GitHub Actions 仍無法使用。本版本以本機檢查把關：桌面核心的 `cargo fmt --check`、`cargo test --lib` 及 `cargo clippy --all-targets -D warnings`、Codex 橋接測試、版本身分測試及 `bun run package:win`；不會宣稱 CI 已通過。
- 自動化測試使用模擬的 Codex 用戶端，不會對桌面送出真正的輸入。驗證期間沒有對真實應用程式進行實際點擊或輸入。
- 對話工作步驟：完整桌面測試共 4,284 項，4,263 項通過、20 項略過。1 項（`native-ao-tree`）失敗只因開發工作樹未簽出 agent-orchestrator 子模組；發佈建置會簽出並執行該測試。渲染器型別檢查無誤。新外觀已在渲染器測試環境中以錄製的回合預覽淺色及深色主題，尚未在已安裝的應用程式中檢視。
- 包含 0.8.98 的所有變更。
