# Coding Tools v0.8.171

## English

### Chat agents ask before they act
- **Your own terminal stays yours.** A chat agent can no longer find, read, type into or stop the terminal you open in the chat's side panel. Before, on Approve for me, typing into it could be approved by the 20-second timer, outside Codex's sandbox.
- **A new preview address is really checked.** On Approve for me the chat's reviewer judges it (Claude Code chats had skipped that review). When the reviewer is unsure, or the chat is not on Approve for me, you decide. A new address is never opened on a timer.
- **view_app is checked like a screenshot.** The tool that shows an agent the Coding Tools window goes to the reviewer, and to you when it is unsure.
- **An agent can't loosen its own permissions.** A chat's patch can no longer change its harness's permission settings (.claude/settings.json and settings.local.json, .codex/config.toml, a root opencode.json) so that its later calls skip the reviewer.

### Approve for me
- **Commands that only look routine are checked again.** Installing a named package (npm install -D x, yarn add, yarn dlx), npx tsc or npx biome where the tool is missing, deleting or moving a git branch, git or sort options that write files, rg options that run programs or search ignored files like .env, reading files outside the project (git diff --no-index), and printing environment variables (env:) now go to the reviewer instead of running unasked.
- **Scripts are reviewed as they will run.** A command that writes and then runs a script goes to the reviewer, because the write could replace what was checked. A script named without a path runs from PATH, so it is not cleared by the folder's file of that name.
- **The safety rules come first.** A read of .env through the app's tools is denied like the agent's own read, and the app's terminal checks the safety rules before treating a command as routine.

### Subagents
- **Never more access than their chat.** Full access on the Subagents page applies only when the chat that starts the subagent runs in Full access.
- **Every agent gets the page's mode.** opencode, Pi and Antigravity subagents get Approve for me or Full access as set. Before, an opencode subagent ran in opencode's own default, which allowed every tool unasked. An agent that runs only in Full access is refused on Approve for me, with the reason.
- **Requests that need a person are denied.** A subagent request that the agent marks as needing a person, that disables the sandbox, runs in the background, names another folder, or is too long to check is denied instead of allowed.
- **Stops and restarts keep their work.** Stopping a subagent that was still starting no longer leaves it stuck holding its places until the app restarts. A subagent that finished just before it was stopped or hit its time limit keeps its report. A long-running subagent is no longer forgotten after a restart, and messages to a running subagent are no longer dropped as repeats after one.

### Privacy
- **Hide secrets covers more.** With Hide secrets on, an agent reading another chat (chat_read) no longer gets its pasted keys back, and handoffs hide more shapes: names like DB_PASSWORD= or AWS_SECRET_ACCESS_KEY=, Stripe, GitLab, npm and Hugging Face tokens, and web tokens (JWT).

### Git, network and computer control
- **Nested repositories run no settings.** The app's git tools no longer run settings from a repository nested inside a chat's worktree, which a sandboxed command could have written, and no fsmonitor program runs for them at all.
- **CPA proxy routes hold.** CPA retries temporary failures when saving an account's proxy route. The network router keeps route edits across a restart and stops cleanly even if its replacement is still starting.
- **A failed window read sends nothing.** When a native window read fails, Coding Tools reports that no input was sent. A failed read no longer blocks a new selection as though a click or keypress might have happened; uncertain input still cannot be replayed.

Includes all changes from v0.8.170.

## 繁體中文

### 聊天代理在行動前先詢問
- **你自己的終端機只屬於你。** 聊天代理不能再找到、讀取、輸入或停止你在聊天側欄中開啟的終端機。先前在「Approve for me」下，輸入可能被 20 秒計時器自動核准，並在 Codex 沙盒之外執行。
- **新的預覽網址確實會被審查。** 在「Approve for me」下由聊天的審查模型判斷（Claude Code 聊天先前略過了這次審查）；審查者不確定時，或聊天不是「Approve for me」時，由你決定。新網址絕不會因計時器而開啟。
- **view_app 會像截圖一樣被審查。** 讓代理看到 Coding Tools 視窗的工具會交給審查者，不確定時再問你。
- **代理不能放寬自己的權限。** 聊天的修補不能再修改其代理工具的權限設定（.claude/settings.json 與 settings.local.json、.codex/config.toml、根目錄的 opencode.json），以讓之後的呼叫略過審查。

### Approve for me
- **只是看似例行的指令會再次檢查。** 安裝指定套件（npm install -D x、yarn add、yarn dlx）、工具缺少時的 npx tsc 或 npx biome、刪除或移動 git 分支、會寫入檔案的 git 或 sort 選項、會執行程式或搜尋 .env 等被忽略檔案的 rg 選項、讀取專案外的檔案（git diff --no-index），以及印出環境變數（env:），現在都交給審查者，而不是不經詢問就執行。
- **腳本依實際執行方式審查。** 先寫入再執行腳本的指令會交給審查者，因為寫入可能取代已檢查的內容。沒有路徑的腳本名稱會從 PATH 執行，因此不會因資料夾中同名的檔案而被放行。
- **安全規則優先。** 透過應用程式工具讀取 .env 會像代理自己讀取一樣被拒絕；應用程式的終端機在把指令視為例行之前會先檢查安全規則。

### 子代理
- **權限絕不超過其聊天。** 子代理頁面的「完整存取」只在啟動它的聊天本身以完整存取執行時才適用。
- **每個代理都會取得頁面設定的模式。** opencode、Pi 與 Antigravity 子代理會依設定取得「Approve for me」或完整存取。先前 opencode 子代理以 opencode 自己的預設執行，會不經詢問允許所有工具。只能以完整存取執行的代理在「Approve for me」下會被拒絕，並說明原因。
- **需要真人的請求會被拒絕。** 代理標示為需要真人、關閉沙盒、在背景執行、指定其他資料夾，或過長而無法檢查的子代理請求，現在會被拒絕，而不是被允許。
- **停止與重新啟動會保留成果。** 停止仍在啟動中的子代理，不再會讓它卡住並佔用名額直到應用程式重新啟動。在被停止或達到時間上限前剛完成的子代理會保留其報告。長時間執行的子代理在重新啟動後不再被遺忘，重新啟動後傳給執行中子代理的訊息也不再被當作重複而遺失。

### 隱私
- **「隱藏祕密」涵蓋更多內容。** 開啟「隱藏祕密」時，代理讀取其他聊天（chat_read）不再取回其中貼上的金鑰；交接內容也會隱藏更多格式：DB_PASSWORD= 或 AWS_SECRET_ACCESS_KEY= 這類名稱、Stripe、GitLab、npm 與 Hugging Face 權杖，以及網頁權杖（JWT）。

### Git、網路與電腦控制
- **巢狀儲存庫不會執行任何設定。** 應用程式的 git 工具不再執行聊天工作樹內巢狀儲存庫的設定（沙盒中的指令可能寫入它）；這些工具也完全不再執行 fsmonitor 程式。
- **CPA 代理路由保持穩定。** CPA 在暫時無法儲存帳戶的代理路由時會重試。網路路由器重新啟動時會保留路由變更，且即使替代程序仍在啟動，也能正常停止。
- **讀取視窗失敗時不會送出任何輸入。** 讀取原生視窗失敗時，Coding Tools 會正確顯示未送出輸入，不再把讀取失敗誤判成可能已點擊或輸入而阻擋選取視窗。結果不明的實際輸入仍不會重送。

包含 v0.8.170 的所有變更。
