# Coding Tools 0.8.101

## English

### Team roles and same-workspace MCP setup
- **Each Browser account shows Role and MCP access separately from its plan.** Freshly verified workspace metadata distinguishes Owner, Admin and Member. Signed-out, incomplete, stale or future-dated metadata is marked Last known / Refresh required instead of granting setup authority.
- **Team members and admins check the existing connector first.** Setup freshly verifies the account, exact workspace UUID and configured tunnel identity before requesting connection consent. This existing-only path cannot open Add/Create, borrow Platform creation permissions or create an owner handoff.
- **New connector creation/publication still requires a freshly verified owner of the same workspace.** A previous connection, matching workspace/app name, cached URL or subscription label cannot authorize it. Login, cookies and OAuth sessions remain isolated between accounts.
- **Context changes stop setup.** A failed existing-connector lookup or identity read cannot hide a simultaneous account/workspace change and trigger owner creation from stale context. Current-page sign-in is also applied consistently to single-account and bulk actions, and owner-required errors retain their actionable native classification.

### Verification and limitations
- Includes [PR #1121](https://github.com/p90-lover/coding-tools-mcp/pull/1121) and everything in 0.8.100. No unrelated open PRs are included in this release's scope.
- GitHub Actions rejected the CI dispatch with HTTP 422 (Actions disabled). This release uses the repository's locally verified delivery fallback, not a claim that CI passed.
- The feature's integrated verification passed **180 tests**, renderer TypeScript checking and the production renderer build. Independent review findings were reproduced, repaired and re-reviewed.
- Release publication is gated on the full merged-source desktop suite, frozen dependency installation, release identity checks, package verification, exact packaged source provenance and downloaded-asset checksum verification.
- Existing-only reuse is conditional: ChatGPT must expose the existing connector's actual readable configuration, including its configured tunnel identity. Discovery currently uses Personal apps; a read-only published app without the required Manage/Edit proof fails closed to the owner path. This is not a promise that every member can use every shared app.
- These source/fixture tests do not establish a live account connection. Live acceptance still requires normal foreground controls, runtime/tunnel readiness, fresh workspace details, per-account consent and a successful real native MCP tool call. No authentication/security challenge bypass is added, and no installed app is patched or restarted by this release task.

## 繁體中文

### 團隊角色與同工作區 MCP 設定
- **每個 Browser 帳戶會分別顯示 Role 與 MCP access，不再與方案資料混在一起。** 最新驗證的工作區資料會區分 Owner、Admin 與 Member。已登出、身分資料不完整、過期或時間在未來的資料，只會標示 Last known / Refresh required，不會因此取得設定權限。
- **團隊成員與管理員會先檢查既有 connector。** 設定流程會重新驗證帳戶、精確的工作區 UUID 與已設定的 tunnel 身分，再要求連線同意。這條僅使用既有 connector 的路徑，不會開啟 Add/Create、借用 Platform 建立權限，或產生擁有者交接憑證。
- **建立或發布新 connector，仍須由同工作區且重新驗證的擁有者執行。** 過去連線成功、相同的工作區或應用程式名稱、快取網址或訂閱標籤，都不能作為授權。不同帳戶的登入、cookies 與 OAuth 工作階段保持隔離。
- **帳戶或工作區改變時會停止設定。** 既有 connector 查找或身分讀取失敗，不再掩蓋同時發生的帳戶／工作區切換，避免依過期狀態改為建立 connector。單一帳戶與批次操作也一致採用目前頁面的登入狀態，並保留原生呼叫端可辨識的擁有者權限錯誤。

### 驗證與限制
- 包含 [PR #1121](https://github.com/p90-lover/coding-tools-mcp/pull/1121) 與 0.8.100 的所有內容。本次發布範圍不包含其他仍開啟且無關的 PR。
- GitHub Actions 以 HTTP 422（Actions disabled）拒絕 CI 請求。本版本使用專案授權的本機驗證交付流程，並不宣稱 CI 已通過。
- 功能整合後的驗證已通過 **180 個測試**、renderer TypeScript 檢查與正式 renderer 建置。獨立審查發現的問題均已重現、修正並再次審查。
- 正式發布前必須通過合併後來源的完整桌面測試套件、鎖定相依套件安裝、版本身分檢查、封裝驗證、封裝來源核對，以及下載後的資產 checksum 驗證。
- 既有 connector 的重用有條件：ChatGPT 必須提供可讀取的真實設定，包含已設定的 tunnel 身分。目前從 Personal apps 查找；若唯讀發布的應用程式沒有必要的 Manage/Edit 證據，流程會安全停止並要求擁有者處理。這不代表每位成員都能使用任何共用應用程式。
- 來源與測試頁面的驗證不等於實際帳戶已連線。實際驗收仍須正常的前景操作、可用的 runtime／tunnel、最新工作區資料、各帳戶同意，以及一次成功的真實原生 MCP 工具呼叫。本次沒有加入登入或安全驗證繞過，也不會修補或重新啟動已安裝的應用程式。
