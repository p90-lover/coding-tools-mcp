# Coding Tools 0.8.101

## English

### More chats than one page holds: pages
- **Pages are on by default.** When a page's ten split screens are full, New chat (the button, Ctrl+N or a project's New chat) opens on the next page with room, or on a new page. Before, it replaced one of the page's chats, because pages sat behind a setting that was off. If you turned pages off in Settings, they stay off.
- **Page tabs sit in the chat title bar:** the page numbers, and **+** for a new page, up to twelve pages. The separate page bar above the window is gone, so the chats get that height back.
- **Shift+Q goes to the previous page and Shift+R to the next.** They never act while you type, so a capital Q or R in a chat stays text. Both keys can be changed in Settings.
- **Scrolling sideways turns pages:** a touchpad swipe, a tilted wheel or Shift+wheel turns one page per gesture. Any scroll over the tabs turns a page. Scrolling messages up and down never does, and neither does scrolling a wide code block.
- **Chats on other pages keep working.** Their runs and queues go on; only their drawing pauses. Turning a page no longer redraws the chats on every other page.
- In Settings, "Show page tabs" is now "Use pages", and "Scroll over the page bar to switch" is now "Scroll to switch pages".
- Pages can't be closed yet. They only grow, up to twelve.

### Thoughts and steps stay open while a chat is on a mission
- **While a turn runs, and while a goal is pursued, a chat's thoughts and step groups are open.** A thought shows its text, and a step group lists its Ran, Read and Edited rows. Tool output, diffs and edit cards still open only when you click them.
- **A turn you watched stays open after its answer arrives.** Before, it folded into "Worked for…" the moment the answer landed.
- **What you fold stays folded**, even as the turn updates.
- An opened thought shows its title once, not again in its body.
- **Settings › Chat › Turns › "Keep work expanded on a mission"** is on by default. Turned off, turns fold as before.

### A chat never refuses a message because its record is full
- **When a chat's history runs out of room, a model summarizes it.** If no model answers, or there's no room for a summary, the newest part is kept. Before, a chat could stop with "task record is full". A long message, a steer arriving at the same moment, or a rewind no longer makes the send fail.
- **A message has one limit everywhere:** 7,936 bytes, in the chat box, in goal rounds and in the bridge. A message over it stays in the chat box with a "Too long" note, instead of failing after it was sent. Chinese text and emoji take more bytes per character, so they reach the limit sooner.
- **A goal round's own message always fits**, so a goal no longer stalls on its message size.

### ChatGPT team roles and shared MCP connectors
- **Browser accounts show a Role row and an MCP access row.** Role shows Owner, Admin or Member, apart from the plan. A role read from old or signed-out data is labeled "Last known" or "Refresh required".
- **A team member or admin can use the workspace's existing connector** once the app has checked that exact connector: the user, workspace, role and tunnel must all match, checked fresh. A member can't create or publish a connector. If the check can't confirm the connector, setup falls back, as before, to a freshly verified owner of the same workspace.
- This works only if ChatGPT shows the connector's settings to the member. If it doesn't, setup asks for the owner.

### Verification and limitations
- GitHub Actions is still unavailable, so this release depends on local checks. It does not claim that CI passed.
- **Pages (#1116):** the type check is clean, and 1,082 tests in 21 suites pass. In a renderer harness, a full ten-screen page opened page 2 with no chat replaced. Shift+Q, Shift+R and sideways scrolling turned pages, and typing a capital Q or R in the composer turned nothing. Not yet checked in the installed app.
- **Mission (#1119):** the type check is clean, and 1,181 tests in 27 suites pass. It was checked in a renderer harness in light and dark themes. Not yet checked in the installed app.
- **Chat record (#1120):** the 942 affected tests pass.
- **Team roles (#1121):** 180 focused tests pass, and so do the renderer type check and the production build. These are mocked checks: a member account connecting to a shared connector has not been tested live.
- **All four together:** with every change merged, the renderer type check is clean and 969 tests pass in the suites the chat changes touch. The release build runs the full desktop suite before packaging.
- Includes everything in 0.8.100.

## 繁體中文

### 一頁放不下的對話：分頁
- **分頁預設開啟。** 當一頁的十個分割畫面都滿了，New chat（按鈕、Ctrl+N 或專案的 New chat）會在下一個還有空位的頁面開啟，或開一個新頁面。以前它會取代該頁的其中一個對話，因為分頁功能藏在一個預設關閉的設定後面。如果你在設定中關閉了分頁，它會保持關閉。
- **分頁標籤位於對話標題列中：** 顯示頁碼，以及用來新增頁面的 **+**，最多十二頁。視窗上方獨立的分頁列已移除，對話因此取回了那段高度。
- **Shift+Q 前往上一頁，Shift+R 前往下一頁。** 你在輸入時它們不會作用，所以在對話中輸入大寫 Q 或 R 仍是文字。兩個按鍵都可以在設定中更改。
- **橫向捲動可以翻頁：** 觸控板滑動、傾斜滾輪或 Shift+滾輪，每個手勢翻一頁。在分頁標籤上的任何捲動都會翻頁。上下捲動訊息永遠不會翻頁，捲動寬的程式碼區塊也不會。
- **其他頁面上的對話會繼續運作。** 它們的執行與佇列照常進行，只有畫面繪製會暫停。翻頁時不再重新繪製其他每一頁的對話。
- 設定中的「Show page tabs」現在叫「Use pages」，「Scroll over the page bar to switch」現在叫「Scroll to switch pages」。
- 目前還不能關閉頁面。頁面只會增加，最多十二頁。

### 對話執行任務時，思考與步驟保持展開
- **回合執行期間，以及目標進行中時，對話的思考與步驟群組會展開。** 思考會顯示內容，步驟群組會列出 Ran、Read 與 Edited 各列。工具輸出、差異與編輯卡片仍只在你點擊時才會開啟。
- **你看著執行的回合，在回答出現後仍保持展開。** 以前回答一出現，它就會收合成「Worked for…」。
- **你收合的內容會保持收合**，即使回合持續更新。
- 展開的思考只顯示一次標題，內容中不再重複。
- **設定 › 對話 › Turns ›「Keep work expanded on a mission」** 預設開啟。關閉後，回合會像以前一樣收合。

### 對話不再因為紀錄已滿而拒絕訊息
- **當對話的歷史紀錄空間用完時，會由模型摘要。** 若沒有模型回應，或沒有空間放摘要，則保留最新的部分。以前對話可能會因「task record is full」而停止。長訊息、同時送達的 steer 或倒轉，都不會再讓送出失敗。
- **訊息在所有地方都使用同一個上限：** 7,936 位元組，包括對話框、目標回合與橋接。超過上限的訊息會留在對話框中並顯示「Too long」，而不是送出後才失敗。中文與 emoji 每個字元佔用較多位元組，因此會較早達到上限。
- **目標回合本身的訊息一定放得下**，所以目標不會再因訊息大小而卡住。

### ChatGPT 團隊角色與共用 MCP 連接器
- **瀏覽器帳號會顯示 Role 與 MCP access 兩列。** Role 顯示 Owner、Admin 或 Member，與方案分開顯示。從舊資料或已登出資料讀到的角色會標示「Last known」或「Refresh required」。
- **團隊成員或管理員可以使用工作區既有的連接器**，前提是應用程式已檢查過該連接器：使用者、工作區、角色與 tunnel 都必須相符，而且是即時檢查。成員不能建立或發佈連接器。如果檢查無法確認該連接器，設定會像以前一樣，改由同一工作區中經即時驗證的擁有者處理。
- 這只有在 ChatGPT 向該成員顯示連接器設定時才有效。若沒有顯示，設定會要求擁有者處理。

### 驗證與限制
- GitHub Actions 仍無法使用，因此本版本依靠本機檢查，並不宣稱 CI 已通過。
- **分頁（#1116）：** 型別檢查沒有錯誤，21 個測試套件共 1,082 個測試通過。在 renderer 測試頁面中，已滿的十畫面頁面開啟了第 2 頁，沒有取代任何對話。Shift+Q、Shift+R 與橫向捲動都能翻頁，在輸入框中輸入大寫 Q 或 R 則不會翻頁。尚未在已安裝的應用程式中檢查。
- **任務中展開（#1119）：** 型別檢查沒有錯誤，27 個測試套件共 1,181 個測試通過。已在 renderer 測試頁面中以淺色與深色主題檢查。尚未在已安裝的應用程式中檢查。
- **對話紀錄（#1120）：** 受影響的 942 個測試通過。
- **團隊角色（#1121）：** 180 個相關測試通過，renderer 型別檢查與正式建置也通過。這些都是模擬檢查：成員帳號連接共用連接器尚未實際測試。
- **四項合併後：** 所有變更合併後，renderer 型別檢查沒有錯誤，對話相關變更涉及的測試套件中 969 個測試通過。發佈建置會在打包前執行完整的桌面應用程式測試套件。
- 包含 0.8.100 的所有內容。
