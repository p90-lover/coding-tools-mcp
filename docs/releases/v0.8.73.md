# Coding Tools 0.8.73

## English

### Chats
- Long chats no longer slow the app down. Each chat drew every turn it ever had. With ten chats open on 0.8.68, the window held 164,000 elements, up to 41,500 of them in one long goal chat. In the visible window, restyling them kept the renderer busy about 70% of the time, with frames of up to 1 second, and a mouse move waited 3.4 seconds for a response. A chat now draws its newest 16 turns. A "Show 16 earlier turns" row above them brings back more, 16 at a time. Folded goal rounds keep their row. Switching chats starts again from the newest 16 (PR #1003).

### Freezes
- The chat's requests to AO and to the local execution service now go out from a worker thread. On 2026-11-03 every window froze for 70 s and 21 s while a network filter held one of main's socket writes; main sent about 1,600 such requests a minute while two chats ran. A socket call that still holds main now names its endpoint in the freeze log (PR #1006).
- Saving proxy settings no longer holds every window for 0.5–1.2 s. The save is written on a pool thread, and a Decodo sync, which saved once per proxy, now ends in at most two writes. Anything that reads the saved route, such as CPA, waits until it is on disk (PR #1010).

### Browser
- After a sign-in check the app made by itself fails, the next automatic check waits 10 minutes. Before, Setup reopened ChatGPT every 10 seconds until ChatGPT blocked the sign-in for too many tries. Your own Sign in, passkey sign-in and refresh never wait (PR #1004).

### Reliability
- A chat wake-up that was cancelled, postponed or replaced while it was looking up its run no longer sends anyway (PR #1005).
- Adding a tunnel no longer overwrites a connector change or an account unassignment that finished at the same time (PR #1007).
- When a chat-list setting can't be saved, every part of the window shows the same value for the rest of the session, and a later failed change no longer drops an earlier one (PR #1008).
- The workspace log viewer no longer shows a Chinese or four-byte character cut in half at the start of its tail, and it stops at the size it started reading (PR #1000).

### Verification and limitations
- A new test covers which turns are drawn, including a folded run of goal rounds. All 721 chat tests pass, and the type check is clean (PR #1003).
- The numbers above were measured in the installed 0.8.68 over 30 seconds with the window visible. The same measurement on this version is still to be taken.
- Freezes: the endpoint counts were taken in the running app; the move to a worker is covered by tests, and the freezes themselves depend on a network filter holding writes, so they were not reproduced (PR #1006).
- Proxy saves: a new test checks that 20 saves make no file call on the calling thread and end with the latest state on disk; 265 related tests pass (PR #1010).
- Sign-in wait: tests run the real check handler and launch retry against a fake browser and clock; 60 checks over 10 minutes reach ChatGPT once (PR #1004).
- Wake-ups: seven new regressions fail on the old code; 18 focused cases pass (PR #1005). Tunnels: 22 focused checks pass (PR #1007). Chat-list settings: 30 tests pass (PR #1008). Log tails: 4 native checks and 3 unit tests pass (PR #1000).
- A native Electron test now also checks that a visualization keeps its state across follow-up turns; test only (PR #1009).
- None of these is checked in the installed app yet.
- Built and published by GitHub CI from main; no local build was made for this version.
- Everything in 0.8.72 is included.

## 繁體中文

### 對話
- 長對話不會再拖慢應用程式。過去每個對話都會繪製它所有的回合。在 0.8.68 開啟十個對話時，視窗共有 164,000 個元素，單一長目標對話多達 41,500 個。視窗可見時，重新計算這些元素的樣式令渲染程序約 70% 時間處於忙碌狀態，單一畫格最長達 1 秒，移動滑鼠要等 3.4 秒才有回應。現在每個對話只繪製最新的 16 個回合，上方的「Show 16 earlier turns」列可再載入更早的回合，每次 16 個。已摺疊的目標回合仍保留其摺疊列。切換對話時，會重新從最新的 16 個回合開始（PR #1003）。

### 凍結
- 對話向 AO 及本機執行服務發出的請求，現在改由背景執行緒送出。2026-11-03 網絡過濾器扣住主執行緒的一次 socket 寫入，令所有視窗分別凍結 70 秒及 21 秒；兩個對話運行時，主執行緒每分鐘發出約 1,600 個這類請求。若仍有 socket 呼叫扣住主執行緒，凍結記錄現在會列出其端點（PR #1006）。
- 儲存代理設定不會再令所有視窗停頓 0.5 至 1.2 秒。儲存改在背景執行緒寫入，而過去每個代理各儲存一次的 Decodo 同步，現在最多只寫入兩次。CPA 等讀取已儲存路由的程式，會等到設定寫入磁碟後才讀取（PR #1010）。

### 瀏覽器
- 應用程式自動進行的登入檢查失敗後，下一次自動檢查會等候 10 分鐘。過去「設定」每 10 秒重新開啟 ChatGPT，直至 ChatGPT 因嘗試次數過多而封鎖登入。你自己按「登入」、使用密碼金鑰登入或重新整理時都不會等候（PR #1004）。

### 可靠性
- 對話的喚醒若在查詢其執行期間被取消、延後或取代，不會再照樣送出（PR #1005）。
- 新增通道時，不會再覆蓋同時完成的連接器變更或帳戶解除指派（PR #1007）。
- 對話清單設定無法儲存時，視窗各部分在本次工作階段內都會顯示相同的值，之後失敗的變更亦不會再丟失先前的變更（PR #1008）。
- 工作區記錄檢視器不會再在記錄尾段開頭顯示被截斷的中文或四位元組字元，並會在開始讀取時的大小停止（PR #1000）。

### 驗證及限制
- 新測試涵蓋繪製哪些回合，包括已摺疊的目標回合。所有 721 項對話測試均通過，型別檢查亦無錯誤（PR #1003）。
- 上述數字是在已安裝的 0.8.68 中，於視窗可見時量測 30 秒所得。此版本的同一量測仍待進行。
- 凍結：端點次數是在運行中的應用程式內取得；改用背景執行緒由測試涵蓋，凍結本身取決於網絡過濾器扣住寫入，因此未有重現（PR #1006）。
- 代理儲存：新測試檢查 20 次儲存不會在呼叫的執行緒上進行任何檔案操作，並以最新狀態寫入磁碟；265 項相關測試通過（PR #1010）。
- 登入等候：測試以假瀏覽器及時鐘執行實際的檢查處理程序及啟動重試；10 分鐘內 60 次檢查只連接 ChatGPT 一次（PR #1004）。
- 喚醒：七項新回歸測試在舊程式碼上失敗，18 項針對性測試通過（PR #1005）。通道：22 項針對性檢查通過（PR #1007）。對話清單設定：30 項測試通過（PR #1008）。記錄尾段：4 項原生檢查及 3 項單元測試通過（PR #1000）。
- Electron 原生測試現在亦檢查視覺化內容在後續回合中保留其狀態；只屬測試（PR #1009）。
- 以上各項尚未在已安裝的應用程式中檢查。
- 由 GitHub CI 從 main 建置及發佈；此版本沒有在本機建置。
- 包含 0.8.72 的所有內容。
