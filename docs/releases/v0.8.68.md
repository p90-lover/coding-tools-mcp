# Coding Tools 0.8.68

## English

### Codex bridge
- When the bridge's saved settings come from an older bridge and it needs to be set up again, the watchdog stops retrying every 2 minutes. A restart can't fix that state, and each retry saved the bridge's ownership file on the app's main thread, freezing the window for 0.4–0.7 s. The watchdog now waits 10 minutes, doubling up to 1 hour, as it already did when another process holds the bridge port. Once the bridge is set up again, the next check finds it ready and the watchdog returns to normal (PR #981).

### Tests
- A chat approval test no longer fails at random on slow CI runners. It now waits for the same state it checks, instead of giving up after 40 reads (PR #980).

### Verification and limitations
- Bridge: seen in installed 0.8.67 on 2026-11-03, where the settings required bridge 5.0.6 but the app bundles 6.1.17, and the retries held the main thread for 383–724 ms each. The runtime, main-thread and startup tests pass (129/129). No test runs the watchdog's timer itself, and the change isn't checked in the installed app yet. You still need to set the bridge up again in the app; this release only stops the retries until you do (PR #981).
- Tests: `agent-orchestrator-workflow` 451/451 (PR #980).
- Built and published by GitHub CI from main; no local build was made for this version.
- Everything in 0.8.67 is included.

## 繁體中文

### Codex 橋接
- 當橋接的已儲存設定來自舊版橋接而需要重新設定時，監察程式不會再每 2 分鐘重試一次。重新啟動無法修正這種狀態，而每次重試都會在應用程式主執行緒上儲存橋接的擁有權檔案，令視窗凍結 0.4 至 0.7 秒。監察程式現在會等候 10 分鐘，之後加倍，最長 1 小時，與其他程序佔用橋接埠時的做法相同。橋接重新設定後，下一次檢查會發現它已就緒，監察程式隨即回復正常（PR #981）。

### 測試
- 一項聊天核准測試不會再在較慢的 CI 執行器上隨機失敗。它現在會等候它所檢查的同一狀態，而不是讀取 40 次後就放棄（PR #980）。

### 驗證及限制
- 橋接：於 2026-11-03 在已安裝的 0.8.67 上觀察到，設定要求橋接 5.0.6，但應用程式內附 6.1.17，每次重試都令主執行緒停頓 383 至 724 毫秒。執行環境、主執行緒及啟動測試全部通過（129/129）。沒有測試直接執行監察程式的計時器，此變更亦尚未在已安裝的應用程式中檢查。你仍需要在應用程式中重新設定橋接；此版本只會在你設定之前停止重試（PR #981）。
- 測試：`agent-orchestrator-workflow` 451/451（PR #980）。
- 由 GitHub CI 從 main 建置及發佈；此版本沒有在本機建置。
- 包含 0.8.67 的所有內容。
