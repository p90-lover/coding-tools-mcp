# Coding Tools 0.8.66

## English

### Performance
- The Codex bridge watchdog stops retrying every two minutes when another program holds the bridge's port. After an update, a bridge kept from the older version could hold the port. The watchdog then tried to restart the bridge every two minutes for the whole session: it never succeeded, and each attempt read the bridge's ownership file and asked Windows about the process, holding the app's windows briefly. It now waits 10 minutes after finding another owner, doubling up to an hour, and starts over as soon as the bridge answers again (PR #974).

### Verification and limitations
- Seen on 0.8.57 on 2026-11-02: a restart every two minutes from 17:20 to 17:35, each ending "external". A new test checks the waiting times (10, 20, 40, 60, 60 minutes). Not yet watched in the installed app.
- Why the kept bridge isn't recognised as the app's own after an update is not fixed here.
- Built and published by GitHub CI from main; no local build was made for this version.
- Everything in 0.8.65 is included.

## 繁體中文

### 效能
- 當另一個程式佔用橋接埠時，Codex 橋接監察程式不再每兩分鐘重試一次。更新後，舊版本保留下來的橋接可能仍佔用該埠。監察程式過去會在整個工作階段中每兩分鐘嘗試重新啟動橋接，但從未成功；每次嘗試都會讀取橋接的擁有權檔案並向 Windows 查詢該程序，令應用程式視窗短暫停頓。現在發現另一個擁有者後會等待 10 分鐘，之後每次加倍，最多一小時；橋接一旦再次回應便重新開始計算（PR #974）。

### 驗證及限制
- 於 2026-11-02 在 0.8.57 上觀察到：17:20 至 17:35 每兩分鐘重新啟動一次，每次都以「external」結束。新測試會檢查等待時間（10、20、40、60、60 分鐘）。尚未在已安裝的應用程式中觀察。
- 此版本沒有修正為何更新後保留的橋接不被視為應用程式自己的橋接。
- 由 GitHub CI 從 main 建置及發佈；此版本沒有在本機建置。
- 包含 0.8.65 的所有內容。
