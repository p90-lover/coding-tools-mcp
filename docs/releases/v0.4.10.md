# v0.4.10 — release validation portability repairs

## English

v0.4.10 keeps the v0.4.9 long-running command and bounded RAM-cache behavior, while repairing the two platform-specific release blockers found by the v0.4.9 hosted desktop validation. The existing v0.4.9 tag and its failed build evidence are preserved; no historical release tag is rewritten.

On Windows, Git metadata collection used by bounded Harness baselines now has up to three seconds for process startup instead of one second. The overall baseline scan deadline remains eight seconds, and the existing per-file, aggregate-byte and directory-entry limits are unchanged. Non-Windows platforms retain the original one-second Git metadata allowance.

On macOS and other non-Windows builds, the native sandbox lifecycle stub now returns a typed job guard instead of a unit value. Unsupported native sandbox execution remains fail-closed; the change only makes lifecycle handling type-consistent with the Windows path and satisfies strict release Clippy checks without weakening policy.

The repair was validated on hosted Windows, macOS and Linux runners. Windows and macOS completed the full Rust test suite and strict Clippy checks. Linux completed build, full tests, strict Clippy and the call-tool, security, history-session and Harness compatibility contracts after the isolated validation runner was supplied with its required PipeWire and GBM development libraries. Frontend checks, build and Node tests also passed. The Linux package additions are CI-runner dependencies only and are not application runtime changes.

Installer publication remains gated by the repository's verified desktop release workflow, including native tests, dependency-boundary checks, credential-history screening, RustSec audit, installer generation and final asset verification.

## 繁體中文

v0.4.10 保留 v0.4.9 嘅長時間一般指令執行同有限 RAM 快取行為，同時修復 v0.4.9 託管桌面發佈驗證發現嘅兩個平台特定阻塞問題。現有 v0.4.9 tag 同失敗建置證據會完整保留，唔會重寫任何歷史發佈 tag。

Windows 方面，有限 Harness baseline 使用嘅 Git metadata 收集，程序啟動等待由一秒調整至最多三秒。整體 baseline 掃描上限仍然係八秒，原有單檔、總位元組同目錄項目限制亦完全不變。非 Windows 平台仍然保留原本一秒嘅 Git metadata 等待上限。

macOS 同其他非 Windows build 方面，native sandbox lifecycle stub 而家會回傳有型別嘅 job guard，而唔再係 unit value。唔支援嘅 native sandbox 執行仍然維持 fail-closed；今次修改只係令 lifecycle 處理同 Windows 路徑保持型別一致，並通過嚴格 release Clippy，冇放寬任何權限或安全政策。

修補已經喺託管 Windows、macOS 同 Linux runner 驗證。Windows 同 macOS 已完成完整 Rust 測試同嚴格 Clippy。Linux 喺隔離驗證 runner 補齊所需 PipeWire 同 GBM development library 後，已完成 build、完整測試、嚴格 Clippy，以及 call-tool、安全、history-session 同 Harness compatibility contract。Frontend 檢查、build 同 Node 測試亦已通過。Linux 新增嘅套件只係 CI runner 依賴，唔係應用程式 runtime 改動。

安裝程式仍然必須通過 repository 嘅 verified desktop release workflow，當中包括 native 測試、dependency boundary 檢查、Git 歷史 credential 掃描、RustSec audit、installer 建置同最終 asset 驗證，先可以正式公開。
