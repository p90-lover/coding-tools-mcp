# Coding Tools 0.8.96

## English

### Chat
- **Replies no longer sit inside a box.** Each agent reply was drawn as a framed card, so the answer read as if it were placed inside a box. A reply now reads as plain text, like your own messages. Everything under it stays: model, status, time taken, changed files and the activity line (steps, failures, LLM time, tokens). A failed or stuck reply still stands out through its coloured status pill. (#1092)
- **"I'll watch it" now really continues the chat.** Chats could say a command was being watched and promise a next step, then stop. Codex, Claude Code and OpenCode chats get `watch_command`, `list_command_watches` and `cancel_command_watch`. A watch follows a command the chat already started. When the command finishes, fails or the watch expires, the chat gets a real follow-up turn on the same model, account and permissions. Stop, pause, a newer turn and archiving all cancel it. (#1093)

### Computer use
- **While a chat controls an app, a pill at the top of the screen shows what it is doing.** It names the agent and the model it runs on, the step it is taking now ("Clicking “Save”", "Typing 14 characters", "Pressing Ctrl+S"), and the app it controls on a bright label. Typed text is never shown, only its length. ▾ opens its history: the last 50 steps with their time, model and whether each finished or failed. Stop is still on it. (#1099)
- **It stays on top without slowing the computer.** It stays above full-screen apps on the screen you are using and never takes the focus, so the controlled app stays in front. It lets clicks through only while the agent clicks, so it never blocks the agent. It uses no mouse hook and no animation: measured at 0.02% CPU when idle.

### Browser accounts and Chrome sign-in
- **Chrome sign-in no longer fails with "EPERM, Permission denied … passkey-login\transfer-…".** Starting a second sign-in tried to delete the folder of the one still open, which held its Chrome profile. Old folders are now cleaned up only when nothing else is signing in, with retries while Chrome or a virus scan still holds them, and a cleanup problem no longer hides the real error. (#1094)
- **Signing in shows what it is waiting for.** After you press Continue, the app showed "Importing…" while it was really waiting for the dedicated Chrome window to close. It now says so, shows importing only once both have happened, and a failed step no longer leaves the buttons stuck. (#1095)
- **Account checks work when Coding Tools isn't the focused window.** Reading an account's sign-in details was treated like a change that needs the app in front, so a chat's approved check could fail. Read-only inspection now works in the background. Account changes, MCP setup and permissions keep their protections. (#1091)
- **Signed-in browser accounts connect to MCP automatically.** Each account's current session is checked in its own isolated profile. When a sign-in, setting or connection needs attention, the existing workspace connector setup runs for it, one account at a time, and only with the app in front. (#1089)

### Verification and limitations
- **Built and published without GitHub CI.** GitHub refused to run any workflow for this repository ("Actions has been disabled for this repository"). With your approval, the pull requests were merged as admin, the tests were run locally on the merged code, and the installer was built on this machine the way the release workflow builds it, then uploaded as a draft, read back, checksum-verified and published.
- Each pull request lists its own tests. Previews: the reply style was applied in the running app to all 144 replies on screen.
- Two tests that #1089 and #1095 broke while GitHub CI was not running are fixed (#1101); the first local build of this version stopped on them.
- Not checked in the installed app after updating.
- Includes all changes in 0.8.95 and agent instructions for releasing while GitHub Actions is blocked (#1090 and this release).

## 繁體中文

### 對話
- **回覆不再放在方框內。** 每個代理回覆過去都以有邊框的卡片顯示，看起來就像答案被放進方框裡。現在回覆會像你自己的訊息一樣，以一般文字顯示。回覆下方的資料全部保留：模型、狀態、所用時間、更改的檔案及活動行（步驟、失敗次數、LLM 時間、token）。失敗或卡住的回覆仍可從彩色狀態標籤看出。(#1092)
- **「我會留意它」現在真的會繼續對話。** 對話過去可能說正在監看某個指令並承諾下一步，然後就停止。Codex、Claude Code 及 OpenCode 對話新增 `watch_command`、`list_command_watches` 及 `cancel_command_watch`。監看會跟隨對話已啟動的指令；指令完成、失敗或監看到期時，對話會以相同的模型、帳戶及權限真正開始下一個回合。停止、暫停、較新的回合及封存都會取消監看。(#1093)

### 電腦操作
- **對話操作應用程式時，畫面頂部會有一個小標籤顯示它正在做甚麼。** 標籤會顯示代理及其使用的模型、目前的步驟（「按下“儲存”」、「輸入 14 個字元」、「按 Ctrl+S」），以及以醒目標籤顯示的受控應用程式。輸入的文字不會顯示，只顯示字元數。按 ▾ 可查看紀錄：最近 50 個步驟的時間、模型，以及每步是否完成或失敗。標籤上仍有「停止」按鈕。(#1099)
- **它一直保持在最上層，卻不會拖慢電腦。** 它會顯示在你正在使用的螢幕上，位於全螢幕應用程式之上，而且不會奪取焦點，受控的應用程式會保持在前景。它只在代理點擊時讓點擊穿透，因此不會擋住代理。它不使用滑鼠掛鉤，也沒有動畫：閒置時量得 CPU 使用率為 0.02%。

### 瀏覽器帳戶及 Chrome 登入
- **Chrome 登入不再出現「EPERM, Permission denied … passkey-login\transfer-…」錯誤。** 開始第二個登入時，會嘗試刪除仍在進行的登入所用的資料夾，而該資料夾存放著它的 Chrome 設定檔。現在只會在沒有其他登入進行時清理舊資料夾，並在 Chrome 或防毒掃描仍佔用時重試；清理問題也不會再掩蓋真正的錯誤。(#1094)
- **登入時會顯示正在等待甚麼。** 按「繼續」後，應用程式過去顯示「匯入中…」，其實是在等待專用 Chrome 視窗關閉。現在會如實顯示，兩者都完成後才顯示匯入中，失敗的步驟也不會再令按鈕卡住。(#1095)
- **Coding Tools 不在前景時，帳戶檢查仍可運作。** 讀取帳戶登入資料過去被當作需要應用程式在前景的更改，令對話已獲批准的檢查失敗。現在唯讀檢查可在背景進行；帳戶更改、MCP 設定及權限保持原有保護。(#1091)
- **已登入的瀏覽器帳戶會自動連接 MCP。** 每個帳戶目前的登入狀態會在其獨立設定檔中檢查；當登入、設定或連線需要處理時，會逐一為帳戶執行現有的工作區連接器設定，而且只在應用程式位於前景時進行。(#1089)

### 驗證及限制
- **此版本在沒有 GitHub CI 的情況下建置及發佈。** GitHub 拒絕為此儲存庫執行任何工作流程（「Actions has been disabled for this repository」）。經你批准後，各拉取請求以管理員身分合併，在合併後的程式碼上於本機執行測試，並按發佈工作流程的方式在本機建置安裝程式，再以草稿上載、下載核對、驗證校驗碼後發佈。
- 各拉取請求列出其各自的測試。預覽：在執行中的應用程式中，把新回覆樣式套用到畫面上全部 144 個回覆。
- 修正了 #1089 及 #1095 在 GitHub CI 未執行期間弄壞的兩項測試（#1101）；此版本第一次本機建置因它們而停止。
- 更新後未在已安裝的應用程式中確認。
- 包含 0.8.95 的所有內容，以及在 GitHub Actions 被封鎖時發佈版本的代理指示（#1090 及此版本）。
