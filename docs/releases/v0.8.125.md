# Coding Tools v0.8.125

## English

### Permissions

- **The permission chip now says when Approve for me is paused.** Since 0.8.122, the app's reviews for Approve for me only run once **Allow quota-based reviews** is on in Settings > Chat. While it was off, every request waited for you, yet the chip still said "Active now", so Auto Review looked like it had turned itself off. Now, when the app reviews an agent's requests (Claude Code under Approve for me, or a running agent that asks the app), the chip turns amber and its tooltip says "Approve for me is paused" and how to turn it back on. The chip follows the switch as soon as you change it in Settings. Codex's own auto-review doesn't depend on that switch and isn't marked paused.

### Agent Orchestrator

Agent Orchestrator is pinned at 3fe7cbdf0 (AO#49, AO#51 and AO#50, on top of 0.8.124's db4fa47cf).

- **Stopping a chat's agent no longer fails at random while the agent is already stopping (AO#49).** On Windows, Agent Orchestrator and the chat's background host could touch the host's status file at the same moment. The stop was then reported as failed, or timed out after 5 seconds, although the host was exiting. Ending an agent, cleaning up ended chats and replacing a stuck host could all show this.
- **A chat no longer fails to start once with "ownership is inconclusive" for the same reason (AO#49).** Starting a chat while its old host was exiting could read the status file at that moment.
- **Closing a terminal session can no longer end an unrelated program (AO#51).** After a restart of the computer, the process ID of a terminal's old background host often belongs to a different program. Agent Orchestrator only checked that the ID was in use, so closing that session could force that program to quit. It now also checks when the process started.
- **Reviewer chats are no longer shut down every time Agent Orchestrator starts (AO#51).** They were restored at startup and then stopped a moment later by the startup cleanup, which did not recognise them.
- **Restoring reviewer chats no longer delays startup (AO#51).** It ran before Agent Orchestrator accepted connections, one reviewer after another, with no time limit. It now runs afterwards, with a limit of 2 minutes per reviewer.
- **A damaged `running.json` no longer stops Agent Orchestrator from starting (AO#51).** A power loss could leave that file empty or cut short, and every start then failed until the file was deleted by hand.
- **The disk no longer stays busy for a long stretch after Coding Tools starts (AO#50).** A cleanup job deletes old streaming text from the agents' event log. To find which rows to delete, it read saved events in full: after every start, every event from the very first one, which on a large history took over 17 minutes of disk reads; then, every 15 minutes, the events of the last day. It now finds those rows in a small index and opens no saved event. The first start after this update builds the index once; that reads only the start of each saved event.

## 繁體中文

### 權限

- **權限晶片現在會顯示「替我核准」已暫停。** 自 0.8.122 起，只有在「設定 > 聊天」中開啟 **允許使用配額的審查** 後，應用程式才會為「替我核准」執行審查。關閉時，每個要求都會等待你處理，但晶片仍顯示「立即生效」，看起來就像自動審查（Auto Review）自行關閉了。現在，當應用程式負責審查代理程式的要求時（「替我核准」下的 Claude Code，或會向應用程式詢問的執行中代理程式），晶片會變成琥珀色，提示文字會顯示「替我核准已暫停」以及如何重新開啟。在設定中變更此開關後，晶片會立即更新。Codex 內建的自動審查不受此開關影響，不會標示為暫停。

### Agent Orchestrator

Agent Orchestrator 固定在 3fe7cbdf0（AO#49、AO#51 和 AO#50，建立在 0.8.124 的 db4fa47cf 之上）。

- **停止對話的代理程式時，不會再因為代理程式正在結束而隨機失敗（AO#49）。** 在 Windows 上，Agent Orchestrator 和對話的背景主機可能同時存取主機的狀態檔。這時即使主機正在結束，停止動作仍會被回報為失敗，或在 5 秒後逾時。結束代理程式、清理已結束的對話、替換卡住的主機都可能出現這個問題。
- **對話不會再因為相同原因，在啟動時出現一次「ownership is inconclusive」而失敗（AO#49）。** 在舊主機結束的同時啟動對話，可能剛好在那一刻讀取狀態檔。
- **關閉終端機工作階段時，不會再結束不相關的程式（AO#51）。** 電腦重新開機後，終端機舊背景主機的處理程序 ID 經常已分配給其他程式。Agent Orchestrator 以前只檢查該 ID 是否在使用中，因此關閉該工作階段時可能會強制結束那個程式。現在也會檢查處理程序的啟動時間。
- **審查者對話不會再於每次 Agent Orchestrator 啟動時被關閉（AO#51）。** 以前它們在啟動時被復原，隨即又被啟動時的清理程序停止，因為清理程序無法辨識它們。
- **復原審查者對話不會再拖慢啟動（AO#51）。** 以前這項工作在 Agent Orchestrator 接受連線之前執行，一個接一個，而且沒有時間限制。現在改為之後執行，每個審查者最多 2 分鐘。
- **損毀的 `running.json` 不會再讓 Agent Orchestrator 無法啟動（AO#51）。** 斷電可能讓該檔案變成空白或不完整，之後每次啟動都會失敗，直到手動刪除檔案為止。
- **Coding Tools 啟動後，硬碟不會再長時間忙碌（AO#50）。** 有一個清理工作會從代理程式的事件紀錄中刪除舊的串流文字。為了找出要刪除哪些資料列，它會完整讀取已儲存的事件：每次啟動後從第一筆開始讀取所有事件，歷史紀錄很大時要讀取硬碟超過 17 分鐘；之後每 15 分鐘再讀取最近一天的事件。現在它改從一個小型索引找出這些資料列，不再開啟任何已儲存的事件。更新後第一次啟動會建立一次索引，只讀取每筆已儲存事件的開頭。
