# Coding Tools v0.8.121

## English

### CPA

- **Auth Files cards show rolling usage while a Codex limit reset is unconfirmed.** A Codex card's 5-hour and weekly lines count from the account's confirmed limit resets. Until a reset is confirmed (no quota window cached yet, or the last one has just ended), the line used to say only "Pending reset", even when the app already had the account's usage.
  - The line now shows the rolling usage under its own label, "Last 5 h" or "Last 7 days", with a "Rolling history" tooltip, so rolling totals are never presented as since-reset ones.
  - A confirmed reset still takes priority. "Pending reset" stays when there is no rolling history either.
- **Provider Manager 0.7.1: a Codex fallback account in Auto Review can use the Default route (#1304).** It then reviews on `codex-auto-review`, as the first account does, so you pick no model for it.
  - Both Auto Review pages offer "Default route (codex-auto-review)" or "Another model…" for a Codex account. A new Codex fallback starts on the default route, and a saved model stays as it is.
  - Accounts of other providers still need a model they serve.
- **Reviews are not free.** A before/after test sent 300 reviews through CPA: one Team account's 5-hour window went from 7% to 10%. That is about 100 small reviews per 1% of a 5-hour window.

### Verification

- Card usage: two new tests cover the labelled rolling fallback and a confirmed reset taking priority (including expiry and a page reload). All 39 tests in the three files that load the CPA panel script pass.
- #1304 bundles Provider Manager v0.7.1 (p90-lover/cpa_provider_manager#13, built from c7cab20; SHA-256 b0fdcf13… matches GitHub's digest). Provider Manager's `build.cmd test` passes (65 node tests and every Go package), and the 9 test files here that touch the bundled plugin pass (128 tests).
- Release identity checks validate the matching product, package and packaging versions. Required CI and package verification run through the GitHub release process.
- Packaging and publication use GitHub Actions. Neither change was checked in the running app, and this release does not install, patch or restart an already running app.

## 繁體中文

### CPA

- **Codex 額度重設尚未確認時，Auth Files 卡片改為顯示滾動用量。**Codex 卡片的「5 小時」與「每週」兩行，從帳號已確認的額度重設時間開始計算。在重設確認之前（尚未取得額度時間窗，或上一個時間窗剛結束），該行過去只顯示「Pending reset」，即使應用程式已有該帳號的用量。
  - 現在該行會以本身的標籤「Last 5 h」或「Last 7 days」顯示滾動用量，並附「Rolling history」提示，因此滾動總計不會被當成自重設以來的用量。
  - 已確認的重設仍然優先；若連滾動紀錄也沒有，仍顯示「Pending reset」。
- **Provider Manager 0.7.1：Auto Review 的 Codex 備援帳號可使用「預設路由」（#1304）。**它會和第一個帳號一樣以 `codex-auto-review` 審查，不必再挑選模型。
  - 兩個 Auto Review 頁面都為 Codex 帳號提供「Default route (codex-auto-review)」或「Another model…」。新增的 Codex 備援預設使用預設路由；已儲存的模型維持不變。
  - 其他供應商的帳號仍須指定其可用的模型。
- **審查並非免費。**實測透過 CPA 送出 300 次審查：一個 Team 帳號的 5 小時額度由 7% 升至 10%，約每 100 次小型審查消耗 1%。

### 驗證

- 卡片用量：新增兩項測試，涵蓋帶標籤的滾動用量備援，以及已確認的重設優先（含時間窗到期與重新載入頁面）。載入 CPA 面板腳本的三個測試檔共 39 項測試全部通過。
- #1304 內含 Provider Manager v0.7.1（p90-lover/cpa_provider_manager#13，由 c7cab20 建置；SHA-256 b0fdcf13… 與 GitHub 摘要一致）。Provider Manager 的 `build.cmd test` 通過（65 項 node 測試及所有 Go 套件），本專案中涉及內含外掛的 9 個測試檔亦通過（128 項測試）。
- 發行識別測試確認產品、套件及封裝版本一致；必要的 CI 與封裝檢查由 GitHub 發行流程執行。
- 透過 GitHub Actions 封裝並發佈。兩項變更皆未在執行中的應用程式內實測；本次發行不會直接安裝、修改或重新啟動正在執行的應用程式。
