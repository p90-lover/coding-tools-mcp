# Coding Tools 0.8.118

## English

### Freezes (#1299)
- **Less disk thrashing from the chat service (#1299).** Agent Orchestrator's cleanup of old streaming chunks no longer rereads its whole database every 15 minutes.
  - On 2026-11-13 it read 297 GB in about twelve hours from a 3.9 GB database, and kept a hard disk fully busy.
  - That busy disk caused chats that failed to resume after about three minutes, timeouts across the app (conversation pages, agent commands, CPA quota and usage), and update downloads that stalled.
  - Each cleanup pass now continues where the last one stopped, reads only the rows old enough to remove, and skips everything already cleaned. After the first pass following a start, it reads only the last day's rows.


### Updates (#1299)
- **An update no longer fails because a file of an earlier, abandoned update is still in use (#1299).** On 2026-11-14 a retried update to 0.8.117 stopped with "EPERM: operation not permitted, unlink ...ao-daemon.exe": the earlier attempt's copy was still open, most likely in an antivirus scan. The update now stages without it, leaves that folder for the next update, and records it in the Activity log.

### Verification and limitations
- Checks for each PR:
  - #1299: Agent Orchestrator is pinned at b19bae7ef (p90-lover/agent-orchestrator#40).
    - `go test ./internal/cdc/` passes, with two new sweep tests.
    - The store's provider-event tests pass, with a new id-range test on real SQLite.
    - `go vet` of both packages is clean.
    - The cause was measured with Agent Orchestrator's CPU profiler, not inferred.
    - The update fix: a new app-update test fails on the old code with the same EPERM and passes with the fix; tests/app-update.test.cjs passes 52/52.
  - #1298 (no visible change) restored two lines in the bundled CPA plugins' change list, so the full desktop suite on `main` passes again.
- Not checked in the running app.
- Built on GitHub from the merged `main` after the full desktop suite and both typechecks.
- Includes everything in 0.8.117.

## 繁體中文

### 卡頓（#1299）
- **聊天服務不再大量讀取硬碟（#1299）。** Agent Orchestrator 清理舊串流片段時，不再每 15 分鐘重讀整個資料庫。
  - 2026-11-13 它在約十二小時內從 3.9 GB 的資料庫讀取了 297 GB，使硬碟持續滿載。
  - 硬碟滿載造成：聊天約三分鐘後仍無法恢復、整個 App 逾時（對話頁面、代理程式指令、CPA 額度與用量），以及更新下載停滯。
  - 每次清理現在會從上次停止處繼續，只讀取夠舊、可刪除的資料列，並略過已清理的部分。啟動後第一次清理完成之後，只會讀取最近一天的資料列。


### 更新（#1299）
- **先前中斷的更新若仍有檔案被占用，不再導致更新失敗（#1299）。** 2026-11-14 重試更新至 0.8.117 時，因「EPERM: operation not permitted, unlink ...ao-daemon.exe」而中止：上一次嘗試留下的副本仍被開啟（很可能是防毒軟體正在掃描）。現在更新會略過該資料夾照常準備，留待下次更新再清除，並記錄在活動記錄中。
