# Coding Tools 0.8.112

## English

### Agent Orchestrator (#1227, agent-orchestrator#31)
- **A busy chat no longer makes AO rescan its usage history nonstop.** After every chunk of a busy chat's usage, AO asked for a full repair pass over its usage records: a scan of the whole table plus a re-read of every routed transcript, many times a minute. On a 3.4 GB database that read about 310 MB a minute and held AO's only database writer about once a minute. Those requests now share one pass at most every 2 minutes. A new pricing catalog or a hook that names a route still repairs at once.
- **AO's own failures are recorded in the activity log.** When Agent Orchestrator answered "Internal server error", the cause was only in its output, which nothing kept in view. Failed requests, warnings and errors are now logged with their cause, the same one at most once a minute.

### Smaller fixes (#1228, #1229, #1230)
- **Memory warnings say which window they are about.** A "Tab" memory warning named only a process id, and placing it took several probes. It now names the window or page that process hosts, such as the main window, with the page's origin only: never a path, title or account.
- **App start no longer reads Nova's saved settings.** Every start read ProxyBridge Nova's settings file on the main thread, although nothing uses Nova unless you do. On a busy disk that froze the window for 377 ms right after the 0.8.111 update. The file is now read the first time Nova is used.
- **Restart Codex stays up until it is done.** The notice switched on and off 35 times in one night: the Codex app kept fetching its model list around the bridge, and the app's own Codex (the same version) fetched it through the bridge in between, which cleared the notice each time. It now clears only once a list fetched 45 minutes after the last one that went around the bridge lists the Web GPT models, from any Codex version. If you see it, quit the Codex app fully and open it again.

### Verification and limitations
- These four changes and the AO update were tested together on main 3e9f4a070 plus all four: 4,711 of 4,731 desktop tests passed, 0 failed, 20 skipped; the renderer typecheck passed.
- Not included, and still waiting: #1231 (a chat start that fails for a passing reason is retried after 5 and 20 seconds), agent-orchestrator#32 (AO checks a refused sign-in again before refusing a start), #1214 with agent-orchestrator#29 (AO's start on a large leftover write-ahead log), and the drafts #1199 and #1213.
- Everything in 0.8.111 is included.

## 繁體中文

### Agent Orchestrator（#1227、agent-orchestrator#31）
- **忙碌的對話不再讓 AO 不停重新掃描用量記錄。**忙碌對話的每一段用量寫入後，AO 都會要求對用量記錄做一次完整修復：掃描整個資料表，並重新讀取每一份已路由的對話記錄，一分鐘內多次。在 3.4 GB 的資料庫上，這每分鐘讀取約 310 MB，並約每分鐘佔用一次 AO 唯一的資料庫寫入者。現在這些要求最多每 2 分鐘共用一次修復。新的計價目錄或指明路由的掛鉤仍會立即修復。
- **AO 本身的失敗會記錄在活動記錄中。**Agent Orchestrator 回覆「Internal server error」時，原因只存在於它自己的輸出，沒有任何地方保留。現在失敗的請求、警告與錯誤都會連同原因記錄下來，相同的項目每分鐘最多記錄一次。

### 其他修正（#1228、#1229、#1230）
- **記憶體警告會說明是哪個視窗。**「Tab」記憶體警告原本只列出處理程序編號，要經過多次查詢才能找出是哪個視窗。現在會列出該處理程序所顯示的視窗或頁面（例如主視窗），只附頁面的來源，不含路徑、標題或帳號。
- **程式啟動時不再讀取 Nova 的設定。**每次啟動都會在主執行緒讀取 ProxyBridge Nova 的設定檔，但除非你使用 Nova，否則沒有任何功能需要它。在忙碌的磁碟上，這在 0.8.111 更新後讓視窗凍結了 377 毫秒。現在會在第一次使用 Nova 時才讀取。
- **「重新啟動 Codex」提示會持續顯示到問題解決。**這個提示在一個晚上開關了 35 次：Codex 應用程式一直繞過橋接取得模型清單，而本程式自己的 Codex（同一版本）在其間經由橋接取得清單，每次都清除了提示。現在只有在最後一次繞過橋接的清單之後 45 分鐘取得、且列出 Web GPT 模型的清單出現時才會清除，不論是哪個 Codex 版本。如果看到這個提示，請完全結束 Codex 應用程式後再開啟。

### 驗證與限制
- 這四項變更與 AO 更新在 main 3e9f4a070 加上全部四項後一起測試：4,731 項桌面測試中 4,711 項通過、0 項失敗、20 項略過；renderer 型別檢查通過。
- 未包含、仍在等待：#1231（因暫時性原因無法啟動的對話會在 5 秒與 20 秒後重試）、agent-orchestrator#32（AO 拒絕啟動前會再次確認被拒的登入）、#1214 與 agent-orchestrator#29（AO 在大型殘留預寫記錄上的啟動），以及草稿 #1199 與 #1213。
- 包含 0.8.111 的所有內容。
