# v0.4.4-rc.3 — Integration reliability and result contracts

## English

Preserves v0.4.4-rc.2's OAuth repair, timeout receipts, 71-tool catalogue, local permissions and optional AppContainer snapshot executor. This increment repairs existing integration paths; it does not claim complete official Codex tool parity or complete autonomous Paseo/Anneal engines.

Paseo/Anneal views now bind asynchronous reads to a per-source generation and the selected endpoint. Clearing a view, editing an endpoint, changing away and back, or starting a newer read prevents older success/error/finally callbacks from restoring stale data or changing the new request's busy state. A new refresh clears the previous snapshot so a failed refresh cannot leave a green connection indicator. Returned source, endpoint and read-only flag must match. Clear view is available during a pending read; it discards the UI result, not the external request or agent. Backend loopback-only validation, two-request capacity, time limits and read-only protocol messages remain unchanged. Tokens are not persisted. The actual compiled page is checked with synthetic desktop IPC, and the Rust adapters are separately checked against loopback fixture servers; no real external agent is started.

Sandbox input preparation now validates and reads the complete selected input set before allocating a retained run directory. Traversal, missing/directory inputs, reserved credentials, canonical duplicate paths and oversized input sets cannot consume the 32-run retention budget. The original 64-file/16 MiB input cap and path checks remain. Input data is copied from the validated buffers, not reopened after validation. Valid runs still count toward the 32-run limit. Destination I/O failures or failures after input preparation may still retain a run as evidence; existing failed runs are not removed. No automatic archive, deletion, host fallback, network grant or project-file write is introduced. This does not certify the absence of every same-user filesystem race.

Adds an explicit outputSchema to list_task_events describing real event pages, nullable event fields, next_cursor and shared structured errors. Additional bounded project_instructions remain allowed. Real dispatcher output for populated, subsequent, empty and invalid calls is schema-validated. The existing mcp_operation_status output schema is preserved. Other tools without outputSchema are not falsely marked as finished; clients need to refresh stored tool metadata before seeing this addition.

codex_tools_status now includes sandbox_status, sandbox_exec and mcp_operation_status when the current tool profile exposes them. It also distinguishes sandbox_exec's opt-in snapshot boundary from ordinary policy-only commands. Discovery is not proof of local consent, helper availability on the user's machine, native isolation acceptance, or provider execution. No new tool names or provider/model sessions are added.

Verification uses the reproduced failures and three focused areas: asynchronous integration state plus rendered UI, snapshot preparation, and real event-result/capability contracts. Existing timeout-recovery, OAuth/extension 0.0.7, read-only adapter, native AppContainer and permission checks are retained. The exact Windows installer is extracted and compared with the compiled source executable, and its uploaded bytes are downloaded and hashed before publication. The source commit, main and tag must agree. Test inputs/IPC are explicitly synthetic; actual Rust dispatcher/native helper and compiled UI code execute. No Codex executable, model inference, real ChatGPT account, game or native computer input is invoked.

Windows x64 unsigned prerelease. Keep existing OAuth settings and extension v0.0.7. Resolve unknown in-flight operations before closing Desktop to upgrade because rc.2 receipts are memory-only. Restart after installation and refresh tool metadata. A changed embedded-helper identity requires deliberate local reapproval, not automatic permission migration. Existing files/releases remain; temporary files and replaced local originals are retained under aiTemp/Trash. No live acceptance on the user's PC is claimed.

## 繁體中文

保留 v0.4.4-rc.2 的 OAuth 修正、逾時操作紀錄、71 個工具目錄、本機權限及需主動同意的 AppContainer 快照執行器。本次改善既有整合流程，不會宣稱完整官方 Codex 工具對等，或完整 Paseo／Anneal 自主引擎已完成。

Paseo／Anneal 畫面的非同步讀取，現在綁定來源各自的請求世代及指定端點。清除顯示、修改端點、切換後再切回或發起新讀取後，舊成功／錯誤／finally 回呼不能恢復過時資料，也不能改變新請求的忙碌狀態。重新讀取時先移除舊狀態，避免失敗後仍顯示綠色連線。回傳來源、端點及唯讀旗標必須相符。等待期間可使用清除顯示；它只丟棄畫面結果，不會取消外部請求或停止 Agent。後端僅限 loopback、兩個並行名額、逾時及唯讀協定訊息均不變，Token 不會持久儲存。真正編譯頁面使用模擬 Desktop IPC 驗證；Rust 介接器另外使用本機測試伺服器驗證，不啟動真實外部 Agent。

沙箱會先驗證並讀取全部指定輸入，再建立保留執行目錄。向上跳出、檔案不存在、資料夾、保留憑證名稱、正式路徑重複及過大輸入，不會消耗 32 次保留名額。保留 64 個檔案／16 MiB 及路徑限制；副本來自已驗證的緩衝區，不會驗證後重新開啟來源。有效執行仍計入 32 次上限。目的地 I/O 或輸入準備後的失敗，仍可能保留紀錄作證據，亦不會移除舊失敗目錄。沒有加入自動封存、刪除、宿主 fallback、網路授權或原專案寫入，也不代表所有同使用者檔案競爭條件均已排除。

為 list_task_events 新增明確 outputSchema，描述真正事件分頁、可為 null 的欄位、next_cursor 及共用結構化錯誤，並允許既有有界 project_instructions。使用真正分派器的有內容、後續、空白及無效請求結果驗證 schema。保留 mcp_operation_status 原有 schema，不會把其他仍未提供 outputSchema 的工具冒稱為完成；用戶端須更新儲存的工具 metadata 才會看到新增內容。

codex_tools_status 會依當前工具設定檔，列出已公開的 sandbox_status、sandbox_exec 及 mcp_operation_status，並區分快照沙箱與一般僅策略限制的命令。能力顯示不代表使用者電腦已有本機同意、helper 可用、原生隔離驗收或供應商執行；沒有增加新的工具名稱或模型／供應商會話。

驗證先重現失敗，再集中檢查三個範圍：非同步整合狀態與真正畫面、快照輸入準備，以及真正事件結果／能力契約。保留逾時恢復、OAuth／擴充功能 0.0.7、唯讀介接器、原生 AppContainer 及權限驗證。實際 Windows installer 會解封並與原編譯執行檔比較，上傳後亦重新下載及校驗；原始碼 commit、main 及 tag 必須一致。輸入／IPC 明確使用模擬，但執行真正 Rust 分派器、原生 helper 及編譯 UI。沒有執行 Codex 執行檔、模型推論、真實 ChatGPT 帳戶、遊戲或原生電腦輸入。

提供 Windows x64 未簽章預發佈版，保留原有 OAuth 設定及擴充功能 v0.0.7。rc.2 操作紀錄只存在記憶體，因此升級關閉 Desktop 前先確認結果未知的執行。安裝後重新啟動並更新工具 metadata；若內嵌 helper 識別值改變，必須再次由本機明確授權，不會自動移轉批准。保留舊檔案及 Release；暫存及被取代原件放於 aiTemp／Trash，未宣稱已在使用者電腦完成真實驗收。
