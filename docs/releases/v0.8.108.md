# Coding Tools 0.8.108

## English

### Browser: Connect MCP works while the background connector setup is running (#1162)
- **Connect for all accounts could fail on every account at once.** On 2026-11-09 it was refused for all 22 accounts within 8 seconds, each with "Finish the active browser or setup operation before creating the connector."
  - The app's own background setup, which connects accounts automatically, was holding the browser. Your Connect neither waited for it nor asked it to stop, and the page went on to try every remaining account the same way.
- **Your Connect now goes first.** The background setup steps aside at its next step and tries that account again later; this is not counted as a failure.
  - Your Connect waits up to a minute for whatever is using the browser, such as a page's account check. A running Codex turn is not waited for.
- **If the browser is still busy, Connect for all accounts stops** and says so ("stopped: the browser is busy with another operation"), instead of marking each remaining account as failed. Accounts it didn't try keep their state.
- Account cards no longer show Electron's "Error invoking remote method…" prefix on an error.

### Chats: agent tool calls no longer freeze the window while their paths are checked (#1160)
- **Each agent tool call with a file path checks that the path stays inside the chat's worktree.** That check read the disk on the app's main thread, and on the busy hard disk one call held every window for 0.4 s (2026-11-09).
- The check now runs off the main thread. What it allows is unchanged:
  - links are followed to their real target;
  - a link that points nowhere is refused;
  - a path that doesn't exist yet is checked through its deepest existing folder.

### Chats: page tabs float as a glass dock under your chats (#1161)
- **The page numbers (1 2 3 … +) move from the title bar to the bottom of the chat column, centred under your chats.** They sit in a frosted, see-through glass pill: light glass over the light chat, smoked glass beside a dark one.
  - A liquid bubble sits behind the open page's number. Turning a page stretches it across to the new number, then springs it into place.
  - Pointing at the dock lifts it a little and sends one gleam across it. The numbers lift when pointed at and shrink when pressed, and + turns a quarter.
  - Nothing moves on its own. With Windows' "Animation effects" off, the bubble just jumps.
- **The chat column keeps a slim strip at the bottom for the dock, so it never covers a message box,** with one chat or ten split chats. The title bar is a plain drag area again.

### Performance: the window no longer freezes for seconds because another app reads the screen (#1166)
- **Coding Tools froze for 2–4 seconds about 7 times an hour while chats were in use** (2026-11-09). In each freeze the app's main thread was busy inside Chromium itself, with none of the app's own code running.
  - The cause was Chromium's accessibility tree. Any app that reads the screen through Windows UI Automation (screen tools, overlays, automation tools, even this app's computer use) turns it on in every Chromium app, and it stays on until the app quits. Every change in a chat then became accessibility work on the main thread, although no screen reader was running.
- **It is now on only while a screen reader runs.** Coding Tools starts with it blocked. When Windows says a screen reader is running (NVDA, JAWS and Narrator say so), it turns on at once, also for a screen reader started later, and off again when the screen reader quits.
- **Settings › General › Accessibility › Screen reader support:** Automatic (the default), Always on, or Off. Always on brings back the old behaviour for every app that reads Coding Tools' window; leaving it takes effect after a restart, which the row says.
- Computer use's inspect of Coding Tools' own window now sees only the window frame unless Screen reader support is Always on.

## 繁體中文

### 瀏覽器：背景連接器設定執行時也能「連接 MCP」（#1162）
- **「連接所有帳戶」可能讓每個帳戶同時失敗。** 2026-11-09 時，22 個帳戶在 8 秒內全部被拒，每個都顯示「Finish the active browser or setup operation before creating the connector.」
  - 原因是應用程式自動連接帳戶的背景設定正佔用瀏覽器。你的連接既不等待它，也不要求它停止，頁面還會以同樣方式繼續嘗試其餘每個帳戶。
- **現在你的連接優先。** 背景設定會在下一步讓開，稍後再為該帳戶重試，這不算失敗。
  - 你的連接最多等待一分鐘，讓正在使用瀏覽器的作業（例如頁面的帳戶檢查）結束。不會等待正在執行的 Codex 回合。
- **若瀏覽器仍然忙碌，「連接所有帳戶」會停下並說明原因**（「stopped: the browser is busy with another operation」），而不是把其餘每個帳戶都標為失敗。未嘗試的帳戶維持原狀。
- 帳戶卡片上的錯誤不再帶有 Electron 的「Error invoking remote method…」前綴。

### 對話：檢查代理工具呼叫的路徑時不再凍結視窗（#1160）
- **每個帶有檔案路徑的代理工具呼叫，都會檢查路徑是否仍在對話的工作樹內。** 這項檢查原本在應用程式主執行緒上讀取磁碟；在忙碌的硬碟上，一次呼叫曾讓所有視窗停住 0.4 秒（2026-11-09）。
- 這項檢查現在在主執行緒之外執行。允許的範圍不變：
  - 連結會追到實際目標；
  - 指向不存在之處的連結會被拒絕；
  - 尚不存在的路徑，會以其最深的現有資料夾檢查。

### 對話：頁籤改為浮在對話下方的玻璃列（#1161）
- **頁碼（1 2 3 … +）從標題列移到對話欄底部，置中於對話下方。** 頁碼放在一個磨砂、半透明的玻璃膠囊中：淺色對話上是淺色玻璃，深色對話旁是煙燻玻璃。
  - 目前頁碼後方有一顆液態氣泡。換頁時，它會伸展到新的頁碼，再彈回定位。
  - 指標移到玻璃列上時，它會微微升起，並有一道光掃過。頁碼在指向時會升起、按下時會縮小，+ 會轉四分之一圈。
  - 沒有任何東西會自行持續動作。若關閉 Windows 的「動畫效果」，氣泡會直接跳到新位置。
- **對話欄底部保留一條窄帶給玻璃列，因此它不會遮住訊息框，** 無論是單一對話或十個分割對話。標題列恢復為單純的拖曳區域。

### 效能：不再因其他程式讀取螢幕而凍結數秒（#1166）
- **使用對話時，Coding Tools 每小時約凍結 7 次，每次 2–4 秒**（2026-11-09）。每次凍結時，應用程式的主執行緒都忙於 Chromium 本身，沒有執行任何應用程式自己的程式碼。
  - 原因是 Chromium 的無障礙樹。任何透過 Windows UI Automation 讀取螢幕的程式（螢幕工具、疊加層、自動化工具，甚至本程式的電腦操作）都會在所有 Chromium 程式中開啟它，並一直開著直到程式結束。之後對話中的每個變更都會在主執行緒上產生無障礙工作，即使並沒有執行螢幕閱讀器。
- **現在只有在螢幕閱讀器執行時才會開啟。** Coding Tools 啟動時會先封鎖它。當 Windows 表示有螢幕閱讀器正在執行（NVDA、JAWS 與 Narrator 都會告知），它會立即開啟，之後才啟動的螢幕閱讀器也一樣；螢幕閱讀器結束時會再關閉。
- **Settings › General › Accessibility › Screen reader support：** Automatic（預設）、Always on 或 Off。Always on 會恢復舊行為，讓所有讀取 Coding Tools 視窗的程式都能讀取；從 Always on 改回要在重新啟動後才生效，該列會說明。
- 除非 Screen reader support 設為 Always on，電腦操作的 inspect 對 Coding Tools 自己的視窗只會看到視窗框架。
