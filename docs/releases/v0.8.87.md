# Coding Tools 0.8.87

## English

### CPA
- **GPT chats through Claude Code no longer show "CPA refused the last 4 requests: HTTP 400" (#1063).** Claude Code checks a model with a tiny request asking for a 1-token answer. CPA passed that limit on to Codex accounts unchanged, and OpenAI refuses anything below 16 ("Invalid 'max_output_tokens': integer below minimum value"). Every check of a GPT model came back refused, even though the chat's real turns were answered. CPA now raises a limit of 1 to 15 tokens to 16 for Codex accounts; a real limit is left as it is.
- **The app's CPA settings now reach a CPA that has already saved its own copy.** CPA keeps its request rules in its own saved config, and that saved copy used to win over the app's, so a rule added in a newer version never arrived. The app's rules now go into the copy CPA reads; rules you added yourself stay.

### Verification and limitations
- Reproduced through the running CPA: a 1- or 15-token request was refused with HTTP 400, a 16-token one was answered. With the new rule all three are answered.
- New tests cover the rule and both config layouts CPA saves; all 131 CPA tests pass.
- Built and published by GitHub CI from main; no local build was made for this version.
- Includes all changes in 0.8.86.

## 繁體中文

### CPA
- **經 Claude Code 使用 GPT 模型的對話，不會再顯示「CPA refused the last 4 requests: HTTP 400」（#1063）。** Claude Code 會先以一個只要求 1 個 token 回應的小請求檢查模型。CPA 把這個上限原封不動交給 Codex 帳戶，而 OpenAI 拒絕任何低於 16 的值（「Invalid 'max_output_tokens': integer below minimum value」）。因此每次檢查 GPT 模型都被拒絕，即使對話本身的回合都有回應。現在 CPA 會把 Codex 帳戶 1 至 15 個 token 的上限提高到 16；真正的上限則保持不變。
- **應用程式的 CPA 設定，現在也會套用到已自行儲存設定的 CPA。** CPA 會把請求規則保存在自己的設定檔中，過去這份已儲存的設定會蓋過應用程式的設定，因此新版本加入的規則從未生效。現在應用程式的規則會寫入 CPA 實際讀取的那一份；你自己加入的規則會保留。

### 驗證及限制
- 已透過執行中的 CPA 重現：要求 1 或 15 個 token 的請求被以 HTTP 400 拒絕，要求 16 個 token 的請求則有回應。加入新規則後，三者均有回應。
- 新增的測試涵蓋此規則及 CPA 儲存的兩種設定格式；全部 131 項 CPA 測試均通過。
- 由 GitHub CI 從 main 建置及發佈；此版本沒有在本機建置。
- 包含 0.8.86 的所有內容。
