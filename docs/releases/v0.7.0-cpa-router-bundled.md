# CPA + Codex Router bundled runtimes

Coding Tools Desktop first Start for **CPA / CLIProxyAPI** and **Codex Router** uses runtimes shipped inside the Desktop package. Users do not download a separate CPA or Codex Router app, and the original `management.html` / Control Center UIs from #180 plus the 7-day keep-alive from #190 stay unchanged.

## Gates removed on first Start

| Gate | Before | After |
|---|---|---|
| CPA `download-release` from GitHub | `managed-components` fetched the v7.3.7 zip/tar | Copy `bundled-runtimes/cpa/{platform}/{arch}/` from extraResources / asarUnpack |
| Codex Router `git clone` / fetch pinned commit | First Start cloned `duolahypercho/codex-router` | Copy `bundled-runtimes/codex-router/source/` |
| Control Center `npm ci` + Vite build | Could hit the network when `dist/` was missing | Renderer is packaged; Start refuses to download npm packages |
| Control Center `electron/install.js` | Could download a second Electron | Uses Coding Tools Electron |

CommandCode Proxy, Paseo, and Anneal keep their existing managed installers (owned by other PRs).

## Package-time vs Start-time

Windows/Linux packaging still **may** fetch the pinned upstream artifacts **once** while building the installer (`scripts/prepare-bundled-runtimes.cjs`). That is CI/package work. The installed Desktop app then activates those files locally. Package-time Router extract leftovers stay in `aiTemp` scratch, not extraResources. The Windows package verifier skips third-party `.venv` / `node_modules` trees under the bundled Router source; first-party Router source still fails closed on secret-like material. Silent Windows installer smoke allows 15 minutes because the bundled CPA/Router payload is hundreds of megabytes.

`CODING_TOOLS_BUNDLED.json` inside the router source sets `skipNetworkPrepare: true` so `codex-router-managed` does not run `bin/install --prepare-only` / `install.ps1` (npm ci, pip, uv) at user Start.

## Cross-use inside Desktop

CPA (`127.0.0.1:8317`) and Codex Router (`127.0.0.1:4202`) are **bundled provider backends** for Desktop, MCP, and Paseo. They are not separately installed apps, and they are not the Paseo/Anneal orchestrators.

| Role | Owner | Local API |
|---|---|---|
| Paseo | other (#192 / Main seeker) | orchestrator: main provider + free subagents → plan → run → review |
| Anneal | other (#192 / Main seeker) | task/preview when review opens a new task |
| CPA | this PR | main provider backend `http://127.0.0.1:8317/v1` |
| Codex Router | this PR | subagent provider backend `http://127.0.0.1:4202/_codex-router/{callerKey}/v1` |

Start/desired-run of Codex Router starts bundled CPA first, injects `CODING_TOOLS_CPA_URL` / `CODING_TOOLS_CPA_OPENAI_BASE_URL` plus the managed `CODING_TOOLS_CPA_PROXY_API_KEY` into the Router process, and publishes both loopbacks on `runtimeEnvironment()`. Paseo and Anneal launches receive the same backend env so they can call these APIs; this PR does not implement Paseo plan/run/review or Anneal task/preview.

Desktop panels read the same contract from `snapshot.providerBackends` (health, chat, control, live inspect). MCP resolves both loopbacks with `describeProviderBackends()` / `resolveCpaConnection()` from the Desktop-injected env, without implementing Paseo plan/run/review.

- CPA health `GET /v1/models` with `Bearer {proxyApiKey}`; chat `POST /v1/chat/completions`; control `management.html`
- Router health `GET /_codex-router/{callerKey}/v1/models`; chat `POST /_codex-router/{callerKey}/v1/chat/completions`; control original Control Center
- CommandCode Proxy is not part of this pair
