# Coding Tools v0.8.161

## English

### Approve for me
- **Approve for me no longer times out when some Codex accounts are out of quota.** CPA's saved settings had its quota cooldown switched off, so every request, from chats and reviews alike, first tried each Codex account that had run out, got a 429 from each, and only then reached one with quota left. Coding Tools now keeps CPA's quota cooldown on: an account that hits its limit rests until it resets, and requests go straight to the accounts that still have quota.
- **Reviews no longer spend their time waiting in line.** Just before answering, the reviewer checks the chat is still running; that check now takes the same fast lane as Stop instead of queueing behind every open chat's updates. The model list comes from the last one read rather than waiting for CPA to list everything again. Seen on 2026-11-23: two of three review accounts were out of quota for 2.5 hours, those checks took 14-35 seconds each, and requests waited for you after "The review attempt timed out or its owner changed" three times in a row.
- **A reviewer that costs no quota.** Shell commands are now checked on your machine first, before Guardian or CPA are asked.
  - It allows a command whose every step reads, or creates, writes, copies, moves or renames files inside the project folder, as Claude Code's auto mode does.
  - When a command runs a PowerShell script, it reads that script and checks each of its steps the same way, including scripts that script runs (up to 3 levels deep).
  - It never allows deletes or starting programs. It never allows writes outside the project, or to `.git`, `.github`, `node_modules`, `AGENTS.md`, `CLAUDE.md` or `package.json`.
  - Anything it can't clear goes to Guardian and the model judge as before.
- **The model judge decides more sensibly, and says why.** When Guardian can't decide, the judge's approval now stands for low-risk commands, unless your authorization is rated low, and for medium-risk commands you clearly asked for, such as an app update your instructions request. It used to stand only for low risk with high authorization. A refusal now shows the judge's own reason instead of "did not confirm low risk and clear user authorization".

### Chats
- **A provider's refusal in a Claude Code chat now shows in its own words, and "Retry automatically" keeps requesting.** (AO#62) Claude Code reports every 403 from a provider as a sign-in failure. So when Google's Vertex refused some Gemini 4 Carbon requests behind CPA ("Access requires an eligible paid billing account in a supported region") and answered others, the chat stopped with "Authentication required", asked for a sign-in that could not help, and was never retried. Coding Tools now reads the error Claude Code recorded for that request. A real sign-in problem (a 401, or "run /login") works as before. Any other refusal is shown as the provider's own message ("API Error: 403 …"), raises no sign-in prompt, and "Retry automatically" retries it with its usual pauses.
- **The assistant can show a live Plan in the chat** with the goal, how to know it is done, and its current checklist. The Plan pane can open on request; progress updates need not reopen it. Viewing a plan does not approve work. Small tasks get direct guidance, longer tasks get a resumable handoff, and verification receipts can be found without rerunning commands.

### Context windows
- **Each agent is told its model's real context window.** CPA lists every model it has no limit for at the same 272K, including every model of an API key: an Anthropic key's Claude Opus 4.6 ran at 272K of its 200K and overflowed, while Claude Opus 5.5, Sonnet 5 and Gemini were held to 272K of their 1M. Those models now take their real limits: a known one from CPA's own model list, else the same model's limit on another provider.
- **A 1M window no longer overflows a model that takes 872K.** Picking 1M for GPT-6 or GPT-5.6 (CPA reports 872K) told the agent 1M, so it compacted too late and the provider refused the chat with "Your input exceeds the context window of this model". The window you pick is kept, but the agent is told at most what the model takes. A chat already running past its model's limit is fitted before its next message, keeping its conversation. A saved window above a model's limit now runs at the limit instead of stopping the chat.
- **The context meter is more accurate.** It no longer shows a "Next run window" for a window the agent already has, and for Codex it shows the window Codex actually uses (95% of the one it was given).
- **The context panel's "ready" count covers every CPA account.** The panel lists up to 12 accounts per provider, and its "X/Y ready", "All accounts at limit · first back in" and "+N" used to count only that list, so it could say "12/12 ready" while another account was failing. These counts now cover all of the provider's accounts in CPA, and "+N" includes the ones not listed.

### MCP
- **When an account's MCP check can't confirm its existing connector, the log now says which part didn't match.** Six different checks (the connector's card, its link, its page, ChatGPT's edit form, the saved name and the saved Tunnel ID) all ended with "Existing connector exact tunnel identity is unverified"; on 2026-11-23 a signed-in workspace owner's automatic check stopped there with nothing more to go on. The log line now names the check, for example "ownership check identity:tunnel-differs". What the account card shows is unchanged.

Includes all changes from v0.8.160.

## 繁體中文

### 代我核准
- **部分 Codex 帳號額度用完時，「代我核准」不再逾時。** CPA 已儲存的設定關閉了額度冷卻，因此每個請求（聊天與審查都一樣）都會先嘗試每個額度已用完的 Codex 帳號，逐一收到 429，之後才輪到仍有額度的帳號。Coding Tools 現在會保持 CPA 的額度冷卻開啟：達到上限的帳號會休息到重設為止，請求會直接送到仍有額度的帳號。
- **審查不再把時間花在排隊上。** 審查員在回覆前會確認聊天仍在執行；這項確認現在和「停止」走同一條快速通道，不再排在所有開啟中聊天的更新後面。模型清單改用上次讀到的清單，不再等 CPA 重新列出全部模型。2026-11-23 觀察到：三個審查帳號中有兩個額度用完達 2.5 小時，每次確認要 14 到 35 秒，請求在連續三次「The review attempt timed out or its owner changed」之後只能等你處理。
- **不耗用額度的審查。** Shell 指令現在會先在你的電腦上檢查，然後才交給 Guardian 或 CPA。
  - 若指令的每一步都只是讀取，或在專案資料夾內建立、寫入、複製、移動或重新命名檔案，就會直接放行，與 Claude Code 的 auto 模式相同。
  - 指令執行 PowerShell 腳本時，會讀取該腳本並以同樣方式檢查每一步，腳本再呼叫的腳本也會檢查（最多 3 層）。
  - 絕不放行刪除或啟動程式。絕不放行專案以外的寫入，也不放行寫入 `.git`、`.github`、`node_modules`、`AGENTS.md`、`CLAUDE.md` 或 `package.json`。
  - 無法確認的指令仍照舊交給 Guardian 與模型判斷。
- **模型判斷更合理，並說明原因。** Guardian 無法判斷時，模型判斷的核准現在在以下情況成立：低風險的指令，除非你的授權被評為低；以及你明確要求的中風險指令，例如你的指示要求的應用程式更新。以前只有「低風險且授權明確」才成立。拒絕時現在會顯示模型自己的理由，而不是「未確認低風險與明確的使用者授權」。

### 對話
- **Claude Code 對話中供應商的拒絕，現在以供應商自己的話顯示，「自動重試」也會繼續送出請求。**（AO#62）Claude Code 會把供應商回傳的任何 403 都當成登入失敗。所以當 Google 的 Vertex 拒絕了經由 CPA 送出的部分 Gemini 4 Carbon 請求（「Access requires an eligible paid billing account in a supported region」），其餘請求卻正常回覆時，對話就以「Authentication required」停下，要求一次無濟於事的登入，而且從未重試。Coding Tools 現在會讀取 Claude Code 為該請求記錄的錯誤。真正的登入問題（401，或「run /login」）照舊處理。其他拒絕則顯示供應商自己的訊息（「API Error: 403 …」），不會要求登入，「自動重試」也會以平常的間隔重試。
- **代理程式可在聊天中顯示即時 Plan**，列出目標、完成判準與工作清單。需要時可開啟 Plan 側邊面板，更新進度不必重新開啟。查看計畫不會核准工作。小任務可直接處理，較長任務保留可接續的交接紀錄；查找驗證紀錄不用重跑指令。

### 內容視窗
- **每個代理程式都會得知其模型真正的內容視窗大小。** CPA 對所有不知道上限的模型一律列為 272K，API 金鑰的每個模型也是如此：Anthropic 金鑰的 Claude Opus 4.6 以 272K 執行，超出其 200K 上限；而 Claude Opus 5.5、Sonnet 5 與 Gemini 則被限制在 272K，遠低於其 1M。這些模型現在會使用真正的上限：優先採用 CPA 自身模型清單中的已知上限，否則採用同一模型在其他供應商上的上限。
- **1M 視窗不再讓只能接受 872K 的模型溢出。** 為 GPT-6 或 GPT-5.6（CPA 回報 872K）選擇 1M 時，代理程式會被告知 1M，因此壓縮得太晚，供應商便以「Your input exceeds the context window of this model」拒絕該聊天。現在會保留你選擇的視窗，但告知代理程式的大小不會超過模型能接受的上限。已在超出模型上限下執行的聊天，會在下一則訊息前調整大小，並保留對話內容。儲存的視窗若高於模型上限，現在會以上限執行，而不是讓聊天停止。
- **內容用量表更準確。** 對代理程式已在使用的視窗，不再顯示「下次執行視窗」；Codex 則顯示其實際使用的視窗（為所給視窗的 95%）。
- **內容面板的「可用」計數涵蓋 CPA 的所有帳號。** 面板每個供應商最多列出 12 個帳號，過去「X/Y 可用」、「所有帳號都已達上限 · 最快恢復時間」與「+N」只計算這份清單，因此可能顯示「12/12 可用」，但另一個帳號其實正在失敗。現在這些計數涵蓋 CPA 中該供應商的所有帳號，「+N」也包含未列出的帳號。

### MCP
- **帳號的 MCP 檢查無法確認既有連接器時，記錄現在會寫明是哪一部分不符。** 過去有六項不同的檢查（連接器卡片、其連結、其頁面、ChatGPT 的編輯表單、已儲存的名稱與已儲存的 Tunnel ID），失敗時都只顯示「Existing connector exact tunnel identity is unverified」；2026-11-23 一個已登入的工作區擁有者的自動檢查就停在這裡，沒有其他線索。記錄現在會寫出是哪一項檢查，例如「ownership check identity:tunnel-differs」。帳號卡片顯示的內容不變。

包含 v0.8.160 的所有變更。
