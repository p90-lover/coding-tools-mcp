# Coding Tools v0.6.0-rc.1 — Electron Full Codex Harness prerelease

## English

### Candidate status

- **Channel:** Windows x64 evaluation candidate.
- **Product identity:** Coding Tools `0.6.0-rc.1`, application ID `dev.codingtools.fullharness`.
- **Connector identities:** `Coding Tools Native2` for production and `Coding Tools Native2 DEV` for the isolated development profile.
- **ChatGPT Web model namespace:** `chatgpt-web/`.
- **Automated gates: required before publication.**
- **Live-account acceptance: pending manual.**
- **Stable rollback:** Coding Tools MCP v0.4.10 remains available as the stable rollback.

This is a Windows-first prerelease for evaluating the Electron-first Coding Tools product boundary. It is not a declaration that every replacement, migration, live-account, connector, computer-control, or cross-platform acceptance item is complete. Publication is permitted only from an exact tested source SHA that passed the dedicated Electron Full Harness CI workflow and produced the verified release inventory described below.

### Source and product boundary

The Electron/browser runtime is derived from the pinned upstream source:

- repository: `miuuyy/codex-chatgpt-web`;
- upstream version: `v5.0.6`;
- upstream commit: `e85e3693fdb4e3e033348c08df0298c20fcdb612`.

The pinned source, its MIT license, and the generated third-party notices remain part of the candidate evidence. The upstream source is imported and verified by manifest rather than followed as a moving branch.

The candidate evaluates one Coding Tools desktop entry point around the pinned browser/Codex harness. The Electron side owns the private ChatGPT browser profile, the Responses-compatible route, task-bound browser surfaces, lifecycle supervision, diagnostics, and the Browser-only, Full Harness, and Zero Risk interaction boundaries. The retained Rust implementation remains the authority for Coding Tools workspaces, local tools, permission policy, approvals, long-running commands, history, computer control, and the optional native Codex App Server bridge whenever those components are present in the exact verified package.

A Full Harness turn may expose only the tools granted to that exact task and turn. The turn capability narrows authority; it does not expand the Rust workspace policy or computer-control approval. Browser-only and Zero Risk modes remain distinct from Full Harness and must not silently acquire local-tool authority.

### Security and account boundaries

This candidate does not bypass ChatGPT plans, quotas, model eligibility, workspace policy, or connector restrictions. Account-specific model rows, effort controls, provider limits, Developer Mode behavior, and connector availability continue to depend on the signed-in account and current service policy.

The application does not copy cookies or browser state from Chrome, Edge, another app, or another OS account. It uses a separate application-owned browser profile. The application also does not silently create, replace, or reauthorize ChatGPT connectors. Reauthorization remains an explicit user/account action.

Unknown remote or local operations are not replayed automatically. This includes an uncertain browser submission, tool call, process start, input write, provider request, migration step, or publication action. Computer-use approval remains separate from permission to use a model or spend provider quota.

The Windows installer is configured as a per-user install with elevation disabled. This disclosure does not claim a trusted publisher signature unless the downloaded installer and publication evidence independently prove one.

### OAuth and live-account qualification

The candidate source includes OAuth compatibility work, but metadata or source-level tests alone do not prove that a real ChatGPT connection is healthy. The previously observed account-connection HTTP 400 must not be treated as resolved until a fresh user-visible authorization succeeds and an authenticated tool-dispatch round trip completes.

Manual qualification must cover at least:

- ChatGPT sign-in in the application-owned browser profile;
- account-observed model and effort availability;
- explicit connector authorization or reauthorization;
- refresh continuity after the original authorization lifetime;
- an authenticated MCP tool catalogue and tool-call round trip;
- tunnel startup, reconnect, and revocation behavior;
- visible cancellation and no replay after an unknown result.

Until that evidence is recorded, `validation-evidence.json` must continue to report `live_account_acceptance` as `pending_manual`.

### Release inventory and verification

The prerelease publisher accepts exactly four public assets:

1. `Coding.Tools_0.6.0-rc.1_windows_x64_setup.exe`
2. `provenance.json`
3. `validation-evidence.json`
4. `SHA256SUMS.txt`

`provenance.json` binds the product identity, pinned upstream source, exact tested source SHA, CI workflow, validation run, installer size, and installer SHA-256. `validation-evidence.json` records the automated-gate result and the separate live-account status. `SHA256SUMS.txt` covers every published asset.

The publication lane must:

- consume the installer and validation evidence from the same successful exact-source CI run;
- reject missing or additional assets;
- reject source, workflow, conclusion, size, or SHA-256 mismatches;
- upload to a draft prerelease first;
- perform asset readback and byte/hash verification for every asset;
- create only a non-forced tag that points to the verified source;
- publish only after those checks succeed.

The tag and release must never be rewritten to hide a failed candidate. A failed validation run remains evidence and requires a new source commit or a separately justified rerun.

### Rollback, preservation, and current limits

Coding Tools MCP v0.4.10 remains available as the stable rollback. The retained Tauri source and historical release remain available while the Electron replacement gate is incomplete. The new application ID prevents the Electron candidate from impersonating the retained Tauri product identity, but it is not by itself proof that data migration, side-by-side use, uninstall, or rollback rehearsal has passed.

No historical tag, release, Tauri source, user data, or project file is deleted. Temporary build, packaging, and validation state belongs under `aiTemp/`; replaced or superseded material is moved into a timestamped `aiTemp/Trash/` or project `Trash/` location instead of being permanently removed.

This prerelease publishes only the Windows x64 installer. macOS and Linux packaging, signing/notarization, live migration and rollback rehearsal, real-account connector acceptance, account-specific model behavior, and background computer-input behavior require their own evidence before being represented as accepted.

### Evaluation guidance

Use this candidate for isolated evaluation, not as evidence that every account or environment will behave identically. Keep v0.4.10 available, preserve the candidate’s `provenance.json`, `validation-evidence.json`, and `SHA256SUMS.txt`, and compare the installer hash before execution. Report the exact source SHA, validation run ID, application log boundary, and whether the failure happened before authorization, before tool dispatch, or after an unknown operation.

### 候選版本狀態

- **渠道：** Windows x64 評估候選版本。
- **產品識別：** Coding Tools `0.6.0-rc.1`，application ID 為 `dev.codingtools.fullharness`。
- **Connector 識別：** 正式環境使用 `Coding Tools Native2`，隔離開發環境使用 `Coding Tools Native2 DEV`。
- **ChatGPT Web 模型 namespace：** `chatgpt-web/`。
- **自動化閘門：公開前必須通過。**
- **真實帳戶驗收：待人工完成。**
- **穩定回復版本：** Coding Tools MCP v0.4.10 仍保留作為穩定回復版本。

呢個係 Windows-first 嘅 Electron-first Coding Tools 評估 prerelease，唔代表所有取代、資料遷移、真實帳戶、connector、電腦控制或者跨平台驗收已經完成。只有同一個 exact tested source SHA 通過專用 Electron Full Harness CI，而且產生下文列明嘅已驗證 release inventory，先可以公開。

### 原始碼同產品界線

Electron／瀏覽器 runtime 固定來自以下 upstream：

- repository：`miuuyy/codex-chatgpt-web`；
- upstream 版本：`v5.0.6`；
- upstream commit：`e85e3693fdb4e3e033348c08df0298c20fcdb612`。

固定原始碼、MIT 授權同產生嘅第三方授權資料都係候選版本證據一部分。Upstream 會按 manifest 驗證，唔會直接跟隨持續變動嘅 branch。

候選版本用一個 Coding Tools desktop 入口包住固定嘅瀏覽器／Codex harness。Electron 端負責私人 ChatGPT browser profile、Responses-compatible route、同任務綁定嘅瀏覽器介面、生命週期管理、診斷，以及 Browser-only、Full Harness、Zero Risk 三種清楚分隔嘅互動界線。喺 exact verified package 真正包含相關元件時，保留嘅 Rust 實作仍然負責 Coding Tools workspace、本機工具、權限政策、批准、長時間指令、history、電腦控制同可選 native Codex App Server bridge。

Full Harness 每一輪只可以見到該任務同該輪獲授權嘅工具。Turn capability 只會縮窄權限，唔會擴大 Rust workspace policy 或電腦控制批准。Browser-only 同 Zero Risk 唔可以靜默取得 Full Harness 嘅本機工具權限。

### 安全同帳戶界線

呢個候選版本唔會繞過 ChatGPT 方案、配額、模型資格、工作區政策或 connector 限制。帳戶可見模型、effort 控制、provider 上限、Developer Mode 行為同 connector 可用性，仍然由登入帳戶同當時服務政策決定。

程式唔會由 Chrome、Edge、其他程式或其他作業系統帳戶複製 cookie 或瀏覽器狀態；佢會使用程式自己管理嘅獨立 browser profile。程式亦唔會靜默建立、取代或重新授權 ChatGPT connector；重新授權仍然係清楚嘅使用者／帳戶操作。

未知結果嘅遠端或本機操作唔會自動重播，包括結果未明嘅瀏覽器送出、工具呼叫、程序啟動、輸入寫入、provider request、資料遷移步驟或者 release 操作。電腦控制批准仍然同模型使用／provider 配額權限分開。

Windows installer 設定為每位使用者安裝，而且停用 elevation。除非下載嘅 installer 同 publication evidence 獨立證明，呢份說明唔會聲稱 installer 已有可信發佈者簽署。

### OAuth 同真實帳戶驗收

候選原始碼包含 OAuth 相容性工作，但 metadata 或 source-level test 唔足以證明真實 ChatGPT 連線健康。之前出現嘅 account-connection HTTP 400，必須等到新一次可見授權成功，而且已認證工具派送 round trip 完成，先可以視為已解決。

人工驗收最少要包括：

- 喺程式自有 browser profile 完成 ChatGPT 登入；
- 確認帳戶實際可見嘅模型同 effort；
- 明確完成 connector 授權或重新授權；
- 原始授權期限之後 refresh 仍可持續；
- 已認證 MCP 工具目錄同工具呼叫 round trip；
- tunnel 啟動、重連同撤銷行為；
- 可見取消功能，而且未知結果後唔會重播。

喺證據未完成之前，`validation-evidence.json` 必須繼續將 `live_account_acceptance` 記錄為 `pending_manual`。

### Release inventory 同驗證

Prerelease publisher 只接受四個公開 asset：

1. `Coding.Tools_0.6.0-rc.1_windows_x64_setup.exe`
2. `provenance.json`
3. `validation-evidence.json`
4. `SHA256SUMS.txt`

`provenance.json` 會綁定產品識別、固定 upstream、exact tested source SHA、CI workflow、validation run、installer 大小同 SHA-256。`validation-evidence.json` 會分開記錄自動化閘門結果同真實帳戶狀態。`SHA256SUMS.txt` 會覆蓋所有公開 asset。

公開流程必須：

- 由同一個成功 exact-source CI run 取得 installer 同驗證證據；
- 拒絕遺漏或者額外 asset；
- 拒絕 source、workflow、conclusion、大小或 SHA-256 唔一致；
- 先上載到 draft prerelease；
- 對每個 asset 做 asset readback 同 byte／hash 驗證；
- 只建立指向已驗證 source 嘅 non-forced tag；
- 所有檢查成功後先公開。

唔可以重寫 tag 或 release 去隱藏失敗候選版本。失敗 validation run 會保留作證據，需要新 source commit 或有獨立理據嘅 rerun。

### 回復、保留政策同目前限制

Coding Tools MCP v0.4.10 仍保留作為穩定回復版本。Electron replacement gate 未完成之前，Tauri 原始碼同歷史 release 都會保留。新 application ID 可避免 Electron 候選版本冒認舊 Tauri 產品，但單靠 application ID 唔足以證明資料遷移、並存使用、解除安裝或者 rollback rehearsal 已通過。

唔會刪除任何歷史 tag、release、Tauri 原始碼、使用者資料或專案檔案。臨時 build、packaging 同 validation 狀態必須放入 `aiTemp/`；被取代或完成嘅材料會移入按時間分類嘅 `aiTemp/Trash/` 或專案 `Trash/`，唔會永久刪除。

呢個 prerelease 只公開 Windows x64 installer。macOS／Linux packaging、簽署／notarization、真實資料遷移同 rollback rehearsal、真實帳戶 connector 驗收、帳戶特定模型行為同背景電腦輸入行為，都要有各自證據先可以標示為已接受。

### 評估建議

請用隔離環境評估呢個候選版本，唔好將單一環境結果當成所有帳戶都相同。保留 v0.4.10，同時保存候選版本嘅 `provenance.json`、`validation-evidence.json` 同 `SHA256SUMS.txt`，執行前核對 installer hash。回報問題時，請包括 exact source SHA、validation run ID、application log 界線，以及失敗係發生喺授權之前、工具派送之前，定係某個未知結果操作之後。
