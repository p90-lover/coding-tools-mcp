# Coding Tools 0.8.104

## English

### Fewer freezes (#1135)
- **Setting up MCP no longer freezes the app.** Connector setup checked the tunnel key file every 50 ms on the main thread. On a busy disk, one check froze every window for up to 18 s. The key is now read once per setup, in the background.
- **Health checks and quota reads connect in the background.** The bridge, tunnel and AO health checks, and the CPA quota, usage and model reads, opened their connections on the main thread. Each could freeze the app for up to 3 s.
- **Saves and reads moved off the main thread:**
  - chat settings: up to 0.6 s;
  - Plugins › MCPs: 0.5 s;
  - the context meter's first read: 0.9 s;
  - each agent tool call's folder check: 0.7 s;
  - the MCP auto-connect check every 15 s.

### Chats (#1135)
- **A message is no longer lost when another chat starts at the same moment.** A send could fail with "AO board revision or initial state changed". It now reads the chat again and retries.
- **A slow AO isn't asked again and again.** Before, the chat asked for a card's activity on every refresh, even after the read failed: seven reads timed out together every 30 s. Now a failed read waits 30 s before the next try, doubling up to 5 minutes.
- **A goal's model pick is no longer dropped.** A pick made while the window was in the background used to be refused. It now applies when you return to the window.
- **The GPT Browser page no longer re-checks a failing account on every visit.** A failed automatic plan check waits 5 minutes, as a successful one does. The Plan button still checks at once.

### Agents launch and recover faster (#1134)
- **A burst of chats on one model stays on pre-started agents.** After a chat takes the agent started in advance for its model, the next one starts 12 seconds later instead of 90.
  - Before, the second and third chats of a burst launched cold. On 2026-11-09, chats sent 34 s and 56 s after a warm start both launched cold, and both cold starts hung.
- **A launch that hangs is retried after 4 minutes, not 10.** With **Retry automatically** on, a new agent that hasn't taken the chat's first message within 4 minutes is stopped, and the step is retried at once, usually on an agent started in advance.
  - Before, the chat said "launching" for AO's whole 10-minute start budget. Healthy cold starts took 15–75 s that day.
  - The step says: "The agent did not start within 4 minutes, so its start was stopped; the step is retried on another agent."
  - Only an agent started fresh for that message is stopped. A chat's own agent, which holds its work, is never ended this way.
  - With Retry automatically off, nothing changes.
- **A stopped start stays stopped.** Before, an agent start the app cancelled could be brought back by the one automatic resume for starts that timed out. That covers this check and **Stop** on a launching chat.

### Verification and limitations
- **Freezes and chats (#1135):**
  - Each fix has a new test. The lost-send and activity-read tests fail without their fixes.
  - The full desktop suite passes except four tests unrelated to it: two need this machine's Python launchers, one reads a fixed git path, and 0.8.103 fixed the fourth.
  - The freezes were measured in the installed 0.8.102's Activity log. Whether they are gone will be checked there after this release.
  - A flaky test that failed 2 of 7 runs, and could fail a build, now checks the result instead of a race.
- **Launch watchdog and warm re-warm (#1134):**
  - Unit tests cover the 4-minute stop (not at 3), Retry automatically off, a resumed agent never ended, the 12 s re-warm, and no resume after a deliberate end.
  - The hang itself was measured live on 0.8.102. The stop was not exercised against a live hang.
- Includes everything in 0.8.103.

## 繁體中文

### 減少卡頓（#1135）
- **設定 MCP 不再讓應用程式卡住。** 連接器設定會每 50 毫秒在主執行緒檢查一次通道金鑰檔案。磁碟忙碌時，一次檢查曾讓所有視窗凍結最多 18 秒。現在每次設定只在背景讀取金鑰一次。
- **健康檢查與用量讀取改在背景連線。** 橋接器、通道與 AO 的健康檢查，以及 CPA 的配額、用量與模型讀取，原本在主執行緒建立連線，每次可能讓應用程式凍結最多 3 秒。
- **儲存與讀取移出主執行緒：**
  - 對話設定：最多 0.6 秒；
  - Plugins › MCPs：0.5 秒；
  - 內容計量器的首次讀取：0.9 秒；
  - 每次代理工具呼叫的資料夾檢查：0.7 秒；
  - 每 15 秒一次的 MCP 自動連線檢查。

### 對話（#1135）
- **另一個對話同時開始時，訊息不再遺失。** 送出訊息可能因「AO board revision or initial state changed」失敗。現在會重新讀取後再試。
- **AO 變慢時不再被反覆詢問。** 之前，即使讀取失敗，對話每次重新整理仍會再讀取卡片的活動：七個讀取每 30 秒一起逾時。現在讀取失敗後會等 30 秒再試，最長加倍至 5 分鐘。
- **目標的模型選擇不再被丟掉。** 視窗在背景時所做的選擇原本會被拒絕，現在會在您回到視窗時套用。
- **GPT 瀏覽器頁面不再每次開啟都重新檢查失敗的帳號。** 自動方案檢查失敗後會等 5 分鐘，與成功時相同。「方案」按鈕仍會立即檢查。

### 代理啟動與恢復更快（#1134）
- **同一模型連續開多個對話時，都能用上預先啟動的代理。** 一個對話取用為其模型預先啟動的代理後，下一個代理在 12 秒後開始啟動，而不是 90 秒。
  - 之前，連續開啟的第二、第三個對話會冷啟動。2026-11-09，在預熱代理被取用後 34 秒和 56 秒送出的兩個對話都冷啟動了，而且兩次冷啟動都卡住。
- **卡住的啟動在 4 分鐘後重試，而不是 10 分鐘。** 開啟**自動重試**時，如果新代理 4 分鐘內沒有接收對話的第一則訊息，它會被停止，步驟立即重試，通常會改用預先啟動的代理。
  - 之前，對話會在 AO 整整 10 分鐘的啟動時限內一直顯示「啟動中」。當天正常的冷啟動需時 15–75 秒。
  - 步驟會顯示：「The agent did not start within 4 minutes, so its start was stopped; the step is retried on another agent.」
  - 只會停止為該訊息新啟動的代理。對話自己的代理保存著它的工作，絕不會以這種方式結束。
  - 關閉自動重試時，行為不變。
- **被停止的啟動不會再自行恢復。** 之前，應用程式取消的代理啟動，可能會被逾時啟動的一次自動恢復重新帶回。這包括這項檢查，以及在啟動中的對話按下**停止**。

### 驗證與限制
- **卡頓與對話（#1135）：**
  - 每項修正都有新測試。訊息遺失與活動讀取的測試在沒有修正時會失敗。
  - 完整桌面測試套件除四個無關的測試外全部通過：兩個需要本機的 Python 啟動器，一個讀取固定的 git 路徑，第四個已在 0.8.103 修正。
  - 卡頓是在已安裝的 0.8.102 的 Activity 記錄中量測的。此版本發佈後會在那裡確認是否已消失。
  - 一個 7 次中失敗 2 次、可能讓建置失敗的不穩定測試，現在檢查結果而不是競態。
- **啟動檢查與預熱（#1134）：**
  - 單元測試涵蓋 4 分鐘停止（3 分鐘時不停止）、關閉自動重試、恢復的代理不被結束、12 秒預熱，以及刻意結束後不再恢復。
  - 卡住的情況是在 0.8.102 上實測的；這項停止尚未在真實卡住的啟動上驗證。
- 包含 0.8.103 的所有內容。
