# Coding Tools 0.8.38

## English

### Chats
- A chat starts on a busy disk. Before, it failed every start with "folder workspace: … is not a git repository: exit status 1" in a folder that is a repository. Two changes:
  - git now gets 30 s to answer, not 10 s;
  - a git that is too slow is reported as slow, not as a missing repository, so the automatic retry can succeed (PR #713).
- Switching a project folder's branch says when git could not answer, instead of calling the folder "not a git repository" (PR #713).
- A backend update installed as a bundle loads #706's background chat queue and restart resume (PR #711, PR #713).

### Verification and limitations
- Build the Windows installer, portable ZIP and update packs from this branch, and confirm CI before publication.
- Known issue: computer control in chats still reports "stopped". The app has no way yet to turn control on for a window. Screenshots and window lists work. A fix is in progress.
- Everything in 0.8.37 is included.

## 繁體中文

### 對話
- 磁碟繁忙時對話也能啟動。過去在本身是儲存庫的資料夾中，對話每次啟動都會失敗，並顯示「folder workspace: … is not a git repository: exit status 1」。兩項改動：
  - git 的回應時限由 10 秒延長至 30 秒；
  - git 回應太慢時會報告為「太慢」，而不是「沒有儲存庫」，因此自動重試可以成功（PR #713）。
- 切換專案資料夾的分支時，若 git 未能回應，會如實說明，而不是說資料夾「不是 git 儲存庫」（PR #713）。
- 以更新包形式安裝的後端更新會載入 #706 的背景對話佇列及重新啟動後繼續（PR #711、PR #713）。

### 驗證及限制
- Windows 安裝程式、免安裝 ZIP 和更新檔需由本分支編譯及通過 CI 才能公開。
- 已知問題：對話中的電腦控制仍顯示「stopped」。應用程式暫時無法為視窗開啟控制，但截圖及視窗清單可正常使用。修正正在進行中。
- 包含 0.8.37 的所有內容。
