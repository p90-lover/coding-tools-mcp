# v0.4.3-rc.3 — OAuth popup origin repair / OAuth 彈出視窗來源修正

## English

This Windows release packages the previously unreleased ChatGPT-origin fix, with a narrower security boundary than main commit `07faa97`. The existing `v0.4.3-rc.2` installer cannot gain that source-only change merely by refreshing ChatGPT.

The HTTP guard accepts the exact HTTPS origins `https://chatgpt.com`, `https://chat.openai.com` and `https://www.chatgpt.com` only for GET/POST `/oauth/authorize`. It no longer trusts an arbitrary matching `Host`/`Origin` pair. `Host`, `Forwarded` and `X-Forwarded-Host` cannot nominate a trusted origin or OAuth issuer. Ordinary MCP, Actions, metadata and token endpoints retain their existing origin policy. Authentication is still required for protected tools.

Opening the OAuth page does not grant access. The existing client/redirect checks, PKCE, password, request-bound consent nonce/cookie, one-use authorization code and token validation remain unchanged. Desktop-managed tunnel changes update the trusted origin used by the running listener; this is separate from changing the endpoint saved in ChatGPT. A new Quick Tunnel URL can still require updating the client connection. The application cannot silently register or reauthorize a ChatGPT connection.

Verification reproduces the original popup rejection in rc.2 and the overbroad Host/origin acceptance in `07faa97`, then checks the corrected guard. The Windows application test follows the actual loopback listener through authorization query preservation, missing/tampered consent rejection, password + PKCE exchange, code replay rejection, authenticated discovery of all 70 registered definitions, and a desktop-managed origin change without replacing the listener or OAuth runtime. The browser account and Cloudflare service are not used by these fixtures; they are not a live-account acceptance test. Existing catalog and transport regressions, frontend build and installer-byte inspection also gate publication. No Codex executable or model inference is invoked.

Install this version and restart the desktop application once to load the new binary. Retry Connect from the existing ChatGPT connection using the application's current HTTPS `/mcp` URL. Complete the normal consent/password flow; do not remove query parameters, erase OAuth state, disable origin checks or raise execution permissions to fix login. If authentication succeeds but tools are missing, use Advanced/Full and the existing Tool exposure diagnostic, then refresh the client's saved tool metadata as needed.

The appearance of a popup without an address bar does not reveal which HTTP headers it sent. The reported Origin failure is reproducible for requests carrying the stated Origin, but the user's actual popup headers, current tunnel reachability and installed H: executable were not inspected in this release process.

This release preserves the previous tool catalog, model-free native command bridge, RAM-only screenshots and remembered computer-control behavior. The broader sandbox/file audit remains separate and unfinished; `sandbox_exec` stays unavailable. This is not complete Codex internal-tool parity or an audit certificate. Windows is publisher-unsigned. Old releases, project files and credentials are retained.

## 繁體中文

本次 Windows 版本將之前只存在原始碼的 ChatGPT 來源修正打包，並收窄 main Commit `07faa97` 的信任範圍。單純刷新 ChatGPT，不能讓既有 `v0.4.3-rc.2` 執行檔取得尚未打包的修改。

HTTP 檢查只在 GET／POST `/oauth/authorize` 接受精確的 HTTPS 來源 `https://chatgpt.com`、`https://chat.openai.com` 及 `https://www.chatgpt.com`。不再因任意 `Host`／`Origin` 相符就視為可信；`Host`、`Forwarded` 及 `X-Forwarded-Host` 不能自行指定可信來源或 OAuth 發行者。一般 MCP、Actions、中繼資料及 Token 端點保留既有來源規則，受保護的工具仍須認證。

開啟 OAuth 頁面不代表已獲授權。既有 Client／Redirect 檢查、PKCE、密碼、綁定原請求的同意 Nonce／Cookie、單次授權碼及 Token 驗證均保留。由桌面程式管理的隧道設定變更，會更新運行中服務採用的可信來源；但這不等於更新 ChatGPT 已存的端點。Quick Tunnel 換網址後，仍可能需要更新用戶端連接；程式無法靜默替帳戶註冊或重新授權。

驗證先重現 rc.2 的彈出視窗來源拒絕，以及 `07faa97` 過於寬鬆的 Host／Origin 接受，再檢查修正版。Windows 應用程式測試使用真正本機監聽服務，走過授權查詢保留、缺少／竄改同意資料的拒絕、密碼及 PKCE 換取 Token、授權碼重放拒絕、認證後取得全部 70 個註冊定義，以及不更換監聽服務或 OAuth 執行環境的可信來源更新。測試不使用真實 ChatGPT 帳戶或 Cloudflare，因此不是使用者環境驗收。既有目錄／傳輸回歸、前端建置及安裝程式位元組檢查亦是發佈關卡；不啟動 Codex 執行檔或模型推論。

安裝後重新啟動桌面程式一次以載入新執行檔，再使用程式目前顯示的 HTTPS `/mcp` 網址，從既有 ChatGPT 連接重試 Connect。照常完成同意／密碼流程；不要刪除查詢參數、清空 OAuth 狀態、停用來源檢查或提高執行權限來修復登入。若認證成功後仍缺工具，使用 Advanced／Full 及既有 Tool exposure 診斷，並按需要刷新用戶端已存的工具資料。

沒有網址列的彈出視窗外觀，不能證明實際發出了哪些 HTTP 標頭。帶有所述 Origin 的請求可重現該拒絕，但本次發佈沒有檢查使用者彈出視窗的真實標頭、目前隧道連通性或 H: 上已安裝的執行檔。

本版保留之前的工具目錄、免模型原生命令橋接、只在記憶體處理的截圖及已記住的電腦操作設定。較廣泛的沙箱／檔案稽核仍獨立保留、尚未完成；`sandbox_exec` 繼續不可用。本版本不代表完整 Codex 內部工具對等功能或稽核認證。Windows 沒有發佈者簽署，舊版本、專案檔案及憑證均保留。
