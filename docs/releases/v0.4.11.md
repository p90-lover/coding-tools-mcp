# v0.4.11 — durable OAuth discovery, response integrity, and listener resilience

## English

v0.4.11 advances the retained Tauri desktop release with focused connection reliability, OAuth interoperability, and release-safety repairs. It does not promote the unfinished Electron `0.6.0-rc.1` migration, rewrite any historical tag, or remove prior release evidence.

The authorization-server metadata now advertises both the existing `mcp` scope and `offline_access`, allowing compatible clients to request durable refresh-token access during a new authorization flow. Successful authorization callbacks now contain exactly one server-controlled `iss` value identifying the validated public issuer. Issuer validation occurs before one-time consent is consumed or a pending authorization code is created, so invalid public-origin configuration fails closed without mutating authorization state.

Protected-resource discovery now distinguishes the origin resource from the actual MCP resource at `/mcp`. The path-derived RFC 9728 document identifies `https://host/mcp`, while root discovery continues to identify `https://host`; MCP bearer challenges advertise the matching `/.well-known/oauth-protected-resource/mcp` metadata location. Both documents keep `authorization_servers` bound to the trusted origin. Access-token scope, redirect allowlists, token lifetime, confidential-client behavior, and refresh-token rotation rules remain unchanged.

These source-level OAuth repairs do not by themselves prove that an already-failed ChatGPT connector account link has recovered. After installing v0.4.11, a fresh visible connector authorization and authenticated catalogue/tool-call round trip are still required to qualify the live-account path.

Runtime supervision now keeps a healthy MCP listener alive through transient Windows port-table misses. A fresh missing-port observation must persist across six checks and the full 15-second grace window before recovery is attempted, while a closed listener shutdown receiver remains an authoritative failure signal so a real listener exit is still handled promptly.

The normal CI and verified-release lanes were hardened. Pull requests and `main` pushes run release-aligned frontend and Rust validation on Linux, Windows, and macOS. Version alignment rejects non-canonical stable numbers, validates every version observation, and requires visible non-comment English and Traditional Chinese release-note content. The verified installer build invokes this same checker against its exact tagged checkout before construction. Release publication remains exact-source and fail-closed, with native tests, strict Clippy, dependency-boundary checks, Git-history credential screening, RustSec audit, installer generation, asset size and SHA-256 verification, and safe rerun handling.

Two worker-capacity saturation fixtures were isolated onto test-local semaphores after concurrent full-suite runs exposed cross-test interference. Production tool-worker capacity, admission behavior, OAuth, tokens, permissions, and runtime limits are unchanged.

No files, branches, prior releases, tags, or validation evidence were deleted. Preparation dispatches and waits for complete CI against its exact final head, including any generated version commit. The legacy manual macOS publisher is retired in source and globally disabled before stable promotion. Stable Windows and universal macOS assets are published only by the verified desktop release workflow after every required gate succeeds.

## 繁體中文

v0.4.11 係保留 Tauri desktop 發佈路線嘅集中修補版本，主要改善連線可靠性、OAuth 互通性同發佈安全。今次唔會推送尚未完成嘅 Electron `0.6.0-rc.1` migration，亦唔會重寫任何歷史 tag 或移除舊有發佈證據。

Authorization-server metadata 而家會同時公開現有 `mcp` scope 同 `offline_access`，令支援嘅 client 可以喺新一次授權流程請求持久 refresh-token access。成功 authorization callback 而家會精確包含一個由 server 控制、用嚟識別已驗證公開 issuer 嘅 `iss` 值。Issuer 會喺一次性 consent 被消耗或 pending authorization code 被建立之前完成驗證，因此無效公開 origin 設定會 fail closed，而且唔會修改授權狀態。

Protected-resource discovery 而家會區分 origin resource 同實際位於 `/mcp` 嘅 MCP resource。Path-derived RFC 9728 文件會識別 `https://host/mcp`，root discovery 則繼續識別 `https://host`；MCP bearer challenge 亦會公開相符嘅 `/.well-known/oauth-protected-resource/mcp` metadata location。兩份文件嘅 `authorization_servers` 都繼續綁定可信 origin。Access-token scope、redirect allowlist、token lifetime、confidential-client 行為同 refresh-token rotation 規則保持不變。

以上 source-level OAuth 修補並唔足以證明之前失敗嘅 ChatGPT connector account link 已經恢復。安裝 v0.4.11 之後，仍然需要重新完成一次可見 connector 授權，同已認證 catalogue／tool-call round trip，先可以確認真實帳戶路線通過。

Runtime supervisor 而家可以喺 Windows port table 暫時漏報時保留健康嘅 MCP listener。新出現嘅 missing-port 狀態必須連續六次檢查，而且維持完整 15 秒 grace window，先會觸發 recovery；另一方面，listener shutdown receiver 關閉仍然係權威失敗訊號，所以真正 listener exit 仍然會被迅速處理。

一般 CI 同 verified-release 路線亦已加強。Pull request 同 `main` push 會喺 Linux、Windows、macOS 執行同正式發佈一致嘅 frontend 同 Rust 驗證。版本對齊會拒絕非 canonical stable number、核對所有版本位置，並要求中英文 release note 都有可見、唔係 HTML comment 嘅實際內容。Verified installer build 亦會喺建置之前，對精確 tagged checkout 執行同一個 checker。正式發佈仍然綁定精確 source，而且採用 fail-closed：包括 native tests、strict Clippy、dependency boundary、Git history credential screening、RustSec audit、installer 建置、asset 大小與 SHA-256 驗證，以及安全 rerun handling。

完整測試曾經發現兩個 worker-capacity saturation fixture 會互相干擾，因此而家已經改用 test-local semaphore。Production tool-worker capacity、admission 行為、OAuth、token、permission 同 runtime limit 完全冇改。

今次冇刪除任何檔案、branch、舊 release、tag 或驗證證據。Preparation 會針對最終精確 head（包括任何自動產生嘅版本 commit）主動啟動完整 CI，並等到驗證完成。舊有 manual macOS publisher 已喺 source 退役，而且會喺 stable promotion 之前全域停用。正式 Windows installer 同 universal macOS asset 只會喺 verified desktop release workflow 所有必要閘門通過後先公開。
