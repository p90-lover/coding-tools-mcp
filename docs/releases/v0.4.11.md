# v0.4.11 — durable OAuth discovery and listener resilience

## English

v0.4.11 advances the retained Tauri desktop release with focused connection reliability, OAuth discovery, and release-safety repairs. It does not promote the unfinished Electron `0.6.0-rc.1` migration, rewrite any historical tag, or remove prior release evidence.

The authorization-server metadata now advertises both the existing `mcp` scope and `offline_access`, allowing compatible clients to request durable refresh-token access during a new authorization flow. Access-token scope, redirect allowlists, token lifetime, protected-resource metadata, and refresh-token rotation rules remain unchanged. This metadata repair does not by itself prove that an already-failed ChatGPT connector account link has recovered: after installing v0.4.11, a fresh visible connector authorization and authenticated tool round trip are still required to qualify the live account path.

Runtime supervision now keeps a healthy MCP listener alive through transient Windows port-table misses. A fresh missing-port observation must persist across six checks and the full 15-second grace window before recovery is attempted, while a closed listener shutdown receiver remains an authoritative failure signal so a real listener exit is still handled promptly.

The normal CI and verified-release lanes were hardened. Pull requests and `main` pushes run release-aligned frontend and Rust validation on Linux, Windows, and macOS. Version alignment is checked across `package.json`, both package-lock observations, Tauri configuration, Cargo manifest, Cargo lockfile, and the matching bilingual release note before tagging. Release publication remains exact-source and fail-closed, with native tests, strict Clippy, dependency-boundary checks, Git-history credential screening, RustSec audit, installer generation, asset size and SHA-256 verification, and safe rerun handling.

Two worker-capacity saturation fixtures were isolated onto test-local semaphores after concurrent full-suite runs exposed cross-test interference. Production tool-worker capacity, admission behavior, OAuth, tokens, permissions, and runtime limits are unchanged.

No files, branches, prior releases, tags, or validation evidence were deleted. The Windows installer and universal macOS image are produced only by the verified desktop release workflow after every required gate succeeds.

## 繁體中文

v0.4.11 係保留 Tauri desktop 發佈路線嘅集中修補版本，主要改善連線可靠性、OAuth discovery 同發佈安全。今次唔會推送尚未完成嘅 Electron `0.6.0-rc.1` migration，亦唔會重寫任何歷史 tag 或移除舊有發佈證據。

Authorization-server metadata 而家會同時公開現有 `mcp` scope 同 `offline_access`，令支援嘅 client 可以喺新一次授權流程請求持久 refresh-token access。Access-token scope、redirect allowlist、token lifetime、protected-resource metadata 同 refresh-token rotation 規則全部保持不變。單靠 metadata 修補並唔代表之前失敗嘅 ChatGPT connector account link 已經恢復；安裝 v0.4.11 之後，仍然需要重新進行一次可見 connector 授權，並成功完成已認證工具 round trip，先可以確認真實帳戶路線通過。

Runtime supervisor 而家可以喺 Windows port table 暫時漏報時保留健康嘅 MCP listener。新出現嘅 missing-port 狀態必須連續六次檢查，而且維持完整 15 秒 grace window，先會觸發 recovery；另一方面，listener shutdown receiver 關閉仍然係權威失敗訊號，所以真正 listener exit 仍然會被迅速處理。

一般 CI 同 verified-release 路線亦已加強。Pull request 同 `main` push 會喺 Linux、Windows、macOS 執行同正式發佈一致嘅 frontend 同 Rust 驗證。建立 tag 之前，系統會檢查 `package.json`、package-lock 兩個版本位置、Tauri config、Cargo manifest、Cargo lockfile，同對應中英文 release note 是否完全一致。正式發佈仍然綁定精確 source，而且採用 fail-closed：包括 native tests、strict Clippy、dependency boundary、Git history credential screening、RustSec audit、installer 建置、asset 大小與 SHA-256 驗證，以及安全 rerun handling。

完整測試曾經發現兩個 worker-capacity saturation fixture 會互相干擾，因此而家已經改用 test-local semaphore。Production tool-worker capacity、admission 行為、OAuth、token、permission 同 runtime limit 完全冇改。

今次冇刪除任何檔案、branch、舊 release、tag 或驗證證據。Windows installer 同 universal macOS image 只會喺 verified desktop release workflow 所有必要閘門通過後先建立同公開。
