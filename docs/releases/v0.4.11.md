# v0.4.11 — long-running listener and native Codex resilience

## English

v0.4.11 improves long-running local reliability without adding a separate long-run mode or weakening permission and replay-safety boundaries.

MCP and Actions listener health now tolerates transient Windows port-table misses under desktop load. A still-live listener must be missing for at least six observations and 15 seconds from the first consecutive miss before the existing error/tunnel-cleanup path runs. A real listener-task exit is still detected immediately through the closed shutdown receiver, so the grace period does not hide a crashed service.

The opt-in native Codex App Server bridge now lets the existing request-limit and lifetime fields use `0`. A zero request limit means no application-side request-count ceiling, and a zero lifetime means the bridge remains active until local disconnect, revocation, listener stop or desktop exit. Provider/account quotas and the local Stop control still apply; this is not a provider-quota bypass.

Native bridge replay protection remains bounded in RAM. The ledger retains at most 64 entries; completed idempotency receipts expire after 90 minutes and are evicted oldest-first under capacity pressure, while pending or unknown outcomes are never evicted merely to make room. A confirmed thread close/unsubscribe now releases its in-memory ownership slot, and individual native RPC waits are extended from 15 to 60 seconds for slow local responses.

The existing general command runner still has no automatic deadline when its timeout is omitted or zero, and the existing 90-minute RAM output-cache policy remains unchanged. Temporary release-generation evidence stays under `aiTemp/Trash/` and is not part of the release source.

Installer publication remains gated by the repository's verified desktop release workflow, including version-parity checks, native tests, strict Clippy, dependency-boundary checks, credential-history screening, RustSec audit, installer generation and final asset verification.

## 繁體中文

v0.4.11 進一步提升長時間本機任務嘅可靠性，唔會另外加入「long-run mode」，亦唔會放寬權限或者 replay safety 邊界。

MCP 同 Actions listener health 而家可以容忍 Windows 喺桌面高負載期間短暫漏報 port table。只要 listener task 仍然存活，就必須連續至少六次偵測唔到 port，而且由第一次連續漏報開始已經過 15 秒，先會進入原本嘅 error／tunnel cleanup 流程。真正 listener task 退出時，仍然會透過已關閉嘅 shutdown receiver 即時偵測，所以 grace period 唔會掩蓋真正 crash。

Opt-in native Codex App Server bridge 而家容許現有 request-limit 同 lifetime 欄位填 `0`。Request limit 為 0 代表本程式唔再設定請求次數上限；lifetime 為 0 代表保持連接，直到本機斷線、撤銷、listener 停止或者桌面程式退出。供應商／帳戶配額同本機 Stop 仍然有效；呢個唔係 provider-quota bypass。

Native bridge replay protection 仍然使用有限 RAM。Ledger 最多保留 64 個 entry；已完成嘅 idempotency receipt 最多保留 90 分鐘，容量有壓力時會優先清走最舊已完成 receipt；pending 或結果未知嘅 outcome 絕對唔會只為騰空位置而被清除。已確認嘅 thread close／unsubscribe 會釋放 in-memory ownership slot；單次 native RPC 等候時間亦由 15 秒延長至 60 秒，以容忍較慢嘅本機回應。

原有一般 command runner 喺 timeout 冇填或者係 0 時仍然冇自動執行期限；原有 90 分鐘 RAM output-cache policy 亦完全不變。Release 產生過程嘅臨時證據會留喺 `aiTemp/Trash/`，唔會進入正式 release source。

安裝程式仍然必須通過 repository 嘅 verified desktop release workflow，包括版本一致性檢查、native tests、strict Clippy、dependency boundary、Git 歷史 credential screening、RustSec audit、installer 建置同最終 asset 驗證，先可以正式發佈。
