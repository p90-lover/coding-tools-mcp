# v0.4.4-rc.4 — Responsive MCP control and selective branch recovery

## English

Keeps Quick Tunnel supported; does not require a paid hostname or change the user's tunnel configuration. The three changes are bounded: a reserved protocol-control lane, pooled/concurrent credential-free endpoint probes, and two recovered read-only output contracts. No agent/model service is started by these changes.

MCP ping, initialize, tools/list and server/discover now have two reserved worker slots and a three-second response deadline instead of sharing the sixteen ordinary tool-execution slots. Real authentication, Origin, envelope, modern header/body agreement and live tool-profile filtering still run. A tool NAMED ping does not enter this lane. mcp_operation_status keeps its separate four-reader capacity. Busy control requests fail explicitly without executing a tool; they do not reboot listeners, restart tunnels, infer work completed or retry mutations. The worker-owned timeout receipts and their runtime-local retention limits are preserved.

The public discovery check reuses HTTP/TLS pools for the same proxy policy and fetches independent health/OAuth documents concurrently. Client cache: maximum four entries, sixty seconds per entry, twenty-second idle connections, maximum three idle connections per host. At most two public probes may run (up to six document requests), with the existing two-second connect limit, five-second per-document limit, a five-second aggregate probe deadline and 64 KiB per-document cap. Every fresh response is checked; health or authentication success is not cached. No cookie, bearer token or OAuth secret is sent. Different proxy policies never reuse each other's clients; system proxy environment is reread after at most sixty seconds. Redirect following and caller-controlled trusted origins remain disallowed.

Local fixture measurements report sequential versus parallel metadata latency and TCP connection counts, and a real HTTP test verifies protocol control while all sixteen execution slots are occupied. These are application/loopback measurements, NOT Cloudflare uptime or a user's public-network benchmark. They do not establish a percentage improvement for actual tool execution, inference or game automation. Quick Tunnels still have random hostnames, no uptime SLA, a documented 200 in-flight-request limit and no SSE support. The JSON transport remains intentional. No keep-alive can override ChatGPT's conversation-level developer-MCP restrictions.

The complete captured branch audit is in docs/audits/branch-recovery-2026-09-11.md. All seventy-four then-existing refs were compared with released main, including support-only/staged branches and one unrelated upstream history. Ahead counts are not missing-feature counts: later ports and squashes already preserve much earlier work. Retired sandbox/network candidates must not overwrite the verified offline AppContainer boundary. Incomplete encoded patches are not treated as runnable integrations. This is source/lineage coverage, not full live acceptance of every historical function.

Selectively recovers read_file and operation_log outputSchema work from fix/verified-contracts-0.4.4-rc.2. Both are wired into the actual registry and validated against real shared-dispatch results, including empty/truncated/error cases. Existing more precise list_task_events and operation-recovery contracts are preserved. Tool count remains 71 (Core 58, Read-only 42, Advanced/Full 71). Refresh client tool metadata after upgrading.

The broader ChatGPT-led Paseo coordinator, assignment/review controls, Anneal visual task execution and their permission/budget model are NOT completed in this release. Existing adapters, shared board and opt-in Codex-style tools are preserved, not re-enabled through an unsafe blanket merge. Model-capable code remains distinct from model-free controls; no Codex quota or live provider session is used in verification.

The existing tunnel crash backoff, intentional Stop behavior, OAuth/refresh handling, native consent and process isolation are unchanged and retained. There is no automatic replay or connection-health-triggered restart in this patch. It cannot reconstruct pre-upgrade operations or persist RAM-only receipts over restart. Reconcile unknown in-flight operations before upgrading. Windows x64 unsigned prerelease; source/tag/main/installer identity and read-back hashes gate publication. No files, branches or previous releases are deleted. Temporary and replaced local originals stay under aiTemp/Trash. User Windows/ChatGPT/CoC live acceptance remains unverified.

## 繁體中文

保留 Quick Tunnel，不要求付費 hostname，也不改動使用者隧道設定。本次集中三項修改：獨立協定控制名額、重用連線及平行進行無憑證端點檢查，以及恢復兩個唯讀結果契約。這些修改不會啟動 Agent／模型服務。

MCP ping、initialize、tools/list 及 server/discover 改用兩個獨立工作名額及三秒回應期限，不再與十六個一般工具執行名額共用。真正認證、Origin、請求格式、現代協定 header／body 一致性及即時工具設定檔仍會驗證。名稱叫 ping 的工具不能進入此通道。mcp_operation_status 保留獨立四個查詢名額。控制通道忙碌時明確返回錯誤，不會執行工具、重新啟動 listener／隧道、推斷工作完成或重試寫入。保留 worker 持有的逾時紀錄及其記憶體保留限制。

公開端點檢查對相同代理策略重用 HTTP／TLS 連線池，並平行取得互相獨立的健康／OAuth 文件。最多四個 Client、每個保留六十秒、閒置連線二十秒，每個 hostname 最多三條閒置連線；最多兩個公開檢查同時進行，即最多六個文件請求。保留兩秒連接、每文件五秒、整體檢查五秒及每文件 64 KiB 上限。每次都驗證最新回應，不快取健康或認證成功結果；不傳送 Cookie、Bearer token 或 OAuth secret。不同代理策略不共用 Client，系統代理環境最多六十秒後重新讀取。仍不跟隨轉址，也不相信呼叫端任意指定來源。

本機測試記錄順序及平行 metadata 延遲、TCP 連線數，並使用真正 HTTP 驗證十六個執行名額全滿時控制通道仍可回應。這是應用程式／loopback 測量，不是 Cloudflare uptime 或使用者公開網路測試，亦不能宣称所有工具執行、推論或遊戲自動化加快某個百分比。Quick Tunnel 仍有隨機 hostname、沒有 uptime SLA、文件列出的 200 個進行中請求限制及不支援 SSE；保留 JSON 傳輸。保活不能覆寫 ChatGPT 對話層 developer MCP 限制。

完整分支審查見 docs/audits/branch-recovery-2026-09-11.md。擷取時全部七十四個 ref 均與已發佈 main 比較，包括支援／暫存分支及一個獨立上游歷史。領先 commit 數不等於缺失功能，後續移植或 squash 已保留很多早期實作。舊沙箱／網路候選不能覆蓋現有已驗證離線 AppContainer 邊界；不完整編碼補丁不能當成已完成整合。這是原始碼／歷史覆蓋，不代表每個歷史功能已完成真實驗收。

選擇性恢復 fix/verified-contracts-0.4.4-rc.2 的 read_file 及 operation_log outputSchema，接入真正工具註冊表，使用真實共用分派結果驗證，包括空白、截斷及錯誤案例。保留現有較精確的 list_task_events／操作恢復契約。工具數仍為 71（Core 58、Read-only 42、Advanced／Full 71），升級後須更新用戶端工具 metadata。

完整 ChatGPT 主導的 Paseo 協調者、指派／審核、Anneal 視覺化任務執行及其權限／預算模型，尚未在此版本完成。保留現有介接、共用看板及需批准的 Codex-style 工具，不透過危險的全部合併重新啟用。可呼叫模型的程式與無模型控制明確分開；驗證不消耗 Codex 配額或啟動真實供應商會話。

現有隧道崩潰退避、明確 Stop、OAuth／refresh、本機同意及程序隔離不變。本次不會自動重跑，亦不因健康檢查失敗而重啟。不能補建升級前的操作，或令 RAM 紀錄跨重啟保留；升級前先確認未知執行。Windows x64 未簽章預發佈版，原始碼／tag／main／installer 一致及下載校驗後才公開。不刪除檔案、分支或舊 Release；暫存及被取代原件保留在 aiTemp／Trash。使用者 Windows／ChatGPT／CoC 真實驗收仍未完成。
