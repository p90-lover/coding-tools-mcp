# Coding Tools v0.8.134

## English

### Model menu: a disabled account's models leave the menu

- **The problem.** The model menu kept showing models that only a disabled CPA account served, for up to 30 days, and every message sent on one failed. Gemini 4 Argon High came from one of ten Antigravity accounts. When that account was disabled in CPA, the menu kept the model, and each message failed with "unknown provider for model gemini-4-argon-high".
- **Why.** The menu remembers every model CPA listed in the last 30 days, so a model survives a short cooldown or a CPA restart. It forgot a model only when every account of its provider was disabled, not when just the one account that served it was.
- **What changed.** When CPA stops listing a remembered Antigravity model, the app now asks CPA which models each enabled Antigravity account still has. If none has it, the model leaves the menu, and a chat that still uses it says "No enabled Antigravity account in CPA serves it now: the account that did is disabled". A model whose account is only cooling down still has it, so it stays in the menu as before. When the account is turned back on, the model returns.
- **Not changed.** Codex, Claude and Gemini models keep the old behavior, because an API key in CPA's settings can also serve them.

## 繁體中文

### 模型選單：已停用帳號的模型會離開選單

- **問題。** 只由已停用的 CPA 帳號提供的模型，會在模型選單裡留最多 30 天，而用它送出的每則訊息都會失敗。Gemini 4 Argon High 來自十個 Antigravity 帳號中的一個。那個帳號在 CPA 裡被停用後，選單仍保留這個模型，每則訊息都失敗，錯誤是「unknown provider for model gemini-4-argon-high」。
- **原因。** 選單會記住 CPA 在過去 30 天內列出的每個模型，讓模型撐過短暫的冷卻或 CPA 重新啟動。只有當它的供應商所有帳號都停用時，選單才會忘記這個模型；只停用提供它的那一個帳號時，則不會。
- **改了什麼。** 當 CPA 不再列出一個記住的 Antigravity 模型時，應用程式現在會向 CPA 查詢每個已啟用的 Antigravity 帳號還有哪些模型。如果沒有任何帳號有它，這個模型就會離開選單，仍在使用它的對話會顯示「No enabled Antigravity account in CPA serves it now: the account that did is disabled」。帳號只是在冷卻中的模型仍然在帳號上，所以會照舊留在選單裡。帳號重新啟用後，模型就會回來。
- **沒有改變的部分。** Codex、Claude 和 Gemini 的模型維持原本的行為，因為 CPA 設定裡的 API 金鑰也可能提供它們。
