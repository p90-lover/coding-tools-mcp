# Coding Tools v0.8.141

## English

### CPA: new installs get Provider Manager 0.10.1

- **The problem.** The installer still carried Provider Manager 0.9.0. A new install or a repair started two versions behind and stayed there until App plugins' automatic update ran (5 minutes after the app starts, then every 6 hours). Until then, OpenCode Go and `gpt-6.1-sol` requests went out through CPA's one global proxy instead of each account's own, and CPA Helper's quota polling and routing, which 0.10.0 removed, were back.
- **What changed.** The installer now carries Provider Manager 0.10.1, the build published on GitHub:
  - Each account's requests, model syncs, balance reads and Test go through that account's own proxy.
  - Upstream cards keep their usage across CPA restarts. **In CPA** lists every account CPA serves, including the API keys in CPA's settings. Quota bars show what is left. Moonshot (Kimi) and StepFun balances are read.
  - From 0.10.0: CPA's own rotation picks accounts again, and its cooldown after a rate limit moves the work to another account. CPA's Plugins sidebar shows one entry, **Provider Manager**.
- **What you will see.** The bundled plugin moves from 0.9.0 to 0.10.1 the next time the app starts CPA. An install that already updated itself to 0.10.1 has the same file, so nothing is replaced.

### Chats open faster after a restart

- **The problem.** Right after a restart, a chat whose turns had no provider id read its whole message history again for every page of the chat it loaded. Most of the database reads right after a restart came from this.
- **What changed.** Agent Orchestrator now skips that read for such chats. What the chat shows is unchanged. On a test chat of 12,000 messages, a page went from 57 ms to 0.25 ms.
- **Also in Agent Orchestrator.** Migration 0119 now wraps the step lists it rebuilds in `json()`, because SQLite 3.54 would otherwise store them as text. A database that already ran 0119 is not changed.

### ChatGPT's native Codex keeps working after an update, and says why when it can't

- **The problem.** ChatGPT could list a workspace through the Coding Tools connector but answered that "its native Codex connection is unavailable". Every workspace's MCP listener was stopped. A listener only starts when you start it, and every app restart, including each automatic update, stopped it again.
- **What changed.**
  - A workspace listener you start (Workspaces > Authentication > Start) now starts again whenever Coding Tools restarts, until you stop it. The confirmation says so.
  - When Coding Tools refuses a native Codex request, ChatGPT now gets the reason, such as "Start this workspace's authenticated MCP listener first", instead of a general "check the connection".
- **Not changed.** Connecting native Codex still needs your confirmation in the Coding Tools window. A listener you started before this version needs starting once more.

## 繁體中文

### CPA：新安裝會取得 Provider Manager 0.10.1

- **問題。** 安裝程式仍內附 Provider Manager 0.9.0。新安裝或修復安裝會落後兩個版本，直到「應用程式外掛」的自動更新執行為止（應用程式啟動 5 分鐘後，之後每 6 小時一次）。在那之前，OpenCode Go 和 `gpt-6.1-sol` 的請求會經過 CPA 唯一的全域代理，而不是各帳號自己的代理；0.10.0 已移除的 CPA Helper 配額輪詢與路由也會回來。
- **改了什麼。** 安裝程式現在內附 Provider Manager 0.10.1，也就是 GitHub 上發佈的版本：
  - 每個帳號的請求、模型同步、餘額讀取和 Test 都經過該帳號自己的代理。
  - 上游卡片在 CPA 重新啟動後仍保留用量。**In CPA** 列出 CPA 服務的每個帳號，包括 CPA 設定中的 API 金鑰。配額條顯示剩餘的量。會讀取 Moonshot（Kimi）和 StepFun 的餘額。
  - 來自 0.10.0：再次由 CPA 自己的輪替挑選帳號，遇到速率限制後的冷卻期會把工作移到另一個帳號。CPA 的外掛側欄只顯示一個項目：**Provider Manager**。
- **你會看到的變化。** 應用程式下次啟動 CPA 時，內附外掛會從 0.9.0 換成 0.10.1。已經自行更新到 0.10.1 的安裝檔案相同，因此不會替換任何東西。

### 重新啟動後對話開啟更快

- **問題。** 重新啟動後，回合沒有供應者 ID 的對話，每載入一頁都會重新讀取整段訊息歷史。重新啟動後的資料庫讀取大多來自這裡。
- **改了什麼。** Agent Orchestrator 現在會為這類對話略過這次讀取。對話顯示的內容不變。在 12,000 則訊息的測試對話中，每頁從 57 ms 降到 0.25 ms。
- **Agent Orchestrator 的其他變更。** 遷移 0119 現在會把它重建的步驟清單包在 `json()` 中，否則 SQLite 3.54 會把它們存成文字。已執行過 0119 的資料庫不會被變更。

### 更新後 ChatGPT 的原生 Codex 仍可使用，無法使用時也會說明原因

- **問題。** ChatGPT 能透過 Coding Tools 連接器列出工作區，卻回答「原生 Codex 連線無法使用」。每個工作區的 MCP 監聽器都已停止。監聽器只有在你啟動時才會啟動，而每次應用程式重新啟動（包括每次自動更新）都會再次將它停止。
- **改了什麼。**
  - 你啟動的工作區監聽器（工作區 > 驗證 > 啟動）現在會在 Coding Tools 每次重新啟動時自動再啟動，直到你停止它為止。確認視窗會說明這一點。
  - 當 Coding Tools 拒絕原生 Codex 請求時，ChatGPT 現在會收到原因，例如「請先啟動此工作區的已驗證 MCP 監聽器」，而不是籠統的「請檢查連線」。
- **沒有改變的部分。** 連接原生 Codex 仍需要你在 Coding Tools 視窗中確認。在此版本之前啟動的監聽器需要再啟動一次。
