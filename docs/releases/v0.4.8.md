# v0.4.8 — unbounded ordinary commands and verified release fixtures

## English

This version retains the ordinary no-deadline execution and RAM-cache changes from
v0.4.7 and repairs the failures that prevented that tag from producing installers.
The v0.4.7 tag and its failed CI evidence are preserved, not replaced.

Ordinary `exec_command` calls have no automatic lifetime limit when `timeout_ms` is
omitted, null, or zero. There is no separate long-run mode; seven days is not a ceiling.
An explicit positive timeout remains a caller-requested stop condition. Short HTTP
response waits, cancellation, permission revocation, and resource admission stay enforced.

Disposable command output remains in a bounded RAM-only cache, with 90-minute maximum
payload age, oldest-payload-first eviction, a 64 MiB shared payload budget, and 1 MiB
per stream. Cache expiry does not expire active commands or their ownership/write leases.
Durable history, authentication, source files, and third-party compiler caches are separate.

The release repair makes the Windows sandbox probe reproducible from checked-in C++
source in Cargo's output directory. It is a test artifact, not an installed app resource.
Test workers sharing the same fixture can share its lease; different fixtures remain
serialized. Descendant-revocation checks ignore retained old markers rather than deleting
them. The output compatibility test now checks 5,400-second retention and waits for
actual completion before reading output.

The application/server still must remain running. No restart-surviving job supervisor,
seven-day wall-clock endurance test, universal provider-policy equivalence, or complete
provider orchestration is claimed. No provider/model calls are required by these checks.
The existing release workflow must pass native tests, strict lint, frontend validation,
dependency audits, and installer verification before publishing this non-prerelease.

## 繁體中文

本版保留 v0.4.7 嘅一般指令無期限執行及 RAM 快取改動，並修正令該 tag 未能產生
安裝程式嘅驗證問題。原有 v0.4.7 tag 同失敗 CI 證據會保留，唔會被覆蓋。

一般 `exec_command` 省略 `timeout_ms`、設為 null 或零時，冇自動運行時限，亦冇獨立
長任務模式；七日唔係上限。明確提供正數時限，先會加入呼叫端要求嘅停止條件。
短 HTTP 回應等待、取消、權限撤銷同資源准入限制仍然保留。

可丟棄嘅指令輸出繼續使用有上限嘅 RAM 快取，資料最多保留 90 分鐘，優先移除最舊
資料，共用資料容量 64 MiB，每個串流 1 MiB。快取到期唔會令運行中指令、程序管理
紀錄或寫入鎖到期。持久化歷史、認證、原始碼同第三方編譯工具快取屬於獨立資料。

今次修正會從已追蹤 C++ 原始碼喺 Cargo 輸出目錄建立 Windows sandbox 測試程式，
唔會將佢當成應用程式資源安裝。同一測試資料來源嘅工作執行緒可以共用測試鎖，
不同測試仍然互相隔離。子程序撤權檢查會忽略保留嘅舊標記，唔會刪除佢哋。
輸出相容性測試已改為檢查 5,400 秒保留期限，並等到程序真正完成先讀取結果。

應用程式／伺服器仍須保持運行。本版唔聲稱支援重啟後自動恢復任務、已完成七日
實際耐久測試、等同所有供應商權限政策，或已完成全部供應商任務編排。
驗證唔需要供應商／模型呼叫。現有發佈流程必須通過原生測試、嚴格 lint、前端檢查、
依賴審計同安裝檔案驗證，先會公開非預發佈版本。
