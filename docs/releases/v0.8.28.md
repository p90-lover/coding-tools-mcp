# Coding Tools 0.8.28

## English

### Improvements
- WebGPT progress notes stay in the chat. Each note sits before the step it was said before, instead of being replaced by the model's next message (PR #627).
- Steer a working WebGPT chat. A message sent while it works joins the running turn, as the Codex bridge does, instead of waiting for the turn to end. Restart on a "may be stuck" WebGPT chat now stops the turn and sends the message as the next one (PR #627).
- A WebGPT chat that was killed mid-turn keeps working. Codex reopening it without its turn metadata or working folder is accepted as a resume, instead of failing every later turn (PR #627).
- A stuck WebGPT turn recovers. A ChatGPT tab that errors, can't send or stops responding moves to a fresh conversation, up to twice per turn. A busy server is retried instead of ending the task. A WebGPT chat whose connection stopped ends its turn, so the next message starts a new one instead of waiting forever behind "not connected" (PR #627).
- WebGPT compaction recovers from long histories and starts at 85% of the context window Codex reports (PR #626).
- After a restart or a closed tab, WebGPT returns to the verified ChatGPT conversation linked to the chat, instead of opening a new one (PR #628).
- Chats created or messaged through the Codex app work with WebGPT, and Coding Tools Chat gets a Native ChatGPT Web mode that uses the GPT Browser's account session (PR #629).
- WebGPT's context window follows the Codex bridge's and is locked in the composer (PR #612).

### Verification and limitations
- Build the Windows installer, portable ZIP and update packs from this branch and confirm CI before publication.
- Everything in 0.8.27 is included.

## 繁體中文

### 更新內容
- WebGPT 的進度說明會保留在對話中，每段說明顯示在它之前所講的步驟前面，不再被模型下一則訊息取代（PR #627）。
- WebGPT 對話運行中也可以插話：運行時傳送的訊息會加入目前的回合（與 Codex 橋接相同），不再等待回合結束。在「可能卡住」的 WebGPT 對話按「重新開始」，現在會停止該回合並把訊息作為下一回合傳送（PR #627）。
- 在回合中途被終止的 WebGPT 對話可以繼續使用：Codex 在缺少回合資料或工作資料夾的情況下重新開啟它時，會被視為繼續執行，不再令之後每個回合都失敗（PR #627）。
- 卡住的 WebGPT 回合會自動恢復：ChatGPT 分頁出錯、無法傳送或停止回應時，會改用新的對話，每回合最多兩次；伺服器繁忙時會重試，不再結束任務。連線已停止的 WebGPT 對話會結束該回合，下一則訊息會開始新回合，不再一直停在「未連線」後面等待（PR #627）。
- WebGPT 壓縮對話時可從過長的歷史中恢復，並在 Codex 回報的上下文視窗達到 85% 時開始壓縮（PR #626）。
- 重新啟動或關閉分頁後，WebGPT 會回到與該對話連結並已驗證的 ChatGPT 對話，不會另開新對話（PR #628）。
- 透過 Codex 應用程式建立或傳送訊息的對話可以使用 WebGPT；Coding Tools 對話新增「原生 ChatGPT Web」模式，使用 GPT 瀏覽器的帳戶登入（PR #629）。
- WebGPT 的上下文視窗跟隨 Codex 橋接的設定，並在輸入框中鎖定（PR #612）。
