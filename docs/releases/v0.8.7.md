Coding Tools 0.8.7

Updates in-app from rc.19 and later. On rc.18 or earlier, install the Windows installer or unpack the portable ZIP with the app closed.

Less CPU:

- The Agent Orchestrator used half a core or more and read about 16 MB a second even with chats sitting idle. Usage tracking kept waiting on 95 ended Claude sessions whose transcripts were never written, so it searched again every 30 seconds and re-read the start of every Claude transcript in the project folder for each session. Those sessions now settle 10 minutes after they end, and a transcript from another workspace is read once.
- The preview check, which runs four times a second, now reads five fields of the live sessions instead of every field of every session ever created.
- A new chat's first request is lighter, and agents warm up while you type.

Chats that no longer get stuck:

- A chat whose newest tool results are megabytes (a page or screenshot dump) still shows its work, and a request waiting behind them shows and gets answered. Before, every read failed with "AO response exceeds the handler limit" and the chat sat at "may be stuck".
- "Retry automatically" retries a failed step by itself once its pause is over, including a step whose loop had ended (an app restart, a launch that failed).
- A run keeps going when a local connection drops for a moment.
- A subagent whose model keeps refusing requests (rate-limited, 429) is stopped and its chat goes on; a turn waiting out a model error says so instead of "may be stuck".
- After an update restart, a card being retried no longer shows "Something went wrong: AO receipt changed". Switching projects no longer shows "AO run not found in this workspace".

Approve for me:

- When its reviewer cannot decide, it is asked once more and must allow or deny, instead of leaving the request to you.
- Reading a file you attached to the chat needs no review; the app's own subagent and wake-up tools need none either.
- A full script of up to 1,500 characters is reviewed as a whole, and a denied tool shows the reviewer's reason.
- The approvals poll asks only the project its run belongs to.

Chat:

- /goal works as Claude Code's: an evaluator judges each round.
- A sent message shows at once and the box clears.
- A message sent just as a failed step retries itself is no longer refused ("This chat is still running") and thrown back into the box: it waits and is steered in, or sent when the turn ends.
- A steer that waits for the agent's own request to be answered stays shown as steering, instead of popping up as "Queued"; one refused only because the window was in the background waits until it is in front again.
- An image you send or steer into a running turn shows as the image, and the agent may read it.
- A single model's messages show once, in its reply, not again between its tool calls.
- A failed step opens on its error with its earlier attempts folded above the attempt now running.
- Claude Code's auto-mode billing notice and a review's card ids are left out of replies.
- Stop releases a chat's agents and their subagents; a chat whose agent never started can be archived.
- Chat agents can capture one program's window (`capture_process`), reviewed like other vision tools.
- Clawd can be dragged anywhere on the screen. Its house stands beside the chat box, and Clawd walks around it and in through its door.

Models and CPA:

- Every Cline Pass model takes a reasoning effort, from Minimal to Max (Cline Pass plugin 0.1.0-codingtools.4).
- Command Code models take a reasoning effort from None to Max; the level you picked used to be dropped on the way (Command Code plugin 1.0.0-codingtools.2).
- Claude through Antigravity takes an effort from Low to Max, which turns its thinking on; CPA lists no levels for it.
- CPA keeps your API providers across a managed restart, and its network proxy can be chosen separately.
- Cline Pass streaming through CPA works across the Claude, Responses and OpenAI Chat formats.

Windows and packaging:

- Profile and state folders behind Windows junctions resolve before the app writes to them, and saves from two processes no longer clash.
- Startup recovers from read and write failures in retired services' archives.
- Portable runtime bundles can no longer mix versions.

Everything in 0.8.6 is included.
