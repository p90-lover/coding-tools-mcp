# v0.4.4-rc.5 — Live project/permission refresh and bounded long-task observations

## English

Targets reproduced local contributors to apparently stuck tasks. It does not establish the cause of a particular ChatGPT screenshot, guarantee every task completes, keep a ChatGPT turn alive indefinitely, or override platform tool eligibility. No user Windows process or CoC account is inspected by release tests.

The previous project-baseline scanner read each file entirely into memory, enumerated excluded trees before skipping them, and could run without an application budget. A project_state max_files argument restricted display, not scanning. The new scanner prunes the original excluded directory set before descent, hashes through a 64 KiB buffer, admits one baseline scan per workspace, and applies 32 MiB per-file, 128 MiB aggregate, 20,000-entry and eight-second cooperative limits. Git metadata has a one-second child-process limit within that budget. File/read/type/change errors and exhausted budgets reject the baseline; no partial result can authorize writes. The output's clean flag is computed before display truncation. Already-blocked filesystem I/O cannot be interrupted by a cooperative deadline, and valid projects exceeding these limits require a deliberately scoped workflow rather than blind retries. No model file or project data is removed or excluded automatically.

Error reporting no longer triggers another full baseline scan. task_context now honors its advertised max_bytes range (8–128 KiB, default 32 KiB) for the task-context payload. Shared project instructions and transport metadata are additional. A bounded response labels omitted baseline entries, shortened text and omitted events; original stored tasks/events remain intact. next_event_cursor refers to the first omitted event, not the end of an unread page. It is a presentation bound, not a new bound on all historical file loading. A summary never implies a verified complete baseline.

Existing live authorization is extended rather than replaced. Explicit changes in the MCP permission form automatically save; hydration does not. The UI serializes saves, shows progress and reports unconfirmed failures without pretending permissions were applied. Long observations no longer hold an execution-policy read lock throughout scanning; their results are withheld if the policy revision changed. Protected writes retain the existing commit/admission fence. A sensitive short commit can still cause LIVE_POLICY_BUSY, requiring reassessment rather than unsafe lock bypass. Existing owned command/sandbox revocation on permission changes is retained. No listener, tunnel, OAuth secret or model session is restarted by a successful policy save. Tool-profile metadata changes may still require the ChatGPT client to refresh its cached tool list.

The workspace sidebar refreshes after successful explicit additions/changes, on focus and every five seconds, with one in-flight metadata read and stale-response suppression. It does not start runtimes or automatically link all profiles. An explicitly approved linked project is available to the next MCP request using the existing listener. Its writable status is the intersection of current workspace policy and the linked root's mode. Merely creating a folder or a separate workspace does not grant the current connector access.

Each request snapshots the approved linked mappings. Further path resolution and protected admission reject changed mappings; stale requests cannot silently acquire a newly added alias. Invalidated default CWD falls back to the primary workspace. Recovery caches are also tied to the roots digest, so removed/remapped roots do not leak old cached results. These are checked boundaries, not OS revocation of file handles or already-running external processes. Manual .mcp-paths edits do not terminate external processes. The prior explicit absolute-read behavior is unchanged; removing an alias revokes that alias and its write authority, not a claim of blocking every independently allowed absolute read. The existing snapshot AppContainer consent remains separately required.

Verification covers actual bounded baseline rejection and unchanged valid fingerprints, actual task_context truncation with original event preservation, live bearer-authenticated reads/writes and permission/root changes on one Rust listener, and the compiled auto-save/sidebar UI with synthetic Tauri IPC. Existing OAuth with extension v0.0.7, timeout recovery, protocol-control, selected schema and AppContainer/permission checks remain release gates. Only synthetic projects, credentials and loopback servers are used; no Codex executable, inference model, live account, game action or file-deletion command is invoked.

Windows x64, publisher-unsigned prerelease. Source/tag/main/installer identity and uploaded-byte readback are checked before publication. Preserve configuration and extension v0.0.7. Resolve unknown in-flight operations before stopping Desktop to upgrade because operation receipts are RAM-only. For a long command use its returned command/task ID; inspect status/output rather than redispatching after 408. Save not confirmed, running, waiting for approval, scan limited and completed are distinct states. Existing files, branches and prior releases are retained; temporary and replaced originals stay under aiTemp/Trash. Complete Paseo/Anneal orchestration is not added by this release.

## 繁體中文

本版本處理已重現、可能令任務看似卡住的本機問題，但不代表已確認某張 ChatGPT 截圖的根因、不保證所有任務永遠成功，也不能令 ChatGPT 對話永久運行或覆寫平台工具權限。發佈測試不會查驗使用者的 Windows 程序或 CoC 帳戶。

舊專案基準掃描會整份讀取檔案，並先遍歷排除目錄才略過，亦沒有應用程式掃描預算；project_state 的 max_files 只限制顯示。新掃描器在進入目錄前沿用原有排除規則，以 64 KiB 緩衝區計算雜湊，每個工作區最多一個掃描，限制每檔 32 MiB、合計 128 MiB、20,000 項及八秒合作式期限。Git metadata 子程序另限一秒且受總預算限制。檔案、讀取、類型、內容變動或超限一律拒絕基準，不會讓不完整結果授權寫入；clean 狀態在截短顯示前計算。合作式期限不能中斷已阻塞的檔案系統 I/O，超出限制的有效專案需要明確縮小工作範圍，不能盲目重試；不會自動移除或排除模型／專案資料。

錯誤回報不再觸發第二次完整掃描。task_context 會遵守已公開的 max_bytes 範圍（8–128 KiB，預設 32 KiB），只限制 task-context 本文；共用專案指示及傳輸 metadata 另計。被省略的基準項目、截短文字及事件均會標示，原始任務／事件仍保留；next_event_cursor 指向第一個未顯示事件，不會跳過整個未讀分頁。這是顯示上限，不代表所有歷史檔案載入都有新上限，也不能把摘要當成完整基準驗證。

擴充原有即時授權，而非重建權限系統。MCP 權限表單的明確操作會自動儲存，初次載入不會。介面限制同時只送出一個儲存、顯示進度，失敗時標示未確認，不冒稱已生效。長時間觀察不再全程持有執行策略讀鎖；若期間權限版本改變，其結果不會回傳。受保護寫入仍保留提交／准入防護；短暫敏感提交可能返回 LIVE_POLICY_BUSY，須重新核對而非繞過鎖。保留權限變更時對所屬命令／沙箱的撤銷。成功儲存不重啟 listener、隧道、OAuth 密鑰或模型會話；改變工具目錄時，ChatGPT 自己的 metadata 快取仍可能需要刷新。

工作區側欄會在成功明確新增／變更後、重新聚焦及每五秒刷新一次，只允許一個進行中 metadata 讀取並抑制過時回應；不啟動 runtime，也不會把所有 profile 自動互相連結。明確批准的 linked project，可在同一 listener 的下一次 MCP 請求使用。可寫狀態取決於目前工作區權限及該 root 的 mode；只建立資料夾或另一個獨立工作區，並不會授權目前連接器存取。

每次請求會快照已批准的連結對應。對應改變後，後續路徑解析及受保護准入會拒絕，舊請求不能悄悄取得新 alias；失效的預設 CWD 回退主工作區。操作恢復快取亦綁定 roots digest，移除／改指向後不會洩漏舊快取結果。這些是檢查邊界，不是作業系統對已開啟 handle 或運行中外部程序的強制撤銷；手動修改 .mcp-paths 不會終止外部程序。原有明確絕對路徑讀取行為不變；移除 alias 撤銷的是該 alias 及其寫入權，不是宣稱阻止所有獨立允許的絕對路徑讀取。快照 AppContainer 仍需另外的本機同意。

驗證涵蓋真正基準超限拒絕及有效指紋、task_context 截短且保留事件、同一 Rust listener 的 Bearer 認證讀寫／權限／root 變更，以及使用模擬 Tauri IPC 的真正编譯自動儲存／側欄畫面。保留 OAuth／擴充功能 v0.0.7、逾時恢復、協定控制、指定 schema 及 AppContainer／權限檢查。只使用測試專案、憑證及 loopback 伺服器，不啟動 Codex、模型推論、真實帳戶、遊戲操作或刪除檔案指令。

提供 Windows x64 未簽章預發佈版，核對原始碼／tag／main／installer 及上傳後重新下載檔案才公開。保留設定及擴充功能 v0.0.7；因操作紀錄只存在 RAM，停止 Desktop 升級前先核實未知執行。長命令應使用回傳的 command／task ID 查狀態／輸出，不要在 408 後重新派發。儲存未確認、運行中、待批准、掃描受限及完成必須分開理解。保留既有檔案、分支及舊 Release；暫存和被取代原件置於 aiTemp／Trash。本版本未加入完整 Paseo／Anneal 協調引擎。
