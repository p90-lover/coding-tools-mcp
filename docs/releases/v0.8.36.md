# Coding Tools 0.8.36

## English

### Update safety
- An update is kept only once the new version proves it works: its window loaded, its backend answered and AO, when started, is ready. Until then the previous version's files stay beside the new ones, and a version still failing after the health window goes back to the previous version by itself, never while a chat is running. Before, an update was kept as soon as the app started, so a version that failed afterwards could not go back (PR #698).
- A launch no longer starts over an update that is still copying its files: it waits for a live update for up to an hour instead of 10 minutes (PR #698).
- An MCP tunnel left running by a different build is restarted instead of reused, so the tunnel runs the program this version ships (PR #698).
- A settings or key file torn by a crash or power loss is read back from its last good copy (PR #695).

### Settings
- Settings, laid out as Codex's, opens from the gear at the bottom of the chat sidebar or with Ctrl+, (press again to close). General: start at login, keep running when the window is closed. Updates: check now, automatic updates, wait for chats to finish, idle time before installing, roll back a failed update, health check window, reuse background services only when they match (PR #698).

### Fixes and speed
- rtk starts from a worker thread and the log history loads in the background: 0.8.35's first start showed them holding every window for 1.6 s and 1.3 s, and rtk ran before every agent command (PR #691). Every MCP tunnel command now starts off the main thread too (PR #697).
- A ready tunnel is not torn down over one slow health check, a timed-out tunnel probe is checked again instead of read as another owner, and stopping the tunnel gets 30 s (PR #690, PR #692).
- An idle AO stops re-reading every session (PR #694).
- Removing a browser account removes it from every list at once (PR #696).
- Clawd holds its tool in the hand on the tool's side (PR #693).

### Verification and limitations
- Build the Windows installer, portable ZIP and update packs from this branch and confirm CI before publication.
- The health gate and rollback run for the first time on the update after this one: this version's own install is still kept the old way.
- Everything in 0.8.35 is included.

## 繁體中文

### 更新安全
- 新版本必須先證明可正常運作（視窗已載入、後端已回應、AO 啟動後已就緒）才會保留更新；在此之前，舊版本的檔案會與新檔案並存。若新版本在健康檢查時限後仍未正常，會自動回復到上一個版本，但在有對話執行期間絕不回復。以往應用程式一啟動就保留更新，之後才失敗的版本無法回復（PR #698）。
- 啟動時不會再在更新仍在複製檔案時開始運作：會等待仍在執行的更新最多一小時，而不是 10 分鐘（PR #698）。
- 由其他版本留下的 MCP 通道會重新啟動而不是沿用，確保通道執行本版本附帶的程式（PR #698）。
- 因當機或斷電而損壞的設定檔或金鑰檔，會從最後一份完好的副本讀回（PR #695）。

### 設定
- 新增仿照 Codex 版面的「Settings」頁面：可從聊天側欄底部的齒輪或 Ctrl+, 開啟（再按一次關閉）。一般：登入時啟動、關閉視窗後繼續執行。更新：立即檢查、自動更新、等待對話完成、安裝前的閒置時間、自動回復失敗的更新、健康檢查時限、只在版本相符時沿用背景服務（PR #698）。

### 修正與效能
- rtk 改由背景執行緒啟動，記錄歷史改為在背景載入：0.8.35 首次啟動時，兩者分別令所有視窗停頓 1.6 秒及 1.3 秒，而 rtk 在每個代理指令前都會執行（PR #691）。所有 MCP 通道指令也改為不在主執行緒啟動（PR #697）。
- 已就緒的通道不會因一次緩慢的健康檢查而被關閉；逾時的通道探測會再次檢查，不會被視為由其他程序擁有；停止通道有 30 秒時間（PR #690、PR #692）。
- 閒置的 AO 不再重複讀取每個工作階段（PR #694）。
- 移除瀏覽器帳戶時，會同時從所有清單移除（PR #696）。
- Clawd 會把工具拿在工具所在那一側的手上（PR #693）。

### 驗證及限制
- Windows 安裝程式、免安裝 ZIP 和更新檔需由本分支編譯及通過 CI 才能公開。
- 健康檢查與自動回復會在本版本之後的下一次更新首次運作；本版本自身的安裝仍以舊方式保留。
- 包含 0.8.35 的所有內容。
