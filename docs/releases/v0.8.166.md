# Coding Tools v0.8.166

## English

### Chats
- **Fast mode for Codex and Claude.** The effort menu has a Fast switch for models that can run fast: Codex models with a fast tier (on Codex's own sign-in and through CPA, which sends OpenAI's priority tier) and Claude Opus models CPA serves from Anthropic. The Provider Manager's Codex and Claude rows have "Fast mode for new chats", the default a new chat starts with; a pick in the effort menu wins and is remembered per model. Changing it on an open chat starts the next message on a new agent, as an effort change does. Fast mode costs more usage; Anthropic bills it as extra usage credits and refuses it without them.

### Goals
- **A goal now keeps going until it is met.** A /goal used to stop for good on things that never meant it was met: three rounds without progress, a few failed rounds or checks, quick rounds, a used-up quota or refused request, a chat that stayed busy, or an error starting the next round (seen live: a full disk, "Workflow revision changed"). Each of these now waits and tries again, after 1, 5, 15, 30, then 60 minutes in a row, and the note says why. Progress, /goal resume or a met goal start the waits over. A round waiting on you keeps the goal going once you answer. A goal ends only when it is met, or when you stop, pause, edit, clear or limit it.
- **Each goal round tells the agent where its turn ends.** Every round's message now closes with the goal's rules: keep working in this turn until the condition holds and you have checked it; don't stop to summarise, ask whether to go on, or list next steps; stay inside the condition instead of swapping in an easier task; if only you can unblock a part, say exactly what and keep working on the rest; end with what was done, how it was checked and what is left. The chat still shows only your condition and the evaluator's reason.
- **A goal is judged done only when all of it is done.** The goal evaluator now needs evidence for every part of the condition, judges the condition as you wrote it rather than as the agent restated it (a unit test doesn't count where you asked for it working live, nor one account where you asked for all), treats "implemented" or "should work" as claims rather than evidence, and reads any remaining work or next steps in the agent's answer as not done. When it is not met, its reason tells the agent exactly which parts are missing and how to show them.

### Approve for me
- **A Codex sign-in out of usage no longer stalls approval reviews.** When the Codex CLI's ChatGPT sign-in hits its usage limit during a Guardian review, Guardian is marked unavailable at once instead of retrying the same spent account (which set off three workflow retries), and that account rests for 10 minutes or until its sign-in changes. Guardian's server also keeps its temporary files inside its own profile, which Codex 0.172.0 needs.

Includes all changes from v0.8.165.

## 繁體中文

### 對話
- **Codex 與 Claude 的快速模式。** 推理強度選單為可快速執行的模型提供「Fast」開關：具快速層級的 Codex 模型（Codex 自身登入或經 CPA，CPA 會改送 OpenAI 的 priority 層級），以及 CPA 由 Anthropic 提供的 Claude Opus 模型。供應商管理員的 Codex 與 Claude 列新增「新聊天預設快速模式」，作為新聊天的起始值；在推理強度選單中的選擇優先，並按模型記住。在進行中的聊天變更此設定時，下一則訊息會由新的代理開始，與變更推理強度相同。快速模式用量較高；Anthropic 以額外用量點數計費，沒有點數時會拒絕。

### 目標
- **目標現在會持續進行，直到真正達成為止。** 以前 /goal 會因為一些並不代表目標已達成的狀況而永久停止：連續三輪沒有進展、幾次回合或檢查失敗、過短的回合、額度用完或請求被拒、聊天一直忙碌，或啟動下一輪時出錯（實際看到：磁碟已滿、「Workflow revision changed」）。現在遇到這些情況都會等待後再試，連續發生時依序等待 1、5、15、30 分鐘，之後每次 60 分鐘，並在附註中說明原因。有進展、執行 /goal resume 或目標達成時，等待會重新計算。等待你處理的回合，在你回覆後目標會繼續。目標只會在達成時，或你停止、暫停、編輯、清除或限制它時才結束。
- **每一輪目標都會告訴代理這一輪何時才算結束。** 每輪訊息的結尾現在都附上目標規則：在這一輪內持續工作，直到條件成立並親自確認；不要停下來做摘要、詢問是否繼續或列出下一步，直接去做；只處理條件本身，不要換成較簡單的任務；若某部分只有你能解除阻礙，要明確說出需要什麼，並繼續處理其他部分；結尾說明做了什麼、如何確認以及還剩什麼。聊天畫面仍然只顯示你的條件和評估者的理由。
- **只有全部完成時，目標才會被判定為完成。** 目標評估者現在要求條件的每個部分都有證據，並依你寫下的條件判斷，而不是代理改寫後的版本（你要求實際運作時，單元測試不算數；你要求所有帳號時，單一帳號也不算數）。「已實作」或「應該可以」會被視為說法而非證據，代理回覆中若還列有待辦工作或下一步，就視為尚未完成。未達成時，評估者的理由會明確告訴代理缺少哪些部分，以及要如何證明。

### 代我核准
- **Codex 登入的額度用完時，核准審查不再卡住。** 當 Codex CLI 的 ChatGPT 登入在 Guardian 審查期間達到用量上限時，Guardian 會立即標示為無法使用，而不再重試同一個已用完的帳號（以前會觸發三次工作流程重試），該帳號會暫停 10 分鐘，或直到其登入變更為止。Guardian 的伺服器也會把暫存檔案放在自己的設定檔內，這是 Codex 0.172.0 所需要的。

包含 v0.8.165 的所有變更。
