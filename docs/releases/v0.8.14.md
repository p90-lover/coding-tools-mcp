Coding Tools 0.8.14

Updates in-app from rc.19 and later. On rc.18 or earlier, install the Windows installer or unpack the portable ZIP with the app closed.

The chat sidebar and queued messages are Claude Code's:

- Projects are Claude Code's folder groups: the folder's name and a caret, no folder icon, and "+" on hover for a new chat there. A collapsed project shows a dot for its most urgent chat (waiting on you, running, or unread). Its menu is on right-click.
- Chats are one line with a status dot only when something is happening: grey and blinking while running, amber when it waits on you, blue when unread. On hover the dot gives way to one "More options" button that holds Pin, Archive and the rest.
- Claude Code's sizes and colours: a 288 px sidebar, 28 px rows, 13 px titles that fade out at the end, 12 px muted group headers.
- A message sent while the agent works waits in Claude Code's queued bar, above the branch bar: "1 message queued" with the message on one line, then Send now, Edit and Remove. One on its way to the agent spins. Two or more fold into "N messages queued · Next: …", which opens a list with a ⋮ menu on each message and Clear all.

Steering and stopping like Claude Code:

- A message typed while the agent works never stops it: only a turn the chat itself calls "may be stuck" is restarted. Enter is never ignored; a message that can't go yet waits in the queued bar and goes the moment it can.
- A chat whose agent process died (often after repeated 429s) stops, steers and resends at once, and its turn says why it stopped. Before, steering showed "the agent controller for this session is not running" and Stop took 30 seconds.
- The agent's wake-up can be edited or deleted: the trash icon deletes it, and the edit icon (or a click on its note) changes the note and the minutes from now.
- An agent left "working" by an app restart, with nothing happening for two hours, is stopped instead of running for good; its chat resumes it with your next message.
- A model CPA no longer serves at all ("unknown provider for model") leaves the model menu until CPA lists it again, and the failed step says to choose another model instead of retrying it three times.

Knowing why a turn is quiet:

- When CPA keeps refusing a turn's model, the turn says so: "CPA refused the last 6 requests: rate limited (429)", with what helps (switch the model or wait, or sign in again). This covers a subagent's requests too, which show no retry notice.
- A sandboxed chat agent is told that programs with windows run on the sandbox's hidden desktop, so it hands you the command to open them instead of waiting on a window nobody can see.

Approve for me:

- The command reviewer sees what you asked in the chat and the agent's own description of the command, so stopping a process you asked it to restart is no longer denied for lack of context.
- Archiving a chat whose agent had stopped no longer fails.

A smoother app on a busy disk:

- Window moves, process stops, the models cache, rtk lookups and polling reads no longer block the app's main thread, which froze the app while the disk was busy.
- The chat's Overview and branch bar stop running git while another app is in front and run one read at a time; the Overview no longer computes a diff it never shows.
- Agent Orchestrator no longer re-reads every untracked file each time the file list refreshes (a project with 52,000 untracked files kept the disk busy without end).

ChatGPT Web:

- Codex goal rounds no longer stall on "composer did not preserve the complete prompt", and a failed context handoff says why.

Also:

- Shorter, plainer wording across the app's labels, notices and errors.
- Test runs no longer leave folders in %TEMP%.
