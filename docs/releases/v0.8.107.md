# Coding Tools 0.8.107

## English

### Chats: Claude agents keep working through a wait instead of stopping (#1163)
- **A Claude chat that had to wait for something slow (a build, a release, a server starting) often stopped for good.**
  - It ended its turn after arming one of Claude Code's own wake-ups, a Monitor, a ScheduleWakeup or a background command, saying something like "monitoring is active". The chat then read Done.
  - When the wake-up fired, Claude Code started working again on its own, but outside any turn the app or the agent service could see. Its first request for permission was shown to nobody and checked by nobody, so the agent waited on it forever and never continued.
  - Seen on 2026-11-09: one chat waited 3½ hours on such a request after its Monitor expired, and two Clash of Clans chats were left the same way.
- **Claude chats no longer get those wake-ups.** Monitor and ScheduleWakeup are turned off, and so are background commands and cron.
  - To wait, the agent now uses the app's own tools: "Wake me up later" (`schedule_wakeup`), or a command started in the chat's terminal with a watch on it (`watch_command`).
  - Each of those sends the chat a real follow-up turn. You see it, "Approve for me" checks its requests, and the agent carries on until the task is done.
- A Claude agent can no longer leave a command running in the background of its own shell. For a long command it is told to use the chat's terminal pane (`exec_command`), where you can watch it.

### Verification and limitations
- GitHub Actions is unavailable for this repository. This release was built, tested and published locally from the merged `main`, following the release workflow's steps.
- #1163: traced on the user's machine through the agent service's own records of the stuck chat. Its turn completed at 10:40:54Z. A self-started cycle began at 11:10:10Z when the Monitor expired. Its PowerShell approval, created at 11:10:38Z with no turn, was still pending at 14:30Z.
  - It moves `module/agent-orchestrator` to 72d3bcd25 (agent-orchestrator#25), and the AO daemon is rebuilt from that pin. A new AO test checks that every Claude session, native or through CPA, gets the tool and environment settings.
  - A capture of Claude Code 2.1.312's first request (local server, dummy key) shows ScheduleWakeup and Monitor gone, and Bash and PowerShell without `run_in_background`.
  - Release identity tests: 18/18.
- Messages from your other local Claude sessions (SendMessage, idle notices) can still start an agent's work outside a turn; that needs a larger change in the agent service.
- Includes everything in 0.8.106.

## 繁體中文

### 對話：Claude 代理在等待期間會繼續工作，不再停住（#1163）
- **Claude 對話需要等待較慢的工作（建置、發佈、伺服器啟動）時，經常就此停住。**
  - 它會先設定 Claude Code 自己的喚醒機制（Monitor、ScheduleWakeup 或背景指令），然後結束回合，並說「正在監控」之類的話。對話隨即顯示為已完成。
  - 喚醒觸發時，Claude Code 會自行重新開始工作，但不在 App 或代理服務看得到的任何回合內。它提出的第一個權限請求沒有人看到、也沒有人審核，於是代理永遠等在那裡，不會繼續。
  - 2026-11-09 實際發生：一個對話在 Monitor 到期後，卡在這樣的請求上 3 個半小時；另有兩個部落衝突對話也同樣停住。
- **Claude 對話不再提供這些喚醒機制。** Monitor 與 ScheduleWakeup 已關閉，背景指令與排程（cron）也一併關閉。
  - 需要等待時，代理改用 App 自己的工具：「稍後喚醒我」（`schedule_wakeup`），或在對話的終端機中執行指令並加以監看（`watch_command`）。
  - 兩者都會讓對話收到真正的後續回合：你看得到它，「替我核准」會審核其請求，代理也會一路繼續直到工作完成。
- Claude 代理不能再把指令留在自己 shell 的背景中執行。較長的指令，代理會被指示改在對話的終端機窗格（`exec_command`）中執行，你可以在那裡看到它。
