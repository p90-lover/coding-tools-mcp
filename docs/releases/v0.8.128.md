# Coding Tools v0.8.128

## English

### CPA

- **Chats on GPT-5 and GPT-6 models work again through an OpenAI API key.** When CPA sent a coding agent's request to an API-key provider at api.openai.com, OpenAI refused it: "Function tools with reasoning_effort are not supported … use /v1/responses", or "Invalid 'tools': array too long" (152 tools sent, 128 allowed). Chats on GPT-6 Astra and GPT-6.1 Sol failed whenever the key was picked instead of a ChatGPT account, which is every time once the accounts' quota is used up. CPA reaches such a provider through `/v1/chat/completions`, and OpenAI accepts those requests only on `/v1/responses`.
- **What the app does now.** Each time it writes CPA's settings, it gives every enabled OpenAI API-key provider a second entry, named "… (Responses)", that uses the same key through `/v1/responses`. The provider's GPT-5 and later and o-series chat models move to that entry. Speech, image, embedding, search and older chat models stay where they were, and no priority changes. If you disable the provider, point it elsewhere or remove its key, the models go back and the second entry is removed.
- **What you will see.** In Provider Manager, the OpenAI API-key provider lists fewer models, and a "… (Responses)" entry with the rest appears under Codex API keys. It takes effect when the app next starts or adopts CPA after the update. Small requests to those models cost a little more input, because CPA adds its standard instructions on that route (about 340 tokens in our test).

### Verification

- The batch is main 7641706ba (v0.8.127) plus this change.
  - Six new tests cover the split, the fields CPA accepts, repeated writes, a re-fetched model list, and a provider that is disabled, moved or left without keys. 108 of 108 tests pass in the 14 test files that load the CPA settings writer.
  - Asked directly, with the owner's approval and their own key: OpenAI's `/v1/responses` answered 200 for tools with a reasoning level, for 152 tools, and with a reasoning summary at the highest effort; `/v1/chat/completions` answered 400 for the same tools with a reasoning level.
  - On a separate test copy of CPA 8.0.75 holding only that key and the new settings: agent-shaped requests with 152 tools answered 200 on gpt-5-nano, gpt-6.1-sol and gpt-6-astra; streamed requests came back as tool calls; plain chats worked on both routes. Without the "not as the Codex client" setting the same key was refused on the new route, so the app sets it.
- Release identity checks validate the matching product, package and packaging versions. CI ran the full desktop suite on this batch before it merged. Packaging and publication run through GitHub Actions.
- The change was not applied to the running CPA or checked in the installed app before publishing. It was tested with one organization's key; another organization's limits may differ.
- Everything in 0.8.127 is included.

## 繁體中文

### CPA

- **透過 OpenAI API 金鑰使用 GPT-5 和 GPT-6 模型的對話又能運作了。** CPA 把程式代理程式的要求送到 api.openai.com 的 API 金鑰供應商時，OpenAI 會拒絕：「Function tools with reasoning_effort are not supported … use /v1/responses」，或「Invalid 'tools': array too long」（送出 152 個工具，上限 128 個）。只要選到金鑰而不是 ChatGPT 帳號，GPT-6 Astra 和 GPT-6.1 Sol 的對話就會失敗；帳號配額用完後則每次都失敗。CPA 透過 `/v1/chat/completions` 連接這類供應商，而 OpenAI 只在 `/v1/responses` 接受這些要求。
- **應用程式現在的做法。** 每次寫入 CPA 設定時，會為每個已啟用的 OpenAI API 金鑰供應商加上第二個項目，名稱為「…(Responses)」，以同一把金鑰透過 `/v1/responses` 連線。供應商的 GPT-5 以後和 o 系列對話模型會移到這個項目。語音、影像、嵌入、搜尋和較舊的對話模型留在原處，優先順序不變。如果你停用供應商、改指向其他位址或移除金鑰，模型會移回去，第二個項目也會移除。
- **你會看到的變化。** 在 Provider Manager 中，OpenAI API 金鑰供應商列出的模型變少，其餘模型出現在 Codex API 金鑰下的「…(Responses)」項目。更新後，應用程式下次啟動或接管 CPA 時生效。對這些模型的小型要求，輸入會稍微增加，因為 CPA 在這條路由會加上它的標準指示（我們的測試約 340 個 token）。
