# Coding Tools 0.8.35

## English

### Fixes
- An interrupted or failed app update repairs itself. A half-applied update rolls forward or back on the next start instead of leaving an app that will not start, missing runtime files are restored, and a full disk is reported instead of retried every hour (PR #687).
- The Register tab no longer drops to "Loading Register…" when the window briefly freezes. A health answer that arrived during the freeze is read before the check gives up, and a ready Register service that is slow for a moment keeps its page; only one that stays silent through three checks is taken down.
- A stale CPA is found and replaced even when Windows' netstat leaves its listener on port 8317 out (PR #677).
- With "Approve for me" on, a request the reviewer may still accept no longer pops up an approval box (PR #685).
- A tunnel that is still starting when its connect step gives up is waited out instead of restarted every two minutes (PR #686).
- A goal moved to another model stops retrying the old one, and a request the provider refused is not retried (PR #680). Stop shows while a step waits to retry, and a restart does not resume refused requests (PR #681).
- A model whose quota is used up sits out until its reset instead of failing every goal check, and the Antigravity CLI terminal opens again (PR #684).
- A saved effort that a CPA plugin model does not take runs at its nearest level instead of failing (PR #682).
- Questions and approvals sit below the chat box (PR #683), and a composer menu in a split pane no longer scrolls the pane sideways (PR #679).
- CPA's Auth Files page shows the OpenCode Go quota and loads idle quota cards; chats restore one at a time (PR #678).

### Diagnostics
- Every main-process stall now names the call that held it. A synchronous call that holds the main thread for 250 ms or more (starting a process, or a file read or write on a busy drive) is logged as `launcher.main_blocked` with its operation, file or program name and calling site, and `launcher.main_stalled` carries it as `blockedBy`. This finds the cause of the window freezes seen on loaded machines.

### Verification and limitations
- Build the Windows installer, portable ZIP and update packs from this branch and confirm CI before publication.
- The window freezes themselves are not fixed yet: this release names their cause so the next one can.
- Everything in 0.8.34 is included.

## 繁體中文

### 修正
- 應用程式更新中斷或失敗時會自行修復：只套用一半的更新會在下次啟動時繼續完成或還原，不再留下無法啟動的應用程式；遺失的執行環境檔案會被還原；磁碟已滿時會回報，而不是每小時重試（PR #687）。
- 視窗短暫凍結時，「Register」分頁不再跌回「Loading Register…」：凍結期間已收到的健康檢查回應會在逾時前讀取；已就緒的 Register 服務短暫變慢時保留頁面，只有連續三次檢查都沒有回應才會關閉。
- 即使 Windows 的 netstat 沒有列出 8317 埠的監聽，也能找到並取代過時的 CPA（PR #677）。
- 開啟「Approve for me」時，審核者可能仍會接受的請求不再彈出核准方塊（PR #685）。
- 連線步驟放棄時仍在啟動中的通道會被等待完成，而不是每兩分鐘重新啟動（PR #686）。
- 目標改用其他模型後不再重試舊模型，供應商拒絕的請求不會重試（PR #680）；步驟等待重試時會顯示「Stop」，重新啟動後不會繼續已被拒絕的請求（PR #681）。
- 配額用盡的模型會暫停至重設時間，不再令每次目標檢查失敗；Antigravity CLI 終端機可再次開啟（PR #684）。
- CPA 外掛模型不支援已儲存的推理強度時，會以最接近的級別執行，而不是失敗（PR #682）。
- 提問和核准方塊顯示在聊天輸入框下方（PR #683）；分割窗格中的輸入框選單不再令窗格橫向捲動（PR #679）。
- CPA 的「Auth Files」頁面會顯示 OpenCode Go 配額並載入閒置的配額卡片；對話逐一還原（PR #678）。

### 診斷
- 每次主程序停頓都會記錄造成停頓的呼叫：在主執行緒上佔用 250 毫秒或以上的同步呼叫（啟動程序，或在繁忙磁碟上讀寫檔案）會記錄為 `launcher.main_blocked`，包括操作、檔案或程式名稱及呼叫位置；`launcher.main_stalled` 會以 `blockedBy` 附上該呼叫，用來找出負載重的電腦上視窗凍結的原因。

### 驗證及限制
- Windows 安裝程式、免安裝 ZIP 和更新檔需由本分支編譯及通過 CI 才能公開。
- 視窗凍結本身尚未修正：本版本會記錄其原因，以便下一版修正。
- 包含 0.8.34 的所有內容。
