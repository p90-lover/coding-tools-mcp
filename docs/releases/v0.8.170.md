# Coding Tools v0.8.170

## English

### Antivirus
- **Coding Tools no longer runs PowerShell in a way antivirus treats as malware.** On Nov 27 Bitdefender's Advanced Threat Control flagged Coding Tools as malicious, closed it, and quarantined its programs plus 115 files they had written: CPA sign-ins, chat goals and drafts, and window state. The trigger was the process list Coding Tools reads for agents: a hidden (encoded) PowerShell command with execution policy turned off, listing every process. That command now runs in plain text, and Coding Tools no longer turns execution policy off anywhere (doing so had no effect on these commands).

### Goals
- **A goal is no longer called done while the agent says work is left.** A goal could end as "achieved" while the agent's own final answer still had a "What's left", "Still open" or "Next steps" section, for example upgrades that still did not run. A goal is now never met while its last answer lists work left. The agent is told to do that work, or to say plainly that an item is outside the goal.
- **A second checker must agree before a goal ends.** The quick model that checks each round can misjudge an open-ended goal. When it says the goal is met, a second model, from another provider when one is available, now checks the same round. If they disagree, the goal goes on with the second checker's reason. If the second check can't run, the first verdict stands.
- **The agent can no longer stop its own goal by reporting a blocker.** Three "blocked" reports in a row used to stall the goal. The goal now stays active. After three reports in a row, the wait before each new round gets longer, as it does for rounds that make no progress. A goal ends only when it is met, or when you stop, pause, edit, clear or limit it.

### Chat commands
- **A command that can't run here says why.** Typing /stop with nothing running, /retry or /structure before the chat's first turn, or /fork, /loop or /compact with no chat open used to clear the box and do nothing. Each now says why it can't run, matching the commands the menu leaves out.

### Computer use
- **Click a numbered control from a recent window view.** Coding Tools rechecks the same approved window during the click. If the view has changed or expired, it sends no input. The helper releases input control after the operation as before.

Includes all changes from v0.8.169.

## 繁體中文

### 防毒軟體
- **Coding Tools 執行 PowerShell 的方式不會再被防毒軟體視為惡意程式。** 11 月 27 日，Bitdefender 的進階威脅防禦（Advanced Threat Control）將 Coding Tools 判定為惡意程式，關閉了它，並隔離了它的程式以及這些程式寫入的 115 個檔案：CPA 登入資料、對話目標與草稿，以及視窗狀態。觸發原因是 Coding Tools 為代理讀取處理程序清單的方式：一個經過編碼隱藏、關閉執行原則並列出所有處理程序的 PowerShell 指令。現在這個指令改以明文執行，Coding Tools 也不再在任何地方關閉執行原則（關閉執行原則對這些指令本來就沒有作用）。

### 目標
- **代理表示還有工作沒做完時，目標不會再被判定為完成。** 先前即使代理的最終回覆裡仍有「還剩什麼」、「尚未完成」或「下一步」段落（例如升級仍未執行），目標也可能被標為「已達成」。現在只要最後一則回覆還列出剩餘工作，目標就不會被判定為達成。代理會被要求完成這些工作，或明確說明哪一項不在目標範圍內。
- **目標結束前，必須有第二個檢查者同意。** 每一輪負責檢查的快速模型可能誤判開放式目標。當它判定目標已達成時，會再由第二個模型（有可用時會選擇其他供應商）檢查同一輪。兩者意見不同時，目標會依第二個檢查者的理由繼續進行。若第二次檢查無法執行，則維持第一次的判定。
- **代理無法再藉由回報阻礙來停止自己的目標。** 先前連續三次回報「blocked」就會讓目標停滯。現在目標會保持進行中。連續回報三次後，每一輪開始前的等待時間會逐漸拉長，與沒有進展的回合相同。目標只會在達成時，或你停止、暫停、編輯、清除或限制它時才結束。

### 對話指令
- **無法在此執行的指令會說明原因。** 先前在沒有任何工作執行時輸入 /stop、在對話第一輪之前輸入 /retry 或 /structure，或在沒有開啟對話時輸入 /fork、/loop 或 /compact，都只會清空輸入框而沒有任何反應。現在每個指令都會說明無法執行的原因，與選單中不顯示的指令一致。

### 電腦操作
- **從最近的視窗檢視點擊編號控制項。** Coding Tools 會在點擊時重新檢查同一個已核准的視窗。若檢視已變更或逾時，就不會送出任何輸入。原生輔助程式仍會在操作後釋放輸入控制。

包含 v0.8.169 的所有變更。
