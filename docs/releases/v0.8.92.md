# Coding Tools 0.8.92

## English

### Chat
- **Requests waiting for you show their approval box again.** A chat could say "waiting for approval" with nothing to answer, and Continue didn't help. Seen on 2026-11-06 in two goal chats: each had a file write waiting for you, too long for the reviewer to read whole.
  - The cause: the chat kept watching the run it was opened on, after the app no longer listed that run. It asked the old run for requests, found none, and never showed the new round's request.
  - Now a chat waits 15 seconds for a run that isn't listed yet, such as one you just started. After that it switches to the chat's working run, or its newest, and that run's requests show as usual.

### Verification and limitations
- New tests cover a missing run: it's still waited for within 15 seconds, then the chat moves to the working run, or to the newest when none is working. The type check and 310 chat and surface tests pass.
- Not checked in the installed app. The cause was found in the running app: both chats were polling runs that were no longer listed, while the app held each chat's request with "check it yourself".
- Built and published by GitHub CI from main; no local build was made for this version.
- Includes all changes in 0.8.91.

## 繁體中文

### 對話
- **等待你處理的請求會再次顯示審批方塊。** 對話可能顯示「等待審批」，卻沒有可回答的內容，按「繼續」也沒有作用。2026-11-06 在兩個目標對話中出現：每個對話都有一個寫入檔案的請求在等你，內容太長，審查員無法完整閱讀。
  - 原因：應用程式不再列出對話開啟時的那個執行後，對話仍在監看它。對話向舊的執行查詢請求，查不到任何請求，因此新一輪的請求從未顯示。
  - 現在，若某個執行尚未列出（例如剛開始的執行），對話會等待 15 秒。之後便會轉到對話正在進行的執行，或最新的執行，該執行的請求會照常顯示。

### 驗證及限制
- 新測試涵蓋找不到執行的情況：15 秒內仍會等待，之後對話會轉到正在進行的執行；若沒有正在進行的，就轉到最新的執行。型別檢查及 310 項對話與介面測試全部通過。
- 尚未在已安裝的應用程式中確認。原因是在執行中的應用程式裡找到的：兩個對話都在查詢已不再列出的執行，而應用程式為每個對話都持有一個標示「請自行檢查」的請求。
- 由 GitHub CI 從 main 建置及發佈；此版本沒有在本機建置。
- 包含 0.8.91 的所有內容。
