# Coding Tools v0.8.135

## English

### Permissions work on every harness

- **The problem.** An Antigravity chat refused Ask for approval and Approve for me with "Choose Full access". Picking Full access then failed with "IPC_TRANSPORT_FAILED: apps.call failed: Select nonempty unique known supported mission role IDs", so the chat could not run at all. Pi, opencode and Unreal Agent had no permission menu. A chat moved onto one of them lost its permission mode and showed "Custom", which ran opencode with every tool allowed.
- **Why.** The app's saved-chat store took a permission pick only on Claude Code and Codex. The launch and the menu kept separate lists that disagreed with it.
- **What changed.**
  - Full access works on every harness. It is each agent's own "skip permissions" mode.
  - Every harness shows all three modes. Ask for approval and Approve for me run on Claude Code, Codex and Native Codex. On the other harnesses they are listed with the reason they can't run:
    - Antigravity and Cline ask in their own terminal, which the chat does not show.
    - Pi and Unreal Agent never ask before running a tool.
    - opencode allows every tool by its own default.
  - A chat sent in one of those modes stops at once with that reason. It no longer waits for good, runs unchecked, or retries eight times.
  - A chat keeps its permission mode when you switch harness.
- **Context window.** The window chip now says why it's off where it can't be set. Antigravity and Unreal Agent size their own window and have no setting for it. Pi takes a window only on CPA models. Where it can be set (Claude Code, Codex, Native Codex, opencode, Pi on CPA), it works as before.
- **Not changed.** Ask for approval and Approve for me on Antigravity, opencode and Pi need their agent to hand its tool requests to the chat. That is separate work in Agent Orchestrator.

## 繁體中文

### 每個 harness 都能使用權限設定

- **問題。** Antigravity 對話拒絕「要求核准」和「替我核准」，並提示「選擇完全存取」。但選了「完全存取」之後卻出現「IPC_TRANSPORT_FAILED: apps.call failed: Select nonempty unique known supported mission role IDs」，對話完全無法執行。Pi、opencode 和 Unreal Agent 沒有權限選單。對話切換到這些 harness 時會失去權限模式並顯示「自訂」，讓 opencode 在允許所有工具的情況下執行。
- **原因。** 應用程式儲存對話的地方只接受 Claude Code 和 Codex 的權限選擇，而啟動流程和選單各自保留了與它不一致的清單。
- **改了什麼。**
  - 「完全存取」在每個 harness 都能使用，對應各代理程式自己的「略過權限」模式。
  - 每個 harness 都會列出三種模式。「要求核准」和「替我核准」可在 Claude Code、Codex 和 Native Codex 上執行。在其他 harness 上，這兩種模式會列出無法使用的原因：
    - Antigravity 和 Cline 在自己的終端機裡詢問，對話看不到。
    - Pi 和 Unreal Agent 執行工具前從不詢問。
    - opencode 預設允許所有工具。
  - 以這些模式送出的對話會立即停止並說明原因，不會再無限等待、在無人審查下執行，或重試八次。
  - 切換 harness 時，對話會保留原本的權限模式。
- **上下文視窗。** 無法設定時，視窗按鈕現在會說明原因：Antigravity 和 Unreal Agent 會自行決定視窗大小，且沒有可調整的設定；Pi 只有在 CPA 模型上才能設定視窗。可以設定的 harness（Claude Code、Codex、Native Codex、opencode、CPA 上的 Pi）維持原本的行為。
- **沒有改變的部分。** 要讓 Antigravity、opencode 和 Pi 支援「要求核准」和「替我核准」，必須讓這些代理程式把工具請求交給對話，這是 Agent Orchestrator 中另外的工作。
