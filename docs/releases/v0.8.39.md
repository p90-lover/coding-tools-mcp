# Coding Tools 0.8.39

## English

### Chats
- Computer control can be turned on from a chat. Before, every chat saw "stopped" and agents asked you to "enable it in the app", which wasn't possible (PR #718).
  - When a chat asks for control, a window picker opens. Pick the window and how long (15 min, 5 min, or until stopped). The app's own windows aren't listed. A checkbox turns on screen capture for the project when it is off.
  - While control is on, a red bar stays on top of the screen showing the window and the time left, with a Stop button. Closing the bar stops control. Ctrl+Alt+Escape still stops it at once.
  - Only the app's own window can turn control on. If you cancel the picker, that chat's control calls are refused before anything reaches the screen, and it won't ask again for 5 minutes.
- The agent's questions and approval requests now show at the end of the conversation, right above the chat box, and scroll with it. Before, they sat under the chat box and took up to 420 px of the pane. In a split pane the conversation had no room left. A new request scrolls into view.
- A tool call that times out no longer stops the chat. Before, "Headless request timed out" showed "Step failed" and waited for a click, even with "Retry automatically" on. Now the chat keeps going by itself and shows one red line saying a tool call timed out (PR #722).
- "Retry automatically" no longer gives up when its own retry fails for a moment (for example while the local service restarts). It tries again after the next pause (PR #722).

### Browser
- `Coding Tools.exe --hidden --create-mcp-connector` runs the saved automatic MCP setup without a window. Setup also handles ChatGPT's current Add and Tunnel controls (PR #719).

### Verification and limitations
- Build the Windows installer, portable ZIP and update packs from this branch, and confirm CI before publication.
- Computer control was tested with unit and API tests, not yet with real windows.
- Everything in 0.8.38 is included.

## 繁體中文

### 對話
- 現在可以從對話開啟電腦控制。過去每個對話都只顯示「stopped」，代理會請你「在應用程式中啟用」，但其實無法做到（PR #718）。
  - 對話要求控制時，會開啟視窗選擇器。請選擇視窗及時長（15 分鐘、5 分鐘或直至停止）。清單不包括本應用程式自己的視窗。若專案的螢幕擷取未開啟，可勾選方塊開啟。
  - 控制開啟期間，畫面最上層會顯示紅色橫條，列出受控視窗及剩餘時間，並附有「停止」按鈕。關閉橫條即停止控制。Ctrl+Alt+Escape 仍可立即停止。
  - 只有本應用程式的視窗可以開啟控制。若你取消選擇器，該對話的控制操作會在影響畫面之前被拒絕，且 5 分鐘內不會再詢問。
- 代理的提問和批准請求現在顯示在對話末尾、對話框正上方，並隨對話捲動。過去它們位於對話框下方，最多佔用窗格 420 px。在分割窗格中，對話完全沒有空間顯示。有新請求時會自動捲動到可見位置。
- 工具呼叫逾時不再令對話停止。過去「Headless request timed out」會顯示「Step failed」並等待你點擊，即使已開啟「Retry automatically」亦然。現在對話會自行繼續，並以一行紅字顯示有工具呼叫逾時（PR #722）。
- 「Retry automatically」本身的重試若短暫失敗（例如本機服務正在重新啟動），不再就此放棄，而會在下一次暫停後再試（PR #722）。

### 瀏覽器
- `Coding Tools.exe --hidden --create-mcp-connector` 可在不開啟視窗的情況下執行已儲存的自動 MCP 設定。設定亦支援 ChatGPT 目前的「Add」及「Tunnel」控制項（PR #719）。

### 驗證及限制
- Windows 安裝程式、免安裝 ZIP 和更新檔需由本分支編譯及通過 CI 才能公開。
- 電腦控制已通過單元測試及 API 測試，但尚未在實際視窗上測試。
- 包含 0.8.38 的所有內容。
