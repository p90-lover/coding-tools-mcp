# Native Orchestrator: Coding Tools release gates

**Cutover is blocked.** The draft branch still uses AO at normal startup. Source-level tests and a green draft PR do not qualify an installed replacement. Record the exact Coding Tools tree, engine version/pin, command, result and fixture dependencies for each check.

- [ ] **Source and dependency boundary.** Trace `chat_input` through the focused-local module boundary, host outbox/attachment worker, atomic task/run acceptance, then the handler and selected engine. Confirm no renderer, untrusted plugin or chat arguments can enable `composeRuntime` or change a saved workspace, provider account, session, turn or approval lease. Check the exact backend/package module inventories, the vendored handler digest, and all native dependencies. Use source inspection and scoped tests; GitNexus is not part of this checkout's workflow.
- [ ] **Security.** Review bound SQL and structured request validation, the local confirmation and per-workspace capability guards, process ownership, and supported plugin config/load/unload. Confirm the supported sandbox and permission behavior with denial, expiry, wrong workspace/turn, and no credential fallback or persistence. Scan the integrated diff and assets for secrets and private data. Do not substitute the inert approval-fixture or the HTTP plugin discovery check for a full tool/sandbox sign-off.
- [ ] **Durability and affinity.** Verify Saving/Saved/Not saved, preserved newer typing, owned attachment bytes, commit before dispatch, exact task/run receipts, bounded outbox pages and no resend after ambiguous delivery. Check Native and legacy routing through the real app factory and verify approved live Native chats, including tools, approvals, steering and provider/session affinity. Existing AO chats must remain readable and unaffected until reversible migration passes.
- [ ] **Upgrade and rollback.** Use only an authorized finished export or an isolated pinned capture source. Rehearse archived data visibility, original source preservation and supported packaged rollback in an isolated profile. Do not read or copy live `ao.db`. Do not use an older release as evidence for a candidate that was not built.
- [ ] **Integrated CI and artifact identity.** Run the required checks on the same coordinated PR head (Electron, frontend, Rust including Windows/Linux and other required platforms, provider and package/security checks as applicable). Confirm source ancestry and verify actual published Windows installer, updater and other required asset hashes against the pinned workflow SHA and manifest. Use the single-owner release workflow; no local installer build as a substitute. Do not patch or restart the installed app for this task without separate authorization.

The input journal's schema 2 adds only a budgeted native follow-up target table; existing drafts and outbox rows retain their schema and contents. A schema-1 reader must refuse the newer journal. Verify the packaged rollback against a protected copy rather than downgrading the journal in place.

See [the handler boundary](../orchestrator-handler.md) and the independent engine's [release gates](https://github.com/p90-lover/Orchestrator/blob/main/docs/gates/GATES.md). These gates do not authorize a release or an installed change.
